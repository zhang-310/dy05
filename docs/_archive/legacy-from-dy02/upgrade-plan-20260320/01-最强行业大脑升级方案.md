## 二、6 大子系统差距分析

### 2.1 检索管线（KbHybridRetrieveServiceImpl）

| # | 差距 | 影响 | 优先级 |
|---|------|------|--------|
| S-1 | 无 HyDE（假设文档嵌入） | 模糊查询召回率低，`QueryRewriteServiceImpl.rewrite()` 仅生成替代查询 | P1 |
| S-2 | 无个性化排序 | `determineWeights()` 仅用查询特征，忽略 `AiUserCognitiveProfile`（已有实体未接入） | P0 |
| S-3 | 无同义词/语义扩展 | 领域术语（"直播"↔"live streaming"）漏召回 | P1 |
| S-4 | 无查询意图分类 | 所有查询统一处理，无法按 how-to/定义/对比 优化检索策略 | P2 |
| S-5 | Reranker 回退不完整 | 三级回退（Cohere→Custom→Ollama）中 LLM 评分未完全集成 | P1 |

**关键文件**：`KbHybridRetrieveServiceImpl.java`、`QueryRewriteServiceImpl.java`、`RerankerServiceImpl.java`

### 2.2 自进化引擎（EvolveEngineServiceImpl）

| # | 差距 | 影响 | 优先级 |
|---|------|------|--------|
| E-1 | 纯 Cron 调度 | 6 个 Agent 全部 `@Scheduled(cron=...)`，无法根据 KB 增长率/搜索未命中率自适应 | P0 |
| E-2 | 无多角度编排 | `runEvolution()` 随机采样角度，无系统覆盖保证 | P1 |
| E-3 | 无质量反馈闭环 | `KnowledgeQualityScoringService` 未接入用户反馈，低质量进化文档持续存在 | P0 |
| E-4 | 无跨进化依赖 | `AiEvolveTask` 无依赖字段，无法编排多阶段工作流 | P2 |
| E-5 | 无分角度 ROI 追踪 | `EvolveRoiService` 仅追踪整体 ROI，无法识别最有价值的进化角度 | P1 |
| E-6 | 无并发安全 | 多 Agent 可能同时修改同一文档（DeepEvolve + CrossDomainShare），无锁机制 | P0-Critical |

**关键文件**：`EvolveEngineServiceImpl.java`、`EvolveScheduler.java`、`DeepEvolveScheduler.java`、`EvolveRoiService.java`

### 2.3 LLM 工具调用（LlmToolOrchestratorService）

| # | 差距 | 影响 | 优先级 |
|---|------|------|--------|
| T-1 | 无工具依赖图 | `run()` 任意顺序执行，LLM 可能次优调用 | P2 |
| T-2 | 无输出 Schema 校验 | `executeRegisteredTool()` 返回原始字符串，畸形输出可能误导 LLM | P1 |
| T-3 | 工具结果缓存 | ✅ Redis：`ai:llm-tool:result:v1:*`，`app.ai.llm-tools.result-cache`；参数 JSON 键规范化 | P1 |
| T-4 | 无错误恢复策略 | 单工具失败终止整个编排，无自动重试/回退 | P0 |
| T-5 | 无性能监控 | 无 Micrometer 指标（执行时间/成功率/token 消耗） | P1 |
| T-6 | 无授权/限流 | 任何 LLM 可调用任何工具，无成本控制 | P0 |

**关键文件**：`LlmToolOrchestratorService.java`、`LlmRegisteredTool.java`

### 2.4 知识图谱（IndustryKnowledgeGraphServiceImpl）

| # | 差距 | 影响 | 优先级 |
|---|------|------|--------|
| G-1 | 无实体链接/消歧 | `extractEntityTokens()` 朴素 token 匹配，"直播"同时匹配"直播间"和"直播话术" | P0 |
| G-2 | 无关系类型推理 | 关系为预定义枚举，无法发现新兴模式 | P2 |
| G-3 | 无多跳遍历 | `getGraphContextForQuery()` 硬编码 1-hop，无法捕获复杂关系链 | P1 |
| G-4 | 无图谱新鲜度追踪 | `AiGraphNode`/`AiGraphEdge` 无 `lastUpdated`/`confidence`/`source` 字段 | P1 |
| G-5 | 无结构化子图返回 | 返回字符串而非结构化图，LLM 无法推理图结构 | P2 |
| G-6 | 无图谱一致性校验 | 无矛盾关系检测（如同时存在 competes_with 和 partners_with） | P2 |

**关键文件**：`IndustryKnowledgeGraphServiceImpl.java`、`AiGraphNode.java`、`AiGraphEdge.java`

### 2.5 前端 AI 页面

| F-6 | 无进化 ROI 可视化 | 报告仅原始分数，无成本收益分析 | P2 |

**关键文件**：`KnowledgeSearchPage.tsx`、`EvolutionTasksPage.tsx`、`AdminInfraPage.tsx`

## 三、分阶段实施计划

### Phase 1：安全与稳定性（Week 1-2，约 16h）

| 任务 | 工时 | 涉及文件 | 验收标准 |
|------|------|---------|---------|
| E-6 进化引擎并发安全 | 3h | `EvolveEngineServiceImpl`、`DeepEvolveScheduler` | Redis 分布式锁，同一文档不被并发修改 |
| T-4 工具调用错误恢复 | 3h | `LlmToolOrchestratorService` | 单工具失败自动重试 1 次 → 跳过 → 继续编排 |
| T-6 工具授权/限流 | 3h | `LlmToolOrchestratorService`、`RateLimiterConfiguration` | 每用户每分钟工具调用上限，按模型配置 |
| G-1 实体链接/消歧 | 4h | `IndustryKnowledgeGraphServiceImpl` | 基于 TF-IDF 的实体消歧，准确率 >80% |
| T-2 工具输出 Schema 校验 | 3h | `LlmRegisteredTool` | JSON Schema 校验，畸形输出自动重试 |

### Phase 2：核心能力补齐（Week 3-4，约 20h）

| 任务 | 工时 | 涉及文件 | 验收标准 |
|------|------|---------|---------|
| S-2 搜索个性化排序 | 5h | `KbHybridRetrieveServiceImpl`、`AiUserCognitiveProfile` | 用户画像接入 RRF 权重，个性化因子 ≤0.3 |
| E-1 自适应进化调度 | 4h | `EvolveScheduler`、`EvolveRoiService` | 基于 KB 健康度（搜索未命中率/文档新鲜度）动态调频 |
| E-3 质量反馈闭环 | 4h | `KnowledgeQualityScoringService` | 用户点赞/踩 → 文档质量分更新 → 低质量自动标记 |
| F-1 搜索自动补全 | 3h | `KnowledgeSearchPage.tsx`、新增 API | 基于搜索日志的 Top-K 动态建议 |
| F-3 分面搜索 | 4h | `KnowledgeSearchPage.tsx`、`KbHybridRetrieveServiceImpl` | 按文档类型/日期/来源 KB 过滤 |

### Phase 3：智能化提升（Week 5-6，约 18h）

| 任务 | 工时 | 涉及文件 | 验收标准 |
|------|------|---------|---------|
| S-1 HyDE 查询改写 | 5h | `QueryRewriteServiceImpl` | LLM 生成假设文档 → 嵌入 → 与原查询向量融合 |
| G-3 知识图谱多跳遍历 | 4h | `IndustryKnowledgeGraphServiceImpl` | 支持 2-hop 遍历，可配置深度 |
| T-3 工具结果缓存 | 3h | `LlmToolOrchestratorService`、`StringRedisTemplate` | 同用户同参命中缓存；默认 TTL 1h（可配）；Schema 变更自动剔除坏条 |
| B-1 GrowthPath 去模板化 | 3h | `GrowthPathServiceImpl` | 里程碑由战略规划输出驱动，无硬编码数组 |
| B-2 FiveHostsSynergy 配置化 | 3h | `FiveHostsSynergyServiceImpl`、`sys_config` | 协同文案迁入 `sys_config` 或 `ai_host_persona` 扩展字段 |

### Phase 4：闭环与可观测（Week 7-8，约 16h）

| 任务 | 工时 | 涉及文件 | 验收标准 |
|------|------|---------|---------|
| T-5 工具性能监控 | 3h | `LlmToolOrchestratorService`、Micrometer | 执行时间/成功率/token 消耗 Prometheus 指标 |
| E-5 分角度 ROI 追踪 | 4h | `EvolveRoiService` | 每个进化角度独立 ROI 指标 + 趋势 |
| F-5 搜索指标仪表盘 | 4h | 新增 `SearchMetricsDashboard.tsx` | 延迟/QPS/回退率/命中率实时可视化 |
| F-6 进化 ROI 可视化 | 3h | `EvolutionTasksPage.tsx` | 成本收益分析图表 + 分角度对比 |
| S-4 查询意图分类 | 2h | `QueryRewriteServiceImpl` | 3 类意图（how-to/定义/对比）→ 差异化检索策略 |
