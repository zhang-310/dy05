# 抖音运营 SaaS 系统 — 产品原型与全面升级方案

> 生成日期：2026-03-29  版本：v1.0  目标：单场 GMV 千万级 → 2000w/3000w

---

## 一、系统工作逻辑总览

### 1.1 核心价值链

```
账号绑定 → 商品准备 → 知识库沉淀 → AI话术生成 → 直播执行 → 数据回收 → 知识进化
  OAuth    卖点提炼   向量检索     RAG+槽位     实时面板   GMV归因   自进化引擎
```

### 1.2 三类用户角色

| 角色 | 核心场景 | 关键页面 |
|------|---------|----------|
| **Admin** | 全局配置、数据监控、AI基础设施 | Dashboard、知识库、进化引擎、系统配置 |
| **Org** | 场次审批、多达人协同、整体分析 | 场次列表、复盘审核、机构分析 |
| **Talent** | 选品排品、话术生成、直播执行 | 工作台、实时面板、短视频工作台 |

### 1.3 核心业务实体关系

```
账号(Account) ──→ 人设(Persona) ──→ 话术风格/语气基调
                        │
              ┌─────────▼──────────┐
              │   场次(Session)     │
              │  ┌───────────────┐ │←── 商品库(Product)
              │  │ 商品关联      │ │←── AI卖点 / 效果评分
              │  │ LiveProduct   │ │
              │  └───────┬───────┘ │
              │  ┌───────▼───────┐ │←── 知识库RAG
              │  │ 话术槽位      │ │←── PromptTemplate
              │  │ LiveScript    │ │←── 文案库复用
              │  └───────┬───────┘ │
              │  ┌───────▼───────┐ │
              │  │ 版本管理      │ │
              │  └───────────────┘ │
              └─────────┬──────────┘
                        │
              ┌─────────▼──────────┐
              │  归因分析 / GMV回收 │
              └────────────────────┘
```

## 六、技术约束与规范

| 约束项 | 规范 |
|--------|------|
| 数据获取 | `useQuery` + `queryFn`，避免 `useEffect` 手动 fetch |
| SSE流式 | `ssePost()` 工具函数，路径含 `-stream` 或 `-sse` |
| 列表页面 | 统一用 `StandardDataGrid` + 服务端分页 |
| 图表 | `ReactECharts`，height 固定 px，option 抽离变量 |
| 状态管理 | Zustand store（liveGenStore/liveProductStore） |
| 类型安全 | `noUnusedLocals` 严格，unknown 类型用 String() 转换 |
| CDN图片 | 缩略图 `url+'@!80X80'`，预览 `url+'@!300X250'` |
| Toast | `const toast = useToast(); toast('msg', 'success')` |
| Grid | MUI legacy: `<Grid item xs={12} sm={6}>` |
