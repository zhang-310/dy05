## 5.1 任务生命周期

### 5.1.1 状态机

```
                    ┌─────────────────────────────────────┐
                    │                                     │
  触发（定时/手动）   │                                     │
        │           │                                     │
        ▼           ▼                                     │
  ┌──────────┐   用户取消                                  │
  │  0=待执行 │──────────────────────────────────────────►│
  └────┬─────┘                                            │
       │                                                  │
       │ MQ Consumer 消费                                  │
       ▼                                                  │
  ┌──────────┐   超时 / 执行异常 / 用户取消                  │
  │  1=执行中 │──────────────────────────────────────────►│
  └────┬─────┘                                            │
       │                                                  ▼
       │ 执行成功                                    ┌──────────┐
       ▼                                            │  3=失败   │
  ┌──────────┐                                      └──────────┘
  │  2=已完成 │
  └──────────┘
```

### 5.1.2 状态转换规则

| 当前状态 | 目标状态 | 触发条件 | 操作 |
|---------|---------|---------|------|
| — | 0=待执行 | 定时调度器触发 / 用户手动触发 | 创建 agent_task，发送 MQ |
| 0=待执行 | 1=执行中 | MQ Consumer 开始消费 | 更新 status=1，记录 start_time |
| 0=待执行 | 3=失败 | 用户取消 | 更新 status=3，error_message="用户取消" |
| 1=执行中 | 2=已完成 | 执行成功，报告写入完成 | 更新 status=2，记录 end_time、result_summary |
| 1=执行中 | 3=失败 | 执行异常 / 超时 / 用户取消 | 更新 status=3，记录 error_message |
| 2=已完成 | — | 不可转换 | — |
| 3=失败 | — | 不可转换（需重新触发） | — |

## 5.2 异步执行架构

### 5.2.1 RabbitMQ 配置

```
Exchange：agent.exchange（Direct Exchange）
Queue：agent.task.execute
Routing Key：agent.task.execute
Dead Letter Queue：agent.task.dlq（失败消息转入）
消息 TTL：无（由任务超时机制控制）
```

### 5.2.2 消息格式

```json
{
  "taskId": 101,
  "agentId": 1,
  "agentType": "data_analysis",
  "ownerId": 1001,
  "triggerTime": "2026-02-24T09:00:00"
}
```

### 5.2.3 Consumer 处理逻辑

```java
@RabbitListener(queues = "agent.task.execute")
public void handleTask(AgentTaskMessage message) {
    Long taskId = message.getTaskId();

    // 1. 查询任务，校验状态（防止重复消费）
    AgentTask task = agentTaskRepository.findById(taskId);
    if (task.getStatus() != 0) {
        log.warn("任务 {} 状态异常，跳过执行: status={}", taskId, task.getStatus());
        return;
    }

    // 2. 更新状态为执行中
    task.setStatus(1);
    task.setStartTime(LocalDateTime.now());
    agentTaskRepository.save(task);

    // 3. 设置超时监控
    Future<?> future = executorService.submit(() -> executeAgent(task));
    try {
        future.get(TASK_TIMEOUT_MINUTES, TimeUnit.MINUTES);
    } catch (TimeoutException e) {
        future.cancel(true);
        failTask(task, "任务执行超时（超过 " + TASK_TIMEOUT_MINUTES + " 分钟）");
    } catch (Exception e) {
        failTask(task, e.getMessage());
    }
}
```

### 5.2.4 超时处理

- 超时时间：默认 10 分钟（可通过 `AGENT_TASK_TIMEOUT_MINUTES` 环境变量配置）
- 超时后：`status=3`，`error_message="任务执行超时（超过 10 分钟）"`
- 超时的任务不生成报告
- 用户可重新手动触发

## 5.3 报告生成流程

### 5.3.1 报告生成时序

```
AgentTaskConsumer
      │
      ├── 1. 调用对应 Agent 的 execute() 方法
      │         │
      │         ├── 2. 拉取业务数据（douyin/shortvideo/live）
      │         │
      │         ├── 3. 数据预处理（计算指标、格式化）
      │         │
      │         ├── 4. 构建 Prompt（系统提示 + 数据上下文 + 生成指令）
      │         │
      │         ├── 5. 调用 AiGenerateService.generate()
      │         │         └── 记录 ai_call_log_id
      │         │
      │         ├── 6. 解析 LLM 输出
      │         │         ├── 提取 report_content（Markdown 正文）
      │         │         └── 提取 report_data（结构化 JSON）
      │         │
      │         └── 7. 返回 AgentExecuteResult
      │
      ├── 8. 写入 agent_report
      │         ├── report_title（自动生成，如"2026年第8周数据分析报告"）
      │         ├── report_content（Markdown）
      │         ├── report_data（JSON）
      │         ├── period_start / period_end
      │         └── is_read=0（默认未读）
      │
      └── 9. 更新 agent_task
                ├── status=2
                ├── result_summary（从 report_data 提取摘要）
                ├── ai_call_log_id
                └── end_time
```

### 5.3.2 Prompt 构建策略

每类智能体使用独立的 Prompt 模板，模板存储在代码中（非数据库），通过 `PromptTemplate` 类管理：

```
系统提示（System Prompt）：
  - 角色定义（你是一个专业的抖音运营数据分析师...）
  - 输出格式要求（必须返回 JSON，包含 reportContent 和 reportData 两个字段）
  - 语言要求（使用中文）

用户提示（User Prompt）：
  - 分析任务描述
  - 数据上下文（格式化的业务数据）
  - 具体分析指令
  - 输出结构示例
```

### 5.3.3 LLM 输出解析

要求 LLM 返回固定 JSON 格式，便于解析：

```json
{
  "reportContent": "## 本周数据概览\n\n...",
  "reportData": {
    "summary": { },
    "charts": [ ],
    "recommendations": [ ]
  },
  "resultSummary": "本周播放量增长23%，发现2条爆款视频"
}
```

解析失败时（LLM 返回格式不符）：
- 将原始 LLM 输出作为 `report_content` 存储
- `report_data` 置为空 JSON `{}`
- 任务仍标记为 `status=2`（已完成），不因格式问题失败

## 5.5 任务执行监控

### 5.5.1 执行统计

`/api/v1/agent/status` 接口返回的统计数据来源：

```sql
-- 总任务数
SELECT COUNT(*) FROM agent_task
WHERE agent_id = ? AND deleted = 0;

-- 成功任务数
SELECT COUNT(*) FROM agent_task
WHERE agent_id = ? AND status = 2 AND deleted = 0;

-- 未读报告数
SELECT COUNT(*) FROM agent_report
WHERE owner_id = ? AND is_read = 0 AND deleted = 0;
```

### 5.5.2 失败重试策略

当前版本不自动重试失败任务，原因：
1. 智能体任务通常依赖特定时间窗口的数据（如上周数据），自动重试可能产生重复报告
2. 失败原因多样（数据不足、LLM 超时、配置错误），需用户确认后手动重新触发

失败任务处理流程：
1. 任务标记为 `status=3`，记录 `error_message`
2. 用户在任务历史页面查看失败原因
3. 用户修正配置后手动重新触发

### 5.5.3 并发控制

同一智能体同时只允许一个任务处于 `status=0` 或 `status=1` 状态：

```java
// 触发前检查
int runningCount = agentTaskRepository.countByAgentIdAndStatusIn(
    agentId, List.of(0, 1)
);
if (runningCount > 0) {
    throw new AgentException(AgentErrorCode.AGENT_ALREADY_RUNNING);
}
```

不同智能体（不同 agentId）之间不互相阻塞，可并发执行。
