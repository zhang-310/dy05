| 类型 | 常量值 | 中文名 | 触发方式 | 数据来源 | 输出报告类型 |
|------|--------|--------|---------|---------|------------|

## 4.2 数据分析智能体（data_analysis）

### 4.2.1 功能描述

自动汇总指定账号在分析周期内的短视频运营数据，识别增长趋势、爆款规律、发布时间规律，生成结构化周报。

### 4.2.2 config_json Schema

```json
{
  "$schema": "agent_config/data_analysis/v1",
  "accountIds": [101, 102],
  "analysisPeriodDays": 7,
  "includeViralAnalysis": true,
  "includePublishTimeRecommend": true,
  "includeCompetitorBenchmark": false,
  "reportLanguage": "zh-CN"
}
```

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| accountIds | number[] | 是 | — | 分析的抖音账号 ID 列表（必须属于当前用户） |
| analysisPeriodDays | number | 否 | 7 | 分析周期天数（7=周报，30=月报） |
| includeViralAnalysis | boolean | 否 | true | 是否包含爆款分析章节 |
| includePublishTimeRecommend | boolean | 否 | true | 是否包含最佳发布时间推荐 |
| includeCompetitorBenchmark | boolean | 否 | false | 是否包含同行业对标分析（需要爆款库数据） |
| reportLanguage | string | 否 | "zh-CN" | 报告语言 |

### 4.2.3 执行流程

```
1. 读取 config_json，确定 accountIds 和分析周期
2. 从 shortvideo 模块拉取数据：
   - sv_video_data：周期内每日数据快照（播放量/点赞/评论/分享）
   - sv_video：发布的视频列表（标题、发布时间、is_viral）
   - sv_viral_video：周期内新增爆款（如 includeViralAnalysis=true）
   - sv_hot_topic：当前热点话题（用于内容建议）
3. 计算关键指标：
   - 总播放量、环比增长率
   - 平均互动率（点赞+评论+分享 / 播放量）
   - 爆款视频数量和爆款率
   - 最佳发布时间段（如 includePublishTimeRecommend=true）
4. 构建 Prompt（数据上下文 + 分析指令）
5. 调用 ai 模块 LLM 生成报告正文（Markdown）
6. 解析 LLM 输出，提取结构化数据（图表数据、建议列表）
7. 写入 agent_report（report_type=weekly_analysis）
8. 更新 agent_task（status=2，result_summary）
```

## 4.3 脚本策划智能体（script_planning）

### 4.3.1 功能描述

结合当前热点话题、历史爆款规律和账号人设，自动规划下一周的内容日历，为每天生成拍摄主题和脚本建议。

### 4.3.2 config_json Schema

```json
{
  "$schema": "agent_config/script_planning/v1",
  "accountId": 101,
  "personaId": 201,
  "planningDays": 7,
  "videosPerDay": 1,
  "contentCategories": ["教程", "日常", "热点"],
  "hotTopicCategories": ["美妆", "生活"],
  "referenceViralCount": 5,
  "scriptDetailLevel": "outline"
}
```

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| accountId | number | 是 | — | 目标抖音账号 ID |
| personaId | number | 是 | — | 使用的人设 ID（来自 douyin 模块） |
| planningDays | number | 否 | 7 | 规划天数 |
| videosPerDay | number | 否 | 1 | 每天计划发布视频数 |
| contentCategories | string[] | 否 | [] | 内容类别偏好 |
| hotTopicCategories | string[] | 否 | [] | 关注的热点类别 |
| referenceViralCount | number | 否 | 5 | 参考的爆款视频数量 |
| scriptDetailLevel | string | 否 | "outline" | 脚本详细程度：outline=大纲 / detailed=详细分镜 |

### 4.3.3 执行流程

```
1. 读取 config_json，获取 accountId、personaId
2. 从 douyin 模块拉取人设信息（人设描述、风格、目标受众）
3. 从 shortvideo 模块拉取数据：
   - sv_hot_topic：当前有效热点话题（按 heat_score 排序，取 Top 20）
   - sv_viral_video：近期爆款视频（取 referenceViralCount 条）
   - sv_video_data：该账号近 30 天表现最好的视频（按互动率排序）
4. 构建 Prompt：
   - 人设信息（风格、受众、调性）
   - 热点话题列表（话题名、热度、类别）
   - 爆款参考（标题、播放量、成功因素摘要）
   - 历史高互动内容（标题、互动率）
   - 规划指令（planningDays 天，每天 videosPerDay 条）
5. 调用 ai 模块 LLM 生成内容日历和脚本建议
6. 解析输出，结构化为 report_data
7. 写入 agent_report（report_type=content_plan）
```

## 4.4 直播复盘智能体（live_review）

### 4.4.1 功能描述

直播结束后，自动拉取场次数据，分析直播表现，识别高峰时段、流失节点、转化效率，生成结构化复盘报告和改进建议。

### 4.4.2 config_json Schema

```json
{
  "$schema": "agent_config/live_review/v1",
  "accountId": 101,
  "autoTriggerOnEnd": true,
  "minDurationMinutes": 30,
  "includeAudienceAnalysis": true,
  "includeProductAnalysis": true,
  "benchmarkPeriodDays": 30
}
```

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| accountId | number | 是 | — | 目标抖音账号 ID |
| autoTriggerOnEnd | boolean | 否 | true | 直播结束后是否自动触发（监听 live 模块事件） |
| minDurationMinutes | number | 否 | 30 | 最短直播时长（分钟），低于此值不触发复盘 |
| includeAudienceAnalysis | boolean | 否 | true | 是否包含观众分析章节 |
| includeProductAnalysis | boolean | 否 | true | 是否包含商品转化分析章节 |
| benchmarkPeriodDays | number | 否 | 30 | 对标历史场次的天数范围 |

### 4.4.3 执行流程

```
1. 读取 input_params 中的 sessionId（直播场次 ID）
2. 从 live 模块拉取数据：
   - live_session：场次基本信息（开始/结束时间、时长）
   - live_session_data：分钟级数据（在线人数、点赞、评论、礼物、商品点击）
3. 计算关键指标：
   - 峰值在线人数及出现时间
   - 平均在线人数
   - 观众留存率（结束时在线 / 峰值在线）
   - 互动率（点赞+评论 / 累计观看）
   - 商品点击率（如 includeProductAnalysis=true）
4. 识别关键节点：
   - 人数增长最快的时间段（引流高峰）
   - 人数下降最快的时间段（流失节点）
   - 互动高峰时间段
5. 与历史场次对标（benchmarkPeriodDays 内的平均值）
6. 构建 Prompt（数据上下文 + 复盘指令）
7. 调用 ai 模块 LLM 生成复盘报告正文
8. 写入 agent_report（report_type=live_review）
```

## 4.5 智能体执行流程总图

```
定时调度器（AgentScheduler）          用户手动触发
        │                                  │
        │ 扫描 status=1 且 Cron 到期的配置   │ POST /agent/task/trigger
        │                                  │
        └──────────────┬───────────────────┘
                       │
                       ▼
              创建 agent_task（status=0）
                       │
                       ▼
          发送 MQ 消息（agent.task.execute）
                       │
                       ▼
          AgentTaskConsumer 消费消息
                       │
                       ├── 更新 task status=1（执行中）
                       │
                       ├── 根据 agent_type 路由到对应 Agent
                       │       ├── DataAnalysisAgent
                       │       ├── ScriptPlanningAgent
                       │       └── LiveReviewAgent
                       │
                       ├── 拉取数据（douyin/shortvideo/live）
                       │
                       ├── 构建 Prompt
                       │
                       ├── 调用 AiGenerateService（记录 ai_call_log_id）
                       │
                       ├── 解析结果，生成 report_content + report_data
                       │
                       ├── 写入 agent_report
                       │
                       └── 更新 agent_task（status=2，result_summary）
                                   │
                              ┌────┴────┐
                              │ 失败时   │
                              ▼         ▼
                         status=3   error_message
                         记录错误原因
```

## 4.6 定时调度设计

### 调度器实现

```java
@Component
public class AgentScheduler {

    // 每分钟扫描一次，检查是否有 Cron 到期的智能体
    @Scheduled(cron = "0 * * * * ?")
    public void checkAndTrigger() {
        // 1. 查询所有 status=1（启用）且 schedule_cron 不为空的配置
        // 2. 用 CronExpression 计算上次应触发时间
        // 3. 若 last_run_time < 上次应触发时间，则触发
        // 4. 防重复：检查是否已有 status=0/1 的任务
    }
}
```

### 默认 Cron 建议

| 智能体类型 | 推荐 Cron | 说明 |
|-----------|-----------|------|
| data_analysis | `0 0 9 ? * MON` | 每周一早 9 点，分析上周数据 |
| script_planning | `0 0 10 ? * FRI` | 每周五早 10 点，规划下周内容 |
| live_review | 不设定时，依赖事件触发 | 直播结束后自动触发 |

### 直播结束事件触发

当 live 模块直播场次结束时，发布 `LiveSessionEndEvent`，agent 模块监听该事件：

```java
@EventListener
public void onLiveSessionEnd(LiveSessionEndEvent event) {
    // 查找该账号下 autoTriggerOnEnd=true 的 live_review 智能体配置
    // 检查直播时长 >= minDurationMinutes
    // 创建 triggered 类型任务，input_params 中写入 sessionId
}
```
