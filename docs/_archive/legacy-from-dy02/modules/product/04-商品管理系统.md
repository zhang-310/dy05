## 4.1 商品 CRUD 流程

### 4.1.1 新增商品

```
前端提交表单
    │
    ▼
ProductController.save(ProductSaveReqVO)
    │
    ├─ 校验必填字段（productName, price）
    ├─ 设置 user_id = 当前登录用户
    ├─ 设置默认值：status=1, featured=0, inventory=0
    │
    ▼
ProductService.save(product)
    │
    ▼
ProductRepository.save(entity)
    │
    ▼
返回新商品 ID（Long）
```

### 4.1.2 更新商品

```
前端提交表单（含 id）
    │
    ▼
ProductController.save(ProductSaveReqVO)
    │
    ├─ id 不为空 → 走更新逻辑
    ├─ 查询商品是否存在 → 不存在抛 3105
    ├─ 校验 user_id 归属 → 不匹配抛 3112
    │
    ▼
ProductService.update(product)
    │
    ▼
ProductRepository.save(entity)（JPA merge）
    │
    ▼
返回商品 ID（Long）
```

### 4.1.3 删除商品

```
前端传入 id
    │
    ▼
ProductController.delete(id)
    │
    ├─ 查询商品是否存在 → 不存在抛 3105
    ├─ 校验 user_id 归属 → 不匹配抛 3112
    │
    ▼
ProductService.delete(id)
    │
    ▼
UPDATE dy_product SET deleted=1 WHERE id=?
（逻辑删除，不物理删除）
```

### 4.1.4 查询商品详情

```
前端传入 id
    │
    ▼
ProductController.get(id)
    │
    ├─ 查询商品（deleted=0）→ 不存在抛 3105
    ├─ 校验 user_id 归属 → 不匹配抛 3112
    │
    ▼
返回 ProductVO（完整字段）
```

## 4.2 商品状态机

```
                    ┌─────────────────┐
                    │                 │
         publish    │    上架（1）     │    unpublish
    ┌──────────────▶│   status = 1    │──────────────┐
    │               │                 │              │
    │               └─────────────────┘              │
    │                                                │
    │               ┌─────────────────┐              │
    │               │                 │              │
    └───────────────│    下架（0）     │◀─────────────┘
                    │   status = 0    │
                    │                 │
                    └─────────────────┘
                           │
                    新建商品默认 status=1
```

### 状态转换规则

| 操作 | 接口 | 前置状态 | 后置状态 | 说明 |
|------|------|---------|---------|------|
| 上架 | POST /publish | 0（下架） | 1（上架） | 商品可被直播选品 |
| 下架 | POST /unpublish | 1（上架） | 0（下架） | 商品不再展示 |
| 新建 | POST /save | — | 1（上架） | 默认上架 |
| 删除 | POST /delete | 任意 | deleted=1 | 逻辑删除 |

## 4.3 推荐标记管理

### 4.3.1 推荐标记说明

featured 字段控制商品在直播选品时的排序优先级：

| featured 值 | 含义 | 直播选品排序 |
|------------|------|------------|
| 0 | 普通商品 | 按 create_time DESC 排序 |
| 1 | 推荐商品 | 排在所有普通商品之前 |

### 4.3.2 设置推荐流程

```
POST /api/v1/product/set-featured
    │
    ├─ 参数：{ id, featured }
    ├─ 校验商品存在 → 不存在抛 3105
    ├─ 校验 user_id 归属 → 不匹配抛 3112
    │
    ▼
UPDATE dy_product SET featured=? WHERE id=?
```

### 4.3.3 直播选品查询排序

```sql
SELECT * FROM dy_product
WHERE user_id = ? AND status = 1 AND deleted = 0
ORDER BY featured DESC, create_time DESC
```

推荐商品（featured=1）始终排在前面，同等 featured 值内按创建时间倒序。

## 4.4 库存管理

### 4.4.1 库存更新流程

```
POST /api/v1/product/update-inventory
    │
    ├─ 参数：{ id, quantity }
    ├─ 校验 quantity >= 0 → 负数返回参数错误
    ├─ 校验商品存在 → 不存在抛 3105
    ├─ 校验 user_id 归属 → 不匹配抛 3112
    │
    ▼
UPDATE dy_product SET inventory=? WHERE id=?
（直接设置，非增减）
```

### 4.4.2 库存字段说明

| 场景 | 操作 | 说明 |
|------|------|------|
| 初始入库 | save（inventory=N） | 新建商品时设置初始库存 |
| 补货 | update-inventory（quantity=新总量） | 直接设置新库存总量 |
| 盘点 | update-inventory（quantity=实际数量） | 盘点后修正库存 |
| 销售扣减 | 由 live 模块或手动调用 update-inventory | 销售后更新剩余库存 |

**注意：** update-inventory 是直接设置库存总量，不是增减操作。如需扣减，调用方需先查询当前库存再计算新值。

## 4.5 数据隔离

### 4.5.1 隔离机制

所有商品操作均基于 user_id 进行数据隔离：

```
用户 A（user_id=100）         用户 B（user_id=200）
    │                              │
    ▼                              ▼
dy_product(user_id=100)    dy_product(user_id=200)
    │                              │
    └──── 完全隔离，互不可见 ────────┘
```

### 4.5.2 隔离实现

**查询时自动附加 user_id 条件：**

```java
// ProductService.search
Specification<Product> spec = (root, query, cb) -> {
    List<Predicate> predicates = new ArrayList<>();
    predicates.add(cb.equal(root.get("userId"), currentUserId));
    predicates.add(cb.equal(root.get("deleted"), 0));
    // ... 其他筛选条件
    return cb.and(predicates.toArray(new Predicate[0]));
};
```

**操作时校验归属：**

```java
// ProductService.checkOwnership
Product product = productRepository.findById(id)
    .orElseThrow(() -> new BusinessException(ErrorCode.PRODUCT_NOT_FOUND));
if (!product.getUserId().equals(currentUserId)) {
    throw new BusinessException(ErrorCode.PRODUCT_FORBIDDEN);
}
```

### 4.5.3 错误码映射

| 场景 | 错误码 | 说明 |
|------|--------|------|
| 商品 ID 不存在（deleted=1 或不存在） | 3105 | PRODUCT_NOT_FOUND |
| 商品存在但不属于当前用户 | 3112 | PRODUCT_FORBIDDEN |

## 4.6 搜索与筛选逻辑

### 4.6.1 关键词搜索

keyword 参数同时匹配以下字段（OR 逻辑）：

```sql
WHERE (
    product_name LIKE '%keyword%'
    OR sku LIKE '%keyword%'
    OR barcode LIKE '%keyword%'
)
AND user_id = ?
AND deleted = 0
```

### 4.6.2 组合筛选

多个筛选条件之间为 AND 逻辑：

```sql
WHERE user_id = ?
  AND deleted = 0
  AND (keyword 条件，如有)
  AND product_category = ? (如有)
  AND status = ? (如有)
  AND featured = ? (如有)
ORDER BY featured DESC, create_time DESC
```

### 4.6.3 分页

使用 Spring Data JPA Pageable 实现分页，pageNum 从 1 开始，内部转换为 0-based offset。
