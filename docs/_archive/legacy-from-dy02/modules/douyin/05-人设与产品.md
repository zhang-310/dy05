## 5.1 人设系统设计

### 5.1.1 人设概念

人设（Persona）是 AI 内容生成的核心参数。所有 AI 生成（短视频文案、直播话术、产品讲解）都需要人设作为上下文输入，确保生成内容风格一致、符合账号定位。

```
人设字段 → AI Prompt 映射：
┌──────────────────────────────────────────────────────────┐
│  persona_name    → "你是{persona_name}"                   │
│  positioning     → "你的定位是{positioning}"               │
│  style           → "你的风格是{style}"                     │
│  tags            → "你的内容标签包括{tags}"                 │
│  target_audience → "你的目标受众是{target_audience}"        │
│  tone            → "你的说话方式是{tone}"                   │
│  description     → "补充说明：{description}"               │
└──────────────────────────────────────────────────────────┘
```

### 5.1.2 人设 CRUD

**创建人设：**

```
用户填写表单
    │
    ├── 必填：personaName（最长 64 字符）
    ├── 选填：positioning / style / tags / targetAudience / tone / description
    ├── 选填：accountId（关联特定账号，不填则为通用人设）
    │
    ├── 后端校验：
    │   ├── personaName 不为空
    │   ├── accountId 如果填写，必须属于当前用户
    │   └── 设置 owner_id = 当前用户 ID
    │
    ├── 首个人设自动激活：
    │   └── 查询用户人设数量，如果为 0 则设置 is_active=1
    │
    └── 保存到 dy_persona
```

**编辑人设：**
- 校验 owner_id 必须是当前用户
- 更新指定字段
- 如果修改了激活人设的内容，后续 AI 生成会使用新内容

**删除人设（BR-12 删除保护）：**

```
删除请求
    │
    ├── 校验 1：是否为唯一人设？
    │   └── 是 → 拒绝删除，返回 3202
    │
    ├── 校验 2：是否为激活人设？
    │   └── 是 → 自动激活最早创建的其他人设
    │           UPDATE dy_persona SET is_active=1
    │           WHERE owner_id=? AND id!=? AND deleted=0
    │           ORDER BY create_time ASC LIMIT 1
    │
    ├── 逻辑删除：UPDATE dy_persona SET deleted=1 WHERE id=?
    │
    └── 关联数据处理：
        ├── sv_plan 中的 persona_id 保留历史值（不清空）
        └── live_session 中的 persona_id 保留历史值（不清空）
```

### 5.1.3 激活切换

每个用户有且仅有一个激活人设（is_active=1），AI 生成默认使用激活人设。

**切换流程（事务内）：**

```sql
-- 步骤 1：取消当前激活
UPDATE dy_persona SET is_active = 0, update_time = NOW()
WHERE owner_id = :userId AND is_active = 1 AND deleted = 0;

-- 步骤 2：激活目标人设
UPDATE dy_persona SET is_active = 1, update_time = NOW()
WHERE id = :personaId AND owner_id = :userId AND deleted = 0;
```

**获取当前激活人设：**

```sql
SELECT * FROM dy_persona
WHERE owner_id = :userId AND is_active = 1 AND deleted = 0;
```

## 5.2 人设模板系统

### 5.2.1 模板设计

人设模板由管理员维护，用户可浏览并从模板创建自己的人设。模板是只读的（BR-06），用户使用模板时复制内容为独立记录。

**系统预设模板：**

| 模板名称 | 分类 | 定位 | 风格 | 目标受众 | 口吻 |
|---------|------|------|------|---------|------|
| 美妆博主 | 美妆 | 平价美妆分享 | 亲切 | 18-30岁女性 | 闺蜜聊天 |
| 健身达人 | 健身 | 家庭健身教练 | 专业 | 20-40岁男女 | 教练指导 |
| 美食探店 | 美食 | 本地美食探店 | 幽默 | 18-35岁 | 吃货分享 |
| 电商带货 | 电商 | 好物推荐官 | 激情 | 25-45岁 | 促销讲解 |
| 知识博主 | 教育 | 行业知识分享 | 专业 | 22-40岁 | 专家讲解 |

### 5.2.2 从模板创建人设

```
用户选择模板
    │
    ├── 查询 dy_persona_template（status=1）
    │
    ├── 复制字段到新的 dy_persona：
    │   ├── persona_name ← template_name
    │   ├── positioning ← positioning
    │   ├── style ← style
    │   ├── tags ← tags
    │   ├── target_audience ← target_audience
    │   ├── tone ← tone
    │   └── description ← description
    │
    ├── 设置 owner_id = 当前用户
    ├── 设置 account_id = 用户指定（可选）
    │
    ├── 首个人设自动激活
    │
    └── 用户可后续编辑修改（独立于模板）
```

### 5.2.3 管理端模板管理

管理员通过管理端维护模板：

| 操作 | 接口 | 说明 |
|------|------|------|
| 模板列表 | POST /api/v1/douyin/admin/template/list | 分页查询，支持按分类筛选 |
| 新增/编辑 | POST /api/v1/douyin/admin/template/save | 填写模板各字段 |
| 删除 | POST /api/v1/douyin/admin/template/delete | 逻辑删除，不影响已从模板创建的人设 |

## 5.3 人设与 AI 生成的关系

### 5.3.1 人设作为 AI 核心参数

```
┌─────────────────────────────────────────────────────────────┐
│                    人设在 AI 生成中的角色                       │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  shortvideo 模块                                            │
│  ├── AI 文案生成 → 需要人设（定位/风格/受众）                  │
│  ├── 爆款复刻 → 需要人设（保持风格一致）                      │
│  ├── 热点创作 → 需要人设（角度选择）                          │
│  └── 每日拍摄脚本 → 需要人设（内容方向）                      │
│                                                             │
│  live 模块                                                  │
│  ├── 开场话术 → 需要人设（口吻/风格）                         │
│  ├── 产品话术 → 需要人设 + 产品信息                           │
│  ├── 转场话术 → 需要人设（过渡风格）                          │
│  ├── 结尾话术 → 需要人设（收尾风格）                          │
│  └── 整场话术 → 需要人设 + 全部产品                           │
│                                                             │
│  douyin 模块（本模块）                                       │
│  └── 产品话术 AI 生成 → 需要人设 + 产品 + 风格                │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 5.3.2 AI 调用时的人设传递

```java
// 获取人设信息（优先使用指定的，否则使用激活的）
DouyinPersona persona;
if (personaId != null) {
    persona = personaService.getById(personaId);
    // 校验 owner_id
} else {
    persona = personaService.getActivePersona(userId);
}

// 构建 AI 上下文
Map<String, Object> context = new HashMap<>();
context.put("persona_name", persona.getPersonaName());
context.put("positioning", persona.getPositioning());
context.put("style", persona.getStyle());
context.put("tags", persona.getTags());
context.put("target_audience", persona.getTargetAudience());
context.put("tone", persona.getTone());
context.put("description", persona.getDescription());
```

## 5.4 产品管理

### 5.4.1 产品数据模型

产品关联到抖音账号（account_id），一个账号下可有多个产品。产品是直播带货的基础数据，live 模块从产品库选品。

```
dy_account
    │
    └─── dy_product（一对多）
              │
              ├── 基本信息：名称/图片/价格/原价
              ├── 营销信息：卖点/场景/受众
              ├── 分类标签：category
              │
              └─── dy_product_script（一对多，多套话术）
                        ├── 种草版
                        ├── 促销版
                        ├── 专业讲解版
                        └── 亲切推荐版
```

### 5.4.2 产品 CRUD

**添加产品：**
- 必填：accountId、productName
- 校验 accountId 对应的账号属于当前用户
- 设置 owner_id = 当前用户

**编辑产品：**
- 校验 owner_id 必须是当前用户
- 更新指定字段

**删除产品：**
- 逻辑删除产品（deleted=1）
- 级联逻辑删除关联的话术（dy_product_script.deleted=1）

**产品列表：**
- 按 account_id 筛选
- 支持按 category 筛选
- 支持关键词搜索（product_name LIKE）
- 分页返回

### 5.4.3 产品与直播场次的关联

产品被 live 模块的直播场次选用：

```
dy_product ←── live_session_product（场次-产品关联表）
                    │
                    ├── product_id → dy_product.id
                    ├── product_name（冗余，避免跨模块查询）
                    ├── position（上播顺序）
                    └── script_source（话术来源：product/session）
                            │
                            ├── product → 引用 dy_product_script 中的话术
                            └── session → 为本场直播重新 AI 生成
```

## 5.5 产品话术系统

### 5.5.1 话术设计

一个产品可有多套话术（BR-10），按风格区分：

| 风格 | script_style | 适用场景 | 特点 |
|------|-------------|---------|------|
| 种草 | seeding | 日常直播、短视频 | 真实体验分享，像朋友推荐 |
| 促销 | promotion | 大促直播、限时活动 | 紧迫感、价格对比、限量 |
| 专业讲解 | professional | 知识型直播 | 成分分析、数据对比、专业术语 |
| 亲切推荐 | friendly | 日常直播 | 温和、贴心、生活化 |

### 5.5.2 话术 CRUD

**新增话术（手动）：**
- 用户手动编写话术内容
- is_ai_generated = 0
- 填写 script_name / script_style / content / duration_hint

**编辑话术：**
- AI 生成的话术也可以手动编辑
- 编辑后 is_ai_generated 保持不变（记录原始来源）

**删除话术：**
- 逻辑删除
- 如果话术被 live_session_product 引用，引用记录中的 product_script_id 保留历史值

### 5.5.3 AI 生成话术

```
AI 生成产品话术流程：
    │
    ├── 输入：
    │   ├── 产品信息（名称/价格/原价/卖点/场景/受众/描述）
    │   ├── 人设信息（定位/风格/标签/受众/口吻/描述）
    │   └── 话术风格（种草/促销/专业讲解/亲切推荐）
    │
    ├── 调用 ai 模块：
    │   ├── 模板：live_script_product
    │   ├── 传入：product + persona + style
    │   └── 返回：话术内容 + 建议时长
    │
    ├── 保存结果：
    │   ├── 写入 dy_product_script
    │   ├── is_ai_generated = 1
    │   ├── ai_call_log_id = AI 调用记录 ID
    │   ├── persona_id = 使用的人设 ID
    │   └── script_name = "{风格}版"（如"种草版"）
    │
    └── 返回：话术内容 + 剩余 AI 额度
```

**AI Prompt 示例（live_script_product 模板）：**

```
你是一位{persona.positioning}，风格{persona.style}，
说话方式是{persona.tone}。

请为以下产品生成一段{style}风格的直播讲解话术：

产品名称：{product.productName}
产品价格：{product.price}元（原价{product.originalPrice}元）
核心卖点：{product.sellingPoints}
使用场景：{product.usageScenario}
目标人群：{product.targetAudience}

要求：
1. 符合{persona.personaName}的人设风格
2. 话术时长控制在 3-5 分钟
3. 包含产品介绍、卖点讲解、使用场景、价格锚定
4. 语言自然流畅，适合直播口播
```

### 5.5.4 话术与 AI 效果归因

产品话术被直播场次引用后，可通过 live 模块的话术效果归因系统追踪效果：

```
dy_product_script（产品话术）
    │
    ├── ai_call_log_id → ai_call_log（AI 调用记录）
    │
    └── 被 live_session_product 引用
            │
            └── live_session_script（场次话术，执行追踪）
                    │
                    ├── executed = true（已执行）
                    ├── actual_execution_time（执行时间点）
                    │
                    └── 关联 live_monitor（时序数据）
                            │
                            └── effectiveness_score（效果评分）
```

这形成了完整的闭环：AI 生成话术 → 直播执行 → 数据采集 → 效果归因 → 优化生成质量。
