## 3.2 关键接口详细设计

### 接口 1：发起 OAuth2 授权

```
GET /api/v1/douyin/oauth/authorize
权限：登录
```

**请求参数（Query）：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| accountId | Long | 否 | 已有账号 ID（重新授权时传入） |

**业务逻辑：**
1. 检查用户绑定数量是否达到套餐上限（BR-01）
2. 生成 state 参数（UUID），存入缓存，关联当前 userId
3. 构建抖音授权 URL：`https://open.douyin.com/platform/oauth/connect?client_key={appId}&response_type=code&scope=user_info&redirect_uri={callbackUrl}&state={state}`
4. 302 重定向到抖音授权页

**响应：** 302 重定向

---

### 接口 2：OAuth2 回调

```
GET /api/v1/douyin/oauth/callback?code={code}&state={state}
权限：公开
```

**业务逻辑：**
1. 验证 state 参数有效性，获取关联的 userId
2. 用 code 换取 access_token：`POST https://open.douyin.com/oauth/access_token/`
3. 用 access_token 获取用户信息：`GET /oauth/userinfo/`
4. 创建或更新 dy_account 记录（通过 open_id 判断是否已存在）
5. 保存 access_token / refresh_token / 过期时间
6. 同步账号基本数据（粉丝数、获赞数等）写入 dy_account_data
7. 重定向到前端绑定成功页面

**错误处理：**
- state 无效 → 重定向到失败页面，提示"授权已过期，请重新发起"
- code 换 token 失败 → 重定向到失败页面，携带错误信息
- 绑定数量超限 → 重定向到失败页面，提示"请升级套餐"

### 接口 4：手动刷新授权 Token

```
POST /api/v1/douyin/account/refresh
权限：登录
```

**请求参数：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| accountId | Long | 是 | 账号 ID |

**业务逻辑：**
1. 校验账号属于当前用户（owner_id）
2. 检查 refresh_token 是否过期
3. 调用抖音 API：`POST https://open.douyin.com/oauth/refresh_token/`
4. 更新 access_token / token_expire_time
5. 如果 refresh_token 也被刷新，同步更新

**响应示例：**

```json
{
  "status": 200,
  "message": "刷新成功",
  "data": {
    "authStatus": 1,
    "tokenExpireTime": "2026-03-01T10:00:00"
  }
}
```

**错误场景：**

| 错误码 | 说明 |
|--------|------|
| 3101 | 账号不存在 |
| 3102 | refresh_token 已过期，需重新授权 |
| 3103 | 抖音 API 调用失败 |

### 接口 5：解除账号绑定

```
POST /api/v1/douyin/account/unbind
权限：登录
```

**请求参数：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| accountId | Long | 是 | 账号 ID |

**业务逻辑：**
1. 校验账号属于当前用户
2. 将 auth_status 设为 2（已解绑）
3. 清空 access_token / refresh_token
4. 不删除已有的视频/直播数据（BR-07）
5. 关联的人设保留，但不再能同步数据

---

### 接口 10：新增/编辑人设

```
POST /api/v1/douyin/persona/save
权限：登录
```

**请求参数：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | Long | 否 | 有值为编辑，无值为新增 |
| accountId | Long | 否 | 关联的账号 ID（可空，通用人设） |
| personaName | String | 是 | 人设名称，最长 64 |
| positioning | String | 否 | 定位 |
| style | String | 否 | 风格 |
| tags | List\<String\> | 否 | 标签列表 |
| targetAudience | String | 否 | 目标受众 |
| tone | String | 否 | 语气/口吻 |
| description | String | 否 | 详细描述 |

**业务逻辑：**
1. 校验 personaName 不为空且长度 <= 64
2. 新增时：检查用户的人设数量（后续可按套餐限制）
3. 编辑时：校验 owner_id 必须是当前用户
4. tags 存储为 JSON 字符串
5. 如果是用户的第一个人设，自动设为激活状态（is_active=1）

**响应示例：**

```json
{
  "status": 200,
  "message": "添加成功!",
  "data": 1
}
```

---

### 接口 12：切换激活人设

```
POST /api/v1/douyin/persona/activate
权限：登录
```

**请求参数：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | Long | 是 | 目标人设 ID |

**业务逻辑：**
1. 校验人设属于当前用户（owner_id）
2. 将当前用户所有人设的 is_active 设为 0
3. 将目标人设的 is_active 设为 1
4. 整个操作在一个事务中（@Transactional）

---

### 接口 15：使用模板创建人设

```
POST /api/v1/douyin/persona/template/use
权限：登录
```

**请求参数：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| templateId | Long | 是 | 模板 ID |
| accountId | Long | 否 | 关联的账号 ID |

**业务逻辑：**
1. 查询模板信息
2. 复制模板字段（positioning/style/tags/targetAudience/tone/description）到新的 dy_persona 记录
3. persona_name 默认为模板名称，用户可后续修改
4. 设置 owner_id 为当前用户
5. 如果是第一个人设，自动激活

**响应示例：**

```json
{
  "status": 200,
  "message": "创建成功",
  "data": {
    "personaId": 5,
    "personaName": "美妆博主"
  }
}
```

### 接口 22：新增/编辑产品

```
POST /api/v1/douyin/product/save
权限：登录
```

**请求参数：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | Long | 否 | 有值为编辑，无值为新增 |
| accountId | Long | 是 | 关联的抖音账号 ID |
| productName | String | 是 | 产品名称 |
| productImage | String | 否 | 产品主图 URL |
| price | BigDecimal | 否 | 价格 |
| originalPrice | BigDecimal | 否 | 原价 |
| category | String | 否 | 分类 |
| sellingPoints | String | 否 | 核心卖点 |
| specifications | String | 否 | 规格 |
| usageScenario | String | 否 | 使用场景 |
| targetAudience | String | 否 | 目标人群 |
| description | String | 否 | 详细描述 |

**业务逻辑：**
1. 校验 accountId 对应的账号属于当前用户
2. 校验 productName 不为空
3. 新增时设置 owner_id 为当前用户
4. 编辑时校验 owner_id 必须是当前用户

### 接口 27：AI 生成产品话术

```
POST /api/v1/douyin/product/script/generate
权限：登录（检查 AI 额度）
```

**请求参数：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| productId | Long | 是 | 产品 ID |
| personaId | Long | 否 | 人设 ID（不填则使用当前激活人设） |
| style | String | 是 | 话术风格：种草 / 促销 / 专业讲解 / 亲切推荐 |

**业务逻辑：**
1. 获取产品信息（名称/价格/卖点/场景等）
2. 获取人设信息（不传 personaId 则查当前激活人设）
3. 校验 AI 调用额度
4. 调用 ai 模块 `live_script_product` 模板，传入产品 + 人设 + 风格
5. 生成结果写入 dy_product_script（is_ai_generated=1，记录 ai_call_log_id）
6. 返回生成的话术内容和剩余额度

**响应示例：**

```json
{
  "status": 200,
  "data": {
    "scriptId": 12,
    "scriptName": "种草版",
    "content": "姐妹们这款面霜真的绝了！我自己用了一个月...",
    "durationHint": "3-5分钟",
    "quotaRemaining": 7
  }
}
```

## 3.3 错误码表

| 错误码 | 说明 | 触发场景 |
|--------|------|----------|
| 3101 | 账号不存在 | 查询/操作的账号 ID 不存在或已删除 |
| 3102 | 授权已过期 | refresh_token 过期，需重新 OAuth2 授权 |
| 3103 | 抖音 API 调用失败 | 调用抖音开放平台接口异常 |
| 3104 | 绑定数量超限 | 用户绑定账号数量达到套餐上限 |
| 3201 | 人设不存在 | 查询/操作的人设 ID 不存在或已删除 |
| 3202 | 人设删除拒绝 | 尝试删除唯一人设 |
| 3203 | 人设权限拒绝 | 操作他人的人设 |
| 3301 | 产品不存在 | 查询/操作的产品 ID 不存在或已删除 |
| 3302 | 产品权限拒绝 | 操作他人的产品 |
| 3401 | 话术不存在 | 查询/操作的话术 ID 不存在或已删除 |
| 3402 | AI 额度不足 | AI 生成话术时额度已用完 |
| 3501 | 模板不存在 | 查询/操作的模板 ID 不存在或已删除 |

## 3.4 通用响应格式

所有接口统一使用 `RESTResult<T>` 格式：

```json
{
  "status": 200,
  "message": "操作成功",
  "data": { ... },
  "traceId": "abc123"
}
```

**分页响应格式（PageResultVO）：**

```json
{
  "status": 200,
  "data": {
    "list": [ ... ],
    "total": 100,
    "page": 1,
    "pageSize": 20
  }
}
```
