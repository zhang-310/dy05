## 5.1 事件追踪流程

### 5.1.1 整体流程

```
前端页面展示变体内容
        │
        │ 用户看到内容（曝光）
        ▼
前端调用 /event/track（eventType=view）
        │
        ▼
后端校验实验状态（运行中才处理）
        │
        ▼
去重检查：(variant_id, event_type, user_fingerprint) 是否已存在
        │
   ┌────┴────┐
   │ 已存在   │ 不存在
   ▼         ▼
 忽略      写入 ab_event
           原子更新 ab_variant.view_count
           重新计算 conversion_rate
        │
        │ 用户点击内容
        ▼
前端调用 /event/track（eventType=click）
        │
        ▼
同上去重 + 写入 + 更新 click_count
        │
        │ 用户完成转化动作（购买/关注/留资等）
        ▼
前端调用 /event/track（eventType=conversion）
        │
        ▼
同上去重 + 写入 + 更新 conversion_count + 重算 conversion_rate
```

### 5.1.2 用户指纹生成

`user_fingerprint` 是客户端生成的匿名标识符，用于跨请求识别同一用户，同时保护用户隐私。

**生成策略（前端）：**

```typescript
// 前端生成用户指纹（TypeScript）
function generateUserFingerprint(): string {
  // 优先使用 localStorage 中已存储的指纹
  const stored = localStorage.getItem('ab_fp');
  if (stored) return stored;

  // 基于浏览器特征生成指纹
  const components = [
    navigator.userAgent,
    navigator.language,
    screen.width + 'x' + screen.height,
    new Date().getTimezoneOffset().toString(),
    navigator.hardwareConcurrency?.toString() || '',
  ];

  // 简单哈希（生产环境建议使用 FingerprintJS 等专业库）
  const raw = components.join('|');
  let hash = 0;
  for (let i = 0; i < raw.length; i++) {
    hash = ((hash << 5) - hash) + raw.charCodeAt(i);
    hash |= 0;
  }
  const fp = 'fp_' + Math.abs(hash).toString(36) + '_' + Date.now().toString(36);
  localStorage.setItem('ab_fp', fp);
  return fp;
}
```

**指纹特性：**
- 同一浏览器/设备在 localStorage 未清除前保持一致
- 不与真实用户 ID 关联，保护隐私
- 用于去重，防止同一用户多次触发同类事件

### 5.1.3 事件采集 SDK（前端封装）

```typescript
// abtest/tracker.ts
import { trackEvent } from '@/api/abtest';

interface TrackOptions {
  experimentId: number;
  variantId: number;
  sessionId?: string;
}

class AbTestTracker {
  private fingerprint: string;

  constructor() {
    this.fingerprint = generateUserFingerprint();
  }

  async trackView(options: TrackOptions): Promise<void> {
    await this.track('view', options);
  }

  async trackClick(options: TrackOptions): Promise<void> {
    await this.track('click', options);
  }

  async trackConversion(options: TrackOptions): Promise<void> {
    await this.track('conversion', options);
  }

  private async track(eventType: string, options: TrackOptions): Promise<void> {
    try {
      await trackEvent({
        experimentId: options.experimentId,
        variantId: options.variantId,
        eventType,
        userFingerprint: this.fingerprint,
        sessionId: options.sessionId,
      });
    } catch (e) {
      // 静默失败，不影响主业务
      console.debug('[AbTest] track failed silently', e);
    }
  }
}

export const abTestTracker = new AbTestTracker();
```

## 5.2 转化率计算

### 5.2.1 指标定义

| 指标 | 计算公式 | 说明 |
|------|---------|------|
| 曝光数（view_count） | 去重后的 view 事件数 | 同一用户指纹只计一次 |
| 点击数（click_count） | 去重后的 click 事件数 | 同一用户指纹只计一次 |
| 转化数（conversion_count） | 去重后的 conversion 事件数 | 同一用户指纹只计一次 |
| 点击率（CTR） | click_count / view_count | 实时计算，不存储 |
| 转化率（CVR） | conversion_count / view_count | 存储在 ab_variant.conversion_rate |
| 点击转化率 | conversion_count / click_count | 实时计算，不存储 |

### 5.2.2 转化漏斗

```
曝光（view）
    │ 点击率 = click / view
    ▼
点击（click）
    │ 点击转化率 = conversion / click
    ▼
转化（conversion）

整体转化率 = conversion / view
```

**示例数据：**
```
变体A：曝光 650 → 点击 34（CTR 5.23%）→ 转化 12（CVR 1.85%）
变体B：曝光 550 → 点击 41（CTR 7.45%）→ 转化 18（CVR 3.27%）

结论：变体B在点击率和转化率上均优于变体A
```

## 5.3 获胜判定算法

### 5.3.1 判定流程

```
获取实验下两个变体的数据
        │
        ▼
样本量检查：
  - 总曝光数 < 100？→ 返回"数据不足"
  - 任一变体转化数 < 5？→ 返回"数据不足"
        │
        ▼
执行卡方检验（见 04-实验管理系统.md 4.4节）
        │
        ▼
计算 p-value 和置信度
        │
   ┌────┴──────────────────┐
   │ p-value >= 0.05        │ p-value < 0.05
   │ 置信度 < 95%           │ 置信度 >= 95%
   ▼                        ▼
"数据不足，继续收集"      比较两变体转化率
                                │
                           ┌────┴────┐
                           │ A > B   │ B > A
                           ▼         ▼
                        推荐A获胜  推荐B获胜
                           │
                           ▼
                    生成推荐文案（含提升幅度、置信度）
```

### 5.3.2 最小样本量估算

在实验设计阶段，可以根据期望的效果提升幅度估算所需最小样本量：

| 基准转化率 | 期望提升 | 所需每组样本量（95%置信度，80%检验效能） |
|-----------|---------|----------------------------------------|
| 2% | 50%（→3%） | ~2,000 |
| 2% | 100%（→4%） | ~600 |
| 5% | 30%（→6.5%） | ~2,500 |
| 5% | 50%（→7.5%） | ~900 |
| 10% | 20%（→12%） | ~3,500 |

> 建议：实验启动前在创建页面展示预估所需样本量，帮助用户设定合理的实验周期。

**SQL 查询（每日趋势）：**

```sql
SELECT
    DATE(e.create_time)                                    AS date,
    SUM(CASE WHEN v.variant_type = 'A' AND e.event_type = 'view'       THEN 1 ELSE 0 END) AS variant_a_views,
    SUM(CASE WHEN v.variant_type = 'B' AND e.event_type = 'view'       THEN 1 ELSE 0 END) AS variant_b_views,
    SUM(CASE WHEN v.variant_type = 'A' AND e.event_type = 'conversion' THEN 1 ELSE 0 END) AS variant_a_conversions,
    SUM(CASE WHEN v.variant_type = 'B' AND e.event_type = 'conversion' THEN 1 ELSE 0 END) AS variant_b_conversions
FROM ab_event e
JOIN ab_variant v ON e.variant_id = v.id
WHERE e.experiment_id = :experimentId
GROUP BY DATE(e.create_time)
ORDER BY date ASC;
```

## 5.5 数据归档策略

ab_event 表随实验运行持续写入，需要定期归档防止表膨胀：

| 策略 | 说明 |
|------|------|
| 归档触发 | 实验状态变为已完成（status=2）后 90 天 |
| 归档方式 | 将 ab_event 数据迁移到归档表 ab_event_archive（按年分区） |
| 保留策略 | ab_variant 的聚合计数字段（view_count/click_count/conversion_count）永久保留 |
| 清理时机 | 每月 01 日 03:00 执行归档任务，处理 90 天前已完成实验的事件数据 |

```sql
-- 归档 SQL（示例）
INSERT INTO ab_event_archive
SELECT * FROM ab_event
WHERE experiment_id IN (
    SELECT id FROM ab_experiment
    WHERE status = 2
      AND end_time < CURRENT_TIMESTAMP - INTERVAL '90 days'
);

DELETE FROM ab_event
WHERE experiment_id IN (
    SELECT id FROM ab_experiment
    WHERE status = 2
      AND end_time < CURRENT_TIMESTAMP - INTERVAL '90 days'
);
```
