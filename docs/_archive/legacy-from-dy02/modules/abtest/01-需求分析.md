# A/B 测试模块 — 需求分析

> 版本：3.0 | 更新日期：2026-02-26

---

## 1.1 模块定位

abtest 模块是平台的 P2 增值功能模块，为内容创作者提供科学的 A/B 测试能力。用户可以针对短视频文案、直播开场脚本、商品描述文案创建对照实验，通过真实用户行为数据（曝光、点击、转化）判断哪个版本效果更好，从而用数据驱动内容决策，替代主观判断。

---

## 1.2 用户故事

| 编号 | 角色 | 故事 | 验收条件 |
|------|------|------|----------|
| **实验管理** | | | |
| AB-01 | 达人 | 我要能创建一个 A/B 测试实验，选择测试类型和两个内容变体 | 创建成功，实验处于草稿状态，包含 A/B 两个变体 |
| AB-02 | 达人 | 我要能启动实验，让系统开始收集数据 | 实验状态变为运行中，开始时间记录，事件采集开启 |
| AB-03 | 达人 | 我要能暂停正在运行的实验 | 实验状态变为已暂停，事件采集停止 |
| AB-04 | 达人 | 我要能查看我的所有实验列表，按状态筛选 | 列表展示实验名称、类型、状态、运行时长、当前转化率 |
| AB-05 | 达人 | 我要能删除草稿状态的实验 | 草稿实验软删除成功；运行中实验不可删除 |
| **变体管理** | | | |
| AB-06 | 达人 | 我要能为实验添加两个内容变体（A 和 B），关联已有内容 | 变体保存成功，关联到对应的内容实体 |
| AB-07 | 达人 | 我要能编辑草稿状态实验的变体内容 | 草稿状态下变体可编辑；运行中不可编辑 |
| AB-08 | 达人 | 我要能删除变体（仅草稿状态） | 变体软删除成功 |
| **数据采集** | | | |
| AB-09 | 达人 | 系统要能自动记录每个变体的曝光、点击、转化事件 | 事件写入 ab_event，同一用户指纹同类事件去重 |
| **结果分析** | | | |
| AB-10 | 达人 | 我要能查看实验的实时数据结果，包括两个变体的转化率对比 | 展示曝光数、点击数、转化数、转化率、置信度 |
| AB-11 | 达人 | 我要能结束实验并设置获胜变体和结论 | 实验状态变为已完成，winner_variant_id 和 conclusion 记录 |
| AB-12 | 达人 | 我要能看到系统基于统计显著性给出的获胜推荐 | 当置信度 ≥ 95% 时，系统自动标注推荐获胜方 |

## 1.3 功能清单

```
abtest 模块
├── 实验管理
│   ├── 实验创建（选择类型：video/live/copy）
│   ├── 实验列表（按状态筛选：草稿/运行中/已完成/已暂停）
│   ├── 实验详情查看
│   ├── 实验启动（草稿 → 运行中）
│   ├── 实验暂停（运行中 → 已暂停）
│   ├── 实验恢复（已暂停 → 运行中）
│   ├── 实验结束并记录结论（运行中/已暂停 → 已完成）
│   └── 实验删除（仅草稿状态）
│
├── 变体管理
│   ├── 变体创建（A/B 两个变体，关联内容实体）
│   ├── 变体编辑（仅草稿状态）
│   ├── 变体列表（按实验查询）
│   └── 变体删除（仅草稿状态）
│
├── 事件采集
│   ├── 曝光事件记录（view）
│   ├── 点击事件记录（click）
│   ├── 转化事件记录（conversion）
│   └── 用户指纹去重（同一指纹同类事件不重复计数）
│
└── 结果分析
    ├── 实验结果看板（转化率对比、漏斗图数据）
    ├── 统计显著性计算（卡方检验，置信度展示）
    ├── 获胜推荐（置信度 ≥ 95% 自动推荐）
    └── 结论记录（手动设置获胜变体 + 文字结论）
```

## 1.4 业务规则

| 编号 | 规则 | 说明 |
|------|------|------|
| BR-01 | 变体数量固定 | 每个实验必须恰好包含 2 个变体（A 和 B），不支持多变量测试 |
| BR-02 | 启动前校验 | 实验启动前必须已保存 2 个变体，否则返回 4205 错误 |
| BR-03 | 运行中不可编辑 | 实验处于运行中状态时，不允许修改实验信息和变体内容，防止数据污染 |
| BR-04 | 状态流转限制 | 草稿→运行中→已暂停→运行中→已完成；草稿可直接删除；已完成不可恢复 |
| BR-05 | 数据隔离 | 用户只能查看和操作自己创建的实验（owner_id 校验） |
| BR-06 | 事件去重 | 同一 user_fingerprint 对同一 variant_id 的同类 event_type 只计数一次（防刷） |
| BR-07 | 转化率计算 | conversion_rate = conversion_count / view_count（以曝光为分母） |
| BR-08 | 显著性阈值 | 置信度 ≥ 95%（p-value < 0.05）时系统标注推荐获胜方，低于阈值显示"数据不足" |
| BR-09 | 关联内容校验 | 变体关联的 entity_id 必须属于当前用户，且 entity_type 与实验类型匹配 |
| BR-10 | 软删除 | 所有业务表使用逻辑删除（deleted 字段），ab_event 不支持删除 |

## 1.5 模块依赖

```
依赖关系：
auth ← abtest（用户身份）
douyin（账号）← abtest（实验归属）
shortvideo（sv_plan 短视频方案）← abtest（video 类型变体）
live（live_session 直播场次）← abtest（live 类型变体）
copy（cp_library 商品文案）← abtest（copy 类型变体）
```

| 依赖模块 | 依赖内容 | 接口 / 表 |
|---------|---------|-----------|
| auth | 当前用户 ID、权限校验 | SecurityUtils.getCurrentUserId() |
| douyin | 账号归属校验 | dy_account.owner_id |
| shortvideo | 短视频创作方案内容 | sv_plan（entity_type = sv_plan） |
| live | 直播场次脚本内容 | live_session（entity_type = live_session_script） |
| copy | 商品文案库内容 | cp_library（entity_type = cp_library） |

## 1.6 非功能需求

| 类别 | 要求 |
|------|------|
| 性能 | 事件追踪接口（/event/track）响应时间 < 100ms，支持高并发写入 |
| 可靠性 | 事件采集失败不影响主业务流程（异步写入，失败静默处理） |
| 数据安全 | user_fingerprint 不存储真实用户 ID，仅用于去重，保护隐私 |
| 扩展性 | entity_type 字段设计为可扩展枚举，未来可支持更多内容类型 |
