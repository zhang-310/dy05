## 4.1 实验生命周期

A/B 实验从创建到结束经历完整的生命周期，每个阶段有明确的状态定义和允许的操作。

```
                    ┌─────────────────────────────────────────┐
                    │           实验生命周期                    │
                    └─────────────────────────────────────────┘

  创建实验
     │
     ▼
┌─────────┐   启动实验（变体已就绪）    ┌──────────┐
│  草稿    │ ─────────────────────────► │  运行中   │
│ status=0 │                           │ status=1  │
└─────────┘                           └──────────┘
     │                                  │      ▲
     │ 删除                              │ 暂停  │ 恢复
     ▼                                  ▼      │
  [已删除]                           ┌──────────┐
  deleted=1                          │  已暂停   │
                                     │ status=3  │
                                     └──────────┘
                                          │
                                          │ 结束（设置结论）
                                          ▼
                                     ┌──────────┐
                                     │  已完成   │
                                     │ status=2  │
                                     └──────────┘
                                     （终态，不可变更）
```

### 状态说明

| 状态值 | 状态名 | 说明 | 允许操作 |
|--------|--------|------|----------|
| 0 | 草稿 | 实验刚创建，尚未启动 | 编辑实验信息、管理变体、启动、删除 |
| 1 | 运行中 | 实验正在收集数据 | 查看结果、暂停、结束并设置结论 |
| 2 | 已完成 | 实验已结束，结论已记录 | 仅查看（终态） |
| 3 | 已暂停 | 实验暂时停止收集数据 | 恢复运行、结束并设置结论 |

### 状态流转规则

| 操作 | 允许的前置状态 | 目标状态 | 备注 |
|------|--------------|----------|------|
| 启动（start） | 0（草稿）、3（已暂停） | 1（运行中） | 需校验变体数量 = 2 |
| 暂停（stop） | 1（运行中） | 3（已暂停） | 停止事件采集 |
| 结束（conclude） | 1（运行中）、3（已暂停） | 2（已完成） | 需设置 winner_variant_id 和 conclusion |
| 删除（delete） | 0（草稿） | deleted=1 | 级联软删除变体 |

## 4.2 变体管理

### 4.2.1 变体设计原则

abtest 模块采用固定双变体设计（A/B），不支持多变量测试（MVT）。这一设计决策基于以下考量：

- **统计简洁性**：双变体卡方检验计算简单，结果易于理解
- **流量效率**：多变量测试需要更大的样本量才能达到统计显著性
- **用户认知**：A/B 对比是内容创作者最熟悉的测试模式

### 4.2.2 变体内容关联

变体通过 `entity_type` + `entity_id` 关联到平台内已有的内容实体：

```
entity_type = sv_plan
    └── entity_id → sv_plan.id（短视频创作方案）
        内容来源：sv_plan.content（文案）或 sv_plan.script（脚本）

entity_type = live_session_script
    └── entity_id → live_session.id（直播场次）
        内容来源：live_session.opening_script（开场脚本）

entity_type = cp_library
    └── entity_id → cp_library.id（商品文案库条目）
        内容来源：cp_library.content（商品描述文案）
```

`content` 字段冗余存储变体内容文本，用于在实验结果页直接展示，避免跨模块查询。

### 4.2.3 变体创建流程

```
用户选择实验类型（video/live/copy）
         │
         ▼
用户选择内容实体（从对应模块的内容列表中选择）
         │
         ▼
系统读取实体内容，填充 content 字段（冗余存储）
         │
         ▼
保存变体（variant_type = A 或 B）
         │
         ▼
校验：同一实验下 A/B 各只能有一个有效变体
         │
         ▼
保存成功，等待实验启动
```

## 4.3 实验启动校验

启动实验前，系统执行以下校验序列：

```java
// 伪代码：实验启动校验逻辑
void validateExperimentStart(Long experimentId, Long userId) {
    // 1. 实验存在性校验
    AbExperiment exp = findById(experimentId)
        .orElseThrow(() -> new BizException(4201));

    // 2. 权限校验
    if (!exp.getOwnerId().equals(userId)) {
        throw new BizException(4202);
    }

    // 3. 状态校验（草稿或已暂停才可启动）
    if (exp.getStatus() == 1) {
        throw new BizException(4206); // 已在运行中
    }
    if (exp.getStatus() == 2) {
        throw new BizException(4203); // 已完成，不可重启
    }

    // 4. 变体数量校验
    long variantCount = variantRepo.countByExperimentIdAndDeleted(experimentId, 0);
    if (variantCount != 2) {
        throw new BizException(4205); // 必须恰好 2 个变体
    }
}
```

## 4.4 统计显著性计算

### 4.4.1 卡方检验原理

abtest 模块使用卡方检验（Chi-Square Test）判断两个变体的转化率差异是否具有统计显著性。

**适用场景：** 比较两组二元结果（转化 vs 未转化）的比例差异。

**计算公式：**

```
观测值矩阵（2×2 列联表）：

              转化     未转化     合计
变体 A    |   a    |    b    |  a+b  |
变体 B    |   c    |    d    |  c+d  |
合计      |  a+c   |   b+d   |   N   |

期望值：
E(a) = (a+b)(a+c) / N
E(b) = (a+b)(b+d) / N
E(c) = (c+d)(a+c) / N
E(d) = (c+d)(b+d) / N

卡方统计量：
χ² = Σ [(观测值 - 期望值)² / 期望值]
   = (a-E(a))²/E(a) + (b-E(b))²/E(b) + (c-E(c))²/E(c) + (d-E(d))²/E(d)

自由度 df = (行数-1)(列数-1) = 1

p-value 通过卡方分布查表或计算得出
```

### 4.4.2 显著性判断标准

| 置信度 | p-value | 结论 |
|--------|---------|------|
| < 90% | > 0.10 | 数据不足，无法判断 |
| 90% ~ 95% | 0.05 ~ 0.10 | 有一定倾向，建议继续收集数据 |
| ≥ 95% | < 0.05 | 统计显著，可以做决策 |
| ≥ 99% | < 0.01 | 高度显著，强烈推荐获胜方 |

### 4.4.3 Java 实现参考

```java
/**
 * 卡方检验计算转化率显著性
 * @param viewA  变体A曝光数
 * @param convA  变体A转化数
 * @param viewB  变体B曝光数
 * @param convB  变体B转化数
 * @return StatisticsResult 包含 chiSquare, pValue, confidenceLevel, isSignificant
 */
public StatisticsResult chiSquareTest(long viewA, long convA, long viewB, long convB) {
    // 构建 2x2 列联表
    long a = convA;           // A 转化
    long b = viewA - convA;   // A 未转化
    long c = convB;           // B 转化
    long d = viewB - convB;   // B 未转化
    long N = viewA + viewB;

    // 样本量不足时直接返回不显著
    if (N < 100 || a + c < 5) {
        return StatisticsResult.insufficient();
    }

    // 计算期望值
    double eA = (double)(a + b) * (a + c) / N;
    double eB = (double)(a + b) * (b + d) / N;
    double eC = (double)(c + d) * (a + c) / N;
    double eD = (double)(c + d) * (b + d) / N;

    // 计算卡方值（Yates 连续性校正，适用于小样本）
    double chiSquare = 0;
    chiSquare += Math.pow(Math.abs(a - eA) - 0.5, 2) / eA;
    chiSquare += Math.pow(Math.abs(b - eB) - 0.5, 2) / eB;
    chiSquare += Math.pow(Math.abs(c - eC) - 0.5, 2) / eC;
    chiSquare += Math.pow(Math.abs(d - eD) - 0.5, 2) / eD;

    // 通过卡方分布计算 p-value（df=1）
    // 使用 Apache Commons Math: ChiSquaredDistribution
    ChiSquaredDistribution dist = new ChiSquaredDistribution(1);
    double pValue = 1 - dist.cumulativeProbability(chiSquare);
    double confidenceLevel = 1 - pValue;

    boolean isSignificant = pValue < 0.05;
    String recommendedWinner = null;
    if (isSignificant) {
        double rateA = (double) convA / viewA;
        double rateB = (double) convB / viewB;
        recommendedWinner = rateA >= rateB ? "A" : "B";
    }

    return new StatisticsResult(chiSquare, pValue, confidenceLevel, isSignificant, recommendedWinner);
}
```

### 4.4.4 推荐文案生成

```java
String buildRecommendation(StatisticsResult stats, AbVariant variantA, AbVariant variantB) {
    if (!stats.isSignificant()) {
        if (stats.getConfidenceLevel() < 0.90) {
            return "当前数据量不足，无法判断哪个版本更优，建议继续收集数据";
        } else {
            return String.format("变体%s略有优势（置信度%.1f%%），但尚未达到统计显著性，建议继续观察",
                stats.getRecommendedWinner(), stats.getConfidenceLevel() * 100);
        }
    }
    AbVariant winner = "A".equals(stats.getRecommendedWinner()) ? variantA : variantB;
    AbVariant loser  = "A".equals(stats.getRecommendedWinner()) ? variantB : variantA;
    double improvement = (winner.getConversionRate() - loser.getConversionRate())
                         / loser.getConversionRate() * 100;
    return String.format("变体%s（%s）转化率（%.2f%%）显著高于变体%s（%.2f%%），提升%.1f%%，置信度%.1f%%，建议采用变体%s",
        stats.getRecommendedWinner(), winner.getVariantName(),
        winner.getConversionRate() * 100,
        "A".equals(stats.getRecommendedWinner()) ? "B" : "A",
        loser.getConversionRate() * 100,
        improvement,
        stats.getConfidenceLevel() * 100,
        stats.getRecommendedWinner());
}
```

## 4.5 计数字段更新策略

为保证高并发下计数字段的准确性，采用数据库原子更新而非先读后写：

```sql
-- 事件追踪时原子更新计数
UPDATE ab_variant
SET view_count = view_count + 1,
    conversion_rate = CASE
        WHEN view_count + 1 > 0
        THEN CAST(conversion_count AS DECIMAL) / (view_count + 1)
        ELSE 0
    END,
    update_time = CURRENT_TIMESTAMP
WHERE id = :variantId AND deleted = 0;
```

转化率在每次事件写入后实时重新计算，保证结果页展示的数据始终最新。
