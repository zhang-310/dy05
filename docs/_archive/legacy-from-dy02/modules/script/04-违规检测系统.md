## 4.1 违规词分类体系

### 4.1.1 违规分类（category）

| 分类 | 编码 | 说明 | 典型词汇 |
|------|------|------|---------|
| 广告法 | ad_law | 违反《广告法》的绝对化用语 | 最好的、第一、最便宜、国家级、永久、万能 |
| 平台规则 | platform | 违反抖音平台运营规则 | 秒杀全网、假一赔十、免费送、去直播间 |
| 敏感词 | sensitive | 政治/社会敏感词汇 | 根据实际情况维护 |
| 低俗词 | vulgar | 低俗/不雅用语 | 根据实际情况维护 |

### 4.1.2 违规等级（level）

| 等级 | 编码 | 说明 | 前端展示 | 处理建议 |
|------|------|------|---------|---------|
| 禁止 | forbidden | 必须修改，否则可能被平台处罚 | 红色标记 | 强制替换 |
| 警告 | warning | 建议修改，存在风险 | 黄色标记 | 建议替换 |
| 建议修改 | suggest | 可以保留，但有更好的表达 | 蓝色标记 | 可选替换 |

### 4.1.3 适用范围（scope）

| 范围 | 编码 | 说明 | 示例 |
|------|------|------|------|
| 全场景 | all | 直播和短视频都违规 | 最好的、第一、秒杀全网 |
| 仅直播 | live_only | 只在直播场景违规 | 点点关注、扣1、截屏抽奖 |
| 仅短视频 | video_only | 只在短视频场景违规 | 根据实际情况维护 |

## 4.2 检测算法流程

```
┌─────────────────────────────────────────────────────────────┐
│                     违规检测流程                              │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  ① 接收请求                                                 │
│  ┌─────────────────────────────────────┐                    │
│  │ text: "这是全网最好的面霜..."        │                    │
│  │ scope: "live"                       │                    │
│  └──────────────┬──────────────────────┘                    │
│                 ▼                                            │
│  ② 加载违规词库                                              │
│  ┌──────────────────────┐  ┌──────────────────────┐         │
│  │   公共违规词库        │  │   个人违规词库        │         │
│  │  （Caffeine 缓存）    │  │  （直接查数据库）     │         │
│  │   TTL = 5 分钟       │  │   无缓存             │         │
│  └──────────┬───────────┘  └──────────┬───────────┘         │
│             ▼                         ▼                     │
│  ③ 按 scope 过滤                                             │
│  ┌─────────────────────────────────────────────┐            │
│  │ scope=live → 保留 scope=all + scope=live_only│            │
│  │ scope=video → 保留 scope=all + scope=video_only│          │
│  │ scope=all → 保留所有                          │            │
│  └──────────────────┬──────────────────────────┘            │
│                     ▼                                       │
│  ④ 合并词库                                                  │
│  ┌─────────────────────────────────────────────┐            │
│  │ 公共库 + 个人库合并                           │            │
│  │ 同一词在两个库都有 → 取更高等级                │            │
│  │ 等级优先级：forbidden > warning > suggest     │            │
│  └──────────────────┬──────────────────────────┘            │
│                     ▼                                       │
│  ⑤ 文本匹配                                                 │
│  ┌─────────────────────────────────────────────┐            │
│  │ 遍历合并后的违规词列表                        │            │
│  │ 对每个违规词做字符串包含匹配（不区分大小写）    │            │
│  │ 记录：word / position / length / category     │            │
│  │       level / replacement / source            │            │
│  └──────────────────┬──────────────────────────┘            │
│                     ▼                                       │
│  ⑥ 返回结果                                                  │
│  ┌─────────────────────────────────────────────┐            │
│  │ hasViolation: true/false                     │            │
│  │ totalCount: N                                │            │
│  │ violations: [...]                            │            │
│  └─────────────────────────────────────────────┘            │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 4.3 缓存策略

### 4.3.1 公共违规词库缓存

```
┌──────────────┐     Cache Miss      ┌──────────────┐
│   Caffeine   │ ──────────────────→ │  PostgreSQL  │
│   Cache      │ ←────────────────── │  数据库       │
│  TTL = 5min  │     Load Data       │              │
└──────────────┘                     └──────────────┘
```

| 配置项 | 值 | 说明 |
|--------|-----|------|
| 缓存类型 | Caffeine | 本地内存缓存 |
| TTL | 5 分钟 | 过期后自动重新加载 |
| 刷新策略 | 被动过期 | 管理员修改后不主动刷新，等 TTL 自动过期 |
| 缓存 Key | `violation_words:public:{scope}` | 按 scope 分别缓存 |
| 适用理由 | 公共库修改频率低，5 分钟延迟可接受 | — |

### 4.3.2 个人违规词库

| 配置项 | 值 | 说明 |
|--------|-----|------|
| 缓存 | 无 | 数据量小（每用户 ~50 条），直接查数据库 |
| 实时性 | 添加/修改后立即生效 | 无缓存延迟 |

## 4.4 批量检测设计

```
┌─────────────────────────────────────────────────────────────┐
│                     批量检测流程                              │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  输入：texts = [                                             │
│    { key: "opening",   text: "开场话术内容..." },            │
│    { key: "product_1", text: "产品1话术内容..." },           │
│    { key: "product_2", text: "产品2话术内容..." },           │
│    { key: "closing",   text: "结尾话术内容..." }             │
│  ]                                                          │
│  scope: "live"                                              │
│                                                             │
│  处理：                                                      │
│  ① 词库只加载一次（公共缓存 + 个人查询）                      │
│  ② scope 过滤一次                                            │
│  ③ 合并一次                                                  │
│  ④ 对每段文本分别执行匹配                                     │
│  ⑤ 按 key 组织返回结果                                       │
│                                                             │
│  输出：results = {                                           │
│    "opening":   { hasViolation: false, violations: [] },    │
│    "product_1": { hasViolation: true,  violations: [...] }, │
│    "product_2": { hasViolation: true,  violations: [...] }, │
│    "closing":   { hasViolation: false, violations: [] }     │
│  }                                                          │
│  totalViolations: 5                                         │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

性能优化：批量检测复用单文本检测逻辑，词库只加载一次，避免重复查询。

## 4.5 AI 替换建议集成

```
┌──────────────┐     违规词列表      ┌──────────────┐
│  违规检测结果  │ ──────────────────→ │   ai 模块    │
│  violations  │ ←────────────────── │  AI 替换建议  │
│              │   合规替代表达       │              │
└──────────────┘                     └──────────────┘
```

流程：

1. 用户在违规检测页面点击「AI 推荐更好的替换」
2. 前端将违规词列表 + 原文上下文发送给 ai 模块
3. ai 模块基于上下文推荐更自然的合规替代表达
4. 返回替换建议，用户可一键应用

> AI 替换建议是可选功能，不影响基础违规检测流程。

## 4.7 性能优化

### 4.7.1 pg_trgm 加速 ILIKE

PostgreSQL 的 `ILIKE` 查询默认走全表扫描。通过 pg_trgm 扩展创建 GIN 索引，可显著加速模糊匹配：

```sql
-- 启用扩展
CREATE EXTENSION IF NOT EXISTS pg_trgm;

-- 创建 GIN 索引
CREATE INDEX idx_sc_vw_word_trgm
    ON sc_violation_word USING GIN (word gin_trgm_ops)
    WHERE deleted = 0 AND status = 1;
```

适用场景：管理端违规词搜索（按关键词模糊查找违规词）。

### 4.7.2 检测性能目标

| 场景 | 目标 | 说明 |
|------|------|------|
| 单文本检测 | < 100ms | 公共库缓存命中时 |
| 批量检测（10段） | < 1s | 词库只加载一次 |
| 公共库缓存命中率 | > 95% | TTL=5min，修改频率低 |

### 4.7.3 检测算法复杂度

```
设：N = 违规词数量，M = 文本长度
单文本检测：O(N * M)  — 遍历每个违规词，在文本中做包含匹配
批量检测（K段）：O(N * M * K)  — 词库加载 O(1)，每段文本独立匹配

当前规模（N~500, M~1000, K~10）下性能完全可接受。
若未来词库规模增长到 5000+，可考虑引入 Aho-Corasick 多模式匹配算法优化。
```
