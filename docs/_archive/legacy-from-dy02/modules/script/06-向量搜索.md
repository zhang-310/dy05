# W-06：向量化搜索与混合检索系统

## 1. 模块概述

向量化搜索与混合检索系统通过融合向量相似度搜索（语义理解）、BM25 关键词搜索（精准匹配）、RRF 融合排序（综合排名），为用户提供高质量的话术库搜索体验。该系统支持自动搜索补全建议、实时热点话题推荐，适应多种查询场景（语义模糊、精准查找、组合搜索等）。

**目标用户**：直播主播、话术库管理员
**核心价值**：从单一关键词搜索 → 智能多维搜索 → 个性化推荐
**关键指标**：搜索准确率 > 85%、用户满意度 > 4.2/5.0

## 2. 核心功能模块

### 2.1 向量相似度搜索（Semantic Search）

| 功能 | 说明 | 技术方案 |
|------|------|--------|
| 向量编码 | 将话术文本转换为 1024D 向量 | BGE-M3 模型（本地 Ollama 或云端 API） |
| 相似度检索 | 在 Milvus 中查询 Top-K 相似结果 | Milvus IVF_FLAT 索引，distance metric: cosine |
| 语义理解 | 理解查询意图，不仅匹配关键词 | "如何提升转化率" → 查询优化技巧相关话术 |
| 上下文感知 | 基于用户行业/产品类型推荐话术 | 向量与用户画像混合过滤 |

### 2.2 BM25 关键词搜索（Lexical Search）

| 功能 | 说明 | 技术方案 |
|------|------|--------|
| 精准匹配 | 关键词精确查找 | Elasticsearch BM25 算法 |
| 字段权重 | 标题/核心观点权重高于内容 | 配置字段 boost（标题 2.0，内容 1.0） |
| 分词处理 | 支持中文分词 + 同义词扩展 | IK 分词器 + 自定义同义词典 |
| 快速过滤 | 按话术类别、风格、行业快速筛选 | Elasticsearch filter aggregation |

### 2.3 RRF 融合与重排

```
融合流程：
向量搜索 Top-100 (score_v)  \
                              → RRF 融合 → 综合排名 Top-20
BM25 搜索 Top-100 (score_b25) /

RRF 公式：
score_rrf = 60 / (k + rank_v) + 60 / (k + rank_b25)
其中 k = 60（超参数）

重排：Cross-Encoder BERT 重新排序前 20 个结果
```

### 2.4 搜索建议与热点推荐

| 功能 | 说明 | 实现 |
|------|------|------|
| 自动补全 | 用户输入时实时提示搜索词 | Redis 前缀树 + 热门搜索词缓存 |
| 热点话题 | 推荐当日高热度话题 | 基于搜索频率 + 互动数动态排序 |
| 个性推荐 | 基于用户历史搜索和采用记录推荐 | Collaborative Filtering（简单版本） |
| 相关推荐 | 查看某个话术后，推荐相关话术 | 向量相似度 + 用户协同过滤 |

## 3. API 设计规范

### 3.1 混合搜索（Hybrid Search）

```
POST /api/v1/script/search/hybrid
Content-Type: application/json

{
  "query": "如何提升转化率",
  "category": "PRODUCT_PITCH",          // 可选过滤条件
  "style": "FRIENDLY",                  // 可选
  "page": 0,
  "rows": 20,
  "vectorWeight": 0.5,                  // 向量搜索权重 (0-1)
  "lexicalWeight": 0.5                  // BM25 权重 (0-1)
}

Response 200 {
  "status": 200,
  "data": {
    "total": 42,
    "pageNum": 1,
    "pageSize": 20,
    "list": [
      {
        "scriptId": 123,
        "title": "高效产品卖点介绍话术",
        "content": "各位亲爱的观众，今天给大家介绍一款...",
        "category": "PRODUCT_PITCH",
        "style": "FRIENDLY",
        "author": "主播 A",
        "vectorScore": 0.92,              // 向量相似度 [0-1]
        "lexicalScore": 0.88,             // BM25 分数 [0-1]
        "hybridScore": 0.90,              // RRF 融合分数
        "effectivenessScore": 82.5,       // 话术效果评分
        "usageCount": 156,                // 使用次数
        "favoriteCount": 23,              // 收藏数

      }
    ],
    "searchTime": 145,                   // 搜索耗时 (ms)
    "executedAt": "2026-03-06T10:30:00Z"
  }
}
```

## 4. 数据模型设计

### 4.1 ScriptVector（向量存储）

```sql
CREATE TABLE sc_script_vector (
  id BIGINT PRIMARY KEY,
  script_version_id BIGINT NOT NULL UNIQUE,
  owner_id BIGINT NOT NULL,
  title VARCHAR(255),
  content_text TEXT,
  vector_embedding BYTEA,               -- 1024D 向量，存为 FLOAT32 数组
  vector_dimension INTEGER DEFAULT 1024,
  embedding_model VARCHAR(100),         -- 模型名称：BGE-M3 等
  embedded_at TIMESTAMP,
  is_indexed_milvus BOOLEAN DEFAULT FALSE,
  milvus_id BIGINT,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP,
  deleted INTEGER DEFAULT 0,
  FOREIGN KEY (script_version_id) REFERENCES live_script_version(id)
);

CREATE INDEX idx_script_version_id ON sc_script_vector(script_version_id);
CREATE INDEX idx_owner_id ON sc_script_vector(owner_id);
CREATE INDEX idx_embedded_at ON sc_script_vector(embedded_at);
```

### 4.2 SearchResult（搜索结果记录）

```sql
CREATE TABLE sc_search_result (
  id BIGINT PRIMARY KEY,
  owner_id BIGINT NOT NULL,
  query TEXT,
  search_type VARCHAR(50),              -- HYBRID / SEMANTIC / LEXICAL
  total_results INTEGER,
  top_result_id BIGINT,
  execution_time_ms INTEGER,
  vector_weight DECIMAL(3,2),
  lexical_weight DECIMAL(3,2),
  clicked_result_id BIGINT,
  clicked_at TIMESTAMP,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  deleted INTEGER DEFAULT 0
);

CREATE INDEX idx_owner_id ON sc_search_result(owner_id);
CREATE INDEX idx_query ON sc_search_result USING gin(query gin_trgm_ops);  -- 模糊查询
```

### 4.3 SearchSuggestion（搜索建议词）

```sql
CREATE TABLE sc_search_suggestion (
  id BIGINT PRIMARY KEY,
  suggestion_text VARCHAR(255) UNIQUE,
  suggestion_type VARCHAR(50),          -- HISTORY / HOT_TOPIC / RECOMMENDED
  search_count INTEGER DEFAULT 0,
  trending_score DECIMAL(3,2),
  result_count INTEGER,
  last_updated TIMESTAMP,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  deleted INTEGER DEFAULT 0
);

CREATE INDEX idx_suggestion_text ON sc_search_suggestion(suggestion_text);
CREATE INDEX idx_trending_score ON sc_search_suggestion(trending_score DESC);
```

## 5. 实现清单

### 5.1 Service 层（2 个）

| 服务 | 职责 | 关键方法 |
|------|------|--------|
| `VectorSearchService` | 向量搜索和索引管理 | `encodeText()` / `indexToMilvus()` / `semanticSearch()` / `rerank()` |
| `HybridSearchService` | 混合搜索和 RRF 融合 | `hybridSearch()` / `fuseResults()` / `calculateHybridScore()` |
| `SearchSuggestionService` | 搜索建议 | `getSuggestions()` / `updateTrendingScores()` / `getHotTopics()` |

**依赖**：
- Milvus Client（向量存储和检索）
- Elasticsearch Client（BM25 搜索）
- ScriptVectorRepository（向量持久化）
- Redis（缓存热点词和建议）

### 5.2 Controller 层（1 个）

| 控制器 | 接口 |
|-------|------|
| `ScriptSearchController` | hybridSearch / semanticSearch / suggest / searchHistory |

### 5.3 VO 层（3 个）

| VO | 用途 |
|----|------|
| `HybridSearchRequestVO` | 混合搜索入参 |
| `SearchResultVO` | 搜索结果返回值 |
| `SearchSuggestionVO` | 搜索建议返回值 |

### 5.4 定时任务

- `VectorEmbeddingTask`：定时将新话术向量化并导入 Milvus（每小时一次）
- `TrendingScoresUpdateTask`：每 6 小时更新一次热点搜索词评分

## 7. 性能与可靠性

### 7.1 性能目标

| 指标 | 目标 | 实现方案 |
|------|------|--------|
| 搜索响应时间 | < 300ms | 向量查询 + BM25 并行执行，Redis 缓存 |
| 建议词延迟 | < 100ms | 前缀树缓存在 Redis |
| 吞吐量 | > 1000 QPS | 连接池 + 查询优化 |
| 向量编码耗时 | < 500ms | 本地 Ollama 或云端 API 调用 |

### 7.2 容错机制

| 场景 | 处理 |
|------|------|
| Milvus 不可用 | 降级至 BM25 搜索 |
| Elasticsearch 故障 | 降级至向量搜索 |
| 向量编码失败 | 只索引不含向量的文本，BM25 可用 |
