## 1. 认证方式总览

auth 模块支持三种登录方式，统一返回 Token：

```
┌─────────────────────────────────────────────────────────┐
│                    登录入口                               │
├──────────┬──────────────┬───────────────────────────────┤
│ 密码登录  │ 短信/邮箱登录  │ OAuth 第三方登录               │
│          │              │                               │
│ username │ target       │ provider                      │
│ password │ code(6位)    │ (wechat/qq/douyin/volcano)    │
│ captcha? │              │                               │
├──────────┴──────────────┴───────────────────────────────┤
│                                                         │
│  校验通过 → 生成 Token(UUID) → 存入 AuthTokenStore       │
│  → 发布 LoginSuccessEvent → 更新 last_login_at          │
│  → 返回 Token + 用户信息                                 │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

## 2. 密码登录流程

```
Client                          Server
  │                               │
  │  POST /api/v1/auth/login      │
  │  {username, password}         │
  │──────────────────────────────→│
  │                               │
  │                    ┌──────────┴──────────┐
  │                    │ requireCaptcha(IP)?  │
  │                    └──────────┬──────────┘
  │                          yes/ \no
  │                          /     \
  │              ┌──────────┐     ┌──────────────┐
  │              │ 需要验证码 │     │ 查询用户      │
  │              │ captchaId │     │ (username,    │
  │              │ + code?   │     │  deleted=0)   │
  │              └─────┬────┘     └──────┬───────┘
  │                    │                 │
  │              校验验证码          用户不存在?
  │              失败→2009          → 2005
  │                    │                 │
  │                    └────────┬────────┘
  │                             │
  │                    ┌────────┴────────┐
  │                    │ 用户被封禁?      │
  │                    │ status=1 → 2006 │
  │                    └────────┬────────┘
  │                             │
  │                    ┌────────┴────────┐
  │                    │ BCrypt 验证密码   │
  │                    │ 错误 → record    │
  │                    │ LoginFailure(IP) │
  │                    │ → 2005          │
  │                    └────────┬────────┘
  │                             │ 成功
  │                    ┌────────┴────────┐
  │                    │ 生成 Token(UUID) │
  │                    │ 存入 TokenStore  │
  │                    │ 发布 LoginEvent  │
  │                    │ 更新 last_login  │
  │                    └────────┬────────┘
  │                             │
  │  {token, userId, username,  │
  │   nickname, avatarUrl,      │
  │   roleCode}                 │
  │←────────────────────────────│
```

**关键节点说明：**

| 步骤 | 说明 |
|------|------|
| requireCaptcha | 检查该 IP 是否在 15 分钟内有密码错误记录 |
| 校验验证码 | captchaId + captchaCode 匹配，且未过期（5分钟），校验后立即失效 |
| BCrypt 验证 | `BCrypt.checkpw(password, passwordHash)` |
| recordLoginFailure | 记录 IP 失败时间，后续该 IP 需验证码 |
| LoginSuccessEvent | 异步记录 auth_login_log（Spring Event） |

## 3. 短信/邮箱验证码登录流程

```
Client                          Server
  │                               │
  │  POST /api/v1/auth/sms/send   │
  │  {target, type:"login"}       │
  │──────────────────────────────→│
  │                               │
  │                    ┌──────────┴──────────┐
  │                    │ 限流检查              │
  │                    │ 同target 60秒内      │
  │                    │ 已发送? → 1003       │
  │                    └──────────┬──────────┘
  │                               │
  │                    ┌──────────┴──────────┐
  │                    │ 生成 6 位纯数字验证码  │
  │                    │ 落库 auth_verify_code│
  │                    │ expire_at=now+5min   │
  │                    └──────────┬──────────┘
  │                               │
  │  {status:200}                 │
  │←────────────────────────────│
  │                               │
  │  POST /api/v1/auth/login      │
  │  {loginType:"sms",            │
  │   target, code}               │
  │──────────────────────────────→│
  │                               │
  │                    ┌──────────┴──────────┐
  │                    │ 通过 target 查找用户  │
  │                    │ (mobile 或 email)    │
  │                    └──────────┬──────────┘
  │                               │
  │                    ┌──────────┴──────────┐
  │                    │ 校验验证码            │
  │                    │ type=login           │
  │                    │ 未过期 & 未使用       │
  │                    │ 错误 → 2010          │
  │                    └──────────┬──────────┘
  │                               │
  │                    ┌──────────┴──────────┐
  │                    │ 标记验证码已使用       │
  │                    │ used=1               │
  │                    └──────────┬──────────┘
  │                               │
  │                    后续同密码登录步骤 4-9
  │                               │
  │  {token, userId, ...}         │
  │←────────────────────────────│
```

**验证码校验规则：**

| 规则 | 说明 |
|------|------|
| 匹配条件 | target + code + type 三者匹配 |
| 有效期 | 5 分钟（expire_at > now） |
| 使用状态 | used=0（未使用） |
| 使用后 | 立即标记 used=1 |
| 尝试次数 | try_count 递增，可用于防暴力（预留） |
| 发送限流 | 同 target 60 秒内仅 1 次（BR-15） |

> 首版仅落库不真实发送，便于开发联调。正式环境需接入短信/邮件服务。

## 4. Token 管理

### 4.1 Token 生成

```java
// AuthTokenStore.createToken(userId, username, roleCode)
String token = UUID.randomUUID().toString();
TokenInfo info = new TokenInfo(userId, username, roleCode, LocalDateTime.now());
tokenMap.put(token, info);  // ConcurrentHashMap
return token;
```

### 4.2 Token 存储

| 属性 | 说明 |
|------|------|
| 格式 | UUID 随机字符串 |
| 存储 | 内存 ConcurrentHashMap（单机部署） |
| 有效期 | 24 小时（可配置） |
| 传递方式 | `Authorization: Bearer <token>` Header |
| 前端存储 | localStorage |

### 4.3 Token 校验流程

```
请求进入
  │
  ├── 路径在白名单? → 直接放行
  │
  ├── 无 Authorization Header? → 2001 (TOKEN_EXPIRED)
  │
  ├── Token 不在 TokenStore? → 2003 (TOKEN_INVALID)
  │
  ├── Token 已过期(>24h)? → 移除 Token → 2001 (TOKEN_EXPIRED)
  │
  └── Token 有效 → 设置 SecurityContext(userId, username, roleCode)
      → 继续处理请求
```

### 4.4 Token 过期清理

```
定时任务（每 10 分钟执行一次）：
  遍历 tokenMap
  → 检查每个 Token 的创建时间
  → 超过 24h 的 Token 移除
  → 记录清理数量日志

集群环境改用 Redis 实现：
  → 利用 Redis TTL 自动过期
  → 无需定时清理任务
```

## 5. 图片验证码系统

### 5.1 生成流程

```
GET /api/v1/auth/captcha
  │
  ├── CaptchaService.generate()
  │   ├── 生成 4 位字母数字混合验证码
  │   ├── 生成 captchaId (UUID)
  │   ├── 绘制验证码图片（含干扰线/噪点）
  │   ├── 存入内存缓存 {captchaId → code}，5 分钟有效
  │   └── 返回 captchaId + base64 编码图片
  │
  └── 响应：{captchaId, image: "data:image/png;base64,..."}
```

### 5.2 校验规则

| 规则 | 说明 |
|------|------|
| 长度 | 4 位 |
| 字符集 | 字母 + 数字混合 |
| 有效期 | 5 分钟 |
| 一次性 | 校验后立即失效（无论成功失败） |
| 大小写 | 不区分大小写 |

| 属性 | 值 |

### 6.2 限流机制

```
POST /api/v1/auth/sms/send
  │
  ├── 查询 auth_verify_code
  │   WHERE target = ? AND create_time > (now - 60s)
  │
  ├── 存在记录? → 1003 (RATE_LIMIT)
  │
  └── 不存在 → 生成验证码 → 落库
```

## 7. 防暴力破解机制

### 7.1 触发条件

```
密码登录失败
  │
  └── CaptchaService.recordLoginFailure(clientIp)
      │
      ├── 记录 {IP → 失败时间} 到内存 Map
      │
      └── 后续该 IP 登录时：
          CaptchaService.requireCaptcha(clientIp)
          │
          ├── 15 分钟内有失败记录? → true（需要验证码）
          │
          └── 超过 15 分钟? → false（自动解除）
```

### 7.2 完整流程

```
第 1 次登录（正确密码）：
  → 无需验证码 → 登录成功

第 1 次登录（错误密码）：
  → recordLoginFailure(IP) → 返回 2005

第 2 次登录（不带验证码）：
  → requireCaptcha(IP) = true → 返回 2004（需要验证码）

第 2 次登录（带正确验证码 + 正确密码）：
  → 校验验证码通过 → 登录成功

15 分钟后登录：
  → requireCaptcha(IP) = false → 无需验证码
```

### 7.3 配置参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| requireCaptchaMinutes | 15 | 密码错误后需验证码的时间窗口（分钟） |
| captchaLength | 4 | 图片验证码长度 |
| captchaExpireMinutes | 5 | 图片验证码有效期（分钟） |

## 8. OAuth 2.0 完整流程

### 8.1 支持的平台

| 平台 | provider 值 | 配置项 |
|------|------------|--------|
| 微信 | wechat | appId, appSecret, redirectUri |
| QQ | qq | appId, appSecret, redirectUri |
| 抖音 | douyin | appId, appSecret, redirectUri |
| 火山 | volcano | appId, appSecret, redirectUri |

### 8.2 OAuth 登录流程

```
┌────────┐     ┌────────┐     ┌──────────────┐
│ Client │     │ Server │     │ 第三方平台     │
└───┬────┘     └───┬────┘     └──────┬───────┘
    │              │                 │
    │ GET /oauth/  │                 │
    │ authorize    │                 │
    │ ?provider=   │                 │
    │  wechat      │                 │
    │─────────────→│                 │
    │              │                 │
    │  {url: "https://open.weixin   │
    │   .qq.com/..."}               │
    │←─────────────│                 │
    │              │                 │
    │  浏览器跳转到第三方授权页        │
    │────────────────────────────────→│
    │              │                 │
    │  用户授权后回调                  │
    │  /oauth/callback?code=xxx      │
    │←────────────────────────────────│
    │              │                 │
    │ GET /oauth/  │                 │
    │ callback     │                 │
    │ ?code=xxx    │                 │
    │ &state=xxx   │                 │
    │─────────────→│                 │
    │              │  code换token    │
    │              │────────────────→│
    │              │  access_token   │
    │              │←────────────────│
    │              │  拉取用户信息    │
    │              │────────────────→│
    │              │  {openId,       │
    │              │   nickname,     │
    │              │   avatar}       │
    │              │←────────────────│
    │              │                 │
    │              │ 查找绑定记录     │
    │              │ (provider+openId)│
    │              │                 │
    │  ┌───────────┴───────────┐    │
    │  │ 已绑定?                │    │
    │  │ Yes → 直接登录         │    │
    │  │ No  → 自动创建用户     │    │
    │  │       + 绑定 + 登录    │    │
    │  └───────────┬───────────┘    │
    │              │                 │
    │  Redirect    │                 │
    │  /oauth-callback.html         │
    │  ?token=xxx&userId=xxx        │
    │←─────────────│                 │
```

### 8.3 OAuth 绑定流程

```
已登录用户绑定第三方账号：

1. GET /oauth/authorize?provider=wechat&state=bind
   → state 改写为 "bind:<userId>"
   → 返回授权 URL

2. 用户在第三方平台授权

3. GET /oauth/callback?code=xxx&state=bind:123
   → 解析 state，识别为绑定操作
   → code 换 token → 拉取用户信息
   → 检查 provider+openId 是否已绑定其他用户
     → 已绑定 → 2012 (OAUTH_ALREADY_BOUND)
     → 未绑定 → 创建 auth_third_party_bind 记录
   → 重定向回前端页面
```

### 8.4 OAuth 首次登录自动创建

```
首次 OAuth 登录（provider+openId 无绑定记录）：

1. 自动创建 auth_user：
   - username: 自动生成（如 "wx_" + openId 前 8 位）
   - password_hash: 随机密码（BCrypt）
   - nickname: 第三方昵称
   - avatar_url: 第三方头像
   - role_code: "user"（默认角色，BR-08）
   - status: 0（正常）

2. 创建 auth_third_party_bind：
   - user_id: 新用户 ID
   - provider: wechat/qq/douyin/volcano
   - open_id: 第三方 openId
   - union_id: 联合 ID（如有）
   - nickname: 第三方昵称
   - avatar: 第三方头像

3. 生成 Token，返回登录结果
```

## 9. 密码安全策略

| 策略 | 实现 |
|------|------|
| 加密算法 | BCrypt（自带盐值，不可逆） |
| 最低长度 | 6 位 |
| 最大长度 | 128 位 |
| 修改密码 | 需验证原密码（BCrypt match） |
| 忘记密码 | 通过手机/邮箱验证码重置 |
| 管理员创建 | 管理员设置初始密码，用户可自行修改 |
| 生产环境 | admin 密码必须修改为强密码（≥12 位，含大小写+数字+特殊字符） |

**BCrypt 特性：**
- 自动生成随机盐值，每次加密结果不同
- 计算成本可调（默认 cost=10）
- 抗彩虹表攻击
- 验证时使用 `BCrypt.checkpw(plaintext, hash)`
