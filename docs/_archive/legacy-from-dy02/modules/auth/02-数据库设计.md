## 2. 表结构（DDL）

### 2.1 auth_user — 用户表

> Entity 对齐：`AuthUser.java`，注解 `@SQLRestriction("deleted = 0")`

```sql
CREATE TABLE auth_user (
    id              BIGSERIAL       PRIMARY KEY,
    username        VARCHAR(64)     NOT NULL,
    password_hash   VARCHAR(128)    NOT NULL,
    mobile          VARCHAR(20),
    email           VARCHAR(128),
    nickname        VARCHAR(64),
    avatar_url      VARCHAR(256),
    role_code       VARCHAR(32)     NOT NULL DEFAULT 'user',
    status          INTEGER         NOT NULL DEFAULT 0,
    banned_at       TIMESTAMP,
    banned_reason   VARCHAR(256),
    last_login_at   TIMESTAMP,
    organization_id BIGINT,
    deleted         INTEGER         NOT NULL DEFAULT 0,
    create_time     TIMESTAMP       DEFAULT CURRENT_TIMESTAMP,
    update_time     TIMESTAMP       DEFAULT CURRENT_TIMESTAMP
);

-- 用户名唯一索引（仅未删除记录）
CREATE UNIQUE INDEX uk_auth_user_username ON auth_user (username) WHERE deleted = 0;
```

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| id | BIGSERIAL | PK | 自增 | 主键 |
| username | VARCHAR(64) | NOT NULL | -- | 用户名（唯一） |
| password_hash | VARCHAR(128) | NOT NULL | -- | 密码哈希（BCrypt） |
| mobile | VARCHAR(20) | | -- | 手机号 |
| email | VARCHAR(128) | | -- | 邮箱 |
| nickname | VARCHAR(64) | | -- | 昵称 |
| avatar_url | VARCHAR(256) | | -- | 头像 URL |
| role_code | VARCHAR(32) | NOT NULL | 'user' | 角色编码，关联 auth_role.role_code |
| status | INTEGER | NOT NULL | 0 | 0=正常 1=封禁 |
| banned_at | TIMESTAMP | | -- | 封禁时间 |
| banned_reason | VARCHAR(256) | | -- | 封禁原因 |
| last_login_at | TIMESTAMP | | -- | 最后登录时间 |
| organization_id | BIGINT | | -- | 所属机构 ID（可空，达人可独立存在） |
| deleted | INTEGER | NOT NULL | 0 | 逻辑删除 |
| create_time | TIMESTAMP | | CURRENT_TIMESTAMP | 创建时间 |
| update_time | TIMESTAMP | | CURRENT_TIMESTAMP | 更新时间 |

### 2.4 auth_role_resource — 角色-资源关联表

> 关联表，不使用逻辑删除（无 deleted 字段）。角色授权更新采用"事务内全删重建"策略。
> Entity 注解：无 `@SQLRestriction`

```sql
CREATE TABLE auth_role_resource (
    id              BIGSERIAL       PRIMARY KEY,
    role_id         BIGINT          NOT NULL,
    resource_id     BIGINT          NOT NULL,
    create_time     TIMESTAMP       DEFAULT CURRENT_TIMESTAMP
);

-- 角色-资源唯一索引
CREATE UNIQUE INDEX uk_role_resource ON auth_role_resource (role_id, resource_id);
```

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| id | BIGSERIAL | PK | 自增 | 主键 |
| role_id | BIGINT | NOT NULL | -- | 角色 ID |
| resource_id | BIGINT | NOT NULL | -- | 资源 ID |
| create_time | TIMESTAMP | | CURRENT_TIMESTAMP | 创建时间 |

### 2.5 auth_login_log — 登录日志表

> Entity 对齐：`AuthLoginLog.java`，无逻辑删除

```sql
CREATE TABLE auth_login_log (
    id              BIGSERIAL       PRIMARY KEY,
    user_id         BIGINT,
    username        VARCHAR(64),
    login_type      VARCHAR(32)     NOT NULL DEFAULT 'password',
    device_type     VARCHAR(16)     NOT NULL DEFAULT 'web',
    ip              VARCHAR(64),
    user_agent      VARCHAR(256),
    status          INTEGER         NOT NULL DEFAULT 1,
```

| login_type | VARCHAR(32) | NOT NULL | 'password' | 登录方式：password / sms / email / oauth |
| device_type | VARCHAR(16) | NOT NULL | 'web' | 设备类型：web / ios / android |
| ip | VARCHAR(64) | | -- | 登录 IP |

| fail_reason | VARCHAR(256) | | -- | 失败原因（如：密码错误、用户不存在） |
| login_time | TIMESTAMP | NOT NULL | CURRENT_TIMESTAMP | 登录时间 |

## 3. 索引设计说明

| 表 | 索引 | 类型 | 说明 |
|---|------|------|------|
| auth_user | uk_auth_user_username | UNIQUE (partial) | `WHERE deleted=0`，保证未删除用户名唯一 |
| auth_role | uk_auth_role_code | UNIQUE (partial) | `WHERE deleted=0`，保证未删除角色编码唯一 |
| auth_role_resource | uk_role_resource | UNIQUE | `(role_id, resource_id)`，防止重复授权 |
| auth_login_log | idx_login_log_user_time | B-tree | `(user_id, login_time DESC)`，加速用户登录日志查询 |
| auth_third_party_bind | uk_provider_openid | UNIQUE (partial) | `WHERE deleted=0`，保证同平台同 open_id 唯一绑定 |

> 所有 partial unique index 使用 PostgreSQL 的 `WHERE deleted = 0` 语法，确保逻辑删除后可重新创建同名记录。

## 5. Entity 注解说明

| Entity 类 | 表名 | @SQLRestriction | 说明 |
|-----------|------|-----------------|------|
| AuthUser | auth_user | `"deleted = 0"` | 所有查询自动过滤已删除记录 |
| AuthRole | auth_role | `"deleted = 0"` | 所有查询自动过滤已删除记录 |
| AuthResource | auth_resource | `"deleted = 0"` | 所有查询自动过滤已删除记录 |
| AuthRoleResource | auth_role_resource | 无 | 关联表无逻辑删除，采用全删重建策略 |
| AuthLoginLog | auth_login_log | 无 | 日志表无逻辑删除 |
| AuthVerifyCode | auth_verify_code | 无 | 验证码表无逻辑删除 |
| AuthThirdPartyBind | auth_third_party_bind | `"deleted = 0"` | 解绑为逻辑删除 |
| AuthOrganization | auth_organization | `"deleted = 0"` | 机构表，逻辑删除 |
| AuthOrgMember | auth_org_member | `"deleted = 0"` | 机构成员表，逻辑删除 |

> 使用 Hibernate 6 的 `@SQLRestriction` 注解（替代已废弃的 `@Where`），在 Entity 级别自动追加 `WHERE deleted = 0` 条件。

## 6. 组织模型（v3.0 新增）

### 6.1 auth_organization — 机构表

> Entity 对齐：`AuthOrganization.java`，注解 `@SQLRestriction("deleted = 0")`

```sql
CREATE TABLE auth_organization (
    id              BIGSERIAL       PRIMARY KEY,
    org_name        VARCHAR(128)    NOT NULL,
    org_code        VARCHAR(64),
    contact_name    VARCHAR(64),
    contact_phone   VARCHAR(20),
    status          INTEGER         NOT NULL DEFAULT 1,
    owner_id        BIGINT          NOT NULL,
    deleted         INTEGER         NOT NULL DEFAULT 0,
    create_time     TIMESTAMP       DEFAULT CURRENT_TIMESTAMP,

CREATE UNIQUE INDEX uk_auth_org_code ON auth_organization (org_code) WHERE deleted = 0 AND org_code IS NOT NULL;
```

### 6.3 组织模型索引

| 表 | 索引 | 类型 | 说明 |
