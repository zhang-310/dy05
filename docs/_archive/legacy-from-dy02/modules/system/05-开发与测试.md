## 7. 功能测试（Functional Test）

### 7.1 API 调用日志（F01-F06）

| # | 场景 | 操作 | 预期 |
|---|------|------|------|
| F01 | 成功调用记录 | 外部 API 调用成功 | status=1，responseStatus=200，durationMs>0 |
| F02 | 失败调用记录 | 外部 API 调用失败（超时/异常） | status=0，errorMessage 有值 |
| F03 | 参数脱敏 | 调用含 access_token 的 API | requestParams 中 access_token 显示为 `***` |
| F04 | 响应截取 | 响应内容超过 2000 字符 | responseBody 截取为 2000 字符 |
| F05 | 按模块筛选 | api-log/list，module=douyin | 只返回 douyin 模块日志 |
| F06 | 按状态筛选 | api-log/list，status=0 | 只返回失败的调用日志 |

### 7.2 API 调用统计（F07-F09）

| # | 场景 | 操作 | 预期 |
|---|------|------|------|
| F07 | 总体统计 | api-log/stats | 返回 totalCalls/successRate/avgDurationMs |
| F08 | 按模块统计 | api-log/stats | byModule 包含各模块统计数据 |
| F09 | 按接口统计 | api-log/stats | byApiName 包含 Top 20 接口统计 |

### 7.3 数据同步日志（F10-F14）

| # | 场景 | 操作 | 预期 |
|---|------|------|------|
| F10 | 开始同步 | SyncLogService.startSync() | 新增 running 状态记录 |
| F11 | 更新进度 | SyncLogService.updateProgress() | totalCount/successCount/failCount 更新 |
| F12 | 完成同步 | SyncLogService.completeSync() | status=success，endTime 有值 |
| F13 | 同步失败 | SyncLogService.failSync() | status=failed，errorMessage 有值 |
| F14 | 同步日志列表 | sync-log/list，syncType=video_sync | 只返回视频同步记录 |

### 7.4 系统健康检查（F15-F18）

| # | 场景 | 操作 | 预期 |
|---|------|------|------|
| F15 | 全部组件正常 | health | 7 个组件均为 UP，latency 有值 |
| F16 | 某组件不可用 | 停止 Redis 后检查 | redis 为 DOWN，其他组件不受影响 |
| F17 | 组件超时 | 某组件响应超过 5 秒 | 该组件为 DOWN |
| F18 | 系统信息 | info | 返回 JVM 内存/线程数/运行时长 |

### 7.5 日志清理（F19-F20）

| # | 场景 | 操作 | 预期 |
|---|------|------|------|
| F19 | 自动清理 | 插入 31 天前的日志，触发清理任务 | 过期日志被删除 |
| F20 | 保留期可配置 | 修改 system.api-log.retention.days=7 | 7 天前的日志被清理 |

## 10. 验收标准

### 10.1 功能验收

- [ ] 外部 API 调用自动记录到 sys_api_call_log
- [ ] API 调用日志包含正确的 module/apiName/url/method/status/durationMs
- [ ] 敏感参数（access_token/client_secret/api_key）已脱敏
- [ ] 管理员可查看 API 调用日志列表，支持分页和多条件筛选
- [ ] API 调用统计正确（成功率、平均耗时、按模块/接口分组）
- [ ] 数据同步日志完整追踪（running → success/failed）
- [ ] 系统健康检查返回 7 个组件状态
- [ ] 系统运行信息返回 JVM 内存/线程数/运行时长
- [ ] 30 天自动清理正常执行

### 10.2 技术验收

- [ ] 所有接口返回 RESTResult 格式，包含 traceId
- [ ] API 调用日志写入使用异步，不影响业务调用性能
- [ ] 拦截器异常不影响业务 API 调用
- [ ] 健康检查各组件并行执行，单组件超时不阻塞其他组件
- [ ] 日志清理使用分批删除，避免长事务
- [ ] 分页参数有上限校验（rows <= 1000）
