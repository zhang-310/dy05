# W-10 监控告警与日志系统设计文档

## 模块概述

监控告警与日志系统是生产环境的眼睛和耳朵，提供完整的应用性能监控（APM）、实时告警、链路追踪和日志聚合分析能力。该模块基于 Prometheus + Grafana + SkyWalking + ELK Stack 开源体系，采集应用层、数据库、缓存、消息队列等多维度指标，实时发现和预警系统异常，支持快速定位和诊断生产问题。

**模块代码位置**: `/module/system/`
**监控数据库**: Prometheus (时序数据库) + InfluxDB (可选)
**错误码范围**: `3800-3899`
**采集间隔**: 15 秒（Prometheus）+ 事件驱动（日志流式）

### 2. 告警规则配置

**告警规则定义**（YAML）
```yaml
groups:
  - name: application
    rules:
      - alert: HighErrorRate
        expr: (rate(http_requests_total{status=~"5.."}[5m])) > 0.05
        for: 5m
        annotations:
          summary: "HTTP 错误率 > 5%，{{ $value }}%"
          description: "过去 5 分钟内平均错误率超过 5%"

      - alert: SlowQuery
        expr: quantile(0.99, rate(sql_query_duration_seconds[5m])) > 2.0
        for: 10m
        annotations:
          summary: "数据库 P99 查询延迟 > 2s"
          description: "{{ $labels.operation }} 操作 {{ $labels.table }} 表太慢"

      - alert: HighMemoryUsage
        expr: (jvm_memory_used_bytes{area="heap"} / jvm_memory_max_bytes{area="heap"}) > 0.85
        for: 3m
        annotations:
          summary: "JVM 堆内存使用率 > 85%，{{ $value }}%"
          description: "可能触发频繁 GC，需要立即优化或扩容"

      - alert: CacheHitRateLow
        expr: redis_cache_hits_total / (redis_cache_hits_total + redis_cache_misses_total) < 0.8
        for: 15m
        annotations:
          summary: "Redis 缓存命中率 < 80%，{{ $value }}%"
          description: "缓存策略可能不合理，检查热数据覆盖"

      - alert: GenerationQueueBacklog
        expr: rabbitmq_queue_messages_ready{queue="script-generation"} > 5000
        for: 10m
        annotations:
          summary: "脚本生成队列堆积 > 5000 条"
          description: "处理延迟高，需要扩容或优化消费速度"
```

**告警级别**
- **P1 (Critical)**：业务中断、数据丢失、安全事件 → 电话告警 + Slack + 钉钉
- **P2 (High)**：性能严重下降、错误率 > 5% → Slack + 钉钉
- **P3 (Medium)**：缓存命中率低、查询慢 → 邮件 + 日志记录
- **P4 (Low)**：磁盘使用率 > 80%、新版本上线 → 日志记录

### 4. 分布式链路追踪（SkyWalking）

**追踪链路示例**（用户发起脚本生成请求）
```
2026-03-06 12:30:45.123 [traceId: 12345abcde]
├─ POST /api/v1/script/generate [8234ms, 200]
   ├─ AuthTokenFilter [5ms] ✓
   ├─ ScriptGenerationController.create [8220ms]
   │  ├─ ScriptGenerationService.submit [8210ms]
   │  │  ├─ RabbitTemplate.convertAndSend [12ms] ✓
   │  │  ├─ JPA save script_generation [15ms] ✓
   │  │  └─ Redis set (缓存) [3ms] ✓
   │  └─ RESTResult.success [5ms] ✓
   └─ 异步消费 (script-generation-queue)
      ├─ DeepSeekAiServiceImpl.generate [8000ms]
      │  ├─ HTTP POST to api.deepseek.com [7900ms]
      │  └─ JSON 解析 [10ms] ✓
      └─ JPA update [40ms] ✓
```

**关键追踪维度**
- HTTP 请求端到端延迟
- RPC/消息队列处理链路
- 外部 API 调用（AI 服务、支付网关）
- 数据库操作（SQL 语句、执行时间）
- 缓存操作（Hit/Miss、延迟）

### 5. 日志收集与分析（ELK Stack）

**日志聚合流程**
```
应用日志 (SLF4J + Logback)
    │
    ├─ 控制台输出 (Console Appender)
    │
    ├─ 本地文件 (RollingFile, 按天或 100MB)
    │
    └─ Filebeat / Fluentd
         │
         └─ Elasticsearch (分布式搜索引擎)
              │
              └─ Kibana (日志查询和分析)
```

**日志索引策略** (每天一个 Index)
```
logs-application-2026-03-06
logs-audit-2026-03-06
logs-performance-2026-03-06
logs-error-2026-03-06
```

**日志查询示例**
```elasticsearch
# 查找过去 1 小时内的所有 500 错误
GET logs-*/_search
{
  "query": {
    "bool": {
      "must": [
        {"match": {"level": "ERROR"}},
        {"match": {"status_code": 500}},
        {"range": {"@timestamp": {"gte": "now-1h"}}}
      ]
    }
  }
}

# 查找用户 123 的所有操作
GET logs-audit-*/_search
{
  "query": {
    "match": {"user_id": 123}
  }
}
```

## 验收清单

### 功能验收

- [ ] **Prometheus 采集**：应用能暴露 /actuator/prometheus 端点，采集 >50 个自定义指标
- [ ] **告警规则**：至少 10 条告警规则生效，触发告警时能正确推送通知
- [ ] **Grafana 仪表板**：预置 5+ 个仪表板，包含实时数据更新
- [ ] **SkyWalking 链路**：关键业务流程的追踪链路完整，拓扑清晰
- [ ] **日志聚合**：应用日志汇聚到 Elasticsearch，Kibana 可搜索查询

### 性能验收

- [ ] **指标查询延迟**：Prometheus 单个指标查询 <200ms
- [ ] **仪表板加载**：Grafana 仪表板首屏加载 <3s
- [ ] **日志搜索**：Kibana 在 1M+ 日志中搜索 <1s
- [ ] **告警延迟**：从指标异常到告警通知 <2 分钟

### 可靠性验收

- [ ] **高可用**：Prometheus、Elasticsearch 支持多副本高可用部署
- [ ] **数据持久化**：监控数据至少保留 30 天（可配置）
- [ ] **故障自恢复**：组件宕机后自动重连和数据同步

## 关键告警规则

| 告警规则 | 表达式 | 阈值 | 级别 |
|--------|--------|------|------|
| 应用错误率 | `rate(http_requests_total{status=~"5.."}[5m])` | >5% | P2 |
| 数据库连接耗尽 | `db_connection_pool_active / db_connection_pool_max` | >90% | P1 |
| JVM 堆内存溢出风险 | `jvm_memory_used_bytes{area="heap"} / jvm_memory_max_bytes` | >85% | P2 |
| 消息队列堆积 | `rabbitmq_queue_messages_ready{queue="..."}` | >5000 | P2 |
| API P99 延迟 | `quantile(0.99, rate(http_request_duration_seconds))` | >5s | P3 |
| Redis 缓存命中率 | `hits / (hits + misses)` | <80% | P3 |
| 磁盘使用率 | `node_filesystem_avail / node_filesystem_size` | <15% | P3 |
