# system 模块 — 需求分析

> 版本：3.0 | 更新日期：2026-02-26

---

## 1. 模块定位

system 模块负责系统级监控和审计，提供 API 调用日志、数据同步记录和系统健康检查。与 log 模块的区别：log 记录业务操作日志（用户行为审计），system 记录系统级技术日志（API 调用、数据同步）。

---

## 2. 功能清单

```
system 模块
├── API 调用日志
│   ├── 记录所有外部 API 调用（抖音 API / AI 模型 API）
│   ├── 调用日志查询（按模块/状态/时间筛选，分页）
│   └── 调用统计（成功率、平均耗时、按接口分组）
│
├── 数据同步日志
│   ├── 记录数据同步任务（视频同步/直播数据同步/账号数据同步）
│   ├── 同步状态追踪（running → success / failed）
│   └── 同步日志查询（按类型/状态/时间筛选，分页）
│
└── 系统监控
    ├── 系统健康检查（7 个组件状态）
    │   ├── database — 数据库连接
    │   ├── ollama — AI 推理服务
    │   ├── milvus — 向量数据库
    │   ├── elasticsearch — 搜索引擎
    │   ├── redis — 缓存服务
    │   ├── rabbitmq — 消息队列
    │   └── storage — 存储服务
    │
    └── 系统运行信息
        ├── JVM 内存使用
        ├── 线程数
        └── 运行时长
```

---

## 3. 业务规则

| 编号 | 规则 | 说明 |
|------|------|------|
| BR-01 | 自动记录 | 外部 API 调用通过拦截器自动记录，业务代码无需手动调用 |
| BR-02 | 日志保留 | API 调用日志保留 30 天（可通过 sys_config `system.api-log.retention.days` 配置），到期自动清理 |
| BR-03 | 敏感信息脱敏 | API Key、Token、Secret 等在日志中脱敏显示为 `***` |

---

## 4. 模块依赖

```
依赖关系：
common (config/vo/util/constant) ← system
auth (SecurityContext 获取当前用户) ← system
config (sys_config 读取保留天数)   ← system
storage (健康检查调用 isAvailable) ← system
                                      ↑
                      douyin / ai 等模块通过拦截器自动记录 API 调用
                      shortvideo / live 等模块调用 SyncLogService 记录同步日志
```

| 依赖方向 | 模块 | 依赖内容 |
|---------|------|---------|
| system → common | vo | RESTResult, BasicQueryDto, PageResultVO |
| system → auth | 认证 | SecurityContext（获取当前用户 userId） |
| system → config | 配置 | sys_config 表（system.api-log.retention.days） |
| system → storage | 健康检查 | StorageProvider.isAvailable() |
| 业务模块 → system | 服务 | ApiCallLogInterceptor 自动记录；SyncLogService 手动调用 |
