# system 模块 — 接口设计

> 版本：3.0 | 更新日期：2026-02-26

---

## 1. 接口总表

共计 **5 个端点**，均在 SystemController 中。

### 1.1 SystemController（/api/v1/system）— 5 个端点

| # | 方法 | 路径 | 权限 | 说明 |
|---|------|------|------|------|
| 1 | POST | /api/v1/system/api-log/list | 管理员 | API 调用日志列表（分页、筛选） |
| 2 | POST | /api/v1/system/api-log/stats | 管理员 | API 调用统计（成功率、平均耗时） |
| 3 | POST | /api/v1/system/sync-log/list | 管理员 | 同步日志列表（分页、筛选） |
| 4 | POST | /api/v1/system/health | 管理员 | 系统健康检查（7 个组件） |
| 5 | POST | /api/v1/system/info | 管理员 | 系统运行信息（JVM/线程/运行时长） |

> 所有接口仅管理员可访问。

## 2. 关键接口详细设计

### 接口 1：API 调用日志列表

```
POST /api/v1/system/api-log/list
权限：管理员
```

**请求参数（ApiCallLogSearchVO，继承 BasicQueryDto）：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| page | Integer | 否 | 页码，默认 0 |
| rows | Integer | 否 | 每页条数，默认 30 |
| sortName | String | 否 | 排序字段，默认 id |
| sortOrder | String | 否 | asc/desc，默认 desc |
| module | String | 否 | 按模块筛选（douyin/ai/live） |
| apiName | String | 否 | 按 API 名称模糊搜索 |
| status | Integer | 否 | 按状态筛选（1=成功 0=失败） |
| startTime | String | 否 | 开始时间（yyyy-MM-dd HH:mm:ss） |
| endTime | String | 否 | 结束时间 |

**响应（PageResultVO）：**

```json
{
  "status": 200,
  "data": {
    "total": 5000,
    "list": [
      {
        "id": 1001,
        "module": "douyin",
        "apiName": "获取视频列表",
        "requestUrl": "https://open.douyin.com/api/v2/video/list/",
        "requestMethod": "GET",
        "responseStatus": 200,
        "status": 1,
        "durationMs": 350,
        "userId": 1,
        "createTime": "2026-02-26 10:30:00"
      }
    ],
    "pageNum": 0,
    "pageSize": 30
  }
}
```

> 列表不返回 requestParams 和 responseBody（大字段），避免传输量过大。

### 接口 4：系统健康检查

```
POST /api/v1/system/health
权限：管理员
```

**请求参数：** 无

**响应：**

```json
{
  "status": 200,
  "data": {
    "database": { "status": "UP", "latency": "5ms" },
    "ollama": { "status": "UP", "latency": "200ms" },
    "milvus": { "status": "UP", "latency": "30ms" },
    "elasticsearch": { "status": "UP", "latency": "15ms" },
    "redis": { "status": "UP", "latency": "2ms" },
    "rabbitmq": { "status": "UP", "latency": "5ms" },
    "storage": { "status": "UP", "provider": "bos" }
  }
}
```

**组件检查方式：**

| 组件 | 检查方式 | 超时 |
|------|---------|------|
| database | 执行 `SELECT 1` | 3s |
| ollama | HTTP GET /api/tags | 5s |
| milvus | 检查连接状态 | 3s |
| elasticsearch | HTTP GET /_cluster/health | 3s |
| redis | 执行 PING | 2s |
| rabbitmq | 检查连接状态 | 3s |
| storage | 调用 StorageProvider.isAvailable() | 3s |

> 任一组件检查超时或异常，该组件 status 返回 "DOWN"，不影响其他组件检查。

## 3. 错误码表

system 模块不定义专属错误码，使用通用错误码：

| 错误码 | 常量名 | 说明 | 触发场景 |
|--------|--------|------|---------|
| 1001 | PARAM_INVALID | 参数校验失败 | 筛选参数格式错误 |
| 2002 | NO_PERMISSION | 无权限 | 非管理员访问 |
