## 2. 表结构（DDL）

### 2.1 sys_api_call_log — API 调用日志表

> Entity 对齐：`SysApiCallLog.java`，无逻辑删除（定期物理清理）

```sql
CREATE TABLE sys_api_call_log (
    id                BIGSERIAL       PRIMARY KEY,
    module            VARCHAR(64)     NOT NULL,
    api_name          VARCHAR(256)    NOT NULL,
    request_url       VARCHAR(512),
    request_method    VARCHAR(16),
    request_params    TEXT,
    response_status   INTEGER,
    response_body     TEXT,
    status            INTEGER         NOT NULL DEFAULT 1,
    error_message     VARCHAR(512),
    duration_ms       BIGINT,
    user_id           BIGINT,
    create_time       TIMESTAMP       DEFAULT CURRENT_TIMESTAMP
);

-- 按模块+时间查询
CREATE INDEX idx_api_log_module_time ON sys_api_call_log (module, create_time DESC);

-- 按状态+时间查询
CREATE INDEX idx_api_log_status_time ON sys_api_call_log (status, create_time DESC);

-- 按时间清理（30 天自动清理用）
CREATE INDEX idx_api_log_create_time ON sys_api_call_log (create_time);
```

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| id | BIGSERIAL | PK | 自增 | 主键 |
| module | VARCHAR(64) | NOT NULL | -- | 模块：douyin / ai / live |
| api_name | VARCHAR(256) | NOT NULL | -- | API 名称/路径（如"获取视频列表""文本生成"） |
| request_url | VARCHAR(512) | | -- | 请求 URL |
| request_method | VARCHAR(16) | | -- | 请求方法：GET / POST |
| request_params | TEXT | | -- | 请求参数（脱敏后，API Key/Token 替换为 ***） |
| response_status | INTEGER | | -- | HTTP 响应状态码 |
| response_body | TEXT | | -- | 响应内容（截取前 2000 字符） |
| status | INTEGER | NOT NULL | 1 | 调用状态：1=成功 0=失败 |
| error_message | VARCHAR(512) | | -- | 错误信息（失败时记录） |
| duration_ms | BIGINT | | -- | 调用耗时（毫秒） |
| user_id | BIGINT | | -- | 触发用户 ID |
| create_time | TIMESTAMP | | CURRENT_TIMESTAMP | 记录时间 |

### 2.2 sys_sync_log — 数据同步日志表

> Entity 对齐：`SysSyncLog.java`，无逻辑删除

```sql
CREATE TABLE sys_sync_log (
    id              BIGSERIAL       PRIMARY KEY,
    sync_type       VARCHAR(64)     NOT NULL,
    user_id         BIGINT,
    account_id      BIGINT,
    status          VARCHAR(16)     NOT NULL DEFAULT 'running',
    total_count     INTEGER         DEFAULT 0,
    success_count   INTEGER         DEFAULT 0,
    fail_count      INTEGER         DEFAULT 0,
    error_message   TEXT,
    start_time      TIMESTAMP,
    end_time        TIMESTAMP,
    create_time     TIMESTAMP       DEFAULT CURRENT_TIMESTAMP
);

-- 按同步类型+时间查询
CREATE INDEX idx_sync_log_type_time ON sys_sync_log (sync_type, create_time DESC);

-- 按用户+时间查询
CREATE INDEX idx_sync_log_user_time ON sys_sync_log (user_id, create_time DESC);
```

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| id | BIGSERIAL | PK | 自增 | 主键 |
| sync_type | VARCHAR(64) | NOT NULL | -- | 同步类型：video_sync / live_data_sync / account_data_sync |
| user_id | BIGINT | | -- | 关联用户 ID |
| account_id | BIGINT | | -- | 关联抖音账号 ID |
| status | VARCHAR(16) | NOT NULL | 'running' | 状态：running / success / failed |
| total_count | INTEGER | | 0 | 总数据量 |
| success_count | INTEGER | | 0 | 成功数量 |
| fail_count | INTEGER | | 0 | 失败数量 |
| error_message | TEXT | | -- | 错误信息（失败时记录） |
| start_time | TIMESTAMP | | -- | 同步开始时间 |
| end_time | TIMESTAMP | | -- | 同步结束时间 |
| create_time | TIMESTAMP | | CURRENT_TIMESTAMP | 记录创建时间 |

## 3. 索引设计说明

### 3.1 sys_api_call_log 索引

| 索引 | 类型 | 列 | 说明 |
|------|------|---|------|
| idx_api_log_module_time | B-tree | (module, create_time DESC) | 按模块查询调用日志 |
| idx_api_log_status_time | B-tree | (status, create_time DESC) | 按成功/失败状态查询 |
| idx_api_log_create_time | B-tree | (create_time) | 30 天自动清理时按时间范围删除 |

### 3.2 sys_sync_log 索引

| 索引 | 类型 | 列 | 说明 |
|------|------|---|------|
| idx_sync_log_type_time | B-tree | (sync_type, create_time DESC) | 按同步类型查询 |
| idx_sync_log_user_time | B-tree | (user_id, create_time DESC) | 按用户查询同步记录 |

## 4. Entity 注解说明

| Entity 类 | 表名 | @SQLRestriction | 说明 |
|-----------|------|-----------------|------|
| SysApiCallLog | sys_api_call_log | 无 | 技术日志表，定期物理清理，无逻辑删除 |
| SysSyncLog | sys_sync_log | 无 | 同步日志表，无逻辑删除 |

> 两张表均不使用 `@SQLRestriction`，不设 deleted 字段。API 调用日志通过定时任务物理删除过期数据。

## 5. 数据增长预估

### 5.1 sys_api_call_log

| 场景 | 日均记录数 | 30 天存量 | 说明 |
|------|-----------|----------|------|
| 初期（10 用户） | ~500 条 | ~15,000 条 | 抖音 API + AI API 调用 |
| 中期（100 用户） | ~5,000 条 | ~150,000 条 | 30 天自动清理控制总量 |
| 后期（1000+ 用户） | ~50,000 条 | ~1,500,000 条 | 索引 + 定期清理可支撑 |

> 30 天自动清理策略保证表数据量可控。

### 5.2 sys_sync_log

| 场景 | 日均记录数 | 月增长 | 说明 |
|------|-----------|--------|------|
| 初期 | ~20 条 | ~600 条 | 每次同步一条记录 |
| 中期 | ~200 条 | ~6,000 条 | 数据量小，无需特殊处理 |
