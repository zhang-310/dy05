## 1. 行业分类树形结构

行业分类采用父子层级结构，最多 2 级（一级行业 + 二级子行业）。

```
行业分类
├── 美妆护肤
│   ├── 护肤品
│   ├── 彩妆
│   └── 美容仪器
├── 服装鞋帽
│   ├── 女装
│   ├── 男装
│   └── 鞋靴
├── 食品饮料
│   ├── 零食
│   ├── 饮品
│   └── 生鲜
├── 数码家电
├── 家居家装
├── 母婴用品
├── 运动户外
├── 图书教育
├── 医疗健康
├── 汽车出行
├── 旅游酒店
├── 金融保险
├── 房产建材
├── 本地生活
└── 其他
```

> 系统预设 15 个一级行业。二级子行业由管理员按需添加。

### 1.1 层级规则

| 规则 | 说明 |
|------|------|
| 最大层级 | 2 级（parent_id = 0 为一级，parent_id > 0 为二级） |
| 新增校验 | 如果 parent_id 指向的行业本身已有 parent_id > 0，则拒绝（不允许三级） |
| 同级唯一 | 同一 parent_id 下 industry_name 不可重复 |
| 排序 | 按 sort_order 升序排列 |

## 2. 行业与其他模块的关联

行业分类是全局共用的基础数据，被多个业务模块引用。

```
                    ┌──────────────┐
                    │ sys_industry │
                    │   行业分类    │
                    └──────┬───────┘
                           │
            ┌──────────────┼──────────────┐
            │              │              │
   ┌────────┴────────┐ ┌──┴──────────┐ ┌─┴──────────────┐
   │ douyin_account  │ │   script    │ │  short_video   │
   │ 抖音账号        │ │   脚本      │ │  短视频         │
   │                 │ │             │ │                │
   │ industry_id ──→ │ │ industry_id │ │ industry_id    │
   └─────────────────┘ └─────────────┘ └────────────────┘
```

### 2.1 引用方式

| 模块 | 表 | 字段 | 说明 |
|------|---|------|------|
| douyin | douyin_account | industry_id | 抖音账号所属行业 |
| script | script | industry_id | 脚本适用行业 |
| shortvideo | short_video | industry_id | 短视频所属行业 |

### 2.2 引用场景

- 创建抖音账号时选择所属行业
- 创建脚本时选择适用行业，用于筛选和推荐
- 短视频关联行业，用于数据分析和分类统计
- 各模块列表页可按行业筛选

## 3. 行业 CRUD

### 3.1 查询

- **树形查询**（/config/industry/tree）：返回完整的行业树，前端用于管理页面展示
- **全量列表**（/config/industry/list）：返回扁平列表，前端用于下拉选择器

### 3.2 新增/编辑

```
POST /api/v1/config/industry/save
```

| 字段 | 必填 | 说明 |
|------|------|------|
| id | 编辑时必填 | 为空时新增 |
| industryName | 是 | 行业名称 |
| parentId | 否 | 父行业 ID，默认 0（一级行业） |
| sortOrder | 否 | 排序序号，默认 0 |

**校验规则：**
- 同一 parent_id 下 industry_name 不可重复
- parent_id 指向的行业必须是一级行业（parent_id = 0），不允许创建三级行业
- industry_name 长度 1-64 字符

### 3.3 删除

```
POST /api/v1/config/industry/delete
```

**删除保护规则（BR-08）：**

删除前检查是否被其他模块引用：

```java
public void deleteIndustry(Long id) {
    // 1. 检查是否有子行业
    long childCount = industryRepository.countByParentId(id);
    if (childCount > 0) {
        throw new BusinessException(ErrorCode.INDUSTRY_IN_USE, "该行业下有子行业，请先删除子行业");
    }

    // 2. 检查是否被 douyin_account 引用
    long douyinCount = douyinAccountRepository.countByIndustryId(id);
    if (douyinCount > 0) {
        throw new BusinessException(ErrorCode.INDUSTRY_IN_USE,
            "该行业被 " + douyinCount + " 个抖音账号引用，不可删除");
    }

    // 3. 检查是否被 script 引用
    long scriptCount = scriptRepository.countByIndustryId(id);
    if (scriptCount > 0) {
        throw new BusinessException(ErrorCode.INDUSTRY_IN_USE,
            "该行业被 " + scriptCount + " 个脚本引用，不可删除");
    }

    // 4. 检查是否被 short_video 引用
    long videoCount = shortVideoRepository.countByIndustryId(id);
    if (videoCount > 0) {
        throw new BusinessException(ErrorCode.INDUSTRY_IN_USE,
            "该行业被 " + videoCount + " 个短视频引用，不可删除");
    }

    // 5. 逻辑删除
    industryRepository.softDelete(id);
}
```

> 删除保护的错误提示中包含引用数量，帮助管理员了解影响范围。

## 5. 行业删除保护

### 5.1 保护机制总结

| 检查项 | 条件 | 错误提示 |
|--------|------|---------|
| 子行业 | `countByParentId(id) > 0` | 该行业下有子行业，请先删除子行业 |
| 抖音账号 | `douyinAccountRepository.countByIndustryId(id) > 0` | 该行业被 N 个抖音账号引用，不可删除 |
| 脚本 | `scriptRepository.countByIndustryId(id) > 0` | 该行业被 N 个脚本引用，不可删除 |
| 短视频 | `shortVideoRepository.countByIndustryId(id) > 0` | 该行业被 N 个短视频引用，不可删除 |

### 5.2 扩展性

当新模块需要引用行业分类时：
1. 在新模块的表中添加 `industry_id` 字段
2. 在 `SysIndustryService.deleteIndustry()` 中增加对应的引用检查
3. 无需修改 sys_industry 表结构
