> 版本：3.0 | 更新日期：2026-02-26

## 1. 分组层级设计

config 模块采用 2 级分组树结构组织配置项：

```
一级分组（大类）
├── 二级分组（子类）
│   ├── 配置项 A
│   ├── 配置项 B
│   └── 配置项 C
├── 二级分组（子类）
│   ├── 配置项 D
│   └── 配置项 E
```

### 1.1 分组树示例

```
系统配置 (system)
├── 基础设置 (system.basic)
│   ├── system.basic.site_name = "抖音运营管理系统"
│   ├── system.basic.logo_url = "/static/logo.png"
│   ├── system.basic.copyright = "Copyright © 2026"
│   └── system.basic.icp = ""
├── 安全设置 (system.security)
│   ├── system.security.token_expire_hours = "24"
│   ├── system.security.password_min_length = "6"
│   └── system.security.login_fail_lock = "5"
└── 通知设置 (system.notification)
    └── ...

AI 配置 (ai)
├── 知识库 (ai.knowledge)
│   ├── ai.knowledge.api_url = ""
│   ├── ai.knowledge.api_key = "******"  ← password 类型
│   └── ai.knowledge.dimension = "1536"
├── 文案生成 (ai.copywriting)
├── 话术生成 (ai.speech)
├── 图像生成 (ai.image)
├── 视频生成 (ai.video)
└── 语音合成 (ai.tts)

存储配置 (storage)
├── 本地存储 (storage.local)
└── 对象存储 (storage.oss)

抖音接口 (douyin)
├── 开放平台 (douyin.open)
└── 数据接口 (douyin.data)
```

### 1.2 分组编码命名规范

- 一级分组：单词，如 `system`、`ai`、`storage`、`douyin`
- 二级分组：`一级编码.子类`，如 `ai.knowledge`、`storage.oss`
- 配置键：`二级分组编码.配置名`，如 `ai.knowledge.api_url`

> 这种点分命名使得按前缀查询非常方便，如查询 `ai.%` 可获取所有 AI 相关配置。

### 1.3 预设分组不可删除机制

预设分组（`is_preset = 1`）由系统初始化时创建，包含所有 4 大类及其 13 个子分组。

- 预设分组不可删除（BR-03），尝试删除返回错误码 3601
- 预设分组可以编辑名称和描述，但不可修改 `group_code`
- 用户可以在预设分组下新增配置项
- 用户可以创建自定义分组（`is_preset = 0`），自定义分组可删除

## 2. 配置值类型系统

config 模块支持 5 种配置值类型，保存时根据类型进行格式校验。

| 类型 | value_type | 校验规则 | 示例值 |
|------|-----------|---------|--------|
| 字符串 | string | 无特殊校验 | `"抖音运营管理系统"` |
| 数字 | number | 必须为合法数字（整数或小数） | `"24"`, `"0.7"` |
| 布尔 | boolean | 必须为 `"true"` 或 `"false"` | `"true"` |
| JSON | json | 必须为合法 JSON 字符串 | `'{"key":"value"}'` |
| 密码 | password | 无特殊校验，列表查询时脱敏 | `"sk-xxxxxxxxxxxx"` |

### 2.1 类型校验实现

```java
public void validateConfigValue(String value, String valueType) {
    if (value == null || value.isEmpty()) return; // 允许空值

    switch (valueType) {
        case "number":
            try {
                new BigDecimal(value);
            } catch (NumberFormatException e) {
                throw new BusinessException(ErrorCode.CONFIG_VALUE_TYPE_INVALID,
                    "值类型为 number，但值不是合法数字");
            }
            break;
        case "boolean":
            if (!"true".equals(value) && !"false".equals(value)) {
                throw new BusinessException(ErrorCode.CONFIG_VALUE_TYPE_INVALID,
                    "值类型为 boolean，但值不是 true/false");
            }
            break;
        case "json":
            try {
                objectMapper.readTree(value);
            } catch (Exception e) {
                throw new BusinessException(ErrorCode.CONFIG_VALUE_TYPE_INVALID,
                    "值类型为 json，但值不是合法 JSON");
            }
            break;
        // string, password 无需校验
    }
}
```

## 3. 敏感值脱敏策略

`value_type = password` 的配置项包含敏感信息（API Key、Secret 等），需要脱敏处理。

### 3.1 脱敏规则

| 场景 | 是否脱敏 | 返回值 |
|------|---------|--------|
| 管理端列表查询（/config/search） | 是 | `"******"` |
| 管理端详情查询（/config/get） | 否 | 原值（编辑时需要看到） |
| 按 key 获取（/config/get-by-key） | 否 | 原值（后端服务调用） |
| 按分组获取（/config/get-by-group） | 否 | 原值（后端服务调用） |
| 导出（/config/export） | 是 | `"******"` |

### 3.2 脱敏实现

```java
// 在 Service 层列表查询后处理
public Page<SysConfigVO> searchConfigs(ConfigSearchVO searchVO) {
    Page<SysConfig> page = configRepository.findByGroupId(...);
    return page.map(config -> {
        SysConfigVO vo = toVO(config);
        if ("password".equals(config.getValueType())) {
            vo.setConfigValue("******");
        }
        return vo;
    });
}
```

## 4. 内存缓存机制

config 模块使用 `ConcurrentHashMap` 作为内存缓存，避免每次读取配置都查询数据库。

### 4.1 缓存结构

```java
@Service
public class SysConfigService {

    // 缓存：config_key → config_value
    private final ConcurrentHashMap<String, String> configCache = new ConcurrentHashMap<>();

    // 缓存：group_code → List<SysConfig>
    private final ConcurrentHashMap<String, List<SysConfigCacheItem>> groupCache = new ConcurrentHashMap<>();
}
```

### 4.2 缓存生命周期

```
应用启动
  │
  ├── @PostConstruct → loadAllConfigs()
  │   从数据库加载全部配置到 configCache 和 groupCache
  │
运行时
  │
  ├── 读取配置 → getValueByKey(key)
  │   优先从 configCache 获取，命中直接返回
  │   未命中 → 查数据库 → 回填缓存 → 返回
  │
  ├── 修改配置 → save() / delete()
  │   写入数据库 → 立即刷新 configCache 和 groupCache
  │
  └── 手动刷新（预留）
      全量重新加载缓存
```

### 4.3 缓存刷新实现

```java
@Transactional
public void saveConfig(SysConfigSaveVO vo) {
    // 1. 校验 + 保存到数据库
    SysConfig config = saveToDatabase(vo);

    // 2. 立即刷新缓存
    refreshCache(config.getConfigKey(), config.getConfigValue(), config.getGroupId());
}

private void refreshCache(String key, String value, Long groupId) {
    // 刷新 key 缓存
    if (value != null) {
        configCache.put(key, value);
    } else {
        configCache.remove(key);
    }

    // 刷新 group 缓存
    SysConfigGroup group = groupRepository.findById(groupId).orElse(null);
    if (group != null) {
        List<SysConfig> configs = configRepository.findByGroupId(groupId);
        groupCache.put(group.getGroupCode(), configs.stream()
            .map(this::toCacheItem)
            .collect(Collectors.toList()));
    }
}
```

### 4.4 注意事项

- 当前为单机部署方案，`ConcurrentHashMap` 足够
- 如需集群部署，需改为 Redis 缓存 + 发布/订阅通知其他节点刷新
- 缓存不设过期时间，仅通过写操作触发刷新

## 5. 配置查询 API

其他模块通过以下两种方式读取配置：

### 5.1 按 key 获取单个配置

```java
// 其他模块调用示例
@Autowired
private SysConfigService configService;

public void doSomething() {
    String apiUrl = configService.getValueByKey("ai.knowledge.api_url");
    String apiKey = configService.getValueByKey("ai.knowledge.api_key");
    // ...
}
```

### 5.2 按分组编码批量获取

```java
// 获取某个分组下的所有配置
Map<String, String> knowledgeConfigs = configService.getValuesByGroupCode("ai.knowledge");
// knowledgeConfigs = {
//   "ai.knowledge.api_url" → "https://...",
//   "ai.knowledge.api_key" → "sk-xxxx",
//   "ai.knowledge.dimension" → "1536"
// }
```

### 5.3 带类型转换的便捷方法

```java
// 获取数字类型配置
int tokenExpireHours = configService.getIntValue("system.security.token_expire_hours", 24);

// 获取布尔类型配置
boolean featureEnabled = configService.getBooleanValue("system.feature.xxx", false);
```

## 6. 配置导入/导出

### 6.1 导出

- 管理员可导出全部或指定大类的配置为 JSON 格式
- `password` 类型的值导出时脱敏为 `"******"`
- 导出内容包含分组结构和配置项

### 6.2 导入（预留）

- 当前版本暂不实现导入功能
- 后续可支持 JSON 文件导入，覆盖或合并已有配置
- 导入时需校验 config_key 唯一性和 value_type 格式

## 7. 其他模块使用配置示例

### 7.1 AI 模块读取模型配置

```java
@Service
public class AiKnowledgeService {

    @Autowired
    private SysConfigService configService;

    public EmbeddingResult embed(String text) {
        String apiUrl = configService.getValueByKey("ai.knowledge.api_url");
        String apiKey = configService.getValueByKey("ai.knowledge.api_key");
        int dimension = configService.getIntValue("ai.knowledge.dimension", 1536);

        // 调用嵌入模型 API
        return callEmbeddingApi(apiUrl, apiKey, dimension, text);
    }
}
```

### 7.2 Storage 模块读取存储配置

```java
@Service
public class StorageService {

    @Autowired
    private SysConfigService configService;

    public String getUploadDir() {
        return configService.getValueByKey("storage.local.upload_dir");
    }

    public long getMaxSizeBytes() {
        int maxSizeMb = configService.getIntValue("storage.local.max_size_mb", 100);
        return maxSizeMb * 1024L * 1024L;
    }
}
```

### 7.3 Douyin 模块读取开放平台配置

```java
@Service
public class DouyinOAuthService {

    @Autowired
    private SysConfigService configService;

    public String buildAuthUrl() {
        String appId = configService.getValueByKey("douyin.open.app_id");
        String redirectUri = configService.getValueByKey("douyin.open.redirect_uri");
        return "https://open.douyin.com/platform/oauth/connect"
            + "?client_key=" + appId
            + "&redirect_uri=" + URLEncoder.encode(redirectUri, StandardCharsets.UTF_8)
            + "&response_type=code&scope=user_info";
    }
}
```
