## 5.1 推送系统总体流程

```
触发源
  ├── 定时任务（@Scheduled）
  └── 业务事件（Spring ApplicationEvent）
         │
         ▼
  规则匹配引擎
  （查询 wc_push_rule，匹配 trigger_type + eventType）
         │
         ▼
  数据采集层
  （根据规则类型，从 shortvideo/live/ai 模块拉取数据）
         │
         ▼
  消息构建层
  （模板变量渲染 → 生成 WeCom API 请求体 JSON）
         │
         ▼
  WeCom Webhook 调用
  （POST {webhook_url}，超时 10 秒）
         │
    ┌────┴────┐
  成功        失败
    │          │
    ▼          ▼
  写日志     写日志（status=0）
  status=1   + 加入重试队列
```

## 5.2 定时推送

### 5.2.1 调度机制

定时推送通过 Spring `@Scheduled` 实现，每分钟扫描一次启用的 scheduled 规则，判断当前时间是否匹配规则的 Cron 表达式：

```java
@Component
public class WecomScheduledPushJob {

    @Scheduled(cron = "0 * * * * ?")  // 每分钟执行一次
    public void executeScheduledRules() {
        // 查询所有 trigger_type=scheduled, status=1, deleted=0 的规则
        List<WcPushRule> rules = pushRuleRepository
            .findByTriggerTypeAndStatusAndDeleted("scheduled", 1, 0);

        LocalDateTime now = LocalDateTime.now();
        for (WcPushRule rule : rules) {
            String cron = extractCron(rule.getTriggerConfig());
            CronExpression cronExpr = CronExpression.parse(cron);
            // 判断当前分钟是否是该 Cron 的触发时间点
            if (cronExpr.isMatch(now)) {
                pushExecutor.executeRule(rule, Collections.emptyMap());
            }
        }
    }
}
```

### 5.2.2 每日数据报告推送流程

```
08:00 定时触发
    │
    ▼
查询所有 trigger_type=scheduled 且 cron 匹配 "0 0 8 * * ?" 的规则
    │
    ▼
对每条规则：
    1. 获取 owner_id
    2. 调用 ShortVideoDataService.getDailySummary(ownerId, yesterday)
       → 返回：video_count, total_play, total_like, total_comment
    3. 渲染消息模板（填充变量）
    4. 调用 WeCom Webhook API
    5. 更新 rule.last_trigger_time = now
    6. 写入 wc_message_log
```

## 5.3 事件驱动推送

### 5.3.1 Spring Events 机制

业务模块在发生关键事件时，发布 Spring ApplicationEvent，wecom 模块监听并触发推送：

```java
// shortvideo 模块发布事件
@Component
public class ViralVideoDetector {
    @Autowired
    private ApplicationEventPublisher eventPublisher;

    public void markViral(SvVideo video) {
        // ... 标记爆款逻辑
        eventPublisher.publishEvent(new ViralVideoDetectedEvent(this, video));
    }
}

// wecom 模块监听事件
@Component
public class WecomEventListener {

    @EventListener
    public void onViralVideoDetected(ViralVideoDetectedEvent event) {
        wecomPushService.handleEvent("VIRAL_VIDEO_DETECTED", event.getOwnerId(),
            Map.of(
                "viral_video_title", event.getVideo().getTitle(),
                "viral_play_count", formatCount(event.getVideo().getViewCount())
            ));
    }

    @EventListener
    public void onLiveSessionEnded(LiveSessionEndedEvent event) {
        wecomPushService.handleEvent("LIVE_SESSION_ENDED", event.getOwnerId(),
            Map.of(
                "live_duration", String.valueOf(event.getDurationMinutes()),
                "live_watch_count", formatCount(event.getWatchCount()),
                "live_peak_watch", formatCount(event.getPeakWatchCount())
            ));
    }

    @EventListener
    public void onNegativeCommentAlert(NegativeCommentAlertEvent event) {
        wecomPushService.handleEvent("NEGATIVE_COMMENT_ALERT", event.getOwnerId(),
            Map.of(
                "negative_ratio", String.format("%.0f%%", event.getRatio() * 100),
                "negative_video_title", event.getVideoTitle()
            ));
    }

    @EventListener
    public void onAiTaskCompleted(AiTaskCompletedEvent event) {
        wecomPushService.handleEvent("AI_TASK_COMPLETED", event.getOwnerId(),
            Map.of(
                "ai_task_type", event.getTaskTypeName(),
                "ai_task_result", truncate(event.getResultSummary(), 100)
            ));
    }
}
```

### 5.3.2 事件处理流程

```java
@Service
public class WecomPushService {

    public void handleEvent(String eventType, Long ownerId, Map<String, String> eventData) {
        // 1. 查询该用户下匹配该事件类型的启用规则
        List<WcPushRule> rules = pushRuleRepository
            .findActiveEventRules(ownerId, eventType);

        for (WcPushRule rule : rules) {
            // 2. 检查 filter 条件（如 minPlayCount）
            if (!matchesFilter(rule.getTriggerConfig(), eventData)) {
                continue;
            }
            // 3. 执行推送
            pushExecutor.executeRule(rule, eventData);
        }
    }
}
```

### 5.3.3 事件 filter 匹配逻辑

| eventType | filter 字段 | 匹配逻辑 |
|-----------|------------|---------|
| VIRAL_VIDEO_DETECTED | minPlayCount | event.playCount >= filter.minPlayCount |
| LIVE_SESSION_ENDED | minDuration | event.durationMinutes >= filter.minDuration |
| NEGATIVE_COMMENT_ALERT | minRatio | event.ratio >= filter.minRatio |
| AI_TASK_COMPLETED | taskType | event.taskType == filter.taskType（为空则全匹配） |

## 5.4 消息构建

### 5.4.1 消息构建流程

```java
@Component
public class WecomMessageBuilder {

    public String buildPayload(WcPushRule rule, Map<String, String> eventData) {
        // 1. 收集系统变量
        Map<String, String> variables = new HashMap<>();
        variables.put("date", LocalDate.now().toString());
        variables.put("datetime", LocalDateTime.now().format(DateTimeFormatter.ofPattern("yyyy-MM-dd HH:mm:ss")));
        variables.put("owner_name", userService.getNickname(rule.getOwnerId()));

        // 2. 合并事件数据（eventData 优先级更高）
        variables.putAll(eventData);

        // 3. 渲染模板
        String content = templateRenderer.render(rule.getMessageTemplate(), variables);

        // 4. 判断消息类型（根据模板内容自动判断：含 ## 或 ** 则为 markdown）
        String msgType = detectMessageType(content);

        // 5. 构建 WeCom API 请求体
        return buildWecomPayload(msgType, content);
    }

    private String buildWecomPayload(String msgType, String content) {
        if ("markdown".equals(msgType)) {
            return """
                {"msgtype":"markdown","markdown":{"content":"%s"}}
                """.formatted(escapeJson(content));
        } else {
            return """
                {"msgtype":"text","text":{"content":"%s"}}
                """.formatted(escapeJson(content));
        }
    }
}
```

### 5.4.2 消息类型自动判断规则

| 条件 | 判断为 |
|------|--------|
| 模板包含 `##`、`**`、`> ` 等 Markdown 语法 | markdown |
| 模板不含 Markdown 语法 | text |
| 规则 message_template 首行为 `[news]` 标记 | news（预留） |

## 5.5 WeCom Webhook 调用

### 5.5.1 HTTP 调用实现

```java
@Component
public class WecomWebhookClient {

    private final RestTemplate restTemplate;

    public WecomSendResult send(String webhookUrl, String payload) {
        HttpHeaders headers = new HttpHeaders();
        headers.setContentType(MediaType.APPLICATION_JSON);
        HttpEntity<String> request = new HttpEntity<>(payload, headers);

        try {
            ResponseEntity<String> response = restTemplate.postForEntity(
                webhookUrl, request, String.class
            );
            // 解析企业微信响应
            WecomApiResponse apiResp = parseResponse(response.getBody());
            if (apiResp.getErrcode() == 0) {
                return WecomSendResult.success();
            } else {
                return WecomSendResult.fail(
                    "errcode=" + apiResp.getErrcode() + ", errmsg=" + apiResp.getErrmsg()
                );
            }
        } catch (RestClientException e) {
            return WecomSendResult.fail("HTTP 调用异常：" + e.getMessage());
        }
    }
}
```

企业微信 Webhook API 响应格式：
```json
{
  "errcode": 0,
  "errmsg": "ok"
}
```

常见错误码：

| errcode | 说明 |
|---------|------|
| 0 | 成功 |
| 93000 | Webhook URL 无效 |
| 45009 | 接口调用超过限制（每分钟 20 次） |
| 40058 | 消息内容格式错误 |

### 5.5.2 调用限流

企业微信机器人 Webhook 限制：每个机器人每分钟最多发送 20 条消息。

wecom 模块限流策略：
- 使用 Guava RateLimiter，每个 robot_id 独立限流，每分钟最多 18 条（留 2 条余量）
- 超出限流时，消息进入等待队列，延迟发送

## 5.6 失败重试机制

### 5.6.1 重试策略

| 重试次数 | 等待时间 | 说明 |
|---------|---------|------|
| 第 1 次重试 | 1 分钟后 | 首次失败后快速重试 |
| 第 2 次重试 | 3 分钟后 | 指数退避 |
| 第 3 次重试 | 5 分钟后 | 最终重试 |
| 超过 3 次 | 不再重试 | 标记为最终失败，等待人工重试 |

### 5.6.2 重试实现

```java
@Component
public class WecomRetryScheduler {

    // 每分钟扫描一次待重试消息
    @Scheduled(cron = "0 * * * * ?")
    public void retryFailedMessages() {
        LocalDateTime now = LocalDateTime.now();

        // 查询 status=0 且 retry_count < 3 且 next_retry_time <= now 的消息
        // （当前版本通过 wc_message_log 的 error_message 字段记录重试次数）
        // 简化实现：查询最近 30 分钟内的失败消息，由人工点击重试
    }
}
```

> 当前版本（V1）重试机制为：自动重试 3 次（通过 Spring Retry 注解），超过 3 次后记录最终失败，用户可在消息记录页面手动点击重试。

Spring Retry 配置：
```java
@Retryable(
    retryFor = WecomSendException.class,
    maxAttempts = 3,
    backoff = @Backoff(delay = 60000, multiplier = 3.0)
)
public void sendWithRetry(String webhookUrl, String payload) {
    WecomSendResult result = webhookClient.send(webhookUrl, payload);
    if (!result.isSuccess()) {
        throw new WecomSendException(result.getErrorMessage());
    }
}
```

## 5.7 消息日志

### 5.7.1 日志写入时机

| 时机 | status | 说明 |
|------|--------|------|
| 推送成功 | 1 | 正常记录 |
| 推送失败（含重试全部失败） | 0 | 记录 error_message |
| 连通性测试 | 0/1 | rule_id=NULL |
| 手动重试 | 0/1 | 新增一条日志，不修改原记录 |

### 5.7.2 日志清理

消息日志保留 90 天，超期日志由定时任务物理删除：

```java
@Scheduled(cron = "0 0 3 * * ?")  // 每天凌晨 3 点执行
public void cleanOldLogs() {
    LocalDateTime cutoff = LocalDateTime.now().minusDays(retentionDays);
    messageLogRepository.deleteByCreateTimeBefore(cutoff);
    log.info("清理 {} 之前的消息日志完成", cutoff);
}
```

### 5.7.3 推送统计

消息日志支持以下统计查询（供前端消息记录页面展示）：

| 统计项 | 查询方式 |
|--------|---------|
| 今日发送总数 | COUNT WHERE send_time >= today |
| 今日成功数 | COUNT WHERE status=1 AND send_time >= today |
| 今日失败数 | COUNT WHERE status=0 AND send_time >= today |
| 成功率 | 成功数 / 总数 × 100% |
| 按机器人分组统计 | GROUP BY robot_id |
