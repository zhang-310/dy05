# W-07：话术知识库自进化引擎

## 1. 模块概述

话术知识库自进化引擎通过持续分析历史数据、用户反馈、AI 智能分析，自动优化知识库内容质量。系统根据话术效果评分、用户采纳率、互动数据等多维指标，自动入库高效话术、标记低效话术、去重合并、生成最佳实践报告，实现知识库的"自我完善"。

**目标用户**：话术库管理员、主播、AI 分析系统
**核心价值**：从静态库 → 动态进化 → 持续优化
**关键指标**：库内高效话术占比 > 70%、自动化处理占比 > 80%

---

## 2. 核心功能模块

### 2.1 高效话术自动入库

| 功能 | 说明 | 规则 |
|------|------|------|
| 效果评分 | 综合评估话术质量 | 互动率 + 转化率 + 粉丝增长 + 评论情绪 |
| 入库条件 | 满足条件的话术自动入库 | 综合评分 ≥ 80 + 使用次数 ≥ 5 次 |
| 自动分类 | 识别话术主题和风格 | 使用 NLP 文本分类模型 |
| 去重检测 | 检测与现有库中内容相似的话术 | 向量相似度 > 0.85 则标记为重复 |
| 版本管理 | 自动建立版本链 | 新版本自动关联前序版本 |

### 2.2 低效话术优化与淘汰

| 功能 | 说明 | 处理流程 |
|------|------|--------|
| 低效标记 | 自动识别效果不达预期的话术 | 连续 3 期评分 < 40 → 标记为"待优化" |
| 优化建议 | 针对低效话术生成改进建议 | AI 分析 + 对标高效话术 → 生成建议 |
| 自动淘汰 | 连续表现不佳则自动下线 | 超过 3 个月评分 < 40 → 归档 |
| 复用库 | 淘汰的话术存入"参考库"供学习 | 便于后续查阅历史和避免重复错误 |

### 2.3 话术去重与合并

| 功能 | 说明 | 实现 |
|------|------|------|
| 相似度检测 | 检测库内内容相似的话术 | 向量相似度 > 0.85 视为重复 |
| 智能合并 | 合并相似话术，保留最高效版本 | 效果评分高的版本为主，低分版本作为变体 |
| 变体管理 | 记录所有合并的变体版本 | 便于风格多样化和 A/B 测试 |
| 去重报告 | 定期生成去重报告 | 每周生成，列出合并情况和预期收益 |

### 2.4 最佳实践报告

| 内容 | 说明 | 生成周期 |
|------|------|--------|
| 高效话术排名 | Top 100 最高效话术 | 每周一次 |
| 风格分析 | 各风格的话术效果对比 | 每月一次 |
| 行业趋势 | 行业新风向和话题热度 | 每月一次 |
| 进化总结 | 新增话术、淘汰话术、优化建议 | 每周一次 |
| 个性化推荐 | 基于主播的历史使用推荐话术 | 实时计算 |

## 3. 规则引擎设计

### 3.1 入库规则

```
条件：
  IF score >= 80
  AND usage_count >= 5
  AND creation_date <= 30 days ago
  THEN auto_add_to_library()

执行频率：每天 00:00 UTC（离线计算）
风险控制：每天最多导入 100 条新话术（防止库污染）
备注：高评分且使用少的话术需人工审核
```

### 3.2 更新规则

```
条件：
  IF new_version_score > current_version_score + 5
  AND new_version_score >= 75
  THEN replace_current_version()

执行频率：每周一次
锁定期：新话术 14 天内评分稳定后才能替换
回滚机制：如果替换 7 天后评分下降 > 10，自动回滚
```

### 3.3 淘汰规则

```
条件 1：连续 3 期评分 < 40
  IF period_1_score < 40 AND period_2_score < 40 AND period_3_score < 40
  THEN mark_as_deprecated()

条件 2：已废弃超过 3 个月
  IF deprecated_date <= 90 days ago
  THEN archive_to_history()

保留机制：淘汰前保留在"参考库"，不在主库展示
通知：发送提醒给相关主播该话术即将下线
```

### 3.4 去重规则

```
相似度检测：
  vector_similarity(text_A, text_B) > 0.85
  → 标记为重复候选

人工确认 or 自动合并（可配置）：
  低评分版本标记为"变体"
  高评分版本作为主版本

变体保留：
  保留所有变体用于风格多样化
  记录合并时间和理由
```

## 5. 数据模型设计

### 5.1 EvolutionAnalysis（进化分析记录）

```sql
CREATE TABLE ai_evolution_analysis (
  id BIGINT PRIMARY KEY,
  analysis_period VARCHAR(50),
  analysis_scope_start DATE,
  analysis_scope_end DATE,
  ready_for_inclusion INTEGER,         -- 符合入库条件的话术数
  needs_optimization INTEGER,          -- 待优化话术数
  duplicates_detected INTEGER,         -- 检测到的重复数
  ready_for_archival INTEGER,          -- 应归档话术数
  expected_improvement DECIMAL(5,2),   -- 预期库质量提升 %
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  deleted INTEGER DEFAULT 0
);
```

### 5.2 EvolutionExecution（进化执行记录）

```sql
CREATE TABLE ai_evolution_execution (
  id BIGINT PRIMARY KEY,
  analysis_id BIGINT NOT NULL,
  execution_status VARCHAR(50),        -- COMPLETED / FAILED / PENDING_APPROVAL
  included_count INTEGER,
  merged_count INTEGER,
  archived_count INTEGER,
  quality_improvement DECIMAL(5,2),
  executed_at TIMESTAMP,
  executed_by VARCHAR(255),            -- 执行人/系统标识
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  deleted INTEGER DEFAULT 0,
  FOREIGN KEY (analysis_id) REFERENCES ai_evolution_analysis(id)
);
```

### 5.3 ScriptDuplicate（话术重复记录）

```sql
CREATE TABLE ai_script_duplicate (
  id BIGINT PRIMARY KEY,
  master_script_id BIGINT NOT NULL,
  duplicate_script_id BIGINT NOT NULL,
  similarity_score DECIMAL(3,2),
  merge_status VARCHAR(50),            -- DETECTED / MERGED / IGNORED
  merged_at TIMESTAMP,
  reason TEXT,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  deleted INTEGER DEFAULT 0,
  FOREIGN KEY (master_script_id) REFERENCES live_script_version(id),
  FOREIGN KEY (duplicate_script_id) REFERENCES live_script_version(id)
);

CREATE INDEX idx_master_script ON ai_script_duplicate(master_script_id);
CREATE INDEX idx_duplicate_script ON ai_script_duplicate(duplicate_script_id);
```

### 5.4 EvolutionReport（进化报告）

```sql
CREATE TABLE ai_evolution_report (
  id BIGINT PRIMARY KEY,
  report_type VARCHAR(50),             -- WEEKLY / MONTHLY
  period_start DATE,
  period_end DATE,
  total_in_library INTEGER,
  new_added INTEGER,
  archived_count INTEGER,
  deduplicated_count INTEGER,
  average_score DECIMAL(5,2),
  report_content JSONB,                -- 报告详细内容
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  deleted INTEGER DEFAULT 0
);
```

## 6. 实现清单

### 6.1 Service 层（2 个）

| 服务 | 职责 | 关键方法 |
|------|------|--------|
| `KnowledgeEvolutionService` | 进化分析与执行 | `analyzeEvolutionOpportunities()` / `executeAutoOptimization()` / `generateEvolutionReport()` |
| `EvolutionRuleEngine` | 规则评估和执行 | `evaluateInclusionRules()` / `evaluateArchivalRules()` / `detectDuplicates()` |

**依赖**：
- ScriptVersionRepository, LiveMonitorRepository
- VectorSearchService（用于去重检测）
- DeepSeek AI API（优化建议生成）
- Redis（规则评估缓存）

### 6.2 Controller 层（1 个）

| 控制器 | 接口 |
|-------|------|
| `EvolutionController` | analyze / autoOptimize / report / history |

### 6.3 VO 层（2 个）

| VO | 用途 |
|----|------|
| `EvolutionAnalysisVO` | 进化分析结果 |
| `EvolutionReportVO` | 进化报告 |

### 6.4 定时任务

- `DailyEvolutionTask`：每天 00:00 UTC 执行一次进化分析和自动优化
- `WeeklyReportGenerationTask`：每周一 09:00 UTC 生成周报告
- `MonthlyReportGenerationTask`：每月 1 号 09:00 UTC 生成月报告
