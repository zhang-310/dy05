### 7.3 日志系统

#### 7.3.1 日志分类

| 日志类型 | 说明 | 存储位置 | 保留期 |
|---------|------|---------|--------|
| 文档导入日志 | 文档上传、解析、分块的记录 | PostgreSQL + 文件 | 90天 |
| 索引操作日志 | ES写入、Milvus写入、缓存更新 | PostgreSQL + 文件 | 90天 |
| 查询日志 | 查询内容、响应时间、结果数、用户反馈 | PostgreSQL | 180天 |
| AI调用日志 | 模型调用、Token消耗、响应时间 | PostgreSQL ai_call_log | 180天 |
| 进化任务日志 | 任务进度、质量评分、报告生成 | PostgreSQL ai_evolve_task | 永久 |
| 错误日志 | 失败原因、重试次数、堆栈信息 | 文件 + 告警 | 90天 |
| 性能日志 | 慢查询、高延迟、资源瓶颈 | 文件 | 30天 |
| 安全日志 | 异常访问、权限违规、API滥用 | PostgreSQL + 文件 | 365天 |

**日志自动清理策略：**

```
定时任务：每日 04:00 执行日志清理

PostgreSQL 表清理：
  - ai_call_log：DELETE WHERE create_time < NOW() - INTERVAL '180 days'
  - ai_query_log：DELETE WHERE create_time < NOW() - INTERVAL '180 days'
  - ai_alert_history：DELETE WHERE create_time < NOW() - INTERVAL '90 days' AND resolved_at IS NOT NULL
  - ai_performance_metrics：DELETE WHERE create_time < NOW() - INTERVAL '90 days'
  - ai_user_feedback：DELETE WHERE create_time < NOW() - INTERVAL '365 days' AND processed = 1
  - 清理前统计：将月度汇总写入 ai_daily_stats

文件日志清理：
  - 日志目录：/var/log/dy-app/
  - 保留策略：按 logback-spring.xml 配置（maxHistory + totalSizeCap）
  - 性能日志：maxHistory=30，totalSizeCap=5GB
  - 错误日志：maxHistory=90，totalSizeCap=10GB
  - 文档导入/索引日志：maxHistory=90，totalSizeCap=10GB

清理安全措施：
  - 批量删除（每次 1000 条），避免长事务锁表
  - 清理任务记录到 ai_daily_stats（stat_type='log_cleanup'）
  - 清理失败触发 warning 告警
```

#### 7.4.4 告警通知渠道与升级策略

**通知渠道实现：**

| 渠道 | 实现方式 | 适用级别 | 说明 |
|------|---------|---------|------|
| 站内通知 | WebSocket 推送到管理端 | 全部 | 所有告警都推送站内通知 |
| 企业微信 | 企微机器人 Webhook（群消息） | warning+ | 配置 WECOM_ALERT_WEBHOOK 环境变量 |
| 邮件 | Spring Mail（SMTP） | critical+ | 配置 ALERT_EMAIL_TO 环境变量（多人逗号分隔） |
| 电话 | 第三方语音通知 API（可选） | emergency | 配置 ALERT_PHONE_NUMBERS 环境变量 |

**告警升级策略：**

```
Level 1（首次触发）：
  - info → 仅站内通知
  - warning → 站内 + 企微群消息
  - critical → 站内 + 企微 + 邮件
  - emergency → 站内 + 企微 + 邮件 + 电话

Level 2（未确认，15 分钟后自动升级）：
  - warning → 升级为 critical 通知方式（追加邮件）
  - critical → 升级为 emergency 通知方式（追加电话）
  - emergency → 每 10 分钟重复通知，直到确认

Level 3（未恢复，1 小时后）：
  - 所有级别 → 通知上级管理员（ALERT_ESCALATION_EMAIL）
  - 生成告警汇总报告

告警确认与静默：
  - 管理员可在运维面板确认告警（记录 acknowledged_at + acknowledged_by）
  - 确认后停止升级，但不停止监控
  - 静默规则：可设置时间窗口内不触发特定告警（如维护期间）
  - 静默最长 24h，到期自动恢复
```

### 7.5 降级策略

| 故障场景 | 降级方案 | 影响 |
|---------|---------|------|
| ES不可用 | 自动切换到纯向量检索（Milvus），跳过BM25评分 | 关键词匹配能力下降 |
| Milvus不可用 | 自动切换到纯关键词检索（ES），跳过向量评分 | 语义理解能力下降 |
| Redis不可用 | 跳过缓存直接查询，使用本地锁替代分布式锁 | 响应时间增加 |
| RabbitMQ不可用 | 索引任务写入 ai_index_queue 表，定时轮询消费 | 索引延迟增加 |
| Ollama不可用 | 嵌入：使用缓存向量；生成：切换DeepSeek API；重排：跳过 | 部分功能降级 |
| 全部不可用 | 返回友好错误提示，记录请求到本地日志，紧急告警 | 服务不可用 |
