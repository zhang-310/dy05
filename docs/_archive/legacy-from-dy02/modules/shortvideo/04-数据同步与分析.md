> 版本：3.0 | 更新日期：2026-02-26

---

## 4.1 数据同步总览

```
抖音开放平台 API
    ↓
[数据同步引擎]
    ├─ 视频列表同步（每 6h 全量）
    ├─ 视频数据快照（每日 02:00）
    ├─ 发布后高频同步（发布后 1h 内每 10min）
    ├─ 评论同步（每 6h + 新视频 24h 内每 1h）
    └─ 手动触发同步
    ↓
[数据分析引擎]
    ├─ 爆款自动发现（每日 03:00）
    ├─ 热点自动追踪（每 2h）
    ├─ 发布时间分析（每周刷新）
    ├─ 评论情感分析（同步后自动）
    └─ 负面评论预警（实时检测）
```

## 4.2 视频列表同步

### 4.2.1 同步流程

```
定时任务（每 6h）或手动触发
    ↓
遍历所有绑定的抖音账号
    ↓
调用抖音 API：GET /video/list（分页拉取）
    ↓
FOR EACH video IN response:
    ├─ 通过 douyin_video_id 查找本地记录
    ├─ 存在 → 更新数据（播放量/点赞/评论等）
    └─ 不存在 → 插入新记录到 sv_video
    ↓
更新 sv_video.last_sync_time
```

### 4.2.2 字段映射

| 抖音 API 字段 | sv_video 字段 | 说明 |
|--------------|--------------|------|
| item_id | douyin_video_id | 视频唯一标识 |
| title | title | 视频标题 |
| video_description | description | 视频描述 |
| cover | cover_url | 封面图 |
| share_url | video_url | 分享链接 |
| duration | duration | 时长（秒） |
| create_time | publish_time | 发布时间 |
| statistics.play_count | view_count | 播放量 |
| statistics.digg_count | like_count | 点赞数 |
| statistics.comment_count | comment_count | 评论数 |
| statistics.share_count | share_count | 分享数 |
| statistics.collect_count | favorite_count | 收藏数 |

### 4.2.3 同步策略

| 场景 | 频率 | 说明 |
|------|------|------|
| 全量同步 | 每 6h | 拉取账号所有视频，更新数据 |
| 增量同步 | 每 6h | 只拉取 last_sync_time 之后的新视频 |
| 发布后高频 | 每 10min × 1h | 新发布视频的数据变化最快 |
| 手动同步 | 用户触发 | 立即同步指定账号 |

## 4.3 视频数据每日快照

### 4.3.1 快照流程

```
定时任务（每日 02:00）
    ↓
查询所有 sv_video（deleted=0, publish_time > 180天前）
    ↓
FOR EACH video:
    ├─ 调用抖音 API 获取最新数据
    ├─ 计算增量：view_delta = 今日 view_count - 昨日 view_count
    ├─ 写入 sv_video_data（snapshot_date=今天）
    └─ 更新 sv_video 的冗余字段（view_count 等）
```

### 4.3.2 增量计算

```sql
-- 计算每日增量
INSERT INTO sv_video_data (video_id, snapshot_date, view_count, like_count, ..., view_delta, like_delta)
SELECT
    v.id,
    CURRENT_DATE,
    v.view_count,
    v.like_count,
    ...,
    v.view_count - COALESCE(prev.view_count, 0),
    v.like_count - COALESCE(prev.like_count, 0)
FROM sv_video v
LEFT JOIN sv_video_data prev ON prev.video_id = v.id
    AND prev.snapshot_date = CURRENT_DATE - INTERVAL '1 day'
WHERE v.deleted = 0
    AND v.publish_time > CURRENT_DATE - INTERVAL '180 days';
```

### 4.3.3 归档策略

- 超过 180 天的快照数据自动归档
- 归档前生成月度汇总（月均播放量/月均互动）
- 归档数据移至 sv_video_data_archive 表

## 4.4 爆款自动发现

### 4.4.1 检测流程

```
定时任务（每日 03:00）
    ↓
FOR EACH account IN 绑定账号:
    ↓
    [计算账号基准]
        ├─ 近 30 天所有视频的平均播放量
        └─ threshold = avg_views × SV_VIRAL_THRESHOLD（默认 3.0）
    ↓
    [扫描爆款]
        ├─ 查询 sv_video WHERE view_count > threshold AND is_viral = false
        └─ 排除已在 sv_viral_video 中的视频
    ↓
    [标记爆款]
        ├─ 更新 sv_video.is_viral = true
        ├─ 插入 sv_viral_video（source=auto_detected）
        ├─ 计算 viral_score = view_count / avg_views
        └─ 触发 ai 模块爆款拆解 Agent（异步）
```

### 4.4.2 爆款拆解对接

```
新检测到爆款视频
    ↓
发送消息到 RabbitMQ（queue: ai.viral.analysis）
    ↓
ai 模块爆款拆解 Agent 消费消息：
    ├─ 收集数据（视频信息 + 评论 + 增长曲线 + 同账号对比）
    ├─ LLM 拆解（成功因素 + 可复制方法论）
    ├─ 质量评分
    └─ 高分入库知识库
    ↓
回写结果到 sv_viral_video：
    ├─ success_factors = AI 分析的成功因素
    ├─ replicable_methods = 可复制方法论
    └─ analysis_report_id = ai_viral_analysis.id
```

## 4.5 热点自动追踪

### 4.5.1 追踪流程

```
定时任务（每 2h）
    ↓
[数据源拉取]
    ├─ 抖音热搜 API（如可用）
    ├─ 第三方数据源（巨量算数等）
    └─ 行业热点聚合
    ↓
[数据处理]
    ├─ 通过 douyin_hot_id 去重
    ├─ 新热点 → 插入 sv_hot_topic（status=active）
    ├─ 已有热点 → 更新 heat_score
    └─ 设置 expiry_time（默认 48h 后过期）
    ↓
[过期清理]
    ├─ expiry_time < 当前时间 → status=expired
    └─ 过期超过 7 天 → 物理删除
```

### 4.5.2 热点分类

| 分类 | 说明 | 数据源 |
|------|------|--------|
| 全网热搜 | 抖音热搜榜 TOP 50 | 抖音热搜 API |
| 行业热点 | 按行业分类的热门话题 | 巨量算数 / 第三方 |
| 挑战赛 | 抖音官方挑战赛 | 抖音 API |
| 热门音乐 | 热门 BGM | 抖音 API |

## 4.6 发布时间分析

### 4.6.1 分析流程

```
定时任务（每周一 04:00）或手动触发
    ↓
FOR EACH account IN 绑定账号:
    ↓
    [数据收集]
        ├─ 查询该账号所有视频的 publish_time 和 view_count
        └─ 至少需要 20 条视频数据才有统计意义
    ↓
    [时段分析]
        ├─ 按 day_of_week × hour_of_day 分组
        ├─ 计算每个时段的平均播放量和视频数
        └─ 写入 sv_publish_time_analysis（UPSERT）
    ↓
    [推荐计算]
        ├─ 按 avg_view_count 降序排列
        ├─ TOP 3 时段标记 recommended=true
        └─ 其余标记 recommended=false
```

### 4.6.2 推荐逻辑

```sql
-- 计算每个时段的平均播放量
WITH time_stats AS (
    SELECT
        account_id,
        EXTRACT(DOW FROM publish_time) AS day_of_week,
        EXTRACT(HOUR FROM publish_time) AS hour_of_day,
        AVG(view_count) AS avg_view_count,
        COUNT(*) AS video_count
    FROM sv_video
    WHERE deleted = 0
        AND publish_time > CURRENT_DATE - INTERVAL '90 days'
    GROUP BY account_id, day_of_week, hour_of_day
    HAVING COUNT(*) >= 2  -- 至少 2 条视频才有参考价值
)
-- UPSERT 到分析表
INSERT INTO sv_publish_time_analysis (account_id, day_of_week, hour_of_day, avg_view_count, video_count)
SELECT * FROM time_stats
ON CONFLICT (account_id, day_of_week, hour_of_day)
DO UPDATE SET avg_view_count = EXCLUDED.avg_view_count, video_count = EXCLUDED.video_count;

-- 标记推荐时段（每个账号 TOP 3）
WITH ranked AS (
    SELECT id, ROW_NUMBER() OVER (PARTITION BY account_id ORDER BY avg_view_count DESC) AS rn
    FROM sv_publish_time_analysis
    WHERE video_count >= 2
)
UPDATE sv_publish_time_analysis SET recommended = (id IN (SELECT id FROM ranked WHERE rn <= 3));
```

## 4.7 评论情感分析

### 4.7.1 分析流程

```
评论同步完成后
    ↓
查询 sentiment IS NULL 的新评论
    ↓
[情感分析]
    ├─ 方案 A：规则引擎（低延迟，免费）
    │   ├─ 正面关键词：好用、推荐、回购、喜欢、赞
    │   ├─ 负面关键词：难用、退款、骗人、差评、假货
    │   └─ 其余 → neutral
    │
    └─ 方案 B：LLM 分析（高精度，有成本）
        ├─ 批量发送评论到 ai 模块
        ├─ 返回 sentiment + sentiment_score
        └─ 降级：LLM 超时 → 回退到规则引擎
    ↓
更新 sv_comment.sentiment + sentiment_score
```

### 4.7.2 负面评论预警

```
评论情感分析完成后
    ↓
按视频聚合负面评论占比：
    negative_rate = COUNT(sentiment='negative') / COUNT(*)
    ↓
IF negative_rate > SV_NEGATIVE_COMMENT_THRESHOLD（默认 0.3）:
    ├─ 触发告警通知（站内消息 / WebSocket 推送）
    └─ 标记该视频需要关注
```

## 4.8 效果归因

### 4.8.1 归因流程

```
定时任务（每日 02:00，与数据快照同步后执行）
    ↓
查询 sv_plan WHERE:
    ├─ ai_call_log_id IS NOT NULL（AI 生成的内容）
    ├─ linked_video_id IS NOT NULL（已发布）
    ├─ content_effect IS NULL（未归因）
    └─ actual_publish_time < NOW() - SV_ATTRIBUTION_WAIT_DAYS（等待数据稳定）
    ↓
FOR EACH plan:
    ├─ 从 sv_video_data 获取关联视频的 7 天累计数据
    ├─ 计算该账号近 30 天视频均值
    ├─ effect_score = video_view_count / account_avg_views
    ├─ IF effect_score > 1.5 → content_effect = 'high_perform'
    ├─ IF effect_score < 0.3 → content_effect = 'low_perform'
    └─ ELSE → content_effect = 'normal'
    ↓
调用 ai 模块效果归因接口：
    ├─ 更新 ai_call_log.content_effect + effect_score
    └─ 触发知识权重反向更新（BR-20）
```

### 4.8.2 知识权重反向更新

```
high_perform 的方案：
    ├─ 读取 ai_call_log.referenced_chunk_ids
    └─ 对应知识条目 boost_factor += 0.15

low_perform 的方案：
    ├─ 读取 ai_call_log.referenced_chunk_ids
    └─ 对应知识条目 boost_factor -= 0.05
```
