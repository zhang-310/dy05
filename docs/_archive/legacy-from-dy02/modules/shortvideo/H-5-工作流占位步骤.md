# H-5：工作流占位步骤披露（musicGen / sfxGen / digitalHuman）

## 现状

`WorkflowExecutionService` 中以下步骤**自动标记为 completed**，但**未调用**真实 BGM/音效/数字人合成服务，仅用于打通 DAG：

- `musicGen`
- `sfxGen`
- `digitalHuman`

## 运营可见

- 查询 `POST /api/v1/short-video/workflow/status` 时，若上一步为上述占位步骤，响应可能携带 **`stepMessage`**，说明「占位已完成、真能力未接入」。
- 服务端日志为 **WARN**，便于与真实失败区分。

## 后续方向（Epic）

1. **真实现**：分别对接 `AiMusicService`、`SfxGenerationService`、`HeyGenProvider`（或当前选型）并在步骤内写回素材 URL。  
2. **或产品开关**：在可视化工作流编辑器中默认隐藏/禁用上述节点，直至能力就绪。

## 配置（已实现）

- `app.shortvideo.workflow.show-placeholder-steps`（环境变量 `SV_WORKFLOW_SHOW_PLACEHOLDERS`）：`false` 时默认画布不展示 `musicGen`/`sfxGen`/`digitalHuman` 节点（主链路 `postProcess → compose`）。前端经 `POST /api/v1/short-video/workflow/editor-flags` 读取。
- 设为 `true` 可恢复完整 DAG，便于联调真能力。
