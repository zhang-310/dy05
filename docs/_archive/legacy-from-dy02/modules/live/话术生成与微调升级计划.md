# 话术生成与微调升级计划

> 版本：1.0 | 创建日期：2026-03-17

---

## 一、目标

实现「**后台生成大概话术 → 前端微调（单句/单段）**」的完整流程：

1. **生成**：后台一键生成全场/单段话术，输出可用的初稿
2. **微调**：用户可针对**其中一句话**或**其中一段话**进行修改，无需重写整段

---

## 二、现状分析

### 2.1 已有能力

| 能力 | 位置 | 说明 |
|------|------|------|
| 全场生成 | `LiveScriptGenerationServiceImpl.generateFull` | 按槽位顺序生成 opening/product/transition/closing |
| 单段生成 | `generateOpening` / `generateProduct` / `generateTransition` / `generateClosing` | 按槽位类型生成 |
| 整段 AI 修改 | `LiveScriptAnalysisServiceImpl.refineScript` | 用户输入修改要求，AI 重写**整段**话术 |
| 整段手动编辑 | `ScriptCard` / `useScriptEditor` | 编辑整个 `scriptContent`，保存整段 |

### 2.2 缺口

| 缺口 | 说明 |
|------|------|
| **段内粒度** | 当前编辑/修改粒度是「整段槽位」，无法针对**单句**或**单段（段落）**微调 |
| **微调入口** | 无「点击某句/某段 → 仅修改该句/该段」的 UI |
| **AI 微调** | `refineScript` 只支持整段修改，无「指定段落 + 修改要求」的 API |

---

## 三、升级方案

### 3.1 整体流程

```
┌─────────────────────────────────────────────────────────────────────────┐
│  1. 生成：后台一键生成全场话术（或单段）                                    │
│     → 输出到 live_script.script_content 整段文本                          │
└─────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌─────────────────────────────────────────────────────────────────────────┐
│  2. 展示：前端将话术分段显示（按句/按段）                                   │
│     → 每句/每段可独立点击、编辑、AI 微调                                    │
└─────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌─────────────────────────────────────────────────────────────────────────┐
│  3. 微调：用户选中某句/某段 → 手动改 或 输入修改要求 → AI 仅改该句/该段      │
│     → 合并回整段后保存到 live_script.script_content                       │
└─────────────────────────────────────────────────────────────────────────┘
```

### 3.2 分段策略

| 粒度 | 规则 | 示例 |
|------|------|------|
| **段落** | 按 `\n\n` 或双换行拆分 | 一段完整话术块 |
| **句子** | 按 `。！？.!?` 结尾拆分 | 单句，便于微调 |

**建议**：默认按**段落**拆分（`\n\n`），段落内可再按句展示；用户可切换「段落视图」/「句子视图」。

### 3.3 后端新增

#### 3.3.1 段内微调 API

**接口**：`POST /api/v1/live/ai/refine-segment`

**请求体**：
```json
{
  "scriptId": 123,
  "segmentText": "今天直播间给大家带来福利价，姐妹们赶紧拍！",
  "instruction": "改成更幽默一点",
  "modelId": 1
}
```

**响应**：`{ "data": "修改后的整段话术" }`（整段，因为需替换 segment 后合并）

**逻辑**：
1. 从 `live_script` 读取完整 `script_content`
2. 定位 `segmentText` 在全文中的位置
3. 调用 LLM：仅对 `segmentText` 按 `instruction` 修改，返回修改后的片段
4. 将修改后的片段替换回原文对应位置
5. 返回完整新内容（前端可选择性保存）

**可选**：支持流式 `refine-segment-sse`，便于长句反馈。

#### 3.3.2 扩展 refineScript（可选）

在现有 `refineScript` 中增加可选参数 `segmentText`：

- 若 `segmentText` 为空：保持现有行为（整段修改）
- 若 `segmentText` 非空：仅修改该片段，其余内容不变

这样可复用现有 API，减少新接口数量。

### 3.4 前端新增

#### 3.4.1 分段展示组件

**组件**：`ScriptSegmentView`（或扩展现有 `ScriptCard`）

- **输入**：`scriptContent` 字符串
- **输出**：按 `\n\n` 拆成段落数组，每个段落可再按 `。！？` 拆成句子
- **渲染**：每段/每句为可点击卡片或行内高亮块

**交互**：
- 点击某段/某句 → 进入「微调模式」
- 微调模式：显示该段/句的编辑框 + 「手动修改」+ 「AI 微调」按钮

#### 3.4.2 微调弹窗

**场景**：用户点击某句/某段后弹出

- **展示**：当前选中内容（只读或可编辑）
- **手动修改**：直接改文本框，保存时合并回整段
- **AI 微调**：输入修改要求（如「改成更幽默」「缩短到 20 字」），调用 `refine-segment`，返回后替换该段并刷新整段

**快捷建议**：可预设「改成更幽默」「缩短」「加歇后语」等 Chip，点击后自动填充 instruction。

#### 3.4.3 与现有编辑的兼容

- **整段编辑**：保留现有「编辑整段」入口（编辑整个槽位）
- **段内微调**：新增「段落视图」模式，在段落内点击单句/单段进行微调

两种模式可并存：用户可切换「整段编辑」/「段落微调」。

## 五、接口设计细节

### 5.1 refine-segment 请求/响应

```json
// Request
{
  "scriptId": 123,
  "segmentText": "今天直播间给大家带来福利价，姐妹们赶紧拍！",
  "instruction": "改成更幽默，加歇后语",
  "modelId": 1
}

// Response (RESTResult)
{
  "status": 200,
  "data": "完整修改后的话术正文（整段）",
  "message": "success"
}
```

### 5.2 边界情况

| 情况 | 处理 |
|------|------|
| segmentText 在原文中不存在 | 返回 400，提示「未找到匹配片段」 |
| segmentText 出现多次 | 替换第一个匹配，或要求传入 startIndex |
| instruction 为空 | 返回 400 |
| 修改后 LLM 输出过长 | 截断或提示用户 |

### 5.3 定位策略（segmentText 重复时）

可选方案：
- **A**：仅替换第一次出现（简单）
- **B**：请求体增加 `segmentIndex`，表示第几处匹配（0-based）
- **C**：请求体增加 `startIndex`：字符在原文中的起始位置（精确）

建议 Phase 1 用方案 A，后续按需扩展。

本升级计划与 `2小时聊天式直播话术需求.md` 互补：

- **2 小时需求**：侧重生成内容、槽位结构、知识库素材

1. 后台生成 2 小时全场话术（含聊家常、利润品等）
2. 用户在前端按段落/句子微调，无需整段重写
