# 2 小时聊天式直播话术 — 升级计划

> 版本：2.0 | 创建日期：2026-03-17 | 升级：2026-03-17（合并深度分析补充）  
> 需求文档：`2小时聊天式直播话术需求.md`  
> 深度分析：`2小时聊天式-方案深度分析与升级建议.md`

---

## 一、升级目标

实现「2 小时全场直播话术」能力：聊家常 + 人气高时卖利润品，全场有独特主播风格（如李阳阳东北人），利用知识库注入幽默、歇后语、名言金句、古诗等，话题涵盖夫妻感情、人生励志、婆媳关系。

**运营逻辑**：微付费刺激自然流 → 话术独特个性拉停留拉互动 → 拉高在线人数 → 再卖产品。话术侧重**留人蓄水**，卖货集中在人气上来后的高在线时段。

### 架构决策

| 决策 | 结论 |
|------|------|
| **槽位创建** | chat_2h 采用**模板驱动**：不依赖 products，直接按固定结构创建槽位；5 个 product 槽位先 `productId=null`，用户后续在排品面板绑定 |
| **chat 与 emotional** | chat 作为**独立 script_type**，用于 2 小时模板中的聊家常槽位；emotional 用于「插入情绪话术」场景 |
| **chat 话题传递** | 复用 `live_script.requirement` 存话题，如 `"聊家常-夫妻感情"`；前端提供话题下拉 |

## 五、Phase 3：全场模板与前端（1-2 天）

### 5.1 场次模板机制

| 任务 | 文件 | 说明 |
|------|------|------|
| 3.9 Flyway 迁移 | `db/migration/Vxxx__live_session_type.sql` | `ALTER TABLE live_session ADD COLUMN session_type VARCHAR(32) DEFAULT 'standard'` |
| 3.1 模板字段 | `LiveSession` 实体 | 映射 `session_type`（standard / chat_2h） |
| 3.2 模板定义 | 配置或枚举 | `chat_2h`：3 利润品 + 2 备用品 + 3 聊家常槽位 |
| 3.10 ensureScriptSlotsForChat2h | `LiveScriptServiceImpl` | **新增方法**：模板驱动，按固定结构创建槽位；5 个 product 槽位 `productId=null`，用户后续绑定 |

**chat_2h 槽位顺序**（模板驱动，不依赖 live_product）：
```
opening → chat → product(profit) → transition → chat → product(profit) → transition 
→ chat → product(profit) → transition → product(backup) → transition → product(backup) → closing
```

## 六、依赖与风险

| 依赖 | 说明 |
|------|------|
| huashu 知识库 | 需有足够素材，否则 RAG 效果差 |
| TianAPI | 歇后语、名言、古诗导入依赖 API 可用 |
| 人设数据 | 李阳阳等主播需预先配置 |

| 风险 | 缓解 |
|------|------|
| chat 生成质量不稳定 | ① 加强 prompt，明确「不推销、纯聊家常」；② 提供话题预设；③ 多轮测试调参 |
| 槽位过多导致生成慢 | ① 分批生成（先 opening+chat×3，再 product×5，再 closing）；② 支持断点续传；③ chat 可异步生成 |
| RAG 无 chat 类文档 | ① 放宽 script_type 过滤；② 用 type:家庭爱情、type:歇后语 等标签检索；③ 提前导入聊家常话术到 huashu |
| 模板与标准场次互斥 | 标准↔chat_2h 切换时提示「将重建话术槽位」 |
