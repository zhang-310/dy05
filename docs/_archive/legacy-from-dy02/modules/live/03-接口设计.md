## 3.2 场次管理接口

### 3.2.1 创建直播场次

```
POST /api/v1/live/sessions
```

**请求体：**
```json
{
  "accountId": 1,
  "personaId": 2,
  "sessionTitle": "春季新品首发直播",
  "sessionCover": "https://...",
  "sessionDescription": "...",
  "scriptStyle": "passionate",
  "plannedStartTime": "2026-03-01T20:00:00",
  "plannedEndTime": "2026-03-01T22:00:00"
}
```

**校验规则：**
- accountId 必须属于当前用户（BR-01）
- personaId 必须属于当前用户且为激活状态（BR-03）
- sessionTitle 必填，最长 256 字符
- scriptStyle 可选值：professional / friendly / passionate / seeding / promotion
- 可选字段：sessionCover、sessionDescription、plannedStartTime、plannedEndTime，不传则 null

**响应：** 201 Created，返回场次详情

---

### 3.2.2 获取场次详情

```
GET /api/v1/live/sessions/{id}
```

**响应包含：** 场次基本信息 + 关联产品列表 + 话术列表 + 汇总数据（如有）

---

### 3.2.3 更新场次信息

```
PUT /api/v1/live/sessions/{id}
```

**校验规则：**
- 只有 status=preparing 的场次可以编辑基本信息
- status=live 时只能更新 liveUrl
- status=ended 时不可编辑

---

### 3.2.4 删除场次

```
DELETE /api/v1/live/sessions/{id}
```

**校验规则：** 逻辑删除，status=live 的场次不能删除

---

### 3.2.5 场次列表

```
GET /api/v1/live/sessions?status=0&page=1&size=20&sort=createTime,desc
```

**筛选参数：**
- status：0=preparing 1=live 2=ended 3=cancelled
- accountId：按账号筛选
- startDate / endDate：按时间范围筛选
- page：页码，默认 1；size：每页条数，默认 20，最大 100

---

### 3.2.6 更新场次状态

```
PUT /api/v1/live/sessions/{id}/status
```

**请求体：**
```json
{
  "status": 1
}
```

**状态机校验（BR-04）：**
```
preparing(0) → live(1) → ended(2)
preparing(0) → cancelled(3)
```
- 0→1：需满足开播前置条件（BR-05）：至少 1 个产品、已关联人设
- 0→1：自动记录 actualStartTime
- 1→2：自动记录 actualEndTime，触发数据同步和 AI 复盘（BR-17）
- 禁止逆向转换（1→0、2→1 等）
- 禁止 ended/cancelled 状态变更

**错误码：**
- 3305：非法状态转换（LIVE_STATUS_TRANSITION_INVALID）
- 3306：开播前置条件不满足（LIVE_READINESS_NOT_MET）


**请求体：**
```json

}
```

**处理流程：**

### 3.4.5 一键生成整场话术（SSE 流式）

> **实际端点**（两种模式二选一）：

```
POST /api/v1/live/ai/generate-full-pipelined-sse   # 标准流水线模式
POST /api/v1/live/ai/generate-skeleton-sse          # 骨架模式（先出大纲再填充）
```

**请求体（`LiveAiGenerateVO`）：**
```json
{
  "sessionId": 1,
  "style": "natural",
  "durationLimitSec": 180,
  "useKbRef": true,
  "personaId": 2,
  "modelId": null,
  "extraPrompt": "结合双十一活动氛围，重点强调回购率高",
  "hotKeywords": ["爆款", "划算"],
  "interactionLevel": "medium",
  "retentionStrategy": "benefit_tease",
  "requirement": null
}
```

**字段说明：**

| 字段 | 类型 | 说明 |
|------|------|------|
| `sessionId` | Long | 场次 ID（必填）|
| `style` | String | 话术风格，见下方枚举 |
| `durationLimitSec` | Integer | 每商品时长上限（秒），默认 180 |
| `useKbRef` | Boolean | 是否引用知识库（RAG），默认 true |
| `personaId` | Long | 人设 ID（不传则用场次关联人设）|
| `modelId` | Long | 指定模型 ID（不传则用默认模型）|
| `extraPrompt` | String | 额外生成要求（≤300字）|
| `hotKeywords` | List\<String\> | 热词关键词列表 |
| `interactionLevel` | String | 互动频率：`low`/`medium`/`high` |
| `retentionStrategy` | String | 留人策略，见下方枚举 |
| `requirement` | String | 话术需求描述（逐段生成时用）|

**`style` 枚举（22种，对齐 `LivePromptFormatServiceImpl`）：**

| 分组 | 值 | 说明 |
|------|-----|------|
| 基础 | `natural` / `friendly` / `warm` / `gentle` / `casual` | 自然/友好/温暖/闺蜜/轻松 |
| 激情 | `enthusiastic` / `passionate` / `promotion` / `seeding` | 激情/热血/促销/种草 |
| 专业 | `professional` | 专业权威 |
| 情感 | `emotional` / `chicken_soup` / `positive` / `heart_piercing` / `family` / `love` | 情感共鸣系列 |
| 创意 | `humorous` / `proverb` / `lyrical` / `creative` / `local_flavor` / `persona_flavor` | 创意风格系列 |

**`retentionStrategy` 枚举：**

| 值 | 说明 |
|----|------|
| `benefit_tease` | 福利预告 |
| `question_hook` | 问题引导 |
| `countdown` | 倒计时 |
| `exclusivity` | 专属福利 |

**话术类型（`scriptType`）枚举（15种，对齐 `LiveScriptPostProcessor.defaultRequirement()`）：**

| 值 | 说明 |
|----|------|
| `opening` | 开场白 |
| `product` | 产品介绍 |
| `transition` | 转场 |
| `closing` | 收尾 |
| `chat` | 聊家常 |
| `interaction` | 互动引导 |
| `welfare` | 福利话术 |
| `closing_deal` | 逼单促单 |
| `hold_back` | 憋单蓄水 |
| `emotional` | 情绪价值 |
| `rapid_intro` | 快速过品 |
| `deep_sell` | 深度单品 |
| `pain_point` | 痛点放大 |
| `testimony` | 用户证言 |
| `custom` | 自定义 |

**SSE 事件流格式：**
```
event: status
data: "正在连接 AI..."

event: progress
data: {"current": 1, "total": 5, "percent": 20, "slotLabel": "产品介绍"}

event: slot_done
data: {"scriptId": 12, "content": "...", "scriptType": "product", "slotLabel": "精华液"}

event: slot_failed
data: {"scriptId": 0, "slotLabel": "精华液", "errorMsg": "LLM 超时"}

event: done
data: {"total": 5, "success": 5, "failed": 0}
```

**处理流程：**
1. 校验场次商品 > 0，否则 400
2. 按商品排序，构建槽位列表（opening → product×N → transition×N-1 → closing）
3. 流水线模式：逐槽位生成，每完成一个推送 `slot_done`
4. 骨架模式：先生成全场大纲骨架，再逐槽位扩展填充
5. 单槽位失败不回滚，推送 `slot_failed`，继续下一个
6. 全部完成推送 `done` 事件
7. 前端收到 `done` 后刷新 `wb-scripts` 缓存

**注意：**
- SSE 连接超时：前端默认 30 分钟空闲超时（50 商品场次约需 10-15 分钟）
- 路径含 `-sse` 后缀，`OperationLogFilter` 自动跳过响应体缓冲
- 前端使用 `ssePost()` 工具函数（`utils/sse-client.ts`），不使用原生 EventSource

### 3.4.5c AI 段内微调（非流式）

> 参考：`docs/modules/live/话术生成与微调升级计划.md` Phase 1

```
POST /api/v1/live/ai/refine-segment
```

**功能：** 针对整段话术中的某一句/某一段进行局部 AI 修改，不影响其他内容。

**请求体：**
```json
{
  "scriptId": 12,
  "segmentText": "今天直播间给大家带来福利价，姐妹们赶紧拍！",
  "instruction": "改成更幽默，加入歇后语",
  "modelId": null
}
```

**字段说明：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `scriptId` | Long | ✅ | 话术 ID，用于读取完整原文 |
| `segmentText` | String | ✅ | 要修改的原始片段文本（需与原文精确匹配）|
| `instruction` | String | ✅ | 修改要求（≤200字）|
| `modelId` | Long | ❌ | 指定模型 ID，不传则用默认模型 |

**处理流程：**
1. 从 `live_script` 读取完整 `script_content`
2. 在原文中定位 `segmentText`（首次出现位置）
3. 若未找到，返回 400（`SEGMENT_NOT_FOUND`）
4. 调用 LLM：仅对 `segmentText` 按 `instruction` 修改，保持其余内容风格一致
5. 将修改后的片段替换回原文（替换第一处匹配）
6. 返回**完整修改后的话术正文**（调用方负责保存）

**响应：**
```json
{
  "status": 200,
  "data": "完整修改后的话术正文（整段）",
  "message": "success"
}
```

**边界情况：**

| 情况 | 处理 |
|------|------|
| `segmentText` 在原文中不存在 | 返回 400，提示「未找到匹配片段」|
| `segmentText` 出现多次 | 替换第一处匹配 |
| `instruction` 为空 | 返回 400 |
| LLM 输出超长 | 截断至原片段长度的 3 倍 |

**前端使用场景：**
- 用户在 `ScriptCard` 段落视图中选中某句 → 输入修改要求 → 调用此接口
- 接口返回完整话术后，前端调用 `saveLiveScript` 保存
- 支持「撤销」：保存前可对比原文与修改后内容

**注意：** 此接口为非 SSE，响应时间通常 3-8 秒，前端需显示 Loading 状态。

## 3.5 数据同步接口

### 3.5.1 同步直播汇总数据

```
POST /api/v1/live/sessions/{sessionId}/sync-data
```

**处理流程：**
1. 通过抖音 API 拉取直播汇总数据
2. 写入/更新 live_session_data
3. 同步分产品数据到 live_product_data

**触发时机：**
- 直播结束（status=ended）后自动触发
- 用户手动触发

**幂等性：** 同一 session 多次调用结果一致，以 last_sync_time 最新为准，重复调用不产生副作用。

## 3.7 错误码

> 直播模块错误码号段：3300-3399，详见 `docs/04-错误码注册表.md`

| 错误码 | 常量名 | 说明 |
|--------|--------|------|
