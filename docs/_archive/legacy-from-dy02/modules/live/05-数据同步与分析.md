# 直播模块 — 数据同步与分析

> 版本：3.0 | 更新日期：2026-02-26 | 与 00-大纲 对齐

---

## 5.1 数据同步总览

```
直播全流程数据采集：

直播前（preparing）
    └─ 无数据采集

直播中（live）
    ├─ LiveMonitor 实时时序数据（每 5s 采集一次）
    └─ SSE 推送到前端（GET /api/v1/live/monitor/stream/{sessionId}）

直播后（ended）
    ├─ 数据同步 → live_session_data、live_product_data（见 5.1.1）
    ├─ 话术效果归因（关联 live_session_script + live_monitor）
    └─ AI 复盘报告生成（延迟 10 分钟）
```

### 5.1.1 当前数据来源（实现状态）

| 数据 | 当前来源 | 抖音 API 对接 |
|------|----------|---------------|
| live_session_data | 手动录入、LiveMonitor 聚合、前端同步接口 | 规划 P2 迭代 |
| live_product_data | 手动录入、同步接口 | 规划 P2 迭代 |
| live_monitor | 内部采集 / 外部推送（POST /monitor/push） | 可对接抖音实时 API |

**说明**：抖音开放平台直播数据接口对接为后续迭代，当前支持手动录入与 LiveMonitor 聚合。

## 5.2 LiveMonitor 实时时序数据

### 5.2.1 采集流程

```
直播状态变为 live（status=1）
    ↓
启动定时采集任务（间隔 = LIVE_MONITOR_INTERVAL，默认 5s）
    ↓
LOOP（直到 status 变为 ended）:
    ├─ 调用抖音 API 获取直播间实时数据
    ├─ 写入 live_monitor（session_id, record_time, viewers, likes, ...）
    └─ 通过 WebSocket 推送到前端
    ↓
直播结束（status=2）
    └─ 停止采集任务
```

### 5.2.2 实时推送（SSE / WebSocket）

**当前实现：SSE（Server-Sent Events）**

```
SSE 端点：GET /api/v1/live/monitor/stream/{sessionId}
Content-Type: text/event-stream

认证：需登录，Cookie/Header 携带 token
心跳：服务端每 5s 推送一次最新数据
超时：30 分钟无活动断开
快照：GET /api/v1/live/monitor/stream/{sessionId}/snapshot
```

**可选：WebSocket** — 文档设计为 `ws://host/api/v1/live/ws/{sessionId}`，与 SSE 功能等价，可按需实现。
心跳：每 30s 发送 ping/pong，60s 无响应断开重连
重连策略：指数退避（1s → 2s → 4s → 8s → 最大 30s）
并发限制：每个直播场次最多 50 个 WebSocket 连接；单用户最多 5 个场次同时连接

消息格式：
{
  "type": "metrics",
  "data": {
    "viewers": 1500,
    "totalViewers": 8000,
    "likes": 25000,
    "comments": 3200,
    "shares": 500,
    "newFollowers": 120,
    "onlineCount": 1500,
    "gmv": 15000.00,
    "orders": 85
  },
  "ts": 1709280000
}
```

### 5.2.3 数据归档

```
定时任务（每月 1 日 03:00）
    ↓
查询 live_monitor WHERE timestamp < NOW() - 90 天
    ↓
批量迁移到 live_monitor_archive 表
    ↓
删除原表中的归档数据
```

## 5.3 直播汇总数据同步

### 5.3.1 同步触发

| 触发方式 | 时机 | 说明 |
|---------|------|------|
| 自动触发 | status 变为 ended | 直播结束后立即同步 |
| 手动触发 | 用户点击同步按钮 | 随时可触发 |
| 定时补偿 | 每日 06:00 | 扫描 ended 但 last_sync_time 为空的场次 |

### 5.3.2 同步流程

```
触发同步
    ↓
调用抖音 API：GET /live/data（传入直播间 ID）
    ↓
[汇总数据]
    ├─ total_viewers, peak_viewers, avg_watch_duration
    ├─ new_followers, likes, comments, shares
    ├─ gift_value, total_gmv, total_orders
    ├─ conversion_rate, avg_order_value
    └─ duration_minutes
    ↓
UPSERT 到 live_session_data（session_id 唯一）
    ↓
[分产品数据]
    ├─ 调用抖音 API：GET /live/product-data
    ├─ FOR EACH product:
    │   ├─ gmv, orders, click_count
    │   ├─ conversion_rate, refund_rate, exposure_count
    │   └─ UPSERT 到 live_product_data
    └─ 更新 live_session_product 的 sale_quantity 和 revenue
    ↓
更新 live_session_data.last_sync_time
```

### 5.3.3 字段映射

| 抖音 API 字段 | live_session_data 字段 | 说明 |
|--------------|----------------------|------|
| total_user | total_viewers | 总观看人数 |
| max_user_count | peak_viewers | 峰值观看 |
| avg_watch_duration | avg_watch_duration | 平均观看时长 |
| new_fans_count | new_followers | 新增粉丝 |
| like_count | likes | 点赞数 |
| comment_count | comments | 评论数 |
| share_count | shares | 分享数 |
| gift_ucoin_count | gift_value | 礼物价值 |
| pay_amount | total_gmv | 总 GMV |
| pay_order_count | total_orders | 总订单数 |

## 5.4 AI 复盘报告

### 5.4.1 触发流程

```
直播结束（status=ended）
    ↓
延迟 LIVE_REVIEW_DELAY_MINUTES（默认 10 分钟）
    ↓
[数据收集]
    ├─ live_session：场次基本信息
    ├─ live_session_data：汇总数据
    ├─ live_product_data：分产品数据
    ├─ live_session_script：话术列表（含执行记录）
    ├─ live_monitor：时序数据
    └─ 该账号历史直播数据（对比基准）
    ↓
[关联分析]（规则引擎，非 LLM）
    ├─ 话术-观众关联：话术执行后 30s 内观众变化
    ├─ 话术-互动关联：话术执行后 30s 内评论/点赞变化
    ├─ 商品-转化关联：商品讲解时段的转化率
    ├─ 峰值分析：观众峰值出现在什么时间点，当时在做什么
    └─ 流失分析：观众大量离开的时间点，当时在做什么
    ↓
[发送到 AI 模块]
    ├─ 发送消息到 RabbitMQ（queue: ai.live.review）
    ├─ ai 模块直播复盘 Agent 消费消息
    ├─ LLM 生成复盘报告（亮点 + 问题 + 改进建议 + 下场话术建议）
    └─ 高分报告入库知识库（source='live_review'）
    ↓
[结果回写]
    ├─ 创建 ai_live_review 记录
    ├─ 更新 live_session_data.ai_review_id
    ├─ 更新 live_session_script 的效果归因字段
    └─ 高效话术入库 live_script_template
```

## 5.5 历史对比分析

### 5.5.1 对比维度

| 维度 | 数据来源 | 说明 |
|------|---------|------|
| 场次对比 | live_session_data | 多场直播的 GMV/观众/转化率对比 |
| 产品对比 | live_product_data | 同一产品在不同场次的表现对比 |
| 话术对比 | live_session_script | 同类型话术的效果评分对比 |
| 时段对比 | live_monitor | 不同场次同一时段的观众变化对比 |
| 趋势分析 | live_session_data | 近 N 场直播的关键指标趋势 |

### 5.5.2 对比查询示例

```sql
-- 近 10 场直播的关键指标趋势
SELECT
    ls.id,
    ls.session_title,
    ls.actual_start_time,
    lsd.total_viewers,
    lsd.peak_viewers,
    lsd.total_gmv,
    lsd.conversion_rate,
    lsd.duration_minutes
FROM live_session ls
JOIN live_session_data lsd ON lsd.session_id = ls.id
WHERE ls.owner_id = :ownerId
    AND ls.status = 2  -- ended
    AND ls.deleted = 0
ORDER BY ls.actual_start_time DESC
LIMIT 10;

-- 同一产品在不同场次的表现
SELECT
    ls.session_title,
    ls.actual_start_time,
    lpd.gmv,
    lpd.orders,
    lpd.conversion_rate,
    lpd.refund_rate
FROM live_product_data lpd
JOIN live_session ls ON ls.id = lpd.session_id
WHERE lpd.product_id = :productId
    AND ls.deleted = 0
ORDER BY ls.actual_start_time DESC;
```

## 5.6 定时任务汇总

| 任务 | Cron | 说明 |
|------|------|------|
| LiveMonitor 采集 | 每 5s（直播中） | 实时时序数据采集 |
| 汇总数据同步 | 直播结束后立即 | 自动触发 |
| AI 复盘报告 | 直播结束后 10min | 延迟触发 |
| 话术效果归因 | 直播结束后 10min | 与复盘同步 |
| 数据同步补偿 | 0 0 6 * * ? | 每日 06:00 |
| LiveMonitor 归档 | 0 0 3 1 * ? | 每月 1 日 03:00 |

## 5.7 数据一致性保证

- **live_session_data**：一场一条，UPSERT 以 session_id 为准
- **live_product_data**：一场一产品一条，UPSERT 以 (session_id, product_id) 为准
- **live_monitor**：append-only，不更新历史点，归档后删除

## 5.8 同步失败告警

| 场景 | 告警方式 | 阈值 |
|------|---------|------|
| 抖音 API 连续失败 3 次 | 日志 + 可选企业微信通知 | 可配置 |
| last_sync_time 超过 24h 仍为空 | 定时任务扫描，标记 sync_status=failed | 每日 06:00 |
| LiveMonitor 写入失败率 > 5% | 日志告警 | 5 分钟窗口 |

## 5.9 降级策略

| 场景 | 降级方案 |
|------|---------|
| 抖音 API 不可用 | 重试 3 次（间隔 10s/30s/60s），失败后标记 sync_status=failed，下次定时任务重试 |
| WebSocket 连接断开 | 客户端指数退避重连，服务端缓存最近 60s 数据，重连后补发 |
| AI 复盘超时 | 超时 60s 后返回基于规则的简化报告（无 LLM 分析） |
| LiveMonitor 写入失败 | Redis Stream 缓冲，批量重试写入 |
