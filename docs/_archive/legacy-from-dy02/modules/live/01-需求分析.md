> 版本：3.0 | 更新日期：2026-02-26 | 与 00-大纲 对齐

---

## 1.1 模块定位

live 模块是平台的核心业务模块，目标是成为**AI 驱动的直播运营助手**，围绕直播全流程管理：

1. **场次管理** — 直播场次创建、选品排序、状态机管理、开播准备清单
2. **AI 话术系统** — 开场/产品/转场/结尾话术 AI 生成、违规检测、话术效果归因
3. **数据同步与分析** — 抖音直播数据同步、实时监控（LiveMonitor 时序数据）、汇总数据
4. **AI 复盘与归因** — 直播结束后自动复盘、话术效果归因、改进建议、高效话术入库

产品数据来自 product 模块（dy_product），AI 能力来自 ai 模块，违规检测来自 script 模块。

## 1.3 功能清单

```
live 模块
├── 场次管理
│   ├── 创建直播场次（绑定账号/人设/时间/主题/封面）
│   ├── 编辑场次信息
│   ├── 删除场次
│   ├── 场次关联产品（从 product 商品库选品 + 排序）
│   ├── 场次状态管理（preparing → live → ended，单向流转，禁止逆向）
│   ├── 开播准备清单（自动检查：商品/话术/合规/人设）
│   ├── 场次列表（分页、按状态筛选）
│   └── 场次详情
│
├── 直播话术
│   ├── 开场话术（AI 按人设 + 场次主题生成）
│   ├── 产品话术（引用 product 模块已有的商品话术，或 AI 按人设+产品重新生成）
│   ├── 转场话术（AI 生成产品间过渡）
│   ├── 结尾话术（AI 按人设生成）
│   ├── 整场话术流程（将开场→产品1→转场→产品2→...→结尾串联）
│   ├── 一键生成整场话术（记录 ai_call_log_id）
│   ├── 话术风格选择（专业/亲切/激情/种草/促销）
│   ├── 手动编辑话术
│   ├── 话术违规检测（调用 script 模块，scope=live）
│   ├── 保存话术到话术库（调用 script 模块）
│   ├── 导出话术（Markdown 格式，支持打印/分享）
│   └── 话术效果归因（关联 LiveMonitor 时序数据，计算 effectiveness_score）
│
├── 违规管理（数据由 script 模块提供，live 提供 UI 入口）
│   ├── 查看公共违规词库
│   ├── 管理个人违规词库
│   └── 话术一键检测
│
├── 直播数据
│   ├── 通过抖音 API 同步直播汇总数据（live_session_data）
│   ├── 通过抖音 API 同步分产品数据（live_product_data）
│   ├── LiveMonitor 实时时序数据（每 5s 采集一次）
│   ├── 直播数据看板（观看人数/峰值/互动/GMV）
│   ├── 分时段数据曲线（基于 LiveMonitor 时序数据）
│   ├── 分产品数据（每个产品的 GMV/转化）
│   └── 历史直播数据对比
│
└── AI 数据分析
    ├── AI 整场直播分析（评级+分析+建议）
    ├── AI 分产品分析
    ├── AI 复盘报告生成（对接 ai 模块直播复盘 Agent）
    ├── 话术效果排行（基于 effectiveness_score）
    └── 改进推荐（话术/选品/时段）
```

## 1.4 业务规则

| 编号 | 规则 | 说明 |
|------|------|------|
| **场次管理** | | |
| BR-01 | 场次关联账号 | 一个场次关联一个抖音账号，account_id 必须属于当前用户（dy_account.owner_id = 当前用户） |
| BR-02 | 场次关联产品 | 从 product 模块的商品库（dy_product）选品，设置排序。product_id 必须属于同一用户 |
| BR-03 | 场次关联人设 | persona_id 必须属于当前用户且为激活状态 |
| BR-04 | 场次状态机 | preparing → live → ended，单向流转，禁止逆向转换。状态变更需校验前置条件 |
| BR-05 | 开播前置条件 | preparing → live 需满足：至少选择 1 个产品、已关联人设 |
| BR-06 | 数据隔离 | talent 只能看到自己的场次和数据（owner_id）；institution 可查看自己+旗下达人的数据（DataScopeService）；admin 可查看全部 |
| **话术生成** | | |
| BR-07 | 话术生成需人设 | 所有话术 AI 生成需要激活的人设，且人设必须属于当前用户（owner_id 校验） |
| BR-08 | 整场话术流程 | 按产品排序串联：开场 → 产品1话术 → 转场 → 产品2话术 → ... → 结尾 |
| BR-09 | 话术可引用或重生成 | 产品话术可直接引用 product 模块已有的商品话术（dy_product_script），也可以为当场直播重新 AI 生成 |
| BR-10 | 自动违规检测 | AI 生成话术后自动调用 script 模块做违规检测，传入 scope=live（匹配 all + live_only 违规词） |
| BR-11 | 整场生成事务 | generate-full 采用"尽力生成"策略：逐产品调用 AI 生成，单个产品失败不回滚已成功的部分，但标记该产品话术为 failed 状态，允许用户手动重试 |
| BR-12 | 话术记录 AI 调用 | 每次 AI 生成话术时记录 ai_call_log_id，用于效果归因 |
| **数据同步** | | |
| BR-13 | 直播数据同步 | 直播结束后通过抖音 API 同步汇总数据到 live_session_data，可手动触发 |
| BR-14 | 分产品数据同步 | 直播结束后同步每个产品的 GMV/订单/转化率到 live_product_data |
| BR-15 | LiveMonitor 采集 | 直播进行中每 5 秒采集一次时序数据（观众/点赞/评论/分享/在线人数） |
| BR-16 | LiveMonitor 归档 | 超过 90 天的 LiveMonitor 数据自动归档，保留汇总数据 |
| **AI 分析与归因** | | |
| BR-17 | AI 复盘触发 | 直播结束（status=ended）后 10 分钟自动触发 AI 复盘报告生成 |
| BR-18 | 话术效果归因 | 直播结束后，关联 live_session_script.actual_execution_time 和 live_monitor 时序数据，计算每句话术执行后 30s 内的观众/互动变化 |
| BR-19 | 高效话术入库 | effectiveness_score > 80 的话术自动入库到 live_script_template（ai 模块 05 中已设计） |
| BR-20 | 违规词库分层 | 公共库（管理员维护，全用户可见）+ 个人库（用户私有） |

## 1.5 模块依赖

```
依赖关系：
auth ← douyin（账号/人设）← live
auth ← product（商品库）← live
ai（AI 生成话术/分析/复盘）← live
script（违规检测/话术库）← live
```

| 依赖模块 | 依赖内容 | 接口 |
|---------|---------|------|
| douyin | 账号信息、人设信息 | DouyinAccountService, DouyinPersonaService |
| product | 商品信息、商品话术 | ProductService, ProductScriptService（dy_product、dy_product_script） |
| ai | AI 话术生成、AI 分析报告、AI 复盘 | AiGenerateService（模板：live_script_*、live_analysis） |
| script | 违规词检测、话术库保存 | ScriptViolationService, ScriptLibraryService |

## 1.6 环境变量

| 变量名 | 级别 | 默认值 | 说明 |
|--------|------|--------|------|
| LIVE_MONITOR_INTERVAL | 🟢 可选 | 5 | LiveMonitor 采集间隔（秒） |

| LIVE_REVIEW_DELAY_MINUTES | 🟢 可选 | 10 | 复盘延迟时间（分钟） |
| LIVE_SCRIPT_EFFECTIVENESS_THRESHOLD | 🟢 可选 | 80 | 高效话术入库阈值 |
| LIVE_DATA_SYNC_RETRY | 🟢 可选 | 3 | 数据同步重试次数 |
