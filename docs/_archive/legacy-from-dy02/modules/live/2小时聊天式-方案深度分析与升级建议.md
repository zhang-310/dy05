## 二、技术实现缺口（需补充到升级计划）

### 2.1 槽位创建逻辑与 products 的依赖关系

**现状**：`ensureScriptSlotsForSession` 是 **product-driven**：
- 槽位结构 = opening + (product + transition)×(n-1) + product + closing
- 完全由 `live_product` 的数量和顺序决定，**无法插入 chat**

**chat_2h 目标结构**：
```
opening → chat → product(profit) → transition → chat → product(profit) → transition 
→ chat → product(profit) → transition → product(backup) → transition → product(backup) → closing
```

**矛盾**：chat 槽位需**穿插在 product 之间**，而当前逻辑是 product 决定一切。

**建议方案**（二选一）：

| 方案 | 实现 | 优缺点 |
|------|------|--------|
| **A：模板驱动** | `session_type=chat_2h` 时，**不依赖 products**，直接按固定结构创建槽位；5 个 product 槽位先 `productId=null`，用户后续在排品面板绑定 | 结构固定，实现简单；需处理 productId 为空的 product 槽位展示与生成 |
| **B：产品驱动 + 插入** | 先创建 5 个 LiveProduct（3 profit + 2 backup），扩展 `ensureScriptSlotsForSession`：当 `session_type=chat_2h` 时，在每两个 product 之间插入 chat 槽位 | 与现有逻辑一致，但需大改 ensureScriptSlotsForSession 分支逻辑 |

**推荐**：方案 A。chat_2h 作为「固定模板」，槽位结构预定义，product 槽位后续绑定商品。

### 2.2 transition 的 fromIdx/toIdx 计算会失效

**现状**：`buildSlotVo` 中 transition 的 `fromProductName`/`toProductName` 计算：
```java
int fromIdx = (ctx.slotIndex() - 2) / 2;
int toIdx = fromIdx + 1;
```
假设结构为 `opening(0) + product(1) + transition(2) + product(3) + ...`。

**chat_2h 结构**：opening(0) + chat(1) + product(2) + transition(3) + chat(4) + ...，索引关系完全变化。

**建议**：新增 `resolveTransitionProducts(slotIndex, allSlots, liveProducts)`，根据**实际槽位序列**找到当前 transition 前后的 product 槽位，再取 productName。不能再用固定公式。

### 2.3 buildScriptTemplate 缺少 chat 分支

**现状**：`LivePromptBuilder.buildScriptTemplate` 的 switch 仅有 opening/product/transition/closing，无 chat。  
当 LLM 不可用 fallback 到模板时，会抛 `"不支持的话术类型: chat"`。

**建议**：新增 `case "chat"`，可调用 `buildEmotionalUserPrompt` 或返回简单占位模板。

### 2.4 defaultRequirement 与 slotLabel 缺少 chat

**现状**：
- `defaultRequirement("chat")` 会 fallback 到 `"互动引导"`
- `slotLabel("chat", index, productCount)` 会 fallback 到 `"chat"`

**建议**：
- `defaultRequirement("chat")` → `"聊家常（夫妻/婆媳/励志/歇后语/名言等）"`
- `slotLabel("chat", ...)` → `"聊家常" + (index/2 + 1)` 或类似

### 2.5 buildCategoryQueries 的 product=null 处理

**现状**：`buildCategoryQueries(product, scriptType, style)` 中，若 product 为 null，q1 仅有 typeTerm + style，可能过泛。

**建议**：当 `scriptType=chat` 且 product==null 时，用 `vo.getRequirement()` 或新增 `chatTopic` 字段提取话题关键词，构建专用检索词（夫妻、婆媳、励志、歇后语等）。

### 2.6 buildRagContext 的 script_type 过滤

**现状**：huashu 的 ES/Milvus 过滤 `script_type`，知识库中现有文档多为 opening/product/transition/closing，**几乎没有 script_type=chat**。

**建议**：chat 检索时**放宽 script_type 过滤**，或不过滤，仅用 query 语义检索。否则 RAG 可能无结果。

### 2.7 LiveSession 表结构

**现状**：`live_session` 无 `session_type` 或 `session_template` 字段。

**建议**：新增 Flyway 迁移 `ALTER TABLE live_session ADD COLUMN session_type VARCHAR(32)`，默认 `standard`，可选 `chat_2h`。

## 三、ChunkLabeler 与知识库标签

**现状**：ChunkLabeler 已有 `type:家庭爱情`（含夫妻、婆媳、婚姻），`type:歇后语`，`type:搞笑幽默`，`type:正能量` 等。

**升级计划**中「古诗、夫妻、婆媳」：
- **夫妻/婆媳**：已由 `type:家庭爱情` 覆盖，无需单独新增
- **古诗**：需新增 `matchAny(..., "古诗", "诗词", "唐诗", "宋词")` → `type:古诗`

**建议**：Phase 1 仅补充 `type:古诗`，夫妻/婆媳沿用 `type:家庭爱情`。

## 五、chat 话题参数传递

**需求**：chat 槽位需指定话题（夫妻/婆媳/励志/歇后语/名言/古诗/幽默）。

**方案**：
- **A**：用 `live_script.requirement` 存话题，如 `"聊家常-夫妻感情"`
- **B**：扩展 `live_script` 表，新增 `chat_topic VARCHAR(32)`
- **C**：扩展 `LiveAiGenerateVO`，新增 `chatTopic`，生成时从 slot.requirement 解析

**建议**：方案 A，复用 requirement。前端 chat 槽位编辑时，提供话题下拉（夫妻/婆媳/励志/歇后语/名言/古诗/幽默），写入 requirement。

## 六、风险与缓解（补充到升级计划）

| 风险 | 缓解 |
|------|------|
| chat 生成质量不稳定 | ① 加强 prompt，明确「不推销、纯聊家常」；② 提供话题预设，限制生成范围；③ 多轮测试调参 |
| 槽位过多导致生成慢 | ① 分批生成（先 opening+chat×3，再 product×5，再 closing）；② 支持断点续传；③ chat 可异步生成 |
| RAG 无 chat 类文档 | ① 放宽 script_type 过滤；② 用 type:家庭爱情、type:歇后语 等标签检索；③ 提前导入聊家常话术到 huashu |
| 模板与标准场次互斥 | 明确 session_type 切换规则：标准→chat_2h 需重建槽位（清空后按模板重建） |

## 八、架构决策建议

### 8.1 模板驱动 vs 产品驱动

**建议**：chat_2h 采用**模板驱动**。创建场次时选择「2小时聊天式」→ 直接创建固定槽位结构，5 个 product 槽位待绑定。用户进入排品面板后，按位置 1–5 绑定具体商品（前 3 利润品，后 2 备用品）。

### 8.2 chat 与 emotional 的关系

**建议**：chat 作为**独立 script_type**，不复用 emotional。emotional 用于「插入情绪话术」场景，chat 用于「2 小时模板中的聊家常槽位」。两者 prompt 可共用 `buildEmotionalUserPrompt` 的部分逻辑，但类型区分清晰。

|------|------|------|
| 需求文档 | 完整、清晰 | 保持，可补充「微付费刺激自然流」在话术中的体现（如少用强推销话术） |
