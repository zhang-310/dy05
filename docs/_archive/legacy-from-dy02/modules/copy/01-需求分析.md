# 文案模块 — 需求分析

> 版本：3.0 | 更新日期：2026-02-26

---

## 1.1 模块定位

copy 模块为平台提供文案内容的全生命周期管理。用户可以创建、搜索、引用文案，管理员负责审核文案质量，确保入库内容合规。文案模板系统支持高频文案结构的复用，提升创作效率。

所有权限控制依赖 auth 模块，AI 辅助创作能力通过调用 ai 模块实现。

---

## 1.2 用户故事

| 编号 | 角色 | 故事 | 验收条件 |
|------|------|------|----------|
| **文案库管理** | | | |
| CP-01 | 达人 | 我要能创建文案并保存到文案库 | 填写标题、内容、分类、标签后保存成功，状态为待审核 |
| CP-02 | 达人 | 我要能搜索文案库中的文案 | 支持按关键词、分类、标签、状态分页搜索 |
| CP-03 | 达人 | 我要能查看文案详情 | 显示标题、内容、分类、标签、字数、使用次数、评分、状态 |
| CP-04 | 达人 | 我要能编辑自己创建的文案 | 只能编辑自己的文案，编辑后状态重置为待审核 |
| CP-05 | 达人 | 我要能删除自己创建的文案 | 只能删除自己的文案，软删除 |
| CP-06 | 达人 | 我要能使用文案（引用到其他场景） | 调用使用接口，use_count 自动加 1 |
| **审批流程** | | | |
| CP-07 | 达人 | 我要能提交文案审批 | 创建审批记录，文案状态变为待审核 |
| CP-08 | 管理员 | 我要能查看待审批的文案列表 | 显示所有待审核文案，支持分页和筛选 |
| CP-09 | 管理员 | 我要能审批通过文案 | 审批通过后文案状态变为已审核，记录审批意见 |
| CP-10 | 管理员 | 我要能拒绝文案审批 | 拒绝后文案状态保持待审核，记录拒绝原因 |
| **模板管理** | | | |
| CP-11 | 达人/机构/管理员 | 我要能创建文案模板 | 填写模板名称、内容、分类、描述后保存 |
| CP-12 | 达人/机构/管理员 | 我要能使用模板快速创建文案 | 选择模板后自动填充内容，用户可修改后保存 |

## 1.3 功能清单

```
copy 模块
├── 文案库管理
│   ├── 文案创建（标题/内容/分类/标签）
│   ├── 文案搜索（关键词/分类/标签/状态，分页）
│   ├── 文案详情查看
│   ├── 文案编辑（仅本人，编辑后重置为待审核）
│   ├── 文案删除（软删除，仅本人）
│   ├── 文案状态更新（admin 专用）
│   └── 使用计数递增（use_count +1）
│
├── 审批流程
│   ├── 提交审批（创建 cp_approval 记录）
│   ├── 审批列表查询（分页，支持按状态筛选）
│   ├── 审批详情查看
│   ├── 审批通过（approval_status=1，cp_library.status=1）
│   └── 审批拒绝（approval_status=0，记录拒绝原因）
│
└── 模板管理
    ├── 模板创建（模板名称/内容/分类/描述）
    ├── 模板搜索（关键词/分类/状态，分页）
    ├── 模板详情查看
    ├── 模板编辑（仅本人或 admin）
    ├── 模板删除（软删除）
    └── 模板启用/禁用（status: 0=禁用/1=有效）
```

## 1.4 业务规则

| 编号 | 规则 | 说明 |
|------|------|------|
| **文案库** | | |
| BR-01 | 新建文案默认待审核 | 用户创建文案后，status 默认为 0（待审核），需经审批才能变为已审核 |
| BR-02 | 数据隔离 | 达人只能查看、编辑、删除自己创建的文案（user_id 过滤）；机构可管理机构范围内达人的文案；管理员可查看全部 |
| BR-03 | 编辑重置状态 | 用户编辑已审核文案后，status 重置为 0（待审核），需重新提交审批 |
| BR-04 | 使用计数 | 调用 increment-use-count 接口时，cp_library.use_count 原子性加 1 |
| BR-05 | 字数自动计算 | 保存文案时，后端自动计算 content 字数并写入 word_count 字段 |
| **审批流程** | | |
| BR-06 | 审批状态流转 | cp_approval.approval_status：2（待审核）→ 1（通过）或 0（拒绝）；不可逆转 |
| BR-07 | 审批与文案联动 | 审批通过时，同步更新 cp_library.status=1；审批拒绝时，cp_library.status 保持 0 |
| BR-08 | 审批权限 | 只有 admin 角色可以执行审批操作（update-status）；达人只能提交和查看自己的审批记录；机构可查看机构范围内的审批记录 |
| **模板系统** | | |
| BR-09 | 模板权限 | admin 可管理所有模板；机构可管理机构范围内的模板；达人只能管理自己创建的模板 |
| BR-10 | 软删除 | 所有业务表使用逻辑删除（deleted 字段），数据不物理删除 |

## 1.5 模块依赖

```
依赖关系：
auth ← copy（用户鉴权、角色权限）
ai ← copy（AI 辅助文案生成，可选）
```

| 依赖模块 | 依赖内容 | 接口 |
|---------|---------|------|
| auth | 用户身份验证、角色判断（admin/institution/talent/user） | SecurityUtils, UserContext |
| ai | AI 辅助生成文案内容（可选扩展） | AiGenerateService |

---

## 1.6 环境变量

copy 模块无特定环境变量，使用全局配置（数据库连接、JWT 等由 auth 模块统一管理）。
