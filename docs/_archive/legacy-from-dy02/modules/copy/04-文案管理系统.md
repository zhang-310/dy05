## 4.1 文案库 CRUD 流程

### 4.1.1 创建文案

```
用户填写表单
    │
    ▼
前端校验（标题/内容不为空）
    │
    ▼
POST /api/v1/copy/library/save（id 为空）
    │
    ▼
后端处理：
  1. 从 SecurityContext 获取当前用户 ID → user_id
  2. 计算 content 字数 → word_count
  3. 设置 status = 0（待审核）
  4. 插入 cp_library 记录
    │
    ▼
返回新建文案 ID
```

### 4.1.2 更新文案

```
用户编辑文案
    │
    ▼
POST /api/v1/copy/library/save（id 不为空）
    │
    ▼
后端处理：
  1. 查询 cp_library，校验存在性（不存在 → 3501）
  2. 校验 user_id == 当前用户（不匹配且非 admin → 3502）
  3. 重新计算 word_count
  4. 若原 status == 1（已审核），重置为 0（待审核）
  5. 更新记录
    │
    ▼
返回文案 ID
```

### 4.1.3 删除文案

```
用户点击删除
    │
    ▼
POST /api/v1/copy/library/delete
    │
    ▼
后端处理：
  1. 查询 cp_library，校验存在性（不存在 → 3501）
  2. 校验 user_id == 当前用户（不匹配且非 admin → 3502）
  3. 软删除：UPDATE SET deleted = 1
    │
    ▼
返回 void
```

## 4.2 文案状态机

```
                    ┌─────────────────────────────────┐
                    │         cp_library.status        │
                    └─────────────────────────────────┘

  [新建文案]
      │
      ▼
  ┌─────────┐    提交审批（创建 cp_approval）    ┌─────────┐
  │ 待审核   │ ─────────────────────────────► │ 待审核   │
  │ status=0│                                │（审批中） │
  └─────────┘                                └────┬────┘
      ▲                                           │
      │                                    ┌──────┴──────┐
      │ 用户编辑已审核文案                  │             │
      │ （自动重置）                    审批通过       审批拒绝
      │                                    │             │
  ┌─────────┐                              ▼             │
  │ 已审核   │ ◄────────────────────── status=1          │
  │ status=1│                                            │
  └─────────┘                              status 保持 0 ◄┘
                                           （可重新提交审批）
```

状态转换规则：

| 当前状态 | 触发动作 | 目标状态 | 执行者 |
|---------|---------|---------|--------|
| 0（待审核） | 管理员审批通过 | 1（已审核） | admin |
| 1（已审核） | 用户编辑文案 | 0（待审核） | talent/institution/admin |
| 0（待审核） | 管理员直接更新状态 | 1（已审核） | admin |
| 1（已审核） | 管理员直接更新状态 | 0（待审核） | admin |

## 4.3 数据隔离

### 隔离规则

| 角色 | 查询范围 | 编辑权限 | 删除权限 |
|------|---------|---------|---------|
| talent | 仅自己的文案（user_id = 当前用户） | 仅自己的文案 | 仅自己的文案 |
| institution | 机构范围内的文案（机构下所有达人） | 机构范围内的文案 | 机构范围内的文案 |
| admin | 全部文案 | 全部文案 | 全部文案 |

### 实现方式

```java
// Service 层数据隔离示例
public PageResultVO<CopyLibraryVO> search(CopyLibrarySearchDTO dto) {
    Long currentUserId = SecurityUtils.getCurrentUserId();
    boolean isAdmin = SecurityUtils.isAdmin();
    boolean isInstitution = SecurityUtils.isInstitution();

    if (isAdmin) {
        // admin 可以传 userId 筛选指定用户，也可以不传查全部
    } else if (isInstitution) {
        // 机构用户过滤机构范围内的数据
        dto.setInstitutionId(SecurityUtils.getInstitutionId());
    } else {
        // 达人强制过滤自己的数据
        dto.setUserId(currentUserId);
    }
    return copyLibraryRepository.search(dto);
}
```

## 4.4 搜索与过滤逻辑

### 搜索条件

| 条件 | 字段 | 匹配方式 |
|------|------|---------|
| 关键词 | title, content | LIKE %keyword% |
| 分类 | category | 精确匹配 |
| 标签 | tags | LIKE %tag% |
| 状态 | status | 精确匹配 |
| 用户 | user_id | 精确匹配（admin 可选，institution 按机构过滤，talent 强制） |

### 排序规则

默认按 `create_time DESC` 排序，支持以下排序字段：
- `create_time DESC` — 最新创建
- `use_count DESC` — 最多使用
- `rating DESC` — 评分最高

### 分页

- 默认每页 20 条
- 最大每页 100 条
- 返回 `total`（总数）和 `list`（当页数据）

## 4.5 使用计数递增机制

### 触发场景

当用户在其他模块（如 shortvideo 创作、script 脚本）中引用某条文案时，调用此接口递增使用次数。

### 实现方式

```sql
-- 原子性递增，避免并发问题
UPDATE cp_library
SET use_count = use_count + 1,
    update_time = NOW()
WHERE id = ? AND deleted = 0;
```

### 接口调用示例

```
POST /api/v1/copy/library/increment-use-count?id=1
```

- 无需请求体，通过 Query Param 传入文案 ID
- 后端校验文案存在性（不存在返回 3501）
- 不校验用户权限（任何已登录用户均可触发）

## 4.6 字数自动计算

保存文案时，后端自动计算 `content` 的字数并写入 `word_count`：

```java
// 计算字数（中文按字符计，英文按单词计）
private int calculateWordCount(String content) {
    if (content == null || content.isEmpty()) return 0;
    // 去除 HTML 标签和多余空白
    String plain = content.replaceAll("<[^>]+>", "").trim();
    return plain.length();
}
```

字数统计规则：
- 每个中文字符计 1 个字
- 英文单词计 1 个词（按空格分隔）
- 标点符号不计入字数（可选，根据业务需求调整）
