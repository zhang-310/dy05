## 5.1 审批流程

### 5.1.1 完整审批流程

```
用户创建文案（cp_library.status = 0）
    │
    │ 用户主动提交审批
    ▼
POST /api/v1/copy/approval/save（仅传 copyId）
    │
    ▼
后端创建 cp_approval 记录：
  - copy_id = 文案 ID
  - approval_status = 2（待审核）
  - reviewer_id = null
  - comments = null
    │
    ▼
管理员在审批管理页查看待审核列表
    │
    ├─── 审批通过 ──────────────────────────────────────────────┐
    │    POST /api/v1/copy/approval/save                        │
    │    { id, approvalStatus: 1, comments: "审批通过" }         │
    │                                                           │
    │    后端处理：                                              │
    │      1. 更新 cp_approval.approval_status = 1              │
    │      2. 更新 cp_approval.reviewer_id = 当前管理员 ID       │
    │      3. 更新 cp_approval.approval_time = NOW()            │
    │      4. 同步更新 cp_library.status = 1（已审核）           │
    │                                                           ▼
    │                                                    文案状态变为已审核
    │
    └─── 审批拒绝 ──────────────────────────────────────────────┐
         POST /api/v1/copy/approval/save                        │
         { id, approvalStatus: 0, comments: "内容不符合规范" }   │
                                                                │
         后端处理：                                              │
           1. 更新 cp_approval.approval_status = 0              │
           2. 更新 cp_approval.reviewer_id = 当前管理员 ID       │
           3. 更新 cp_approval.approval_time = NOW()            │
           4. cp_library.status 保持 0（待审核）                 │
                                                                ▼
                                                    文案状态保持待审核
                                                    用户可修改后重新提交
```

## 5.2 审批状态机

```
                ┌──────────────────────────────────────┐
                │       cp_approval.approval_status     │
                └──────────────────────────────────────┘

  [用户提交审批]
        │
        ▼
  ┌──────────┐
  │  待审核   │  approval_status = 2
  │  (默认)  │
  └────┬─────┘
       │
  ┌────┴────┐
  │         │
  ▼         ▼
┌──────┐  ┌──────┐
│ 通过  │  │ 拒绝  │
│  =1  │  │  =0  │
└──────┘  └──────┘
  （终态）  （终态）
```

状态转换规则：

| 当前状态 | 触发动作 | 目标状态 | 联动操作 |
|---------|---------|---------|---------|
| 2（待审核） | admin 审批通过 | 1（通过） | cp_library.status → 1 |
| 2（待审核） | admin 审批拒绝 | 0（拒绝） | cp_library.status 不变（保持 0） |
| 1 或 0 | — | 不可变更 | 审批结果为终态，不可撤销 |

## 5.4 模板系统

### 5.4.1 模板分类

| 类型 | 创建者 | 可见范围 | 管理权限 |
|------|--------|---------|---------|
| 系统模板 | admin 用户 | 所有用户可见 | 仅 admin |
| 机构模板 | institution 用户 | 机构范围内可见 | 仅 institution 和 admin |
| 个人模板 | talent 用户 | 仅创建者可见 | 仅创建者和 admin |

判断逻辑：`user_id` 对应的用户角色为 admin，则该模板为系统模板；角色为 institution，则为机构模板；角色为 talent，则为个人模板。

---

### 5.4.2 模板 CRUD 流程

#### 创建模板

```
用户/管理员填写模板表单
    │
    ▼
POST /api/v1/copy/template/save（id 为空）
    │
    ▼
后端处理：
  1. 从 SecurityContext 获取当前用户 ID → user_id
  2. 设置 status = 1（有效）
  3. 插入 cp_template 记录
    │
    ▼
返回模板 ID
```

#### 更新模板

```
POST /api/v1/copy/template/save（id 不为空）
    │
    ▼
后端处理：
  1. 查询 cp_template，校验存在性（不存在 → 3505）
  2. 若模板为系统模板（创建者为 admin）且当前用户非 admin → 3507
  3. 若模板为个人模板且 user_id != 当前用户 → 3506
  4. 更新记录
```

#### 启用/禁用模板

```
POST /api/v1/copy/template/update-status?id=1&status=0
    │
    ▼
后端处理（仅 admin）：
  1. 查询 cp_template，校验存在性（不存在 → 3505）
  2. 更新 status 字段
```

### 5.4.3 使用模板创建文案

```
用户在模板列表选择模板
    │
    ▼
GET /api/v1/copy/template/get（获取模板详情）
    │
    ▼
前端将 template_content 填充到文案编辑器
    │
    ▼
用户修改内容（替换占位符，调整文案）
    │
    ▼
POST /api/v1/copy/library/save（保存为新文案）
    │
    ▼
新文案创建成功，status = 0（待审核）
```

模板内容占位符约定（建议）：
- `{产品名称}` — 产品名
- `{价格}` — 价格信息
- `{活动时间}` — 活动时间段
- `{品牌}` — 品牌名称

### 5.4.4 模板搜索逻辑

达人搜索模板时，后端返回：
1. 当前用户创建的所有模板（无论状态）
2. 所有系统级有效模板（status = 1）
3. 所属机构创建的有效模板（status = 1）

机构搜索模板时，后端返回：
1. 当前机构创建的所有模板（无论状态）
2. 所有系统级有效模板（status = 1）

管理员搜索模板时，后端返回全部模板（可按 userId、status 筛选）。

```java
// Service 层模板搜索逻辑示例
public PageResultVO<CopyTemplateVO> search(CopyTemplateSearchDTO dto) {
    Long currentUserId = SecurityUtils.getCurrentUserId();
    boolean isAdmin = SecurityUtils.isAdmin();
    boolean isInstitution = SecurityUtils.isInstitution();

    if (isAdmin) {
        // 管理员查看全部
    } else if (isInstitution) {
        // 机构：自己的模板 + 系统有效模板
        dto.setCurrentUserId(currentUserId);
        dto.setIncludeSystemTemplates(true);
    } else {
        // 达人：自己的模板 + 所属机构的有效模板 + 系统有效模板
        dto.setCurrentUserId(currentUserId);
        dto.setInstitutionId(SecurityUtils.getInstitutionId());
        dto.setIncludeSystemTemplates(true);
    }
    return copyTemplateRepository.search(dto);
}
```

对应 SQL 逻辑：
```sql
WHERE deleted = 0
  AND (
    user_id = #{currentUserId}
    OR (user_id IN (SELECT id FROM sys_user WHERE role = 'admin') AND status = 1)
    OR (user_id IN (SELECT id FROM sys_user WHERE role = 'institution' AND institution_id = #{institutionId}) AND status = 1)
  )
  AND (#{keyword} IS NULL OR template_name LIKE CONCAT('%', #{keyword}, '%'))
  AND (#{category} IS NULL OR category = #{category})
```
