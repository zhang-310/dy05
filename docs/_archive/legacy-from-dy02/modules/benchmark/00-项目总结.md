# 对标账号分析系统 - 项目总结

## 项目概述

**项目名称**：对标账号分析系统（Benchmark Analysis System）

**项目目标**：帮助用户分析竞品抖音账号的短视频内容，学习其优势并应用到自己的内容创作中。

**开发周期**：2026-04-08（1 天完成）

**代码统计**：
- 后端：54 个文件，6433 行代码
- 前端：8 个文件（API + 页面 + 类型）
- 文档：2 个文档（验证清单 + 使用指南）

## 核心功能

### 1. 账号管理
- ✅ 按关键词搜索抖音账号（粉丝数筛选）
- ✅ 按 URL 分析账号（直接输入账号链接）
- ✅ 账号信息自动抓取（名称、粉丝数、视频数、点赞数、简介、头像）
- ✅ 账号列表管理（查询、删除）

### 2. 视频采集
- ✅ 采集账号下的视频列表
- ✅ 按点赞数筛选（只采集高质量视频）
- ✅ 自动去重（避免重复采集）
- ✅ 视频信息完整（标题、封面、时长、互动数据、发布时间）

### 3. 深度分析（9 步流程）
- ✅ Step 1: 视频下载（yt-dlp）
- ✅ Step 2: BOS 上传（百度云存储）
- ✅ Step 3: 内容提取（ASR + OCR + API 并行）
- ✅ Step 4: 场景分析（FFmpeg 场景检测 + 关键帧）
- ✅ Step 5-9: AI 深度分析（12 个维度）

### 4. 多维度分析报告
- ✅ 文案内容（ASR/OCR/API/合并）
- ✅ 场景分析（场景数量、关键帧、描述）
- ✅ 创意分析（创意类型、钩子策略、内容结构、情绪曲线、节奏分析）
- ✅ 爆款因素（爆款因素、优势、弊端、可复制要素）
- ✅ 竞品对比（对比报告、差异化要点）
- ✅ AI 深度分析（综合分析、话术拆解、改进建议、目标受众）

### 5. Cookie 管理
- ✅ Cookie CRUD 操作
- ✅ Cookie 有效性验证
- ✅ 自动选择可用 Cookie
- ✅ 多账号管理

### 6. 批量操作
- ✅ 批量采集视频
- ✅ 批量分析视频
- ✅ 任务进度跟踪

## 数据库设计

### 5 张核心表

1. **benchmark_account** - 对标账号表
   - 存储账号基本信息
   - 支持按关键词搜索结果批量导入
   - 记录最后采集时间

2. **benchmark_video** - 对标视频表
   - 存储视频元数据
   - 记录分析状态（pending/processing/completed/failed）
   - 关联本地路径和 BOS URL

3. **benchmark_analysis** - 深度分析结果表
   - 存储多源文案（ASR、OCR、API、合并后）
   - 场景分析（关键帧、场景描述）
   - AI 分析结果（12 个维度）

4. **douyin_cookie** - Cookie 管理表
   - 存储抖音登录 Cookie
   - 支持多账号管理
   - 记录有效性和使用统计

5. **benchmark_task** - 分析任务表
   - 任务编排和进度跟踪
   - 支持批量分析和单个分析
   - 记录成功/失败统计

### 数据隔离

- 所有表包含 `owner_id` 字段
- Service 层强制过滤（JPA Specification）
- 用户只能访问自己的数据

### 逻辑删除

- 所有表包含 `deleted` 字段（默认 0）
- Entity 使用 `@SQLRestriction("deleted = 0")`
- 删除操作只更新 `deleted = 1`

## 9 步分析流程

### 流程图

```
视频采集 → 视频下载 → BOS 上传 → 内容提取（并行）→ 场景分析 → AI 深度分析 → 保存结果
                                    ↓
                            ASR + OCR + API
```

### 详细步骤

1. **视频采集**
   - 使用 Playwright 抓取账号视频列表
   - 按点赞数筛选符合条件的视频
   - 保存视频元数据到数据库

2. **视频下载**
   - 使用 yt-dlp 下载视频到本地
   - 更新 `local_video_path` 字段
   - 支持断点续传（可选）

3. **BOS 上传**
   - 读取本地视频文件
   - 上传到百度云 BOS
   - 更新 `bos_video_url` 字段

4. **内容提取（并行）**
   - **ASR 语音识别**：提取音频 → Whisper 识别 → 保存到 `transcript_text`
   - **OCR 字幕识别**：提取关键帧 → Tesseract 识别 → 保存到 `ocr_text`
   - **抖音 API 获取**：调用抖音 API → 获取视频描述 → 保存到 `api_description`
   - **内容合并**：合并上述内容 → 去重整理 → 保存到 `merged_content`

5. **场景分析**
   - 使用 FFmpeg 检测场景切换
   - 提取每个场景的关键帧
   - 生成场景描述
   - 保存到 `scene_count`、`key_frames_json`、`scene_description`

6. **创意分析**
   - 分析创意类型（情感共鸣、知识科普、娱乐搞笑、产品展示等）
   - 分析钩子策略（前 3 秒如何吸引注意力）
   - 分析内容结构（起承转合）
   - 分析情绪曲线（情绪变化节奏）
   - 分析节奏（镜头切换、语速等）

7. **爆款因素分析**
   - 分析爆款因素（话题性、共鸣点、实用性等）
   - 分析优势（做得好的地方）
   - 分析弊端（可以改进的地方）
   - 分析可复制要素（可以借鉴的技巧）

8. **竞品对比**
   - 对比分析竞品视频
   - 找出差异化要点

9. **AI 深度分析**
   - 调用 LLM API 进行综合分析
   - 生成话术拆解
   - 提供改进建议
   - 识别目标受众
   - 保存所有分析结果到数据库

## 技术亮点

### 1. 可选服务注入

**问题**：不同环境可能缺少某些服务（如 Playwright、FFmpeg、LLM API）

**解决方案**：
```java
@Autowired(required = false)
private VideoAnalysisService videoAnalysisService;

@Autowired(required = false)
private BosStorageService bosStorageService;

@Autowired(required = false)
private SceneDetectionService sceneDetectionService;

@Autowired(required = false)
private LlmClient llmClient;

@Autowired(required = false)
private DouyinApiClient douyinApiClient;
```

**优势**：
- 服务不可用时优雅降级
- 不影响其他功能正常运行
- 便于开发和测试

### 2. 并行内容提取

**问题**：ASR、OCR、API 三个步骤串行执行耗时长

**解决方案**：
```java
CompletableFuture<String> asrFuture = CompletableFuture.supplyAsync(() -> extractTranscript(localVideoPath));
CompletableFuture<String> ocrFuture = CompletableFuture.supplyAsync(() -> ocrService.recognizeTextFromVideo(localVideoPath));
CompletableFuture<String> apiFuture = CompletableFuture.supplyAsync(() -> fetchApiDescription(video.getVideoId()));

String transcriptText = asrFuture.join();
String ocrText = ocrFuture.join();
String apiDescription = apiFuture.join();
```

**优势**：
- 三个步骤并行执行
- 总耗时 = max(ASR, OCR, API)
- 提升 2-3 倍效率

### 3. 异步任务编排

**问题**：视频分析耗时长（2-5 分钟），不能阻塞主线程

**解决方案**：
```java
@Async
public void executeBatchAnalysisAsync(Long taskId, BatchAnalyzeVideosVO batchVO, Long ownerId) {
    // 异步执行批量分析
    // 更新任务进度
    // 记录成功/失败统计
}
```

**优势**：
- 不阻塞主线程
- 支持批量分析
- 实时进度更新

### 4. 动态查询

**问题**：查询条件动态变化，不想写大量 Repository 方法

**解决方案**：
```java
Specification<BenchmarkVideo> spec = (root, query, cb) -> {
    List<Predicate> predicates = new ArrayList<>();
    
    // 数据隔离
    predicates.add(cb.equal(root.get("ownerId"), ownerId));
    
    // 动态条件
    if (StringUtils.hasText(searchVO.getKeyword())) {
        predicates.add(cb.like(root.get("title"), "%" + searchVO.getKeyword() + "%"));
    }
    
    return cb.and(predicates.toArray(new Predicate[0]));
};

Page<BenchmarkVideo> page = videoRepository.findAll(spec, pageable);
```

**优势**：
- 灵活的查询条件组合
- 避免 SQL 注入
- 代码简洁易维护

### 5. 类型安全

**问题**：前后端类型不一致导致运行时错误

**解决方案**：
- 前端类型定义与后端 Entity/VO 完全对齐
- 字段名称一致（transcriptText ↔ transcript_text）
- 使用 TypeScript 严格模式
- 避免 `any` 类型

**优势**：
- 编译时发现类型错误
- IDE 自动补全和提示
- 重构更安全

## 错误处理

- 跳过场景分析
- 不影响其他分析维度

**LlmClient 不可用**：
- 跳过 AI 深度分析
- 保留 ASR/OCR/场景分析结果

## 已知限制

1. **Playwright 依赖**：账号搜索和视频采集依赖 Playwright，需要安装浏览器驱动
2. **Cookie 管理**：需要手动获取抖音 Cookie，暂不支持自动登录
3. **抖音 API**：需要 accessToken，当前实现暂不支持
4. **视频下载**：依赖 yt-dlp，需要确保网络可访问抖音
5. **AI 分析**：需要配置 LLM API Key，否则跳过 AI 分析
6. **BOS 存储**：需要配置百度云 BOS，否则跳过上传
