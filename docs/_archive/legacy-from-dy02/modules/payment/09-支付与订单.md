# W-09 支付与订单管理系统设计文档

## 模块概述

支付与订单管理模块是多租户 SaaS 平台的核心商业功能模块，提供完整的支付接入、订单管理、支付回调处理、退款管理和结算统计功能。模块集成支付宝和微信支付两大主流支付平台，支持 H5 支付和 JS 支付，覆盖从订单创建、支付发起、异步回调、状态更新到结算统计的完整流程。

**模块代码位置**: `/module/payment/`
**数据库前缀**: `pay_`
**错误码范围**: `4500-4599`

---

## 核心功能

### 1. 支付通道接入

- **支付宝 H5 支付**：集成支付宝开放平台 SDK，支持移动端 Web 跳转支付
- **微信 JS 支付**：集成微信支付 API，支持公众号 H5 支付和扫码支付
- **支付参数配置**：商户号、应用 ID、密钥等敏感信息存储在 Redis（加密）或配置中心
- **签名验证**：双向签名验证，防止中间人攻击和数据篡改

### 2. 订单 CRUD + 状态管理

```
订单状态流转：
待支付 (PENDING) → 已支付 (PAID) → 已发货 (SHIPPED) → 已完成 (COMPLETED)
                 ↓
            已取消 (CANCELLED)  或  退款中 (REFUNDING) → 已退款 (REFUNDED)
```

**订单字段**：
- `order_id` (PK) - 订单号（YYYYMMDDHHMMSS + 6位随机数）
- `user_id` (FK) - 用户 ID，数据隔离
- `product_id` - 产品 ID（可选，支持自定义商品）
- `amount` - 订单金额（分）
- `status` - 订单状态（枚举）
- `payment_method` - 支付方式（ALIPAY / WECHAT）
- `created_time` - 创建时间
- `paid_time` - 支付完成时间

### 3. 支付回调处理

- **异步通知处理**：接收支付宝/微信的服务端异步通知，更新订单状态
- **幂等校验**：通过业务流水号（trade_no）防重，同一笔支付重复通知只处理一次
- **超时重试**：支付方最多重试 N 次，应用端需要幂等处理
- **失败日志**：将失败的回调记录到审计表，便于人工排查

### 4. 退款管理

- **部分退款**：支持按金额退款，订单可退款金额 = 已支付金额 - 已退款金额
- **全额退款**：一次性退回全部支付金额
- **退款流程**：
  1. 用户或管理员发起退款申请
  2. 系统调用支付宝/微信退款 API
  3. 支付方异步通知退款完成
  4. 订单状态更新为已退款

### 5. 结算统计

- **日结报告**：每日自动统计当日订单金额、支付笔数、退款笔数
- **周结/月结**：按周/月聚合数据，用于财务对账
- **汇总数据**：总金额、平均订单金额、支付成功率等关键指标

## API 设计

### 订单管理

```
POST /api/v1/payment/order/create
描述：创建订单
请求体：
{
  "productId": 1,
  "amount": 9999,           // 单位：分
  "description": "年度会员",
  "notifyUrl": "https://example.com/notify"  // 回调地址
}
响应：
{
  "orderId": "20260306120000001234",
  "amount": 9999,
  "status": "PENDING"
}

POST /api/v1/payment/order/list
描述：查询用户订单列表（分页）
请求体：
{
  "page": 0,
  "rows": 20,
  "status": "PAID",          // 可选过滤
  "sortName": "createdTime",
  "sortOrder": "desc"
}
响应：
{
  "total": 100,
  "list": [...],
  "pageNum": 0,
  "pageSize": 20

描述：获取订单详情
请求体：
{
  "orderId": "20260306120000001234"
}

{
  "orderId": "20260306120000001234",

  "amount": 9999,
```

## 数据模型

### Order 表（pay_order）

```sql
CREATE TABLE pay_order (
  id BIGINT PRIMARY KEY,
  order_id VARCHAR(50) UNIQUE NOT NULL,
  user_id BIGINT NOT NULL,
  product_id BIGINT,
  amount BIGINT NOT NULL,                  -- 单位：分
  status VARCHAR(20) NOT NULL,             -- PENDING|PAID|SHIPPED|COMPLETED|CANCELLED|REFUNDING|REFUNDED
  payment_method VARCHAR(20),              -- ALIPAY|WECHAT
  trade_no VARCHAR(100),
  notify_url TEXT,
  created_time TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  paid_time TIMESTAMP,
  deleted INTEGER DEFAULT 0,
  FOREIGN KEY (user_id) REFERENCES auth_user(id)
);
```

### Payment 表（pay_payment）

```sql
CREATE TABLE pay_payment (
  id BIGINT PRIMARY KEY,
  order_id VARCHAR(50) NOT NULL,
  trade_no VARCHAR(100) UNIQUE,
  payment_method VARCHAR(20) NOT NULL,    -- ALIPAY|WECHAT
  amount BIGINT NOT NULL,
  status VARCHAR(20) NOT NULL,            -- INITIATED|SUCCESS|FAILED|EXPIRED
  expire_time TIMESTAMP,
  paid_time TIMESTAMP,
  created_time TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  deleted INTEGER DEFAULT 0,
  FOREIGN KEY (order_id) REFERENCES pay_order(order_id)
);
```

### Refund 表（pay_refund）

```sql
CREATE TABLE pay_refund (
  id BIGINT PRIMARY KEY,
  refund_id VARCHAR(50) UNIQUE NOT NULL,
  order_id VARCHAR(50) NOT NULL,
  refund_amount BIGINT NOT NULL,
  reason TEXT,
  status VARCHAR(20) NOT NULL,            -- APPLYING|PROCESSING|SUCCESS|FAILED
  refund_trade_no VARCHAR(100),
  created_time TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  completed_time TIMESTAMP,
  deleted INTEGER DEFAULT 0,
  FOREIGN KEY (order_id) REFERENCES pay_order(order_id)
);
```

### Settlement 表（pay_settlement）

```sql
CREATE TABLE pay_settlement (
  id BIGINT PRIMARY KEY,
  settlement_id VARCHAR(50) UNIQUE NOT NULL,
  period_type VARCHAR(20) NOT NULL,       -- DAILY|WEEKLY|MONTHLY
  period VARCHAR(20) NOT NULL,            -- 2026-03-06 或 2026-W10 或 2026-03
  total_orders INT NOT NULL,
  total_amount BIGINT NOT NULL,
  total_refunds BIGINT NOT NULL,
  success_orders INT NOT NULL,
  failure_orders INT NOT NULL,
  status VARCHAR(20) DEFAULT 'PENDING',   -- PENDING|SETTLED|VERIFIED
  created_time TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  settled_time TIMESTAMP,
  deleted INTEGER DEFAULT 0
);
```

## 验收清单

### 功能验收

- [ ] **订单创建**：可创建不同产品的订单，order_id 全局唯一
- [ ] **支付接入**：支付宝和微信支付都可正常发起，生成正确的支付链接
- [ ] **回调处理**：异步通知能够正确更新订单状态，幂等校验有效
- [ ] **退款申请**：支持部分退款和全额退款，可追踪退款状态
- [ ] **结算统计**：日结、周结、月结数据正确，关键指标准确

### 非功能验收

- [ ] **安全性**：支付参数加密存储，签名验证通过
- [ ] **幂等性**：重复回调不重复更新订单状态
- [ ] **性能**：订单查询（100W+ 记录）<500ms，settlement 计算耗时可控
- [ ] **可靠性**：支付失败、网络中断、数据库异常都有对应处理
- [ ] **合规性**：敏感数据（bank_card_no）脱敏，审计日志完整

### 代码质量

- [ ] `mvn compile` 通过，无告警
- [ ] 所有 Service 方法有单元测试（目标覆盖率 >70%）
- [ ] 错误码定义在 `ErrorCode.java`，前端 `error-codes.ts` 同步
- [ ] 数据隔离：所有查询都强制过滤 user_id，防止跨租户访问

## 风险与缓解

| 风险 | 缓解方案 |
|------|--------|
| 支付回调丢失 | 支付 API 查询接口 + 定时对账任务 |
| 订单状态不一致 | 数据库事务 + 操作日志 |
| 敏感数据泄露 | AES-256 加密存储、定期审计日志 |
| 并发订单创建重复 | 数据库唯一约束 order_id |

## 后续扩展

1. **分期付款**：支持按月分期，需要新增 Installment 表和对应服务
2. **多币种支持**：扩展 amount 字段，记录兑换汇率
3. **发票管理**：集成发票开具服务，与订单绑定
4. **联合营销**：优惠券、积分、折扣功能集成
5. **对账系统**：定时拉取支付宝/微信账单，自动对账报警
