# 数据库迁移管理

## 迁移策略

项目使用双轨迁移策略：

1. **模块 SQL 目录**（`sql/<模块>/`）：手动管理的建表和迁移脚本
2. **Flyway**（`src/main/resources/db/migration/`）：版本化自动迁移

## SQL 目录结构

```
sql/
├── init.sql              # 初始化入口
├── init-all.sql           # 全量初始化（包含所有模块）
├── init-docker.sql        # Docker 初始化
├── reset-and-demo.sql     # 重置 + 演示数据
│
├── <模块名>/              # 各模块 SQL
│   ├── schema.sql         #   建表语句（CREATE TABLE IF NOT EXISTS）
│   ├── sample-data.sql    #   示例/演示数据
│   ├── resource-data.sql  #   权限资源菜单数据
│   └── migration-*.sql    #   增量迁移脚本
│
├── migrations/            # 聚合迁移
│   ├── migrate-all.sql    #   所有迁移汇总
│   └── V001-V011          #   版本化迁移（与 Flyway 同步）
│
└── performance/
    └── indexes-optimization.sql  # 性能索引
```

## Flyway 迁移

配置：
```yaml
spring:
  flyway:
    enabled: ${FLYWAY_ENABLED:false}   # 默认关闭
    locations: classpath:db/migration
    baseline-on-migrate: true
    baseline-version: 0
```

脚本目录：`src/main/resources/db/migration/`

命名规则：`V<序号>__<描述>.sql`

> **权威来源**：以仓库内 `src/main/resources/db/migration/*.sql` 为准。

## 新增迁移流程

### 模块内迁移

1. 在 `sql/<模块>/` 下创建 `migration-<描述>.sql`
2. 内容必须幂等（使用 `IF NOT EXISTS`、`ADD COLUMN IF NOT EXISTS` 等）
3. 手动执行：

```bash
docker exec -it dy-postgres psql -U postgres -d douyin_operations -f migration-xxx.sql
```

### Flyway 迁移

1. 在 `src/main/resources/db/migration/` 创建 `V<下一版本>__<描述>.sql`
2. 启用 Flyway：`FLYWAY_ENABLED=true`
3. 启动应用自动执行

## 回滚

回滚脚本放在 `sql/migrations/rollback-v*.sql`，手动执行。

## 最佳实践

- 所有 DDL 使用 `IF NOT EXISTS` / `IF EXISTS` 保证幂等
- 大表 ALTER 使用 `CONCURRENTLY`（PostgreSQL 支持）
- 数据迁移先 DML 后 DDL
- 保留回滚脚本
- 生产环境先在 staging 测试
