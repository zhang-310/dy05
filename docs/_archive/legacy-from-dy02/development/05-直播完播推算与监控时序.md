# 直播「完播/留存」推算与监控时序（L-3 运营说明）

## 结论（给运营）

- 系统里的 **完播率/完成率** 在多数场次 **不是抖音官方后台的完播率**，而是根据 **本场监控采样** 或 **配置回退百分比** 推算的代理指标。
- **至少需要 2 条时序采样**（不同时间点的在线人数），才能用「峰值在线 → 末次在线」做 **留存型** 推算。来源可以是：
  - **`live_session_realtime_viewer_sample`**（GMV-02）：每次 `ingestDouyinLiveMetrics`（抖音采集 R-1）追加一行；`EffectivenessScoreServiceImpl` 优先使用该表 **≥2 条** 推算，`completionSource`=`monitor_derived`。
  - 或 **≥2 条 `live_monitor`**：`completionSource`=`retention_peak`。
- **`live_session_realtime_data` 是单场单行快照**，用于实时面板展示最新值；**持久时序**见上述 `*_viewer_sample` / `live_monitor`。

## 与代码的对应关系

- `EffectivenessScoreServiceImpl#deriveCompletionRate`：**优先** `live_session_realtime_viewer_sample` **≥2** 条时用峰值与末次观众数推算（`monitor_derived`）；否则 `live_monitor.size() >= 2` 推算（`retention_peak`）；否则使用 `completion-fallback-percent` 并标记降级（`configured_fallback`）。
- API 返回中的 **`completionHint`** / **`completionDegraded`** 会说明当前是 **实测推算** 还是 **配置回退**；降级文案中已互链本文档。
- 前端 **`EffectivenessCard`** / **`EffectivenessRanking`**：展示「完播率（代理）」与 **`completionHint`** 提示（L-3）；不将代理值表述为平台官方完播率。

## 如何改善数据质量（仍非平台官方口径）

1. 开启 **R-1** 抖音采集（`DOUYIN_COLLECTOR_ENABLED` 等），使监控数据持续写入。
2. 或通过业务侧 **增加手动/自动打点**，保证单场存在 **多条** `live_monitor` 记录。
