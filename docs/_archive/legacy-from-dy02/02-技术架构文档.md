## 五、请求链路

```
客户端请求
    ↓
Nginx              SSL 终结、静态资源、反向代理、限流
    ↓
TraceIdFilter      生成 traceId → MDC
    ↓
AuthTokenFilter    提取 Token → 验证 → 获取 userId/roleCode → 校验权限
    ↓
Controller         接收参数、调用 Service
    ↓
Service            业务逻辑、事务、缓存读写
    ↓
Repository (JPA)   数据库操作
    ↓
返回 RESTResult    status + message + data + traceId
```

鉴权白名单（无需 Token）：
- POST /api/v1/auth/login
- GET /api/v1/auth/captcha（图片验证码，img src 加载需 GET）
- POST /api/v1/auth/sms/send
- POST /api/v1/auth/forgot-password
- /api/v1/auth/oauth/*

## 八、缓存架构

采用 **Caffeine 本地缓存 + Redis 分布式缓存** 双层架构。

```
┌─────────────────────────────────────────────────────────────┐
│               Spring Boot 应用                                │
│                                                               │
│  ┌─────────── L1: Caffeine 本地缓存 ──────────────────┐     │
│  │ ConfigCache      (永不过期, 写时刷新)                │     │
│  │ ViolationCache   (TTL=5min, 自动重载)               │     │
│  │ ModelCache       (永不过期, 写时刷新)                │     │
│  └─────────────────────────────────────────────────────┘     │
│                          ↓ 未命中                             │
│  ┌─────────── L2: Redis 7 分布式缓存 ─────────────────┐     │
│  │ cache:kb:query:{hash}   知识检索结果  TTL=3600s     │     │
│  │ cache:kb:embed:{hash}   嵌入向量缓存  TTL=7200s     │     │
│  │ lock:kb:index:{id}      分布式索引锁  TTL=300s      │     │
│  │ cache:ai:request:{id}   幂等去重缓存  TTL=86400s    │     │
│  └─────────────────────────────────────────────────────┘     │
└─────────────────────────────────────────────────────────────┘
```

| 缓存层 | 场景 | 策略 | TTL | 刷新方式 |
|--------|------|------|-----|----------|
| L1 Caffeine | 系统配置 | Write-through | 无过期 | 修改时主动刷新 |
| L1 Caffeine | 公共违规词库 | TTL | 5 分钟 | 自动过期重载 |
| L1 Caffeine | AI 模型配置 | Write-through | 无过期 | 修改时主动刷新 |
| L2 Redis | 知识库检索 | TTL | 可配置（默认 1h） | 自动过期 |
| L2 Redis | 嵌入向量 | TTL | 2h | 自动过期 |
| L2 Redis | 分布式锁 | TTL | 5min | 自动释放 |
| L2 Redis | AI 幂等去重 | TTL | 24h | 自动过期 |

> **降级策略：** Redis 不可用时，自动降级为仅使用 Caffeine 本地缓存，AI 检索跳过缓存直接查询。

## 十、AI 推理架构

### 3 层 LLM 回退机制

```
请求发起
    ↓
Layer 1: Ollama 本地 (DeepSeek)     timeout=360s
    ↓ 失败（超时/500/503）
Layer 2: DeepSeek API (远程)         timeout=180s
    ↓ 失败
Layer 3: Ollama 本地 (Qwen3 备用)    timeout=180s
    ↓ 失败
抛出 AI_MODEL_UNAVAILABLE (4002)
```

**重试策略：**
- 每层内最多重试 1 次（指数退避）
- HTTP 429（限流）: 等待 Retry-After 后重试
- HTTP 502/503: 直接跳到下一层
- 整体可用性目标 ≥ 99.5%

### 任务-模型映射

每个 AI 任务（17 种，含 knowledge_embed 和 knowledge_rerank）可独立配置主模型 + 2 个备用模型，通过 `ai_task_model_config` 表管理，支持管理后台动态切换。

## 十一、容错与重试设计

### 熔断策略

当外部服务连续失败时，自动降级避免雪崩：

| 服务 | 熔断条件 | 降级行为 |
|------|----------|----------|
| AI 文本生成 | 3 层模型全部失败 | 返回 4002 错误，前端提示"AI 暂时不可用" |
| AI 多媒体生成 | 连续 3 次失败 | 标记分镜为 failed，允许用户手动重试 |
| Milvus 检索 | 连接超时 3 次 | 降级为纯 ES BM25 检索（精度下降但可用） |
| Elasticsearch | 连接超时 3 次 | 降级为纯 Milvus 语义检索（关键词召回丢失但可用） |
| Redis 缓存 | 连接失败 | 跳过缓存层，直接查询后端存储（性能下降但可用） |
| RabbitMQ | 连接失败 | 降级为 PostgreSQL ai_index_queue 表队列（吞吐下降但不丢消息） |
| 抖音 API | HTTP 429/503 | 等待 Retry-After 后重试，最多 2 次 |
| 对象存储 | 上传失败 | 返回 3702 错误，不重试（用户可手动重传） |

### 事务与部分失败策略

| 场景 | 策略 | 说明 |
|------|------|------|
| 配置批量保存 | 全量事务 | 同一分组的配置项在一个事务中保存，任一失败全部回滚 |
| 直播整场话术生成 | 尽力生成 | 逐产品生成，单个失败不回滚已成功的，标记为 failed 允许重试 |
| AI 视频分镜制作 | 逐分镜独立 | 每个分镜独立异步任务，互不影响，失败可单独重试 |
| 违规词批量导入 | 跳过重复 | 逐行导入，已存在的跳过，不影响其他行 |
| 知识库索引 | 队列重试 | 索引失败推入重试队列，最多 3 次，超过标记为 failed |

### 幂等性设计

- **AI 生成接口**：前端提交时携带 requestId（UUID），后端去重（24h 内同 requestId 直接返回缓存结果）
- **文件上传**：MD5 校验去重，相同文件不重复上传
- **配置保存**：基于 config_key 做 upsert，天然幂等

## 十二、安全设计

| 层面 | 措施 | 说明 |
|------|------|------|
| 传输安全 | HTTPS（Nginx SSL 终结） | 全站 HTTPS，HTTP 自动跳转 |
| 认证 | UUID Token + BCrypt 密码 | Token 存 localStorage，每次请求 Header 携带，服务端 Redis 校验 |
| 鉴权 | RBAC 到按钮/API 级 | AuthTokenFilter 拦截校验，白名单放行 |
| CORS | Nginx 配置 Access-Control-Allow-Origin | 限制允许的域名 |
| XSS | 前端输出转义 + CSP 头 | 用户输入不直接渲染 HTML |
| SQL 注入 | JPA 参数绑定 | 不拼接 SQL，Specification 参数化查询 |
| CSRF | 前后端分离 + Token 认证 | Spring Security 已禁用 CSRF（API 场景不需要） |
| 频率限制 | Nginx limit_req | 登录接口限制 10 次/分钟，API 接口限制 100 次/秒 |
| 敏感数据 | config_type=password 脱敏 | API Key / Secret 页面显示 ******，API 不返回原值 |
| 数据隔离 | owner_id 强制过滤 | Service 层强制添加 owner_id 条件 |
| 审计日志 | 关键操作记录 | 登录/配置修改/权限变更/数据删除 |

## 十五、监控与运维

| 项目 | 方案 | 说明 |
|------|------|------|
| 健康检查 | Spring Boot Actuator /actuator/health | 检查应用、PostgreSQL、Milvus、ES、Redis、RabbitMQ 连通性 |
| 基础设施监控 | /api/v1/ai/admin/infra/health | Milvus/ES/Redis/RabbitMQ 独立健康状态 + 延迟检测 |
| 日志 | Logback → 文件（按天轮转）+ 控制台 | traceId 贯穿每条日志 |
| API 调用统计 | sys_log_api 表 | 记录接口、耗时、Token 数（AI 调用） |
| 异常告警 | GlobalExceptionHandler 记录 + 邮件通知 | 关键异常触发邮件（可配置） |
| 备份 | pg_dump 定时备份 | 每天凌晨全量备份 PostgreSQL |
| AI 模型监控 | ai_call_log 表 | 记录模型调用成功率、响应时间、回退次数 |
| 进化引擎监控 | 管理后台看板 | 任务成功率、评分趋势、主题分布 |
| 缓存监控 | Redis INFO + 管理后台 | 缓存命中率、内存使用、Key 数量 |
| 消息队列监控 | RabbitMQ Management :15672 | 队列深度、消费速率、死信队列数量 |
| 向量库监控 | Milvus Attu + API | Collection 行数、索引状态、查询延迟 |
