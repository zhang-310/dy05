# 前端工作台全面升级分解

> 对应主方案：[`00-AI-三大专家系统全面升级计划`](./00-AI-三大专家系统全面升级计划.md)  
> 范围：AI、直播、短视频工作台及其共享组件  
> 目标：把前端从“功能入口集合”升级为“可解释、可执行、可回写”的专家工作台

---

## 一、前端升级总目标

前端本轮升级不是简单补页面，而是让三类专家系统真正“可被运营使用”：

1. 看得到建议依据
2. 看得懂风险和置信度
3. 能把建议转为执行动作
4. 能在执行后看到结果回流

---

## 二、工作台拆解

## F0：共享能力层

### 目标

先升级三类页面都会依赖的基础 UI 能力。

### 核心任务

1. **统一 Evidence 展示组件**
   显示引用文档、趋势来源、竞品来源、场次数据来源。
2. **统一 Decision Card**
   每条建议展示：
   结论、依据、置信度、风险、推荐动作。
3. **统一 Action Panel**
   把 AI 建议变成可执行操作。
4. **统一 Outcome Feedback 组件**
   显示采纳与否、执行结果、后续效果。
5. **统一 AI 调用状态**
   loading、fallback、tool-used、inferred、empirical、error。

### 重点目录

1. `front/src/components`
2. `front/src/components/base`
3. `front/src/components/ai`
4. `front/src/pages/components`

---

## F1：行业大脑工作台

### 目标

让 AI 页面从“多个孤立页”升级为统一的脑图式决策台。

### 当前问题

1. AI 页面数量多，但认知路径分散。
2. 行业洞察、趋势、图谱、诊断、策略、增长、风险没有统一入口。
3. 很多页只能看结果，不能看证据和动作。

### 需要重构的页面

1. `front/src/pages/ai/AiDashboardPage.tsx`
2. `front/src/pages/ai/IndustryBrainPage.tsx`
3. `front/src/pages/ai/IndustryBrainDiagnosisPage.tsx`
4. `front/src/pages/ai/KnowledgeSearchPage.tsx`
5. `front/src/pages/ai/KnowledgeBasePage.tsx`
6. `front/src/pages/ai/EvolutionPage.tsx`
7. `front/src/pages/ai/EvolutionTasksPage.tsx`
8. `front/src/pages/ai/EvolutionReviewPage.tsx`

### 改造方向

1. **统一入口**
   行业大脑首页聚合：
   趋势、竞品、图谱、诊断、增长、风险、可执行动作。
2. **统一证据展开**
   每条洞察都可展开引用来源。
3. **统一策略页**
   账号诊断 → 战略规划 → 增长路径 → 风险预警 → 执行动作。
4. **统一进化治理页**
   主题池、任务、报告、审核、ROI、引用率一体展示。
5. **统一图谱视图**
   从字符串上下文切到结构化子图可视化。

### 交付物

1. 行业大脑总览页
2. 证据展开侧栏
3. 策略执行工作区
4. 进化治理工作区

---

## F2：直播专家工作台

### 目标

让直播页面具备“准备、生成、实时、复盘、学习”完整闭环。

### 需要重构的页面与组件

1. `front/src/pages/live/LiveWorkbenchPage.tsx`
2. `front/src/pages/live/LiveRealtimePanelPage.tsx`
3. `front/src/pages/live/SessionWorkspacePage.tsx`
4. `front/src/pages/live/components/*`
5. `front/src/components/live/*`

### 改造方向

1. **准备态**
   展示本场知识引用、竞品差异化、库存风险、跨场次学习要点。
2. **生成态**
   每个槽位展示：
   prompt 来源、引用证据、A/B 变体、风险提示、时长校验。
3. **实时态**
   实时建议不只是列表，要可执行：
   下一槽、切商品、插入话术、价格重构、安抚弹幕。
4. **复盘态**
   展示本场高效段落、低效段落、观众异议、商品转化差异。
5. **学习态**
   展示本场回写到知识库/效果库的条目。

### 交付物

1. 直播场次准备面板
2. 直播生成证据面板
3. 实时行动建议面板
4. 复盘与学习面板

---

## F3：短视频专家工作台

### 目标

让短视频页面具备“选题、竞品、爆款拆解、脚本、日历、效果学习”的闭环。

### 需要重构的页面

1. `front/src/pages/shortvideo/ProjectsPage.tsx`
2. `front/src/pages/shortvideo/ShortVideoDashboardPage.tsx`
3. `front/src/pages/shortvideo/HotTopicPage.tsx`
4. `front/src/pages/shortvideo/CompetitorMonitorPage.tsx`
5. `front/src/pages/shortvideo/ContentCalendarPage.tsx`
6. `front/src/pages/shortvideo/ContentEffectPredictPage.tsx`
7. `front/src/pages/shortvideo/ViralVideoPage.tsx`
8. `front/src/pages/shortvideo/ScriptPlanningPage.tsx`

### 改造方向

1. **选题工作台**
   热点、竞品、账号阶段、平台窗口、历史效果融合排序。
2. **爆款拆解工作台**
   明确显示实证分析与推演分析的差别。
3. **脚本工作台**
   文案、脚本、标题、方案统一展示引用与建议依据。
4. **日历工作台**
   AI 推荐理由、预计收益、内容冲突、账号排期风险。
5. **效果工作台**
   显示哪些题材、标题、脚本结构对你有效。

### 交付物

1. 短视频策略总览页
2. 爆款拆解证据页
3. 内容日历智能排期页
4. 内容效果学习页

---

## F4：API 与状态管理对齐

### 目标

避免前端继续围绕 mock / 老接口 / 多套语义并存。

### 核心任务

1. 统一 AI / evolution API 语义
2. 统一 evidence 数据结构
3. 统一 suggestion action payload
4. 统一 score / confidence / evidenceLevel 字段
5. 统一页面 loading / fallback / partial-data 状态

### 重点目录

1. `front/src/api`
2. `front/src/types`
3. `front/src/stores`
4. `front/src/hooks`

---

## 三、实施顺序

1. 先做 `F0`
2. 再做 `F2` 与 `F3`
3. 最后重构 `F1`

原因：

1. 直播和短视频先吃到真实闭环收益
2. 行业大脑要建立在统一事实和统一组件之上

---

## 四、前端交付物

1. 统一 evidence 组件
2. 统一 action 执行组件
3. 行业大脑统一工作台
4. 直播专家统一工作台
5. 短视频专家统一工作台
6. 统一 AI 状态与回写展示能力
