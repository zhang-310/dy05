# 后端全面升级执行分解

> 对应主方案：[`00-AI-三大专家系统全面升级计划`](./00-AI-三大专家系统全面升级计划.md)  
> 范围：`module/ai`、`module/live`、`module/shortvideo`、共享基础设施  
> 目标：把当前后端从“AI 能力集合”升级为“统一事实层 + 真工具执行 + 三类专家闭环”

---

## 一、后端升级总目标

后端本轮不是继续加零散接口，而是完成 6 件事：

1. **打通 LLM tools 真执行**
2. **建立统一事实层和证据层**
3. **统一行业大脑服务边界**
4. **把直播专家做成真实闭环**
5. **把短视频专家做成真实闭环**
6. **把进化、实验、监控纳入统一治理**

---

## 二、工作流拆解

## B0：LLM Tool 执行层落地

### 目标

让 `LlmToolOrchestratorService` 真正可用，而不是设计存在、运行降级。

### 当前问题

1. `LlmClient.chatWithToolsStructured()` 仍是默认未实现。
2. `OpenAiCompatibleLlmClient` 没有提供 tools 请求/响应处理。
3. 已注册工具无法形成真实 Agent 行为。

### 核心改造

1. 在 `OpenAiCompatibleLlmClient` 中实现 `chatWithToolsStructured()`
2. 支持 OpenAI 兼容 `tool_calls`
3. 统一 tool message 序列化/反序列化
4. 统一 tool 错误重试与结构化输出
5. 工具执行日志与指标埋点统一写入

### 关键文件

1. `src/main/java/cn/gaifan/douyinOperations/module/ai/service/LlmClient.java`
2. `src/main/java/cn/gaifan/douyinOperations/module/ai/service/LlmToolOrchestratorService.java`
3. `src/main/java/cn/gaifan/douyinOperations/module/ai/service/LlmToolAugmentedChatHelper.java`
4. `src/main/java/cn/gaifan/douyinOperations/module/ai/service/impl/OpenAiCompatibleLlmClient.java`
5. `src/main/java/cn/gaifan/douyinOperations/module/ai/tool/impl/*`

### 实施任务

| 编号 | 任务 | 输出 |
|------|------|------|
| B0-1 | 实现 tools 请求体生成 | 支持 messages + tools + tool_choice |
| B0-2 | 实现 tools 响应解析 | 支持 assistant tool_calls / content 混合返回 |
| B0-3 | 工具执行结果 schema 校验 | 畸形输出自动重试 / 失败降级 |
| B0-4 | 工具执行日志 | 写入调用日志与工具执行日志 |
| B0-5 | 工具限流 / 鉴权 / 熔断 | 每用户、每工具、每场景策略 |

### 完成定义

1. `kb_rag_search` 能被模型真实调用
2. `live_session_stats` 能被模型真实调用
3. `competitor_analysis` 能被模型真实调用
4. 直播话术质检、Agent 场景能真实消费工具结果

## B1：统一事实层与证据层

### 目标

让行业大脑、直播、短视频共享同一套事实与证据。

### 核心原则

1. 建议必须能追溯事实来源
2. 不允许默认 `1L` 用户知识污染
3. 不允许“推演结果”伪装成“实证结果”

### 需要统一的事实域

1. 账号事实
2. 人设事实
3. 商品与产品脚本事实
4. 直播场次事实
5. 短视频内容事实
6. 趋势事实
7. 竞品事实
8. 知识文档事实
9. 引用与效果事实

### 关键文件

1. `src/main/java/cn/gaifan/douyinOperations/module/ai/service/impl/KnowledgeBaseServiceImpl.java`
2. `src/main/java/cn/gaifan/douyinOperations/module/ai/service/impl/KbHybridRetrieveServiceImpl.java`
3. `src/main/java/cn/gaifan/douyinOperations/module/ai/service/impl/brain/IndustryKnowledgeGraphServiceImpl.java`
4. `src/main/java/cn/gaifan/douyinOperations/module/ai/service/impl/CompetitorInsightServiceImpl.java`
5. `src/main/java/cn/gaifan/douyinOperations/module/ai/service/impl/HuashuGenerateServiceImpl.java`

### 实施任务

| 编号 | 任务 | 输出 |
|------|------|------|
| B1-1 | 去除默认 `1L` 回退 | 所有知识查询强制显式租户策略 |
| B1-2 | 建立 EvidenceTrace 记录模型 | 所有关键建议可追溯引用 |
| B1-3 | 统一检索 explain 输出 | 返回来源通道、RRF 分量、重排分、图谱增强信息 |
| B1-4 | 统一 evidence level | `empirical` / `derived` / `inferred` |
| B1-5 | 统一事实快照对象 | 直播 / 短视频 / 策略输入可复现 |

### 完成定义

1. 图谱、竞品、话术、知识检索不再默认读写平台用户 `1L`
2. 任何关键 AI 建议均可展示 evidence
3. 所有推演型结果显式标注 `inferred`

### 实施任务

| 编号 | 任务 | 输出 |
|------|------|------|
| B2-1 | 重写 `industry/insights` | 真实趋势 + 竞品 + 知识 + 账号表现汇总 |
| B2-2 | 诊断输入结构化 | 账号、短视频、直播、商品、趋势事实统一注入 |

## B3：直播专家闭环

### 目标

2. `LiveRealtimeSuggestionServiceImpl` 存在空弹幕意图分析。
3. 直播结果回写还不够统一。
4. Prompt 侧能力很强，但后续学习链还不够完整。

### 关键文件

7. `src/main/java/cn/gaifan/douyinOperations/module/live/service/impl/CrossSessionLearningServiceImpl.java`

### 实施任务

| 编号 | 任务 | 输出 |
|------|------|------|
| B3-1 | 重构效果评分口径 | 真实成交、真实互动、真实观看、真实时长 |

## B4：短视频专家闭环

### 目标

让短视频链路形成“选题、生成、分析、发布、学习”的完整专家系统。

### 当前问题

1. `ShortVideoAiServiceImpl` 大量场景还是 prompt 包装器。
2. `ViralDeepAnalyzeExecutor` 在依赖缺失时大量使用推演。
3. `DailyContentServiceImpl` 在非热点场景只返回“默认话题”。
4. `CompetitorMonitorServiceImpl` 仍偏向 LLM 概述。

### 关键文件

1. `src/main/java/cn/gaifan/douyinOperations/module/shortvideo/service/impl/ShortVideoAiServiceImpl.java`
2. `src/main/java/cn/gaifan/douyinOperations/module/shortvideo/service/impl/ViralDeepAnalyzeExecutor.java`

4. `src/main/java/cn/gaifan/douyinOperations/module/shortvideo/service/impl/CompetitorMonitorServiceImpl.java`
5. `src/main/java/cn/gaifan/douyinOperations/module/shortvideo/service/impl/ContentEffectPredictorImpl.java`
6. `src/main/java/cn/gaifan/douyinOperations/module/shortvideo/service/impl/ViralVideoServiceImpl.java`

### 实施任务

| 编号 | 任务 | 输出 |
|------|------|------|
| B4-1 | 扩充短视频生成上下文 | 接入知识、竞品、趋势、历史表现、平台策略 |
| B4-2 | 深度分析优先实证 | 默认启用下载 / ASR / 抽帧 / 场景识别 |
| B4-3 | 降级口径统一 | 无实证时显式 `inferred` |

| B4-6 | 效果预测接入真实数据 | 基于历史表现与赛道基线训练/回归 |

### 完成定义

1. 短视频生成不再只是 prompt 拼装

3. 题材、脚本、标题、发布表现形成学习闭环
