# 基础设施、可观测与发布升级分解

> 对应主方案：[`00-AI-三大专家系统全面升级计划`](./00-AI-三大专家系统全面升级计划.md)  
> 目标：让三类专家系统具备稳定运行、成本可控、可灰度、可审计的生产能力

---

## 一、升级目标

1. tools、模型、检索、进化、直播、短视频任务都可观测
2. 成本、配额、回退、失败、重试都能量化
3. 新策略和新工作流支持灰度、回滚、实验

---

## 二、基础设施升级项

## I0：模型与工具运行层

### 任务

1. 支持 OpenAI 兼容 tools
2. 模型失败时统一降级链
3. 工具失败时统一重试/跳过/告警
4. 每用户、每工具、每场景限流
5. 不同模型能力标签化：
   `chat` / `vision` / `tools` / `stream` / `cheap` / `premium`

---

## I1：检索与知识基础设施

### 任务

1. Milvus / ES / Redis / RabbitMQ 健康监控
2. 检索耗时拆分：
   rewrite / hyde / vector / es / rerank / graph / merge
3. 知识导入与索引失败告警
4. 多租户知识污染告警

---

## I2：任务与异步编排

### 任务

1. 直播生成队列监控
2. 进化任务队列监控
3. 短视频深度分析与视频生成队列监控
4. DLQ 与超时治理

---

## I3：成本与配额治理

### 任务

1. 统一配额管理后台
2. 调用成本按模型、场景、用户、租户统计
3. 高成本策略自动告警
4. 大模型与小模型路由策略可配置

---

## I4：灰度与发布

### 任务

1. Prompt 版本灰度
2. Strategy 版本灰度
3. Agent workflow 灰度
4. 实验开关与回滚策略

### 发布建议

1. 先灰度工具执行层
2. 再灰度行业大脑
3. 再灰度直播专家
4. 最后灰度短视频专家

---

## 三、指标体系

建议增加以下 Prometheus / Dashboard 指标：

1. `ai.llm_tool.orchestration.total`
2. `ai.llm_tool.orchestration.duration`
3. `ai.llm_tool.invocations`
4. `ai.kb.hybrid.retrieve.duration`
5. `ai.kb.hybrid.retrieve.fallback`
6. `ai.brain.recommendation.outcome`
7. `live.expert.suggestion.adoption`
8. `live.expert.score.confidence_low`
9. `shortvideo.expert.analysis.evidence_level`
10. `shortvideo.expert.plan.outcome`

---

## 四、验收标准

1. 所有核心 AI 能力都有 dashboard
2. 任何调用失败都能追溯模型、工具、上下文、trace
3. 新策略支持灰度与回滚
4. 成本与配额可按用户/场景查看
