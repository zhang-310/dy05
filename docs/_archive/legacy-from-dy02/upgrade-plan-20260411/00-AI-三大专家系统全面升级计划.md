## 一、结论先行

当前系统已经具备较强的知识库、混合检索、直播 prompt 编排、短视频生成、多媒体生成、进化引擎骨架，但距离“最强专家系统”仍有明显差距：

1. **缺少统一事实层**
   诊断、图谱、竞品、趋势、话术、短视频分析没有基于同一套真实业务事实做决策。
2. **缺少真实闭环**
   很多能力停留在 `prompt + LLM`，没有形成“生成 → 执行 → 数据回流 → 评分 → 策略更新”的稳定闭环。
3. **缺少工具真执行**
   Tool orchestration 架构已存在，但底层 `LlmClient` 还没有真正实现 tools 调用。
4. **缺少租户与上下文一致性**
   行业图谱、话术知识、竞品入库等链路仍存在默认用户 `1L` 的硬编码回退，削弱个性化和隔离。
5. **缺少专家级策略引擎**
   行业大脑中仍有 mock、模板、默认阈值、占位实现；短视频深度分析和直播评分里仍有推演/假设值。

因此，本轮升级的核心不是“再接更多模型”，而是：

1. 先做 **真实数据与工具闭环**
2. 再做 **行业/短视频/直播三类专家策略**
3. 最后做 **规模化、实验化、可观测化**

## 二、北极星目标

### 2.1 产品目标

1. AI 不再只是“生成器”，而是能基于真实业务数据给出可执行决策的专家系统。
2. 行业大脑、短视频、直播三条链路共用统一知识、统一反馈、统一指标。
3. 所有关键 AI 结果都能追踪来源、引用事实、执行结果和后续效果。

### 2.2 技术目标

1. 建立统一的 **AI 决策事实层**：
   账号、内容、商品、话术、直播场次、短视频表现、竞品、趋势、知识文档、引用记录、效果评分。
2. 建立统一的 **AI 工具执行层**：
   RAG、竞品、场次统计、趋势、商品搜索、策略解释、任务触发。
3. 建立统一的 **AI 反馈闭环层**：
   调用日志、引用日志、效果回写、质量评分、ROI、实验数据。

### 2.3 业务验收目标

1. 行业大脑输出不再包含 mock 市场数据和模板化建议。
2. 短视频深度分析默认具备实证能力，无法实证时明确降级并标注证据等级。
3. 直播评分与实时建议基于真实成交、真实弹幕、真实时长和真实执行结果。
4. 三类专家系统都支持“建议依据展示”与“执行后效果回写”。

## 三、当前基线判断

### 3.1 已有强项

1. **知识库基础设施成熟**
   `KnowledgeBaseServiceImpl` 已具备分块、MD5/SimHash 去重、Milvus + ES 混合检索、反馈加权、调用日志接入。
2. **高级检索骨架已经存在**
   `KbHybridRetrieveServiceImpl` 已接入 GraphRAG、HyDE、自适应权重、个性化排序、重排器。
3. **直播 prompt 编排最接近专家系统**
   `LiveScriptLlmUserPromptComposer` 已可注入 RAG、效果反馈、因果增强、竞品差异化、跨场次学习、A/B 变体。
4. **短视频生成面广**
   文案、脚本、标题、视频方案、爆款拆解、素材生成、数字人、视频供应商路由都已铺开。
5. **进化引擎有较完整编排骨架**
   `EvolveEngineServiceImpl` 已支持主题采样、上下文收集、报告评分、主题扩展、灰度审核、索引队列。

### 3.2 当前硬伤

1. `LlmToolOrchestratorService` 已存在，但 `LlmClient.chatWithToolsStructured()` 仍是默认未实现，工具编排未真正落地。
2. `IndustryBrainController` 的 `industry/insights` 直接返回写死市场数据。
3. `IndustryKnowledgeGraphServiceImpl`、`CompetitorInsightServiceImpl`、`HuashuGenerateServiceImpl` 仍存在默认用户 `1L` 回退。
4. `KnowledgeEvolutionController` / `EvolutionController` 同挂 `/api/v1/ai/evolution`，语义和实现分裂。
5. `KnowledgeQualityScoringServiceImpl`、`KnowledgeEvolutionServiceImpl` 含大量 placeholder。
6. `AiQuotaController` 管理端仍是 mock + TODO。
7. `EffectivenessScoreServiceImpl` 仍使用固定权重、假设转化率和固定完播率。
8. `LiveRealtimeSuggestionServiceImpl` 有意图分析调用空弹幕列表的问题。
9. `VideoAnalysisService` 的视觉分析仍是占位返回，`ViralDeepAnalyzeExecutor` 大量场景仍是“推演”而非“实证”。
10. `ShortVideoAiServiceImpl` 多数能力仍是 prompt 包装器，缺少真实效果反馈和知识/竞品/素材联动。

## 四、总体升级原则

### 4.1 先修真，再做强

优先级顺序必须是：

1. 去 mock / 去占位 / 去默认用户污染
2. 打通 tools 真执行
3. 打通数据回流与质量评分
4. 再增强专家策略

### 4.2 统一事实来源

三类专家系统必须共用以下事实层：

1. 账号画像
2. 人设画像
3. 商品与产品脚本
4. 直播场次与实时/复盘数据
5. 短视频内容、素材、爆款样本、成片表现
6. 竞品情报
7. 趋势数据
8. 知识库文档与引用记录
9. AI 调用日志与效果回写

### 4.3 所有 AI 输出必须可解释

任何关键建议都应尽量给出：

1. 引用依据
2. 使用数据
3. 风险提示
4. 置信度 / 证据等级
5. 后续验证方式

### 4.4 三条链路统一升级，不各自为战

1. 行业大脑负责“认知、诊断、策略”
2. 直播专家负责“场次策略、话术生成、实时干预、复盘回流”
3. 短视频专家负责“选题、竞品、脚本、实证分析、日历排期、效果学习”

## 七、分阶段升级计划

## Phase 0：纠偏与去假闭环

### 目标

把所有直接影响“专家真实性”的问题先处理掉。

### 任务

1. **实现真正的 tools 调用**
   在 `OpenAiCompatibleLlmClient` 中落地 `chatWithToolsStructured()`，完成 OpenAI 兼容工具调用协议解析。
2. **清理默认用户 `1L` 硬编码**
   去掉图谱查询、话术生成、竞品入库中默认用户知识库回退；改为显式租户策略。
3. **去除行业大脑 mock**
   `industry/insights` 改为真实数据汇总接口，至少由趋势、竞品、知识库命中、账号表现拼出。
4. **修复 AI 管理端伪接口**
   把 `AiQuotaController` 从 mock 改成真实配额查询/修改/历史。
5. **统一进化控制面**
   明确 `KnowledgeEvolutionController` 与 `EvolutionController` 的边界，消除同路径语义重叠。
6. **清理 placeholder 服务**
   `KnowledgeQualityScoringServiceImpl`、`KnowledgeEvolutionServiceImpl` 中假数据全部替换为真实聚合或明确下线。

### 验收标准

1. tools 编排链路在支持 tools 的模型上可实际执行工具并返回结果。
2. 不再存在生产链路默认读写 `1L` 用户知识库。
3. 行业大脑不再返回写死市场数据。
4. 配额管理页数据来自真实表与真实服务。
5. 进化接口边界明确，不再存在重复语义控制器。

---

## Phase 1：统一事实层与反馈闭环

### 目标

构建三类专家共用的真实业务事实层和回流机制。

### 任务

1. **统一 AI 事实域模型**
   定义统一的内容、场次、商品、账号、趋势、竞品、知识引用、效果结果模型。
2. **统一引用与回写**
   RAG 检索、tool 检索、直播生成、短视频生成都写引用记录和效果归因。
3. **统一质量评分**
   文档、话术、短视频分析结果使用同一套质量维度，但允许领域定制权重。
4. **统一 ROI 与实验**
   AI 调用、知识引用、效果提升、人工采纳、失败率、回退率进入同一监控面。
5. **统一 evidence 标识**
   所有短视频深度分析、行业推理、直播建议都明确区分：
   `empirical`、`derived`、`inferred`。

### 验收标准

1. 关键 AI 输出都能查到“用过哪些数据/知识/工具”。
2. 直播与短视频均支持“生成结果 → 表现数据 → 质量更新”。
3. 行业大脑、短视频、直播三端共享核心指标定义。

---

## Phase 2：最强行业大脑

### 目标

把 Brain 从“多服务集合”升级为统一决策大脑。

### 任务

1. **统一战略诊断层**
   整合 `AccountDiagnosisService`、`StrategicPlanningService`、`GrowthPathService`、`RiskWarningService`。
2. **重构图谱与 GraphRAG**
   图谱查询必须使用当前用户上下文；补齐实体消歧、多跳关系、来源与新鲜度字段。
3. **建立行业情报层**
   趋势、竞品、爆款拆解、直播复盘、知识文档进入统一行业情报仓。
4. **建立策略解释器**
   新增 strategy explain / evidence trace / what-if 分析工具，不再只返回模板说明。
5. **把协同与增长路径去模板化**
   `FiveHostsSynergyServiceImpl`、`GrowthPathServiceImpl` 改为真实配置 + 真实数据驱动。
6. **建立脑图式前端工作台**
   前端增加策略总览、证据展开、风险面板、机会池、执行建议看板。

### 验收标准

1. 任意脑内建议都能展开来源与依据。
2. 增长路径和战略规划不再依赖默认三阶段模板。
3. 图谱查询结果与当前账号/团队上下文一致。
4. 行业洞察页可以展示真实趋势、竞品、知识来源和推荐动作。

---

## Phase 3：最强直播运营专家

### 目标

让直播链路从“生成话术”升级为“能准备、能干预、能复盘、能学习”的闭环专家。

### 任务

1. **修正效果评分**
   `EffectivenessScoreServiceImpl` 改为真实成交、真实观看、真实互动、真实完播口径，评分权重配置化。
2. **修正实时建议链**
   `LiveRealtimeSuggestionServiceImpl` 必须吃到真实弹幕窗口、真实意图分析结果、真实库存和转化走势。
3. **强化直播 Prompt 编排**
   在现有 RAG / 竞品 / 因果 / 跨场次学习基础上，增加：
   场次目标、库存风险、价格策略、近场失效话术、竞品压制点。
4. **真正做实时干预**
   让建议不只是文本，而是能定位到：
   下一槽位、插入脚本类型、改价格话术、安抚弹幕、切商品。
5. **复盘学习自动回写**
   场次结束后自动把优质段落、不佳段落、弹幕异议、转化低点写回知识库与效果库。
6. **Prompt 实验平台化**
   把 A/B 变体、引用效果、策略效果统一纳入实验分析。

### 验收标准

1. 直播评分不再使用假设值。
2. 实时建议命中率和采纳率可追踪。
3. 场次结束后自动生成“可学习知识”并回写。
4. 直播专家可以基于真实弹幕和成交变化给出下一动作。

---

## Phase 4：最强短视频运营专家

### 目标

让短视频链路从“文案/脚本生成器”升级为“选题 + 竞品 + 实证分析 + 日历 + 效果学习”的完整专家系统。

### 任务

1. **升级短视频生成上下文**
   `ShortVideoAiServiceImpl` 接入知识库、竞品、历史表现、目标平台、日历计划、素材偏好。
2. **让爆款深度分析尽量实证化**
   默认启用下载 / ASR / 抽帧 / 场景检测；仅在依赖不可用时才降级为推演。
3. **建立内容效果学习**
   文案、标题、脚本、分镜、发布结果进入可学习样本库。
4. **升级日更与内容日历**
   `DailyContentServiceImpl` 不再只有“默认话题”，而是联动热点、竞品、账号阶段、平台窗口、库存/营销周期。
5. **升级竞品能力**
   `CompetitorMonitorServiceImpl` 从 prompt 生成摘要升级为结构化竞品知识库。
6. **做选题与效果预测**
   内容效果预测器接入真实历史表现和行业基线，而不是存根。

### 验收标准

1. 短视频 AI 生成时能看到引用的竞品、知识、热点、历史表现。
2. 深度分析报告明确标出哪些来自实证，哪些来自推演。
3. 内容日历不再依赖默认话题，可按赛道、账号阶段、趋势窗口自动给出计划。
4. 标题/脚本/题材的效果能进入持续学习。

---

## Phase 5：多 Agent 与自治工作流升级

### 目标

把当前 toy 级多 Agent 编排升级为真实业务工作流。

### 任务

1. **扩展 Agent 角色**
   从当前 4 个角色扩展到：
   数据分析、竞品策略、内容策划、风险审查、促单策略、节奏控制、复盘总结等。
2. **输入改为结构化事实**
   不再只传一句 `直播场次ID`，而是注入场次结构化上下文。
3. **接入工具层**
   Agent 可调用知识库、场次统计、竞品分析、趋势、商品信息、历史效果。
4. **结果校验与恢复**
   输出必须通过 schema 校验；失败可重试、回退、局部跳过。
5. **工作流持久化**
   将每个节点的输入、输出、耗时、错误、重试、引用都持久化。

### 验收标准

1. 多 Agent 结果不再是“空上下文文字游戏”。
2. 每个 Agent 节点都可以追踪事实来源和执行结果。
3. 工作流中任一节点失败不影响整体可恢复性。

---

## Phase 6：可观测、风控、成本、治理

### 目标

支撑系统从“能用”走向“长期可运营”。

### 任务

1. **统一 AI 调用看板**
   成本、配额、调用量、成功率、重试率、降级率、工具命中率、引用率。
2. **统一风险治理**
   风险预警指标改为真实精确率/召回率口径，不再用违规占比反推 accuracy。
3. **统一实验与版本治理**
   Prompt、模型、Agent、策略全部可版本化、可灰度、可回滚。
4. **统一租户隔离与权限**
   平台知识、租户知识、账号知识、场次知识必须明确边界。
5. **统一验收基线**
   三类专家系统都需要：
   Golden path、回归集、指标基线、灰度发布规则。

### 验收标准

1. AI 能力的成本、成功率和效果提升都可量化。
2. 线上任何高风险建议都能回溯来源、版本与执行链路。
3. 多租户知识污染问题彻底解决。

## 十、实施注意事项

1. **不要继续堆新接口再补实现**
   先清 placeholder，再扩功能。
2. **不要让 AI 直读不可信数据**
   所有策略链路优先接统一事实层。
3. **不要继续使用系统默认用户知识库兜底**
   这会污染专家结论。
4. **不要把“生成成功”当成“专家成功”**
   专家系统的真正结果是业务效果与学习闭环。
5. **不要让前端页面和后端事实层继续漂移**
   每个升级阶段都要同步 API、页面、指标定义。
