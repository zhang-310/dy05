# 模块12：支付 & 订阅 — 商业化引擎

> 文档版本：v3.0 | 更新：2026-03-30 | 对齐 API：paymentApi（subscriptionCurrent/subscriptionUpgrade/quotaUsage/quotaAlertConfig/planList/list/detail/create/confirmPayment/refundCreate/refundListByOrder/refundApprove/refundReject）+ 新增：配额耗尽预测 / 发票管理 / 升级转化漏斗 / 降级保护 / 账单下载

## 一、产品目标

提供清晰的套餐订阅管理和配额使用展示，让用户实时了解 AI 调用余量、存储空间、场次数量等资源消耗，促进续费和升级。

**成功指标**：配额预警触达率 ≥ 90%；看到配额页后升级转化率 ≥ 15%

**产品远景**

| 阶段 | 能力 |
|------|------|
| 现阶段 | 套餐展示 + 配额进度 + 退款管理 |
| 6个月 | 智能续费提醒（AI预测耗尽时间）+ 自动升级推荐 |
| 1年 | 按用量计费（Pay-as-you-go）+ 企业多席位管理 |

**数据**：`paymentApi.subscriptionCurrent()`

**配额耗尽预测算法**（前端本地计算）：
- 取 `quotaUsage().aiCallUsed`（已用量）和 `quotaUsage().aiCallLimit`（上限）
- 取近 7 天日均消耗速率：`dailyRate = usedLast7d / 7`
- 预计剩余天数：`daysLeft = (limit - used) / dailyRate`
- 若 `daysLeft < 30` → 显示橙色预测警示框

**套餐数据**：`paymentApi.planList()` → 动态渲染套餐列，不硬编码

**当前套餐高亮**：当前套餐列顶部显示「✅ 当前套餐」绿色 Banner，按钮置灰为「已订阅」。

**推荐标签**：根据当前使用量自动标注「推荐升级」标签（超过当前套餐 80% 配额时触发）。

**升级流程**：
```
点击「升级」
  ↓
升级确认弹窗
  ├── 差价明细：当前剩余价值 ¥XXX + 新套餐费用
  ├── 升级后立即生效的功能清单
  ├── 支付方式：支付宝 / 微信 / 银行转账
  └── [确认支付]
         ↓
  paymentApi.create({ planId, payType }) → 返回 orderNo + payUrl
         ↓
  paymentApi.confirmPayment(orderNo) 轮询 3s × 10次
         ↓
  成功 → Toast「升级成功！」→ 刷新当前套餐
  超时 → 「支付确认中，请稍候...」+ 手动刷新按钮
```

**降级保护**：订阅到期未续费时，不立即删除数据，进入 14 天宽限期（只读模式，显示橙色 Banner 提示）。

## 七、边界状态与错误处理

| 状态 | UI 表现 |
|------|--------|
| 套餐已到期（宽限期内）| 橙色顶部 Banner：「订阅已到期，您有 14 天宽限期，数据只读」|
| 宽限期已过 | 红色 Banner：「账号已冻结，请续费后恢复使用」|
| 配额 100% 耗尽 | 该维度进度条变红，功能入口显示灰色遮罩 + 「配额不足，请升级」|
| 支付超时（轮询 10 次未确认）| 「支付确认中，请稍候...」+ 「手动刷新」按钮 |
| 退款申请超出 7 天 | 申请退款按钮置灰 + Tooltip「仅支持 7 天内订单退款」|
| 网络错误 | Skeleton + 「重试」按钮 |
| 发票已作废 | 下载按钮置灰 + Tooltip「该发票已作废」|
