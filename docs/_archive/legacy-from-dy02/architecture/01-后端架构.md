## 模块分层约定

每个业务模块严格遵循以下分层：

```
module/<模块名>/
├── config/          # 模块专属配置、定时任务、消息监听
├── controller/      # REST 接口（主体 @PostMapping，部分 GET/PUT/DELETE）
├── entity/          # JPA 实体（@Entity + @SQLRestriction("deleted = 0")）
├── repository/      # JpaRepository + JpaSpecificationExecutor
├── service/         # 服务接口
├── service/impl/    # 服务实现（JPA Specification 动态查询）
└── vo/              # 值对象
    ├── XxxSearchVO  #   查询参数（extends BasicQueryDto）
    ├── XxxSaveVO    #   保存入参（@Valid 校验）
    └── XxxVO        #   返回值
```

## API 规范

| 规则 | 说明 |
|------|------|
| HTTP 方法 | **主体 POST**（含查询），例外见下方 |
| 路径模式 | `/api/v1/<模块>/<资源>/<动作>` |
| 认证 | `Authorization: Bearer <token>`，AuthTokenFilter 校验 |
| 响应格式 | `RESTResult<T>` → `{ status: 200, message, data, traceId, timestamp }` |
| 分页参数 | `page`（0-indexed）、`rows`（1-1000，默认 30）、`sortName`、`sortOrder` |
| traceId | MDC 自动注入，随响应返回 |

### HTTP 方法使用情况

| 方法 | 数量 | 使用场景 |
|------|------|----------|
| POST | 绝大多数 | 业务 CRUD、SSE 流式（10 处） |
| GET | 11 处 | SSE EventSource 流（6 处）、OAuth 回调（3 处）、Prometheus（1 处）、Webhook 校验（1 处） |
| PUT | 2 处 | 话术激活/更新 |
| DELETE | 7 处 | 知识库/进化/话术/风格/归因删除 |

详细清单见 [`docs/adr/001-统一POST接口.md`](../adr/001-统一POST接口.md) 和 [`docs/api/01-前后端对齐问题清单.md`](../api/01-前后端对齐问题清单.md)。

## 数据库规范

| 规则 | 实现 |
|------|------|
| 逻辑删除 | `deleted INTEGER DEFAULT 0` + `@SQLRestriction("deleted = 0")` |
| 数据隔离 | `owner_id BIGINT` + Service 层强制过滤 |
| 时间维护 | `@PrePersist` / `@PreUpdate` 自动设置 `create_time` / `update_time` |
| DDL 策略 | `ddl-auto: validate`，先写 SQL 再写 Entity |
| 跨模块关联 | 不使用数据库外键，应用层校验 |

## SSE 流式接口

项目中 SSE 有两种实现方式：

| 方式 | HTTP 方法 | 前端实现 | 数量 | 使用场景 |
|------|-----------|----------|------|----------|
| ssePost | POST | `utils/sse-client.ts`（fetch + ReadableStream） | 10 | 话术生成、Agent 对话、批量生成 |
| EventSource | GET | 浏览器原生 API | 6 | 直播实时面板、监控流、短视频 AI 生成 |

路径需含 `-sse`、`chat-stream`、`-stream` 或 `/stream/` 关键字，否则 `OperationLogFilter` 的 `ContentCachingResponseWrapper` 会缓冲全响应。`SseStreamingFilter` 对匹配路径跳过缓冲包装。
