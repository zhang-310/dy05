### 1.1 工具编排（已接入业务）

| 组件 | 说明 |
|------|------|
| `LlmClient.chatWithToolsStructured` | 支持 `assistant` 带 `tool_calls`、`tool` 角色回传结果（多轮） |
| `LlmToolOrchestratorService` | 将 `tools` JSON 注册表与多轮 HTTP 调用串起来，`app.ai.llm-tools.max-rounds` 限制轮次 |
| `LlmRegisteredTool` | 扩展点：实现接口并 `@Component` 即可注册 |
| `KnowledgeBaseRagLlmTool` | 内置 `kb_rag_search` → `KnowledgeBaseService.hybridSearchAllKbs`，并打点评检索 |
| `LlmToolAugmentedChatHelper` | 商品话术 AI 修改、直播整场话术优化：在支持 tools 的模型上优先走编排，失败回退原 `chatWithFallback` |
| `AgentServiceImpl.chatWithAgent` | 非流式对话走工具编排（需 `app.agent.llm-tools.enabled`；`agent.model_config` 可设 `"llmTools": false` 关闭） |
| 流式 `chatWithAgentStream` / SSE | 仍走原 `ModelChatStreamService`（未接多轮 tools） |

## 3. 视频生成（arkvideo）

- 实现类：`VolcengineArkVideoProvider`，`name()` = **`arkvideo`**。  
- HTTP（与控制台地域一致）：`POST {base}/contents/generations/tasks`，`GET {base}/contents/generations/tasks/{id}` 轮询。  
- 请求体：`model` + `content` 数组（`text` 含 `--ratio` / `--dur` 提示后缀 + `image_url` 首帧；若传入尾帧 URL 则再追加一条 `image_url`）。  
- `supportsEndFrame()=true`；`IntelligentModelRouter` 在存在尾帧时仅选用支持首尾帧的 Provider（如 arkvideo、Luma、MiniMax、Seedance2 等），避免无效调用。  
- 需在控制台开通 **视频类** 接入点；仅 `ARK_VIDEO_ENABLED=true` 且配置了 `ARK_VIDEO_MODEL` 后 `isConfigured()` 为 true，路由才会选中。

## 3.1 图片生成（文生图 / 图生图）

- 实现类：`VolcengineArkImageService`（非独立路由名，由 `ImageGenerationServiceImpl` 调用）。  
- 与视频同源 **tasks** API；`content` 为 `text` + 可选参考图 `image_url`（图生图）。  
- 默认 **优先方舟**（`app.ai.image.try-volcengine-ark-first=true`）；方舟未启用、未配置 `ARK_IMAGE_MODEL` 或调用失败时 **自动回退** 可灵 / 本地 Stable Diffusion（与原行为一致）。  
- 控制台需 **图片类** 推理接入点（与视频 ep 区分）。

## 4. 向量化与 Milvus

1. 切换 `AI_EMBEDDING_PROVIDER=volcengine` 后，请求走方舟 **`/embeddings`**（OpenAI 形态：`model` + `input`，响应 `data[0].embedding`）。  
2. **系统固定 1024 维**；须选用输出 1024 维的方舟向量 Endpoint。与现有 Milvus 集合不一致时，需 **重建集合并全量重嵌入**。  
3. 代码在向量长度 ≠ 1024 时 **打 WARN**，不自动截断/填充。

## 5. 推理审计表（数据回流底座）

- 表：`ai_inference_audit`（**V066** / `sql/ai/migration-ai-inference-audit.sql`）。  
- 开关：`app.ai.inference-audit.enabled=true`（否则不注册 `AiInferenceAuditServiceImpl`）。  
- 字段：`provider`、`capability`（`chat` / `tools`）、`model_ref`、`input_chars`、`latency_ms`、`ok`、`error_message` 等；**不落全文 prompt**。  
- 写入点：`OpenAiCompatibleLlmClient` 的 HTTP Chat、`chatWithTools`（Ollama Spring 路径亦会写 chat 审计）。

## 6. 进化模型顺序（EvolveModelOrderUtil）

有序链：**DeepSeek 思考 → DeepSeek Chat → Claude → 火山方舟**。  
全未命中时回退：**ollama → deepseek → volcengine → 580ai**。  
与 `app.ai.evolution.allowed-model-providers` 中的 `volcengine`、`ark` 配合使用。

## 7. 注意事项

1. **Endpoint 与地域**：Host 须与控制台一致，否则易 403/404。  
2. **流式**：当前 `OpenAiCompatibleLlmClient` 非流式 `stream=false`；长 SSE 仍走现有业务封装。  
3. **429 / 计费**：沿用 LLM 429 退避与 `ai.quota`。  
4. **合规**：美妆带货仍走行业大脑与合规词，与供应商无关。
