## 二、发现的缺口与风险点

### 🔴 必须修复（Critical）

#### C-1. `migrate-all.sql` 缺失 LF-01~04 引用

**现状**: `sql/migrations/migrate-all.sql` 只引用了 LF-05 的 `migration-viral-deep-analysis.sql`，LF-01~04 的 4 个 SQL 文件未注册。

**影响**: Flyway（V101-V105）会自动执行，但手动执行 `migrate-all.sql` 的场景（初始化新环境/灾备恢复）会遗漏 4 个迁移。

**修复**: 在 `migrate-all.sql` 中 LF-05 之前插入 LF-01~04 的 `\i` 引用。

#### C-2. `deepAnalyze` 同步阻塞风险

**现状**: `ViralVideoDeepAnalysisServiceImpl.deepAnalyze()` 是同步方法。下载视频 + ASR 转写 + 抽帧 + 多模态分析 + LLM 拆解，全链路可能耗时 30-120 秒。

**影响**: 前端 POST 请求可能超时；Tomcat 线程被长时间占用。

**修复方案**: 改为异步任务模式 — 提交后立即返回 taskId，前端轮询 `/deep-analyze/status/{taskId}`。

#### C-3. 视频文件临时存储无清理调度

**现状**: `VideoAnalysisService.downloadVideo()` 下载视频到临时目录，但无定时清理 Scheduler。

**影响**: 高频深度分析会积累大量临时视频文件，磁盘空间耗尽。

**修复**: 增加 `@Scheduled` 清理任务，删除 24 小时前的临时文件。

### 🟡 建议改进（Important）

#### I-1. 人设融合 `generatePersonaFusedScript` 缺少合规检查

**现状**: 生成的二创脚本直接返回，未经过 `ViolationCheckService.checkScript()` 合规检测。

**影响**: 主播使用未检查的脚本直接开播/发布，可能触犯广告法或平台规则。

**方案**: 在生成后自动调用合规检查，返回结果中附带 `complianceWarnings`。

#### I-2. `autoGenerate` 日历规划过于简单

**现状**: `SvContentCalendarServiceImpl.autoGenerate()` 使用固定 9 类型轮转，不考虑：
- 人设历史内容类型分布
- 产品推广节奏
- 节假日/大促日历
- 爆款二创待办积压

**方案**: 二期接入 LLM 策略推荐，输入人设+历史+热点，输出最优排布。

#### I-3. 深度分析结果缺少持久化到独立字段

**现状**: `deepAnalyze()` 的 LLM 综合分析结果存入 `analysis_result` 字段（覆盖旧的文本分析），`transcript`/`scene_descriptions`/`remake_variable_table` 三个新字段仅在 deepAnalyze 内部赋值但**未在 `deepAnalyze()` 方法末尾 `save`**——只保存了 `analysis_result`。

**影响**: ASR 文案和变量表未持久化到独立字段，前端展示依赖解析 `analysis_result` JSON。

**修复**: 在 Step 3 LLM 完成后，同时 `viral.setTranscript(transcript)`, `viral.setSceneDescriptions(sceneDescriptions)`, `viral.setRemakeVariableTable(extractedTable)`, `viral.setDeepAnalyzedAt(now)` 再 save。

#### I-4. 前端 AI 浮动助手功能薄弱

**现状**: `FloatingAiAssistant.tsx` 仅显示描述文字 + 跳转链接到 `/agent` 页面，不支持：
- 页面上下文感知（当前在哪个页面/编辑什么数据）
- 内嵌对话（需跳转才能聊天）
- 结果回填到当前编辑区

**方案**: 升级为侧滑抽屉内嵌对话面板，传入当前路由+实体上下文。

#### I-5. 热点借势创作缺少前端入口

**现状**: 后端 `generateHotspotFusedScript()` 已实现，但前端没有从热搜列表进入"热点×人设×产品融合"的入口按钮。

**方案**: 在 ViralLibraryPage 热搜 Tab 或 ShortVideoDashboardPage 热搜区新增"热点借势创作"按钮。

#### I-6. 批量深度分析无队列

**现状**: 运营看到 30 条未分析爆款，需逐个点击"AI 深度分析"。

**方案**: 前端增加"全选+批量分析"按钮，后端用 `@Async` + 进度追踪。

#### C-2 详细方案：deepAnalyze 异步化

```java
// 1. 提交任务（立即返回）
@PostMapping("/deep-analyze")
public RESTResult<Map<String, Object>> deepAnalyze(...) {
    String taskId = UUID.randomUUID().toString();
    deepAnalysisService.submitAsync(id, userId, taskId); // @Async
    return RESTResult.success(Map.of("taskId", taskId, "status", "processing"));
}

// 2. 轮询状态
@PostMapping("/deep-analyze/status")
public RESTResult<Map<String, Object>> deepAnalyzeStatus(@RequestBody Map<String, String> body) {
    return RESTResult.success(deepAnalysisService.getTaskStatus(body.get("taskId")));
}
```

前端改为：
```typescript
const { taskId } = await deepAnalyze(id)
// 轮询直到 status === 'completed'
const poll = setInterval(async () => {
  const status = await deepAnalyzeStatus(taskId)
  if (status.status === 'completed') { clearInterval(poll); setResult(status) }
}, 3000)
```
