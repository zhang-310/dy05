# 直播话术 × 短视频文案 深度策划

> **日期**: 2026-03-21 | **优先级**: 最高（日常核心生产力工具）
> **定位**: 从"功能可用"升级到"日常生产主力"
> **依赖**: 与 `10-内部运营体系战略规划.md` 角色体系配合实施

---

## 一、现状深度诊断

### 1.1 直播话术系统 — 代码级问题清单

**实体层（LiveSession + LiveScript）**:

| 字段/能力 | 现状 | 问题 |
|-----------|------|------|
| `session_type` | `standard` / `chat_2h` | **只有两种类型**，无法区分娱乐直播/重付费/仓播/单品 |
| `script_type` | `opening/product/transition/closing/chat/custom` | 缺少**互动话术、福利话术、逼单话术、憋单话术**等关键类型 |
| `product_type` | `profit/loss/flat/hot/control` | 有产品角色区分，但**没有与直播类型联动**（仓播逻辑完全不同） |
| `LivePromptBuilder` | 5 种 scriptType 的 switch-case | **只按话术类型分支**，没有按直播类型分支；`chat_2h` 的约束是硬编码 if 判断 |
| `chat2hConstraint` | 硬编码在 `buildPrompt` 中 | 只有自然流约束，**重付费直播没有对应的约束模板** |
| `SYSTEM_PROMPT` | "产品类型时长规则：亏品3-10秒..." | 这个规则**只适用于过品类直播**，娱乐直播/单品直播完全不适用 |
| 情绪话术 | `buildEmotionalUserPrompt` 15 种情绪类别 | 非常丰富，但**只适用于娱乐/聊天式直播**，与带货话术完全分离 |
| 多风格融合 | `buildProductScriptFusedPrompt` | 支持多风格融合（好），但**没有按直播类型推荐默认风格组合** |

**LivePromptBuilder 的核心缺陷**：

```java
// 当前: 所有直播类型共享同一个 SYSTEM_PROMPT
public static final String SYSTEM_PROMPT = """
    你是资深直播话术专家...
    产品类型时长规则：亏品3-10秒；平价品约15秒；爆品1-5分钟；利润品30-60秒。
    人气策略：人气高时主推爆品和高客单价高利润品...
    """;

// 问题: 娱乐直播不需要"亏品3-10秒"这种规则
// 仓播需要"快速过品、每品15-30秒"的完全不同逻辑
// 单品直播需要"反复洗脑、多角度卖点轰炸"
```

### 1.2 短视频脚本系统 — 代码级问题清单

**实体层（SvScript + SvScriptTemplate + SvViralVideo）**:

| 字段/能力 | 现状 | 问题 |
|-----------|------|------|
| `SvScript.script_type` | `viral_clone/daily/soft_ad` | **只有 3 种**，缺少测评/教程/开箱/种草/段子/Vlog 等内容类型 |
| `SvViralVideo` | 有 viralScore + analysisResult | **缺少 remake_status/industry_tags**，检测到爆款后没有工作流 |
| `SvScriptTemplate.scene` | `hook/body/cta/full` | 按视频结构分，**没有按行业/品类分** |
| `AiScriptGenerateVO` | 13 个参数 | 参数很丰富，但**没有"每日自动规划"的调度入口** |
| `RemakeTemplate` | 有 API（createFromViral/generateFromTemplate）| **后端 Service 实现存在**，但缺少自动化触发和运营确认流程 |
| 人设一致性 | `PersonaConsistencyChecker` 评分 | 有人设评分（好），但**分数低时没有自动修正** |

**ShortVideoAiServiceImpl 的核心缺陷**：
- 单次生成，没有批量生产能力（"今天生成 5 条脚本"）
- 没有"每日内容日历"概念
- 爆款分析和二创生成是分离的两步，没有闭环

### 1.3 最关键的缺失：直播类型体系

**现实中的 5 种直播**完全不同的话术逻辑：

| 类型 | 节奏 | 话术比例 | 核心指标 | 当前支持 |
|------|------|----------|----------|---------|
| **娱乐/聊天** | 慢节奏 8-10分钟/段 | 情绪80% + 带货20%（穿插） | 停留时长 + 互动率 | `chat_2h` ✅ 部分支持 |
| **自然流+微付费** | 中等 3-5分钟/品 | 情绪50% + 带货50% | 停留 + 转化率 | ❌ 无 |
| **重付费过品** | 快节奏 1-3分钟/品 | 带货90% + 互动10% | GPM + ROI | `standard` ❌ 混用 |
| **仓播** | 极快 15-60秒/品 | 纯带货100%，口播极简 | 过品效率 + 成交量 | ❌ 无 |
| **单品直播** | 反复循环 | 单品洗脑 + 逼单 + 互动 | 转化率 + 客单价 | ❌ 无 |

## 二、直播类型体系设计

### 2.1 `live_format` 字段（新增到 LiveSession）

```sql
-- live_session 新增字段
ALTER TABLE live_session ADD COLUMN IF NOT EXISTS live_format VARCHAR(32) DEFAULT 'standard';
COMMENT ON COLUMN live_session.live_format IS
  '直播形式：entertainment=娱乐聊天, natural_flow=自然流+微付费, heavy_paid=重付费过品, warehouse=仓播, single_product=单品';

-- 迁移：将已有 session_type='chat_2h' 映射为 live_format='entertainment'
UPDATE live_session SET live_format = 'entertainment' WHERE session_type = 'chat_2h' AND live_format = 'standard';
```

### 2.2 五种直播的话术结构模板

#### A. 娱乐/聊天直播 (`entertainment`)

```
整场结构（2-4小时）:
┌─────────────────────────────────────────────────────────┐
│ 开场暖场（10-15分钟）                                      │
│   → 问候 + 段子/金句 + 引导关注                            │
├─────────────────────────────────────────────────────────┤
│ 循环节奏（每30分钟为一个循环）:                              │
│   ├── 8-10分钟 情绪话术（家常/金句/歇后语/鸡汤）            │
│   ├── 2分钟   互动话术（提问/投票/连麦预告）                │
│   ├── 3-5分钟 穿插带货（1-2个品，软植入）                  │
│   │   └── "姐妹们刚才说护肤，正好这个面膜…"               │
│   ├── 8-10分钟 情绪话术（换主题）                          │
│   └── 2分钟   互动+预告下一段                              │
├─────────────────────────────────────────────────────────┤
│ 高在线时段（系统检测到在线人数高峰）                        │
│   → 自动建议切换到利润品话术                                │
├─────────────────────────────────────────────────────────┤
│ 收尾（5-10分钟）                                           │
│   → 感谢 + 总结金句 + 预告下次 + 最后福利品                │
└─────────────────────────────────────────────────────────┘

话术类型占比: 情绪60% / 互动20% / 带货15% / 开场收尾5%
核心策略: 内容留人 → 攒人气 → 高在线时段集中转化
```

#### B. 自然流+微付费 (`natural_flow`)

```
整场结构（2-3小时）:
┌─────────────────────────────────────────────────────────┐
│ 开场（5分钟）                                              │
│   → 人设开场 + 今日主题预告 + 福利预告                     │
├─────────────────────────────────────────────────────────┤
│ 循环节奏（每20分钟为一个循环）:                              │
│   ├── 5分钟  情绪/话题（引流+停留）                        │
│   ├── 5分钟  产品话术（1个品，故事化种草）                  │
│   ├── 3分钟  逼单+促单（限时/限量/倒计时）                 │
│   ├── 2分钟  互动（"刚才下单的扣1"）                      │
│   └── 5分钟  过渡+下一个品的铺垫                           │
├─────────────────────────────────────────────────────────┤
│ 福利环节（每小时1次）                                      │
│   → 福利品/赠品/抽奖，拉人气峰值                           │
├─────────────────────────────────────────────────────────┤
│ 收尾                                                       │
│   → 最后福利 + 感谢 + 预告                                 │
└─────────────────────────────────────────────────────────┘

话术类型占比: 产品50% / 情绪20% / 互动15% / 逼单10% / 福利5%
核心策略: 内容与带货各半，故事化种草，温和逼单
```

#### C. 重付费过品 (`heavy_paid`)

```
整场结构（3-6小时）:
┌─────────────────────────────────────────────────────────┐
│ 开场（2-3分钟）                                            │
│   → 极简开场 + 今日爆品预告 + "先点关注不迷路"             │
├─────────────────────────────────────────────────────────┤
│ 过品循环（每品1-3分钟，按产品角色调时长）:                   │
│   ├── 亏品:  30秒-1分钟（快速过，拉转化率数据）            │
│   ├── 平价品: 1-2分钟（基础卖点+引导）                     │
│   ├── 爆品:  3-5分钟（重点讲解+多角度卖点+逼单）           │
│   ├── 利润品: 1-2分钟（高客单价，人气高时推）              │
│   └── 控单品: 用于拉互动数据                               │
├─────────────────────────────────────────────────────────┤
│ 每10品穿插:                                                │
│   → 2分钟互动话术（拉互动数据）                            │
│   → 福利品/赠品（拉停留数据）                              │
├─────────────────────────────────────────────────────────┤
│ 人气低谷时:                                                │
│   → 切换福利品/憋单话术（"不要走，马上放大招"）            │
├─────────────────────────────────────────────────────────┤
│ 收尾                                                       │
│   → 最后爆品 + 极简收尾                                    │
└─────────────────────────────────────────────────────────┘

话术类型占比: 产品75% / 逼单15% / 互动5% / 福利5%
核心策略: GPM 最大化，快速过品，产品角色决定时长
SYSTEM_PROMPT 差异: "产品类型时长规则" 是此类型的核心
```

#### D. 仓播 (`warehouse`)

```
整场结构（4-8小时，轮班制）:
┌─────────────────────────────────────────────────────────┐
│ 开场（1分钟）                                              │
│   → "欢迎来到XX仓库，今天清仓价！走过路过不要错过！"       │
├─────────────────────────────────────────────────────────┤
│ 极速过品（每品15-60秒）:                                    │
│   ├── 15-30秒: 拿起商品 → 报名字报价格 → 展示 → 上链接    │
│   ├── 话术模板: "这个[品名]，原价XX，今天仓库价XX！"       │
│   │            "看好了！1号链接！赶紧拍！"                 │
│   ├── 不需要详细卖点描述，纯价格驱动                       │
│   └── 每品一句话核心卖点足够                               │
├─────────────────────────────────────────────────────────┤
│ 每20品穿插:                                                │
│   → "刚才没抢到的别急，一会还有更便宜的！"                │
│   → 倒计时/限量话术                                        │
├─────────────────────────────────────────────────────────┤
│ 收尾                                                       │
│   → "今天清仓到这里，明天同一时间！"                       │
└─────────────────────────────────────────────────────────┘

话术类型占比: 产品速报90% / 逼单5% / 互动5%
核心策略: 极致效率，一句话一个品，价格是唯一武器
SYSTEM_PROMPT 差异: 完全不同——"极简口语，15-30秒/品，只报品名+价格+核心卖点"
```

#### E. 单品直播 (`single_product`)

```
整场结构（1-3小时，循环洗脑）:
┌─────────────────────────────────────────────────────────┐
│ 开场（5分钟）                                              │
│   → 痛点引入 + 悬念（"今天一个产品让你彻底告别XX"）       │
├─────────────────────────────────────────────────────────┤
│ 循环话术（每30分钟一轮，至少3轮）:                          │
│   ├── 5分钟  痛点放大（为什么你需要这个）                  │
│   ├── 5分钟  产品介绍（卖点角度1: 成分/技术）              │
│   ├── 3分钟  场景演示（"你看我现在涂，马上..."）           │
│   ├── 5分钟  产品介绍（卖点角度2: 对比/数据）              │
│   ├── 3分钟  用户证言（"XX姐刚才说用了一周..."）           │
│   ├── 5分钟  逼单话术（限时+限量+赠品+价格锚定）           │
│   └── 4分钟  互动+回答问题                                 │
│                                                            │
│ 每轮换不同角度但说的是同一个产品:                          │
│   第1轮: 侧重成分/技术                                    │
│   第2轮: 侧重使用体验/场景                                │
│   第3轮: 侧重性价比/对比                                  │
│   第4轮+: 侧重用户反馈/紧迫感                             │
├─────────────────────────────────────────────────────────┤
│ 收尾                                                       │
│   → "最后XX单！倒计时！3！2！1！没了！"                   │
└─────────────────────────────────────────────────────────┘

话术类型占比: 产品多角度50% / 逼单25% / 互动15% / 情绪10%
核心策略: 同一品不同角度反复洗脑，每轮递进式加强紧迫感
SYSTEM_PROMPT 差异: "单品深度话术，每轮从不同卖点角度切入，避免重复用词"
```

### 3.2 每种直播类型的 SYSTEM_PROMPT

```java
// 新增: LiveFormatPromptStrategy（按直播形式选择 System Prompt）

public String getSystemPromptByFormat(String liveFormat) {
    return switch (liveFormat) {
        case "entertainment" -> """
            你是情感直播话术专家，擅长聊天留人+软植入带货。
            核心原则：
            1. 以内容吸引力为第一优先级，80%时间做内容留人
            2. 带货环节必须"话题自然过渡"，不能生硬切换
            3. 融入歇后语/金句/家常话题，保持真实感和亲和力
            4. 口语化、有停顿感、有情绪起伏
            5. 互动话术每10分钟至少1次（提问/投票/连麦邀请）
            6. 合规：严禁违禁词、绝对化用语
            7. 输出格式：只输出话术正文，可标注【表情/动作提示】
            """;

        case "natural_flow" -> """
            你是种草带货话术专家，擅长"内容+商品"各半的自然流直播。
            核心原则：
            1. 产品介绍用故事化/场景化方式，不要硬推
            2. 每个品讲3-5分钟，先铺垫再介绍再逼单
            3. 情绪话术用于过渡和蓄水，不是主体
            4. 逼单话术温和但有效：限时/限量/对比/赠品
            5. 口语化，有真实感，像朋友推荐
            6. 合规：严禁违禁词、绝对化用语
            7. 输出格式：只输出话术正文
            """;

        case "heavy_paid" -> """
            你是资深直播话术专家，输出「即用型」话术供主播微调。
            产品类型时长规则：亏品3-10秒；平价品约15秒；爆品1-5分钟；利润品30-60秒。
            人气策略：人气高时主推爆品和高客单价高利润品，炸爆款、做转化。
            核心原则：
            1. 口语化：像真人说话，有停顿感、语气词
            2. 有感染力：情绪饱满、节奏感强
            3. 引导动作：明确引导下单，每段至少1个动作指令
            4. 合规：严禁违禁词、绝对化用语
            5. 输出格式：只输出话术正文
            """;

        case "warehouse" -> """
            你是仓播话术专家，输出极简快速过品话术。
            核心原则：
            1. 每个品15-60秒，极致简短
            2. 话术模板：品名+一句卖点+价格+引导下单
            3. 语气快速、有冲击力、制造抢购氛围
            4. 不需要详细描述，价格是最大武器
            5. 示例："姐妹们看这个[品名]！XX成分/XX功效，专柜价XX，
               今天仓库价才XX！2号链接！手慢无！赶紧拍！"
            6. 合规：严禁违禁词、绝对化用语
            7. 输出格式：只输出话术正文
            """;

        case "single_product" -> """
            你是单品深度带货话术专家，擅长同一产品多角度反复种草。
            核心原则：
            1. 每轮从不同角度切入：成分/体验/数据/对比/场景/证言
            2. 避免重复用词，每轮话术新鲜感不低于70%
            3. 逼单力度随轮次递进：第1轮温和，第3轮强烈
            4. 穿插痛点放大和用户证言增强可信度
            5. 口语化，像真实推荐而非广告
            6. 合规：严禁违禁词、绝对化用语
            7. 输出格式：只输出话术正文
            """;

        default -> SYSTEM_PROMPT; // 默认通用
    };
}
```

## 四、短视频文案策划体系重构

### 4.1 内容类型扩展

现有 3 种 → 扩展为 10+ 种：

```
现有: viral_clone / daily / soft_ad

新增:
  review        — 测评视频（产品开箱/对比测评/使用体验）
  tutorial      — 教程视频（化妆教程/护肤步骤/穿搭教学）
  unboxing      — 开箱视频（新品首发/期待开箱）
  seeding       — 种草视频（好物推荐/安利分享）
  skit          — 段子/情景剧（搞笑+软植入）
  vlog          — 日常Vlog（主播日常+产品自然出镜）
  before_after  — 前后对比（使用前后效果对比）
  live_preview  — 直播预热（明天直播预告+福利剧透）
  trending      — 蹭热点（热门话题+品牌关联）
```

### 4.2 每日内容日历系统

**核心理念**：运营设定每周内容策略 → 系统每天自动生成脚本列表 → 审核 → 分配拍摄

```
┌────────┬──────────┬──────────┬──────────┐
│  周一   │  测评×1   │  种草×1   │  日常×1   │
│  周二   │  教程×1   │  热点×1   │  预热×1   │
│  周三   │  二创×1   │  段子×1   │  种草×1   │
│  周四   │  对比×1   │  开箱×1   │  预热×1   │
│  周五   │  教程×1   │  二创×1   │  段子×1   │
```

```
目标（闭环）:
```

### 6.2 `LivePromptBuilder` 改造要点

```java
// 当前: buildPrompt(scriptType, session, persona, vo)
// 改造: buildPrompt 内部根据 session.getLiveFormat() 分支

public String buildPrompt(String scriptType, LiveSession session, DyPersona persona, LiveAiGenerateVO vo) {
    String format = session.getLiveFormat() != null ? session.getLiveFormat() : "heavy_paid";

    // 1. 选择 System Prompt（已在 getSystemPromptByFormat 中实现）

    // 2. 按 format 构建 User Prompt
    return switch (format) {
        case "entertainment" -> buildEntertainmentPrompt(scriptType, session, persona, vo);
        case "natural_flow"  -> buildNaturalFlowPrompt(scriptType, session, persona, vo);
        case "heavy_paid"    -> buildHeavyPaidPrompt(scriptType, session, persona, vo); // 现有逻辑
        case "warehouse"     -> buildWarehousePrompt(scriptType, session, persona, vo);
        case "single_product"-> buildSingleProductPrompt(scriptType, session, persona, vo);
        default              -> buildHeavyPaidPrompt(scriptType, session, persona, vo);
    };
}
```
