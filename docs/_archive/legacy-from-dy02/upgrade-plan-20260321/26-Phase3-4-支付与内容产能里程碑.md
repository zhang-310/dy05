# Phase 3 / Phase 4：支付网关与内容产能 — 里程碑排期

> **目的**：将路线图中的「真实收单」与「AI 成片 + 自动发布」拆成可排期、可验收的里程碑，便于迭代规划。  
> **关联**：多维度分析 [23-系统全面深度多维度分析报告.md](./23-系统全面深度多维度分析报告.md) §5.2。

## Phase 3：支付网关（预估 2–3 周）

| 里程碑 | 交付物 | 验收要点 |
|--------|--------|----------|
| M3-1 环境与密钥 | 微信/支付宝（或选定网关）沙箱配置、`application.yml` / 密钥注入规范 | 非生产可拉起下单请求，无密钥入库 |
| M3-2 下单与回调 | 统一下单 API、支付回调验签、订单状态机与 `payment_order` 一致 | 沙箱全流程可走通，幂等与重放防护 |
| M3-3 对账与退款 | 对账任务、退款接口与 `live_product.revenue` 回扣逻辑联调 | 与现有 GMV 对账调度 [INFRA-03] 口径说明文档一致 |
| M3-4 前端闭环 | 订单列表/状态、失败重试与提示 | 与 `error-codes`、Toast 规范一致 |

## Phase 4：内容产能 — AI 成片与发布（预估 3–4 周）

| 里程碑 | 交付物 | 验收要点 |
|--------|--------|----------|
| M4-1 工作流真执行 | `WorkflowExecutionService` 中 `video_gen` / `compose` 等步骤对接真实任务（队列或供应商 API） | 任务可失败可重试，状态与 DB 一致 |
| M4-2 成片预览 | 前端可播放参考成片或预览链接 | 与项目/任务详情页关联 |
| M4-3 发布抖音 | 开放平台能力梳理、OAuth/授权、发布 API 封装 | 合规前置（话术/素材校验入口） |
| M4-4 观测 | 关键指标日志与可选 Prometheus 计数 | 与现有短视频任务 Webhook/DLQ 模式对齐 |

## 依赖与风险

- **Phase 3** 依赖法务/商户资质与平台审核周期，排期应留缓冲。
- **Phase 4** 依赖外部视频生成 SLA 与成本上限，建议在 `application.yml` 中单列配额与开关。
- **自动发布** 需与合规、版权、平台规则并行评审，不宜与 M4-1 强耦合同一发布列车。
