## 1. 背景与范围

### 1.1 业务目标

- **五主播**（李阳阳、王智慧、田玲红、肖瑶、肖蝉）每人：直播话术可生成、短视频日更可执行、摄影师有单可接。  
- **AI 参考成片**：可选，用于拍摄参考，**非**法定成片。

### 1.2 与现有模块关系

| 模块 | 已有能力 | 本规格增量 |
|------|----------|------------|
| 直播 `live_*` | 场次、话术生成、`session_type`、`script_style` | 话术侧不新建表；`live_format` 仍按 `11` 另迭代 |
| 短视频 `sv_*` | `SvScript`、`SvProject`、`DailyShootService.generateDaily`、分镜/镜头表 | **`sv_shooting_task`**：运营派单 + 摄影师执行闭环 |
| 视频任务 | `SvVideoGenerationTask`、`/video-task/submit` | 任务表上 **`reference_video_task_id` / `reference_video_url`** 挂接 |

### 1.3 非目标（本版不做）

- 企微推送、Cron 日更调度（见 §8 二期）。  
- 自动从脚本提交 `video-task`（见 §7.3 二期）。  
- `live_format` 字段落库（归 `11` 单独迁移）。

## 2. 用户角色与数据可见性

沿用 `DataScopeService`：

| 角色 | 列表可见规则 |
|------|----------------|
| admin | 全部 `sv_shooting_task`（`deleted=0`） |
| institution | `owner_id ∈ visibleOwnerIds` **或** `photographer_id = 当前用户` **或** `anchor_user_id = 当前用户` |
| talent / user | 同上（visible 通常仅本人，摄影师/主播靠后两列看到自己相关任务） |

**保存/删除**：仅 **`owner_id = 当前登录用户`** 的任务可改（与 `SvProject.save` 一致）；摄影师改状态、上传素材可后续增加 `POST /status` 放宽校验。

## 3. 数据模型：`sv_shooting_task`

### 3.1 表结构（PostgreSQL）

| 列 | 类型 | 约束 | 说明 |
|----|------|------|------|
| id | BIGSERIAL | PK | |
| owner_id | BIGINT | NOT NULL | 创建人（运营账号），数据隔离主键 |
| anchor_user_id | BIGINT | NULL | 可选：主播 `auth_user.id`，便于主播端筛选 |
| persona_id | BIGINT | NULL | `dy_persona.id` |
| photographer_id | BIGINT | NULL | 摄影师 `auth_user.id` |
| script_id | BIGINT | NULL | `sv_script.id` |
| project_id | BIGINT | NULL | `sv_project.id`（与 daily 项目联动） |
| title | VARCHAR(256) | NOT NULL | 任务标题 |
| description | TEXT | NULL | 拍摄要求 |
| script_content | TEXT | NULL | 冗余脚本正文，便于未关联 script 时阅读 |
| shooting_brief | TEXT | NULL | 分镜/景别/时长要点 |
| shoot_date | DATE | NOT NULL | 计划拍摄日 |
| priority | INT | DEFAULT 0 | 0 普通 1 加急 |
| status | INT | NOT NULL DEFAULT 0 | 见 §3.2 |
| material_urls | TEXT | NULL | JSON 数组 URL |
| review_notes | TEXT | NULL | 审核备注 |
| reviewed_by | BIGINT | NULL | 审核人 user id |
| reference_video_url | VARCHAR(512) | NULL | AI 参考成片地址 |
| reference_video_task_id | BIGINT | NULL | `sv_video_generation_task.id` |
| reference_generated_at | TIMESTAMP | NULL | 参考片生成时间 |
| deleted | INT | NOT NULL DEFAULT 0 | 逻辑删除 |
| create_time | TIMESTAMP | DEFAULT now() | |
| update_time | TIMESTAMP | DEFAULT now() | |

**索引**：

- `idx_sv_shooting_task_owner (owner_id, deleted, shoot_date DESC)`  
- `idx_sv_shooting_task_photo (photographer_id, status) WHERE photographer_id IS NOT NULL`  
- `idx_sv_shooting_task_date (shoot_date, status)`

### 3.2 状态机 `status`

| 值 | 含义 |
|----|------|
| 0 | 待分配（无摄影师或刚创建） |
| 1 | 已分配 |
| 2 | 拍摄中 |
| 3 | 已上传素材 |
| 4 | 已审核 |
| 5 | 已发布 / 结案 |

与 `11` 爆款二创状态机**不同域**，禁止混用。

### 3.3 与 `DailyShootService` / `SvProject` 的关系

- `DailyShootService.generateDaily` 已能按人设+日期生成 `SvProject` + `SvScript` + shots。  
- **本表**可手工新建，也可在二期由调度器在 `generateDaily` 成功后 **自动插入** `sv_shooting_task`（填入 `project_id`、`script_id`、`persona_id`）。  
- `SvProject.shoot_status`（not_started/ready/shooting/shot_done）描述**项目**拍摄进度；**本表**描述**跨人任务工单**，二者可并存，以任务表为对摄影师的主视图。

## 4. API 规格（统一 POST）

Base path：`/api/v1/short-video/shooting-task`

| 路径 | 说明 | 请求体要点 |
|------|------|------------|
| `/list` | 分页查询 | `SvShootingTaskSearchVO`：`page, rows, sortName, sortOrder, title?, status?, shootDateFrom?, shootDateTo?, personaId?, photographerId?, anchorUserId?` |
| `/get` | 详情 | `{ "id": long }` |
| `/save` | 创建或更新 | `SvShootingTaskSaveVO`：`id?`, 必填 `title`, `shootDate` (yyyy-MM-dd)，可选关联字段 |
| `/delete` | 逻辑删除 | `{ "id": long }` |

**错误码**：沿用 `DATA_NOT_FOUND`、`FORBIDDEN`、`VALIDATION_FAIL`、`UNAUTHORIZED`。

## 6. 流水线 A（直播话术）

无新表。操作指引：

1. 创建 `live_session`，绑定 `persona_id`、`session_type`、`script_style`。  
2. 使用现有话术生成与审核流程。  
3. 预热短视频可用 `export-to-short-video` 或手工建 `sv_shooting_task` 关联同场商品。

---

## 7. 流水线 B / C（日更脚本 + AI 参考）

### 7.1 日更脚本（当前）

- 继续用 **`POST /api/v1/short-video/project/generate-daily`**（或脚本策划页生成后保存 `SvScript`）。  
- 运营在「拍摄任务」页 **新建任务**，关联 `script_id` / `project_id`，指定 `shoot_date`、`photographer_id`。

### 7.2 AI 参考成片（当前）

- 表字段已预留：`reference_video_url`、`reference_video_task_id`、`reference_generated_at`。  
- **人工**：运营在视频任务模块提交任务完成后，将 URL 填回任务 **save**（或通过 DB 更新）。  
- **自动**（二期）：`POST /video-task/submit` 成功后 webhook 或轮询写回 `sv_shooting_task`（需任务与 shooting_task 关联表或扩展 meta）。

### 7.3 配额与合规

- 建议在 `sys_config` 或 `application.yml` 增加 `app.shortvideo.shooting-task.reference-daily-cap-per-persona`（二期）；本版不实现。

## 8. 二期 backlog（按优先级）

1. **`DailyShootingTaskBootstrap`**：`generateDaily` 成功后可选自动创建 `sv_shooting_task`。  
2. **`ShootingTaskMorningScheduler`**：扫描明日有 `live_session` 的主播，自动生成 `soft_ad` 脚本 + 任务（对齐 `10` §6.3）。  
3. **`POST /shooting-task/bind-reference-video`**：根据 `script` 摘要拼 keyframes 调 `VideoGenerationTaskService`。  
4. 摄影师 **仅更新状态/素材** 的专用接口（不开放完整 save）。  
5. 企微推送今日拍摄单。
