# 内部运营体系战略规划

> **日期**: 2026-03-21 | **定位**: SaaS 搁置 → 内部公司运营工具
> **核心目标**: 护肤彩妆直播 GMV 千万级，以人（角色）为中心的工作流驱动

---

## 一、现状诊断

### 1.1 当前角色体系（4 角色）

```
AuthUser.roleCode: admin / institution / talent / user
```

**问题**：`institution`（机构）和 `user`（普通用户）是 SaaS 多租户概念，内部运营不需要。而实际工作中的**运营人员、摄影师、中控人员、选品人员**没有对应角色，全部挤在 `admin` 或 `talent` 下，权限粒度不够。

### 1.2 已有基础设施（可直接复用）

| 能力 | 现状 | 复用度 |
|------|------|--------|
| **人设系统** (DyPersona) | 20+ 字段：tone/content_ratio/live_style/persona_traits/local_flavor | ★★★★★ 完美匹配 |
| **AI Agent** | 3 类 agent + 流式对话 + function calling + 知识库 RAG | ★★★★★ 直接复用 |
| **企微机器人** | WcRobotConfig（webhook）+ WcPushRule（cron/event 触发）+ NotificationTriggerService | ★★★★☆ 缺每日推送调度 |
| **爆款检测** | AiViralDetectionScheduler（3AM）+ SvViralVideo + viralScore + analysisResult | ★★★★☆ 缺行业筛选 |
| **热点同步** | SvHotTopicSyncScheduler（30分钟）+ ViralVideoCollector（4AM/4:30AM） | ★★★★☆ 已自动化 |
| **话术生成** | 人设感知 Prompt → LLM → 评分 → 多变体 | ★★★★★ 直接复用 |
| **短视频脚本** | ScriptPlanningPage + 13 参数 + 模板画廊 | ★★★★☆ 需简化入口 |
| **定时任务** | 30+ @Scheduled 任务，覆盖凌晨 2-5 点和实时轮询 | ★★★★★ 调度框架成熟 |
| **知识进化** | 6 类 Agent 巡检 + 日/周/月报告 | ★★★★☆ 缺推送到人 |

### 1.3 核心缺失

1. **角色不匹配** — 摄影师、中控、选品人员无对应 roleCode
2. **无每日工作台** — 每个角色登录后看到的是同一个 Dashboard（系统监控）
3. **无每日任务推送** — 晨会前没有自动化的"今日任务清单"
4. **主播无法自助** — 主播想用自己人设问 AI/规划话术，需切到 AI 页面手动操作
5. **拍摄脚本未闭环** — 运营提需求 → 系统生成脚本 → 摄影师接单的链路断裂
6. **爆款二创无工作流** — 检测到爆款后停在数据库，缺"分配 → 改编 → 审核 → 发布"流程

## 二、角色体系重构

### 2.1 新角色定义（6 角色）

| roleCode | 名称 | 核心职责 | 首页视图 |
|----------|------|----------|----------|
| `admin` | 管理员 | 系统配置、人员管理、数据总览 | 全局 GMV + 人员效能 + 系统状态 |
| `operations` | 运营人员 | 场次策划、选品审核、话术审核、数据复盘 | 今日场次 + 待审核 + GMV 排行 |
| `anchor` | 主播 | 直播执行、人设对话、话术规划、短视频创作 | 我的日程 + AI 助手 + 话术推荐 |
| `photographer` | 摄影师 | 短视频拍摄、素材制作 | 今日拍摄任务 + 素材上传 |
| `director` | 中控人员 | 直播中控台、实时数据、话术提词 | 实时面板 + 商品切换 + 互动数据 |
| `selector` | 选品人员 | 商品筛选、竞品分析、选品提报 | 待选品场次 + 商品库 + 趋势数据 |

### 2.2 数据库改动

```sql
-- 1. auth_user 扩展（无需改表结构，roleCode 已是 VARCHAR(32)）
-- 只需在 AuthService 中注册新角色即可
-- 新增角色常量:
--   operations / anchor / photographer / director / selector

-- 2. 角色能力矩阵（建议新增配置表，或硬编码到 SecurityConfig）
-- 核心权限映射:
--   admin       → 全部
--   operations  → live/product/script/copy/shortvideo/ai（除系统配置）
--   anchor      → 仅自己的 persona/live/script/shortvideo + AI 对话
--   photographer → shortvideo/storage（素材相关）
--   director    → live-realtime/product（直播中控相关）
--   selector    → product/live-product（选品相关）

-- 3. 人设绑定强化：anchor 角色自动关联 DyPersona
-- DyPersona.owner_id = AuthUser.id（已有字段，无需改动）
```

### 2.3 迁移策略

| 原角色 | 迁移到 | 说明 |
|--------|--------|------|
| `admin` | `admin` | 不变 |
| `institution` | `operations` | 机构管理者 → 运营人员 |
| `talent` | `anchor` | 达人 → 主播 |
| `user` | 按实际分配 | 可能是摄影师/中控/选品 |

**兼容方案**：`roleCode` 在 `SecurityConfig` 中按新旧两套映射，过渡期同时支持。

## 五、主播人设 AI 自助系统

### 5.1 核心理念

**主播不是"使用 AI 工具的人"，而是"和自己的 AI 分身对话的人"**。

现有 `DyPersona` 已有 20+ 字段描述主播人设，但这些数据只用于后台话术生成的 Prompt 模板。主播本人无法直接与自己的人设 AI 交互。

### 5.2 人设 Agent 设计

```
┌─────────────────────────────────────────────────────────┐
│ 主播小美 ──── DyPersona ──── PersonaAgent               │
│                                                          │
│ persona_name: "温柔知性姐姐"                              │
│ tone: "warm"                                             │
│ target_audience: "25-40岁女性，关注护肤抗衰"              │
│ live_style: "emotional"                                  │
│ persona_traits: "爱说'姐姐们注意了', 喜欢用数据说话"       │
│ content_ratio: {"emotional":40,"humor":30,...}            │
│ local_flavor: "东北"                                     │
│                                                          │
│ ──→ 自动生成 system_prompt:                              │
│     "你是小美的 AI 助手，她的人设是'温柔知性姐姐'，       │
│      语气温暖，目标受众 25-40 岁女性，擅长护肤抗衰。     │
│      她喜欢用数据说话，口头禅是'姐姐们注意了'。          │
│      请基于这个人设帮她规划话术和短视频内容。"            │
└─────────────────────────────────────────────────────────┘
```

#### 实现路径

1. **PersonaAgentService**（新建）

```java
// module/agent/service/PersonaAgentService.java

public interface PersonaAgentService {
    /**
     * 获取或创建主播的人设 Agent
     * 如果主播还没有绑定的 Agent，自动根据 DyPersona 创建一个
     */
    Agent getOrCreatePersonaAgent(Long anchorUserId);

    /**
     * 与人设 Agent 对话（流式）
     * 自动注入人设上下文 + 当前商品/场次信息
     */
    SseEmitter chatWithPersona(Long anchorUserId, String message, Long sessionId);

    /**
     * 基于人设生成直播话术建议
     */
    List<String> suggestScripts(Long anchorUserId, Long sessionId, int count);

    /**
     * 基于人设生成短视频脚本
     */
    String planVideoScript(Long anchorUserId, VideoScriptRequest request);
}
```

### 5.3 主播可执行的 AI 操作

```java
@Scheduled(cron = "0 0 6 * * ?")  // 每天 06:00
public void generateDailyShootingScripts() {
```

### 7.2 补齐二创工作流


## 十、关键决策点（已确认 ✅）

| 序号 | 决策 | 结论 | 实施要点 |
|------|------|------|----------|
| 1 | `institution` 角色如何处理 | ✅ **保留兼容** | 过渡期 `institution` 映射到 `operations` 权限，SecurityConfig 同时识别新旧 roleCode |
