# 对外验收口径与「三层 100%」定义

> **目的**：对外承诺「100% 对齐 / 100% 覆盖」前，必须先书面固定**口径**；本文件为唯一解释依据，避免与「全仓库行覆盖率 100%」等误解混淆。

## 1. 禁止混用的三种「100%」

| 口径 | 含义 | 当前落地物 | 是否等于「全接口业务正确」 |
|------|------|------------|---------------------------|
| **A. 契约 100%（清单内）** | 维护《端点清单》或 OpenAPI；清单内每条路径 **方法 + 路径 + 关键 body/query** 与前端 `src/api` 一致 | `docs/api/01-前后端对齐问题清单.md`、脚本 `scripts/list-backend-mappings.ps1` 输出 | **否**（仅保证对齐关系可追溯） |
| **B. 自动化覆盖 100%（清单内）** | 清单内端点 **至少一种**自动化验证：单测 / 契约测试 / 冒烟请求 | `ApiCoverageTest`（默认 `@Disabled`，见 §4）、JaCoCo、Vitest | **否**（冒烟≠业务断言） |
| **C. 黄金路径 100%** | 约定的 **N 条**端到端用户旅程 **每条必绿**（见 §3） | Playwright `e2e/golden-paths.spec.ts` | **否**（仅覆盖主旅程） |

对外话术示例：

- ✅ 「**契约清单内** 接口已与前端封装对齐，并列在 `docs/api/01`。」
- ✅ 「**黄金路径**（登录前防护、登录页可达）在 CI 可执行用例中 100% 通过。」
- ❌ 「全站 **900+** 接口均已业务级测试 100% 覆盖」——**除非**已维护完整清单并逐项举证。

## 2. 端点清单（A 层）— 怎么维护

1. **生成原始映射**（后端 Controller）：
   ```powershell
   cd <项目根>
   .\scripts\list-backend-mappings.ps1
   ```
   输出：`target/backend-mappings.txt`（便于 diff / 归档）。

2. **权威契约**（推荐演进方向）：
   - 以 **SpringDoc OpenAPI** 导出 JSON/YAML 为「服务端契约」；
   - 前端对 **P0/P1** 模块做路径与字段 snapshot（可逐步加）。

3. **与前端对齐**：
   - 人工维护 `docs/api/01`「已对齐 / 待办」；
   - 大版本发布前：对 `src/api/**/*.ts` 中 `post('/...')` 路径做抽检或脚本对比（可后续增强脚本）。

## 3. 黄金路径（C 层）— 必选场景与验收标准

以下路径 **每条必须在 Playwright 黄金路径用例中通过**（当前实现见 `e2e/golden-paths.spec.ts`）。

| ID | 场景 | 验收标准 | 依赖 |
|----|------|----------|------|
| **GP-01** | 登录页可达 | 访问 `/login` 出现可交互的登录表单（账号/密码或主按钮） | 仅前端 dev server |
| **GP-02** | 未登录不可进后台 | 访问 `/admin/dashboard` 被重定向到 `/login`（或统一登录页） | 仅前端 dev server |
| **GP-03** | （扩展）登录后进工作台 | 使用测试账号登录后 `/admin/dashboard` 出现工作台内容 | **需后端 + 测试账号**；默认 CI 不强制，见下节 |
| **GP-04** | 站点根路径可打开 | 访问 `/` HTTP 状态 &lt; 500（与 GP-01 同为「站点可投递」冒烟） | 仅前端 dev server |

**扩展路径（可选 / 发布前人工或夜间任务）**：

- GP-10：商品列表页加载（需后端 + 登录）
- GP-11：直播场次列表加载
- GP-12：脚本合规检查页加载

扩展项通过环境变量 **`E2E_FULL_STACK=1`** 启用（见 `golden-paths.spec.ts` 内说明），避免默认 CI 因无后端失败。

## 4. 覆盖率阈值（B 层）— 与「全站 100%」脱钩

| 工具 | 当前策略 | 说明 |
|------|----------|------|
| **JaCoCo**（`mvn verify`） | 全 BUNDLE **行覆盖率 ≥ 30%**（`pom.xml` 中 `jacoco-maven-plugin` 的 `check`） | 这是 **质量底线**，不是「对外承诺 100%」 |
| **Vitest** | `front/vitest.config.ts` 对 lines/functions/branches/statements 配置 **100%** 阈值；**仅**在 `npm run test:coverage` 时生效 | `npm run test` 不收集覆盖率，**不受**上述阈值约束；CI 若只跑 `test` 则前端覆盖率门禁不生效，可按需改为跑 `test:coverage` |
| **`ApiCoverageTest`** | `@Disabled`：需完整 ApplicationContext + 鉴权/DB 策略 | 启用后语义仍为「每端点请求一次」，**不替代**业务断言；启用前需 `test` profile 与排除破坏性端点 |

对外承诺「测试 100%」时，应写明：**JaCoCo 底线 + 黄金路径列表 +（可选）契约清单覆盖率**。

## 5. CI 与本地命令对照

| 动作 | 命令 |
|------|------|
| 后端测试 + JaCoCo 检查 | `mvn clean verify` |
| 前端单测 | `cd front && npm run test` |
| 前端覆盖率报告 | `cd front && npm run test:coverage` |
| 黄金路径 E2E（GP-01/02） | `cd front && npm run test:e2e -- e2e/golden-paths.spec.ts` |
| 全量路由 E2E（耗时长） | `cd front && npm run test:e2e -- e2e/routes.spec.ts` |
| 导出后端映射 | `.\scripts\list-backend-mappings.ps1` |

**GitHub Actions**：若仓库已配置 `.github/workflows/ci-cd.yml`，其中 **`test-frontend-e2e-golden`** 可在 PR/Push 时执行黄金路径；`quality-checks` 依赖该 Job 通过。（本机克隆若不含该目录，以实际流水线为准。）
