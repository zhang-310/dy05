# 商品库模块 — 深度分析与升级建议

> 范围：`module/product` 后端 + 前端「商品库」相关页面、组件与 API 客户端（含话术、风格预设、效果评分、优化子域）。  
> 分析日期：2026-03-19

---

## 一、模块边界与架构

| 层级 | 说明 |
|------|------|
| **核心域** | 商品主数据（`DyProduct`）、CRUD、上下架、精选、库存、链接/文本提取、排品 Excel 导入 |
| **话术域** | `dy_product_script` 多风格/多类型/应用场景、AI 生成（含 SSE）、版本历史、效果摘要、AI 微调 |
| **平行版本域** | `product_script_version` 及优化链路（分析/建议/重生成），与 `dy_product_script` 双轨并存 |
| **运营域** | 销售历史、话术效果评分（`script-effectiveness`）、风格预设（`style_preset`） |
| **跨模块** | 直播排品 `live_product.product_script_id` 引用商品库话术；数据范围 `DataScopeService` 影响搜索 |

## 二、后端接口清单（按 Controller）

| POST `/trigger-extract-batch` | 批量触发提取 | 仅计数 submitted，无任务 ID |
| POST `/extract-from-link` | 同步从链接提取 | |
| POST `/extract-selling-points-from-text` | 文本提炼卖点 | |
| POST `/import-paiping` | 排品 Excel 导入 | multipart |

| POST `/publish`、`/unpublish` | 上下架 | |
| POST `/set-featured` | 精选标记 | |
| POST `/batch-publish`、`/batch-unpublish`、`/batch-set-featured` | 批量操作 | |
| POST `/sales-history/search`、`/get`、`/save` | 销售历史 | |

**评估**：商品主链路完整；**异步提取**缺少「任务状态/进度/失败原因」统一查询，运营侧只能刷新列表猜测结果。

### 2.2 `ProductScriptController` — `/api/v1/product/script`

| 路径 | 功能 |
|------|------|
| POST `/save` | 保存话术 |
| POST `/list`、`/list-by-type`、`/list-by-style` | 列表 |
| POST `/active-by-style` | 按风格激活话术 |
| POST `/count-by-products` | 批量话术条数 |
| POST `/effect-summary`、`/effect-summary-batch` | 效果摘要（usage + 排品引用） |
| POST `/generate-multi-style`、SSE `/generate-multi-style-sse` | 多风格/融合生成 |
| POST SSE `/generate-batch-stream` | 多商品批量生成 |
| PUT `/activate/{id}`、`/update/{id}`、DELETE `/{id}` | 激活/更新/删除 |
| POST `/get`、`/history`、POST `/rollback/{historyId}` | 详情/版本历史/回滚 |
| POST `/refine-with-ai`、SSE `/refine-with-ai-sse` | AI 微调 |

**评估**：话术 CRUD 与 AI 能力较全；与 **优化子域**（依赖 `scriptVersionId`）的衔接仍依赖文档约定（见第五节）。

### 2.3 `ScriptOptimizationController` — `/api/v1/product/script`

| 路径 | 功能 |
|------|------|
| POST `/analyze` | 分析（body：`scriptVersionId` 等） |
| POST `/suggestions` | 建议（需 `scriptVersionId` + `analysisResultId`） |
| POST `/regenerate` | 按建议重生成（`suggestionId` 单条） |
| POST `/optimization-history` | 优化历史（分页） |
| POST `/accept-suggestion`、`/reject-suggestion` | 采纳/拒绝建议 |
| POST `/apply-regenerated`、`/approve-regenerated` | 应用/审批重生成结果 |

**评估**：能力完整但**强绑定 `product_script_version`**；与主话术表 `dy_product_script.id` 无统一入口时，前端难以从「商品库话术抽屉」一键打通。

---

### 2.4 `ProductScriptVersionController` — `/api/v1/product/script-version`

| 路径 | 功能 |
|------|------|
| POST `/save`、`/list`、`/search`、`/detail/{id}` | 版本 CRUD/查询 |
| POST `/recommend`、`/update-effectiveness`、`/apply-from-library` | 推荐与效果 |
| POST `/delete/{id}`、`/update-status` | 删除/状态 |
| POST `/list-by-product`、`/best`、`/increase-usage` | 按商品/最佳/使用计数 |

**评估**：独立版本线能力齐全；需与 **dy_product_script** 的同步策略或统一 ID 映射才能在产品心智上「一套话术」。

---

### 2.5 `StylePresetController` — `/api/v1/product/style-preset`

| 路径 | 功能 |
|------|------|
| POST `/list`、`/list-all`、`/get`、`/save` | 预设管理 |
| DELETE `/{id}` | 删除 |

**评估**：与前端 `STYLE_CODE_LABELS` 等存在**双源**（DB + 前端兜底），需持续同步（已在 `04-文档代码同步清单` 六.1 说明）。

### 2.6 `EffectivenessScoreController` — `/api/v1/product/script-effectiveness`

| 路径 | 功能 |
|------|------|
| POST `/ranking`、`/compare`、`/trend` | 排行/对比/趋势 |
| POST `/recalculate`、`/style-comparison`、`/analysis` | 重算/风格/分析 |
| POST `/record-snapshot`、`/clear-cache` | 快照与缓存 |

**评估**：与 `dy_product_script_usage` 效果摘要（ProductScript 效果 API）**数据来源可能不一致**，需在文档与产品上明确「排行榜 vs 使用记录摘要」各自适用场景。

### 3.3 API 客户端文件

| 文件 | 与后端对齐情况 |
|------|----------------|
| `api/product.ts` | **主路径对齐**，话术与商品核心接口完整 |
| `api/effectiveness.ts` | 商品侧使用 `POST .../script-effectiveness/*` + `params`，与 Controller **RequestParam** 方式需保持 axios 配置一致（当前设计可用） |
| `api/optimization.ts` | **部分与后端契约不一致**：后端 `analyze`/`suggestions`/`regenerate` 使用 `scriptVersionId`、`analysisResultId`、`suggestionId` 等；前端常发 `versionId`、`suggestionIds` 数组等 → **易 400 或静默失败** |
| `api/product-script-version.ts` | 含 `/current`、`/diff`、`/rollback` 等路径；**与 `ProductScriptVersionController` 实际路径不完全一致** → 调用前需逐一对照 OpenAPI 或源码 |

## 四、综合评估

### 4.1 优势

- 商品 + 话术 + AI 生成 + SSE 进度 + 效果摘要 + 应用场景（scene）已形成**可演示闭环**。
- 权限与数据范围在搜索等接口有体现。
- 风格预设、效果评分、优化子域**后端能力储备较全**。

### 4.2 主要风险与缺口

1. **双轨话术模型**：`dy_product_script`（商品库主路径）与 `product_script_version`（优化/部分效果评分）并行，前端主界面以主表为中心，**优化与版本页未接入主路径**。
2. **前端优化 API 与后端字段名/结构不一致**：`optimization.ts` 与 `ScriptOptimizationController` 请求体不对齐。
3. **`product-script-version.ts` 与后端路由漂移**：存在未使用或错误路径风险。
4. **异步提取无任务可观测性**：批量/单条 trigger 后无法查状态。
5. **效果数据多源**：`script-effectiveness`、`dy_product_script_usage`、直播侧 effectiveness 并存，**产品定义与 UI 说明不足**时易误解指标含义。
6. **Org 端菜单**：`OrgLayout` 未检索到与 Admin 对称的「商品库」菜单项（若机构端需用商品库，需单独补齐导航与权限）。

## 五、升级建议（按优先级）

### P0 — 对齐与可用性（建议 1～2 迭代内）

| 序号 | 建议 | 说明 |
|------|------|------|
| P0-1 | **修正 `optimization.ts` 与后端契约** | `analyze` 传 `scriptVersionId`；`suggestions` 传 `scriptVersionId` + `analysisResultId`；`regenerate` 按后端单次 `suggestionId` 或扩展后端支持批量 |
| P0-2 | **审计 `product-script-version.ts`** | 删除或改正不存在接口；与 `ProductScriptVersionController` 一一对应；补充类型 |
| P0-3 | **话术优化入口与主表打通** | 方案 A：从 `dy_product_script` 进入优化时自动 upsert `product_script_version` 并拿到 `scriptVersionId`；方案 B：后端新增 `scriptId`（dy_product_script.id）版 analyze/suggestions（已在 P0-P4 计划中间接涉及） |

### P1 — 体验与运营

| 序号 | 建议 | 说明 |
|------|------|------|
| P1-1 | **挂载 `ProductScriptVersionPage` 或合并进话术抽屉** | 避免已实现页面闲置；与菜单、权限、面包屑一致 |
| P1-2 | **异步提取任务** | 增加任务表或复用消息通知：状态（排队/成功/失败）、错误摘要、重试 |
| P1-3 | **效果指标说明组件** | 在「效果评分页」与「话术卡片效果摘要」旁增加 Tooltip/帮助文档链接，说明数据来源与更新频率 |
| P1-4 | **商品库高级筛选** | 按话术条数、是否有卖点、是否有链接、应用场景（scene）、上架状态组合筛选（后端 Specification + 前端筛选栏） |

### P2 — 架构与复用

| 序号 | 建议 | 说明 |
|------|------|------|
| P2-1 | **统一话术领域模型文档** | 在 `docs/architecture` 或 `04-文档代码同步清单` 中增加序列图：主表版本历史 → usage → 排品引用 → product_script_version 优化 |
| P2-2 | **OpenAPI 聚合** | 商品库相关 Tag 分组导出，供前端代码生成或契约测试 |
| P2-3 | **批量操作幂等与限流** | batch extract / batch publish 返回明确失败明细（部分已有），统一错误码与前端展示 |

### P3 — 数据与智能

| 序号 | 建议 | 说明 |
|------|------|------|
| P3-1 | **效果回写统一** | 直播复盘 → `dy_product_script_usage` 与 `script-effectiveness` 计算链路对齐（见商品库话术 P1 计划） |
| P3-2 | **推荐话术接入场景** | 排品或直播选品时按 `scene` + 商品类型推荐激活话术（读 `active-by-style` + scene 过滤，需后端 list 支持 scene） |

### P4 — 质量与合规

| 序号 | 建议 | 说明 |
|------|------|------|
| P4-1 | **E2E/集成测试** | 商品保存 → 话术生成 SSE → 效果摘要 → 更新话术 关键路径 |
| P4-2 | **错误码** | 商品/话术/优化子域新增错误时保持 Java + `error-codes.ts` + `03-错误码注册表.md` 三处同步 |
