# 产品库话术 P0-P4 升级执行计划

> 基于《产品库话术-深度分析与升级建议》的 P0-P4 逐条拆解为可执行任务，按依赖顺序实施。

---

## 一、P0：统一话术版本与效果入口

### P0.1 效果摘要 API（后端）

| 序号 | 任务 | 说明 | 依赖 |
|------|------|------|------|
| P0.1.1 | 新增「按 dy_product_script.id 查询效果摘要」接口 | 使用现有 `dy_product_script_usage`（product_script_id = dy_product_script.id）聚合：使用次数、平均效果分、平均转化率、总销售额；可选：统计 live_product 中 product_script_id = 该 id 的排品引用场次数 | 无 |
| P0.1.2 | ProductScriptService 新增 getScriptEffectSummary(scriptId, userId) | 校验话术归属 product 的 owner_id = userId；查 usage 聚合 + 排品引用数（LiveProductRepository.countByProductScriptId） | P0.1.1 设计 |
| P0.1.3 | Controller GET/POST 暴露 /product/script/effect-summary | 请求体 scriptId，返回 { usageCount, avgEffectivenessScore, avgConversionRate, totalSalesAmount, referenceCount } | P0.1.2 |
| P0.1.4 | LiveProductRepository 新增 countByProductScriptId(Long productScriptId) | 统计排品中引用该话术的条数（场次维度可再议） | 无 |

**产出**：接口 `POST /api/v1/product/script/effect-summary`，请求 `{ scriptId }`，返回效果摘要；前端可轮询或按需调用。

### P0.2 话术抽屉内效果展示与优化入口（前端）

| 序号 | 任务 | 说明 | 依赖 |
|------|------|------|------|
| P0.2.1 | 话术卡片展示「使用次数」「引用场次」「效果分」 | 在 ProductScriptManageDialog 每条话术卡片上，根据 scriptId 调用 effect-summary，展示摘要（若无可显示「暂无数据」） | P0.1 |
| P0.2.2 | 增加「优化建议」入口 | 卡片或列表操作区增加「优化建议」按钮，跳转到话术优化页（传 scriptId）或打开抽屉内 Tab/区块（见 P1） | 无 |
| P0.2.3 | 文档：双表关系说明 | 在 04-文档代码同步清单 或 architecture 中说明 dy_product_script 与 product_script_version、dy_product_script_usage 的关系及使用场景 | 无 |

**产出**：用户可在话术管理抽屉内看到每段话术的效果数据，并进入优化建议流程。

### P0.3 映射规则（可选，本阶段可仅文档）

| 序号 | 任务 | 说明 |
|------|------|------|
| P0.3.1 | 文档明确「当前以 dy_product_script 为主、usage 按 script_id 统计」 | 不强制同步到 product_script_version；若后续要接入 ScriptOptimization 的 analyze/suggestions，再定「由 dy_product_script 同步一条到 product_script_version 再分析」或「直接按 scriptId 适配分析接口」 |
| P0.3.2 | （可选）保存/激活时同步写入 product_script_version | 若产品要求优化建议必须用 product_script_version，可在 saveScript/updateScript/activateScript 时 upsert product_script_version，script_id = dy_product_script.id |

**本阶段建议**：先不做 P0.3.2，只做 P0.1 + P0.2 + P0.3.1 文档，效果展示与入口先行。

## 二、P1：效果闭环与优化建议接入

### P1.1 效果回写

| 序号 | 任务 | 说明 | 依赖 |
|------|------|------|------|
| P1.1.1 | 确认直播排品使用 product_script_id 后的落库点 | 排品保存 live_product.product_script_id 后，是否有地方写入 dy_product_script_usage；若无，在「直播复盘/效果上报」或排品保存时写入一条 usage（session_id、product_script_id、applied_time） | 无 |
| P1.1.2 | 效果数据回写 usage 的 effectiveness_score、conversion_rate、sales_amount | 直播复盘或效果上报时，按 session/商品维度回写或更新 dy_product_script_usage | P1.1.1 |

### P1.2 话术抽屉内「AI 优化建议」区块

| 序号 | 任务 | 说明 | 依赖 |
|------|------|------|------|
| P1.2.1 | 后端：按 scriptId（dy_product_script.id）获取优化建议 | 方案 A：若 product_script_version 存在 script_id 关联，先查 ProductScriptVersion by scriptId，再用其 id 调现有 getOptimizationSuggestions；方案 B：新增「按 dy_product_script.id 直接生成建议」的轻量接口（不依赖 product_script_version） | P0.3 决策 |
| P1.2.2 | 前端：抽屉内「优化建议」Tab 或折叠区块 | 展示建议列表；支持「按建议重新生成」→ 调用现有 regenerate 或新写「按建议重写并更新 dy_product_script」 | P1.2.1 |
| P1.2.3 | 「按建议重新生成」结果写回 dy_product_script | 若当前优化接口写的是 product_script_version/regenerated_version，增加「采纳到商品库话术」：更新 dy_product_script.script_content 并写版本历史 | P1.2.2 |

### P1.3 产出

- 效果数据有回写路径，P0 展示的「使用次数/效果分」可持续更新。
- 用户在话术管理抽屉内即可看到建议并一键「重新生成并采纳到当前话术」。

## 三、P2：体验与效率增强

| 序号 | 任务 | 说明 |
|------|------|------|
| P2.1 | 引用与推荐 | 话术卡片展示「已被 X 场引用」（P0 已含 referenceCount）；「推荐用于本场」需当前场次上下文，可放在直播排品页而非商品库抽屉 |
| P2.2 | 一键同步到当前场次排品 | 在话术抽屉或列表提供「同步到排品」：选择当前场次，将当前激活话术写入 live_product.product_script_id（需接口：按 productId 取激活话术 + 排品绑定） |
| P2.3 | 本商品内复制话术 | 支持「从本商品其他风格/类型复制内容」到当前风格（复制 script_content 生成新版本） |
| P2.4 | 跨商品复制话术 | 支持选择其他商品的某条话术，复制内容到当前商品当前风格（需权限：目标商品为本人或同机构） |
| P2.5 | 合规前置与高亮 | 生成/微调前可选「严格合规模式」；合规未通过时返回违规项简短说明或高亮片段，便于人工修改 |
