## ai 模块深度分析

### 1. 模块概述

**功能范围**：
- **知识库管理**：多知识库支持，文档上传、分块、去重、向量化存储
- **混合检索**：Milvus 向量 + Elasticsearch 全文 → RRF 融合 → Cross-Encoder 重排
- **内容生成**：文案、话术、脚本、报告等 AI 生成能力
- **AI 直播分析**：实时数据分析、诊断、建议（AiLiveReview）
- **爆款拆解**：短视频分析、成功因素提取（AiViralAnalysis）
- **知识进化引擎**：6 类 Agent 定时巡检（质量评分、时效性检测、自动分类、跨域共享等）
- **索引队列**：RabbitMQ 异步索引管理（viral_video、live_review、manual 等源类型）
- **运维监控**：调用日志、额度管理、性能统计、告警

**核心能力**：企业级抖音知识库服务 + 知识自进化 + 全链路性能监控

```java
// 1. 混合搜索（RRF 融合）
- 向量检索（权重 0.7）+ 关键词检索（0.3）
- RRF k=60（标准参数）
- 初筛 top 20 用于重排
- Redis 缓存 3600s

// 2. 文档处理管道
- 分块：512 字 + 50 重叠（脚本感知分块 vs 通用分块）
- 去重：MD5 完全一致 + SimHash 近似（海明距离<3）
- 标签打标：ChunkLabeler 自动分类
- 批量向量化 + 批量 ES 索引

// 3. 去重预览（dry-run）
- 分块后逐条检索判重
- 返回 skip/downweight/keep 统计与明细，不入库
- 前端 UX 友好

// 4. 知识反馈
- submitFeedback(docId, rating, comment) 
- 更新 boost_factor（权重调整）
- 支持按搜索模式分类反馈
```

**质量评估**：
- ✅✅ **混合搜索设计优秀**：权重可配、RRF 标准参数、重排支持、缓存管理完整
- ✅✅ **分块策略丰富**：脚本感知 + 通用，应用场景覆盖
- ✅ **CircuitBreaker 容错**：ResIlience4j 集成，Milvus/ES 不可用时降级
- ✅ **Redis 缓存**：查询缓存 + 嵌入缓存，缓存预热机制
- ⚠️ **异步导入**：KnowledgeBaseImportService 实现复杂，需关注导入大文件场景的 OOM 风险
- ⚠️ **向量维度固定**：代码中写死 CHUNK_SIZE=512，不支持动态调整

#### **3.3 向量存储集成**

**Milvus Collection 设计**：
```
Collection: ai_kb_documents
├─ Partition (按 kb_id)
├─ Field (entity_id: INT64, embedding: FLOAT_VECTOR[1024], metadata: JSON)
├─ Index: HNSW (COSINE 相似度)
├─ 定期清理：30 天未访问的 Collection 归档
```

**Elasticsearch Index 设计**：
```
Index: ai_kb_documents
├─ Analyzer: IK 中文分词 + 拼音分词
├─ Mapping: 
│  ├─ doc_id (keyword)
│  ├─ title (text + keyword)
│  ├─ content (text)
│  ├─ chunk_index (integer)
│  ├─ kb_id (keyword)
│  └─ created_at (date)
├─ Shards: 3 | Replicas: 1
```

**Redis Key 设计**：
```
ai:kb:{kbId}:search-cache:{queryHash}  TTL: 3600s
ai:kb:{kbId}:embedding-cache:{textHash}  TTL: 7200s
ai:evolve:scheduler:lock  TTL: 2h (分布式锁)
```

**质量评估**：
- ✅✅ **多引擎融合**：Milvus（语义）+ ES（关键词）+ Redis（缓存）完整组合
- ✅ **分区策略**：Milvus 按 kb_id 分区，支持多知识库并存
- ⚠️ **向量维度**：BGE-M3 1024D 写死，不支持动态调整（扩展到 DeepSeek 等需手动改）
- ⚠️ **缓存策略**：查询缓存基于 queryHash（可能出现 hash 碰撞），建议加 query 原文

### 5. 问题清单（需升级/修复）

#### **🔴 严重问题**

1. **API 规范不一致（15+ 个 GET 端点）**
   - 违反项目"统一 POST"规范
   - 位置：EvolveController, TaskModelConfigController, AiAdminInfraController, AiQuotaController, KnowledgeBaseController
   - 影响：与前端期望不符，可能导致认证失败
   - 修复：改为 POST

2. **前端关键 API 缺失**
   - 混合搜索：后端 hybridSearch 未暴露前端
   - 进化状态：getEvolveStatus 未编码成前端 API
   - 影响：功能无法使用
   - 修复：补全 ai.ts

3. **向量维度写死（1024D）**
   - 代码：VectorService.generateEmbedding 中 1024 写死
   - 风险：升级 embedding 模型（如 Ollama BGE-M3 → Huggingface BERT-2048D）需改代码
   - 修复：环境变量 AI_EMBEDDING_DIMENSION

4. **知识库导入 OOM 风险**
   - KnowledgeBaseImportService：大文件一次性加载到内存
   - 风险：50MB 文件 × 多用户并发导入
   - 修复：流式处理 + 分页加载

5. **分布式锁依赖 Redis 不可用**
   - EvolveScheduler 中 stringRedisTemplate 可能为 null
   - 若 Redis 不可用，多实例部署时可能多个实例同时执行进化任务
   - 修复：添加备用锁机制（数据库行锁）

#### **🟡 建议优化**

6. **缺少关键索引**
   - 优化：
     ```sql
     CREATE INDEX idx_kb_document_kb_status ON ai_kb_document(kb_id, status, create_time DESC);
     CREATE INDEX idx_call_log_user_time ON ai_call_log(user_id, create_time DESC);
     CREATE INDEX idx_evolve_task_status ON ai_evolve_task(status, create_time DESC);
     ```

7. **缓存策略不完整**
   - 问题：查询缓存基于 queryHash，易碰撞；缺少 embedding 缓存 TTL 配置
   - 优化：
     ```java
     // 在 ai.properties 中添加
     app.ai.cache.query-ttl-seconds=3600
     app.ai.cache.embedding-ttl-seconds=7200
     app.ai.cache.warm-up-enabled=true
     ```

8. **VO 类型安全性低**
   - 问题：部分接口直接用 Map<String, Object> 而非强类型 VO
   - 位置：EvolutionController, AiDashboardController
   - 优化：补全 VO 类（如 EvolveTaskSearchVO, DashboardParamsVO）

9. **前端状态管理过于分散**
   - 问题：KnowledgeDocumentsPage 有 10+ 个 useState，难以维护
   - 优化：迁移到 Zustand store（ai-knowledge.store.ts）

10. **循环调用可能导致死锁**
    - 进化引擎中：EvolveEngineService.runEvolution → enqueueIndex → IndexQueueConsumerService.consume
    - 若 RabbitMQ 不可用，任务可能堆积
    - 优化：添加最大重试次数、死信队列

11. **文档导入的元数据不完整**
    - KbImportReport 缺少导入用户、数据源（URL vs 文件上传）等元数据
    - 优化：补充 import_source、import_user_id、source_uri 等字段

12. **额度管理粒度太粗**
    - 当前：user_id + quota_date（日粒度）
    - 问题：高频用户无法精细控制
    - 优化：支持小时粒度配额（ai_call_quota_hourly）

#### **🟢 良好实践**

13. ✅ **混合检索设计优秀**
