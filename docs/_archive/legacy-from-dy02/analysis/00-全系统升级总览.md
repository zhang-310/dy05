## P0 紧急问题（需立即修复）

1. **auth**: 多租户数据隔离未在 Service 层强制执行
2. **auth**: InMemoryAuthTokenStore 非集群安全 → 迁移到 Redis
3. **ai**: 15+ GET 端点违反统一 POST 规范
4. **ai**: 分布式锁仅依赖 Redis，无备用方案
5. **live**: LiveMonitor/LiveProduct/LiveSessionData 缺 @SQLRestriction（逻辑删除失效）
6. **live**: AI 生成无重试/超时/降级机制
7. **shortvideo**: ContentAuditServiceImpl 3 个 TODO 未实现（审核功能不可用）
8. **shortvideo**: 上传接口无文件大小限制
9. **shortvideo**: Dashboard 数据全为零/造假
10. **script**: CSV 导入无权限检查（安全漏洞）
11. **copy**: 审批流程无角色验证
12. **dashboard**: DashboardService 实现完全缺失
13. **agent**: 缺少 VO 层，Controller 直接接收原始参数

## 跨模块共性问题

1. **@Transactional 缺失** — product/shortvideo/live 多处写操作无事务保证
2. **缓存策略不统一** — 仅 config 模块有缓存，其他高频查询模块缺失
3. **错误码同步** — 前端 error-codes.ts 需补全新增错误码
4. **VO 层不完整** — agent/douyinapi/dashboard 缺少 VO 定义
5. **异步处理可靠性** — 多处使用 @Async 而非消息队列，不可靠

## 分阶段升级建议

### 第一阶段：安全与数据完整性（1-2 周）
- 修复所有 P0 安全问题（权限检查、数据隔离、文件验证）
- 补齐缺失的 @SQLRestriction 和 @Transactional
- auth TokenStore 迁移到 Redis

### 第二阶段：功能补全（2-4 周）
- 实现 dashboard/attribution/sms 空壳模块
- 补全 agent VO 层和 LLM 集成
- AI 模块 GET→POST 统一
- shortvideo ContentAudit 实现

### 第三阶段：性能与可靠性（1-2 月）
- 缓存策略统一（Redis 缓存 + 热更新）
- 异步处理改造（@Async → RabbitMQ）
- storage 断点续传
- AI 容错（Resilience4j 集成）

### 第四阶段：可观测性与运维（2-3 月）
- ELK 日志集成
- Prometheus + Grafana 监控
- abtest 统计显著性检验
- 配置版本管理
