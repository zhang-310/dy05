# 产品库「产品话术」深度分析与升级建议

> 从产品经理/产品原型维度、技术架构设计立场对产品库内「产品话术」能力进行分析评估，并给出升级建议。  
> 与代码现状对齐：`module/product`（DyProductScript、ProductScriptService、ProductScriptController）、前端 `ProductScriptManageDialog`、`ProductPage`。

---

## 一、产品经理 / 产品原型维度

### 1.1 当前用户旅程与能力

| 环节 | 入口 | 能力 | 说明 |
|------|------|------|------|
| 商品库 | 产品列表 / 卡片 | 查看「话术(N)」 | 每个商品展示已有话术条数，点击进入话术管理 |
| 话术管理 | 产品行「话术」/ 卡片「话术」 | 右侧抽屉 | 左：生成设置（风格多选、人设、时长、知识库参考、多风格融合）；右：按风格分组的话术列表 |
| 生成 | 左侧「开始生成」 | 多风格生成 / 多风格融合 | 多风格=每条风格一条话术；融合=多种风格一条长话术（适合 30 分钟～2 小时） |
| 进度 | 同一抽屉 | SSE 流式进度 | 逐个风格或单次融合的进度与成功/失败 |
| 单条话术 | 每条话术卡片 | 激活、删除、版本历史、复制、**AI 微调** | 微调为对话式：输入修改要求 → AI 流式返回 → 采纳并保存 |
| 版本 | 版本历史弹窗 | 查看历史、回滚 | 更新话术前自动写入历史，可回滚 |

**已覆盖的产品诉求**：按风格/类型/时长生成、长话术融合多风格、人工微调 + AI 对话微调、版本可回滚、与直播排品引用（live_product.product_script_id）挂钩。

### 1.2 场景与角色

- **达人/运营**：在商品库维护「每个商品多套话术」，用于直播排品时选用；需要快速生成、微调、区分风格与时长。
- **产品目标**：护肤/彩妆类直播 GMV 千万级（见 `docs/00-业务范围.md`），话术需支撑高客单转化、专业形象、成分科普等。

### 1.3 痛点与缺口（产品视角）

| 痛点 | 说明 |
|------|------|
| **效果不可见** | 商品库话术列表内看不到「这段话术被用了多少场、转化如何」。效果评分/使用次数在另一套「话术版本库」（product_script_version）中，与当前抽屉数据未打通。 |
| **优化建议未接入** | 分析/建议/重新生成（ScriptOptimizationController）基于 scriptVersionId（product_script_version），商品库用户从 DyProductScript 入口无法直接看到「AI 优化建议」或「基于效果数据的推荐话术」。 |
| **引用关系不直观** | 排品引用 product_script_id（即 dy_product_script.id），但商品库话术卡片未展示「已被 X 场直播引用」或「推荐用于下一场」的引导。 |
| **批量与复用** | 批量生成有（BatchScriptGenerateDialog），但缺少「从模板/历史话术片段复用」「跨商品复制话术」等效率能力。 |
| **合规前置** | 生成与微调后均有合规校验并自动修稿，但缺少「生成前可选：严格合规模式」及违规高亮说明，对强合规场景支持可加强。 |

## 二、技术架构设计立场

### 2.1 数据模型现状

**主用表：dy_product_script（产品话术表）**

- 维度：`product_id` + `script_type`（seed/promotion/formal）+ `style`（单风格或 "fused"）。
- 同一维度下多版本：`version` 递增，`is_active` 标记当前使用版本。
- 字段：script_content、persona_id、duration、token_usage、source（ai/manual/import）、is_emotional（情绪价值话术时 product_id 可空）。
- 配套：`script_version_history` 在每次 update 前写入快照，支持回滚。

**另一套：product_script_version（商品话术版本表）**

- 定位：带效果评分、使用次数、转化率等，与 `dy_script_analysis_result`、`dy_optimization_suggestion`、`dy_script_regenerated_version` 等优化链路绑定。
- 关联：`script_id` 可关联「话术库」（与 dy_product_script 的对应关系未在代码中统一维护），导致**双轨**：
  - 商品库「话术」入口 → 仅操作 **dy_product_script**；
  - 话术优化/效果分析/建议/重新生成 → 基于 **product_script_version** 的 scriptVersionId。

**结论**：两套模型并存，业务上「商品库话术」与「效果/优化」未形成统一心智与统一入口，存在数据与体验割裂。

### 2.2 接口与依赖

- **ProductScriptController**：REST（save/list/update/delete/activate/rollback/get/count-by-products/list-by-style/active-by-style）+ 同步多风格生成 + **SSE**（generate-multi-style-sse、refine-with-ai-sse）。
- **权限**：所有接口依赖登录；写操作通过 product 的 owner_id（userId）校验，数据隔离清晰。
- **跨模块**：
  - **Product → Live**：ProductAiService 由 LiveProductAiServiceImpl 实现（生成/融合调用 LivePromptBuilder、LiveScriptGenerationServiceImpl）。
  - **Product → AI**：LlmClient、ModelChatStreamService、AiModelRepository 等用于 AI 微调流式输出；合规使用 ComplianceService。

### 2.3 架构评估

| 维度 | 评估 | 说明 |
|------|------|------|
| **扩展性** | 良好 | 风格/类型通过常量与配置扩展；融合、微调与单风格生成共用同一套 Prompt 与模型链路。 |
| **一致性** | 存在双轨 | dy_product_script 与 product_script_version 职责重叠（都是「商品话术版本」），但入口与 ID 体系不统一。 |
| **可观测** | 部分 | 有 rateLimit、日志；缺少「生成/微调」的 AI 调用计量与效果归因（如 token、模型、是否采纳）的统计上报。 |
| **性能与限流** | 已考虑 | 多风格数量上限、批量上限、SSE 超时与流式缓冲（路径含 -sse 避免整响应缓冲）已配置。 |

## 三、升级建议（按优先级）

### P0：统一话术版本与效果入口（产品 + 技术）

- **产品**：在商品库话术抽屉内增加「效果」视角——若当前话术对应或可关联到 product_script_version，展示「使用次数、效果评分、最近 N 场引用」；提供入口跳转「优化建议」或「基于效果推荐」。
- **技术**：
  - 明确 **dy_product_script** 与 **product_script_version** 的映射规则：例如「每次保存/激活时同步写入或更新 product_script_version，并以 script_id 指向 dy_product_script.id」，或收敛为单一主表（二选一需结合历史数据与排品引用做迁移方案）。
  - 若保留双表：在 ProductScriptService 层提供「按 dy_product_script.id 查询关联的 product_script_version 及效果摘要」的接口，供前端展示与跳转。

### P1：效果闭环与优化建议接入

- **效果回写**：直播排品使用某 product_script_id 后，在直播复盘/效果上报时回写「话术使用记录」到 product_script_usage 或等效表，并更新 product_script_version 的 usage_count/effectiveness_score（若已与 dy_product_script 打通）。
- **优化建议**：在话术管理抽屉中增加「AI 优化建议」区块——对应当前 DyProductScript（或关联的 ProductScriptVersion）调用现有 analyze/suggestions 接口，展示建议列表，并可触发「按建议重新生成」后写回 dy_product_script（或同步到 product_script_version），避免用户需要去「话术版本库」单独操作。

### P2：体验与效率增强（产品原型）

- **引用与推荐**：在话术卡片或列表上展示「已被 X 场引用」「推荐用于本场」等（依赖排品与场次数据）；支持「一键同步到当前场次排品」。
- **批量与复用**：支持「从本商品其他风格/类型复制话术」「从模板库插入片段」「跨商品复制话术结构」等，减少重复编辑。
- **合规与安全**：生成/微调前可选「严格合规模式」（更强校验与修稿策略）；对合规未通过项做简短说明或高亮，便于运营快速修改。

### P3：可观测与运营能力（技术）

- **AI 调用与采纳统计**：对「多风格生成 / 融合 / AI 微调」记录模型、token、是否采纳（微调后点击采纳并保存），便于成本与效果分析。
- **操作日志**：关键操作（生成、激活、删除、回滚、采纳微调）写入操作日志或审计表，便于排查与复盘。
- **与 AB 实验集成**：当前已有 assignScriptStyle（实验分配风格），可扩展为「实验分配话术版本」或「实验分配是否使用 AI 推荐话术」，形成数据驱动的选品选话术闭环。

### P4：文档与规范同步

- **文档**：在 `docs/development/04-文档代码同步清单.md` 或 `docs/architecture` 中补充「产品话术」数据模型说明、dy_product_script 与 product_script_version 的关系与使用场景、SSE 接口清单。
- **错误码**：若有产品话术专属错误码，保持 `ErrorCode.java`、`error-codes.ts`、`03-错误码注册表.md` 三处同步。

## 四、小结

| 维度 | 现状 | 建议重点 |
|------|------|----------|
| **产品/原型** | 生成、多风格/融合、AI 微调、版本历史已闭环；效果与优化入口缺失 | 统一效果展示、优化建议接入、引用与推荐、批量复用 |
| **技术架构** | 接口与权限清晰，流式与限流到位；存在 dy_product_script 与 product_script_version 双轨 | 统一或明确双表映射、效果回写与查询、可观测与日志 |
| **优先级** | — | P0 统一版本与效果入口 → P1 效果闭环与建议接入 → P2 体验增强 → P3 可观测与 AB |

以上建议在实施时需与「直播排品引用 product_script_id」「话术版本库/效果评分现有使用方」对齐，避免破坏现有能力，可先做「只读效果展示 + 优化建议入口」，再逐步推进双表统一或同步规则。
