## 一、与前一版分析的差异（必须读）

| 维度 | 08 / Phase6 叙述重点 | 迭代一复核结论 |
|------|----------------------|----------------|
| **安全** | Phase6：「`anyRequest().permitAll()` 形同虚设」 | 当前 `SecurityConfig` **有意**对 `/api/v1/**` 放行，**业务鉴权在 `AuthTokenFilter`**（未登录返回 REST `2001`）。风险主因是 **白名单与 Filter 双处维护、易漂移**，而非「完全无鉴权」。 |
| **契约** | 以人工清单 `docs/api/01` 为主 | 已增加 **P0 机器清单** `p0-endpoints.json`、**冒烟测试** `P0ApiContractSmokeTest`、**文档** [api/03-P0契约清单.md](../api/03-P0契约清单.md)、**OpenAPI 导出** `scripts/export-openapi.ps1`。对应 [quality/00](../quality/00-对外验收口径与三层100%.md) 的 **A 层**可逐步从「仅 01」扩展到「P0 JSON + OpenAPI 快照」。 |
| **工作流** | 08 曾列「工作流引擎」为缺口；后文 3.1 标为已补 | **以代码与迁移为准**：若存在 `SvWorkflowTemplate` 等实现，则 **08 第四节 4.1 中「短期补工作流」已过时**；迭代排期应改为 **端到端验收 + 页面接入**。 |
| **测试** | Phase6：集成/E2E 不足 | 已有 **黄金路径** GP-01/02（Playwright）、**JaCoCo 底线**、**P0 契约冒烟**（Testcontainers Redis，`disabledWithoutDocker` 时跳过）。**仍缺**：全量 ApiCoverage 启用策略、B 层对 `src/api` 的单独阈值。 |

## 三、六维复评（相对 Phase6 目标 8.0）

> 评分 **主观+相对**，用于**排序**而非对外背书；每项 1–10。

| 维度 | Phase6 基线（约） | 迭代一估计 | 变化说明 |
|------|------------------|------------|----------|
| **安全性** | 5.0 | **6.0** | 架构上 Filter 鉴权明确；仍需：**白名单单一来源**审计、密钥/生产配置核查（Phase6 原列项仍建议逐项过表）。 |
| **契约与可观测** | 5.5 | **6.5** | P0 JSON + 冒烟 + OpenAPI 导出 + 01/03 联动。 |
| **功能完整度** | 7.0 | **7.2** | 商品话术、合规加强、方舟/工具链等多处已落地；**未接页面/API** 仍拉低「可运营完整度」。 |
| **测试与质量** | 3.0 | **4.0** | P0 契约、黄金路径、JaCoCo 底线；**离 Phase6 目标 7.0 仍远**（核心业务单测/E2E 扩展）。 |
| **监控运维** | 2.0 | **2.5~3.0** | 若 Monitoring 仍为 stub，本项几乎无变化；需对照 `MonitoringController` 现状复测。 |
| **性能** | 6.0 | **6.0** | 08 所列 **P95 压测仍未执行**，维持。 |

**综合（粗）**：由 Phase6 的 **5.0** 抬至约 **5.5~6.0**（主因契约与部分业务闭环），距 **8.0** 仍差 **监控真实化、测试体系、压测** 三大块。

## 五、下一轮优先级（建议 2 周节奏）

### Wave A（本周可开）

1. **S1 白名单单一真相源**（P0，工作量小，降漂移风险）。  
2. **F1 孤儿页面处置**（P1，减少维护噪音与安全暴露面）。  
3. **V1 中选 3 条**做冒烟级手工/脚本记录（贴到 `docs/api/01` 或 quality 附录）。

### Wave B（紧随）

4. **C1 shortvideo 前缀策略**（文档 + OpenAPI + 新接口约束）。  
5. **监控非 stub 或显式「未实现」**（避免运营误判系统健康）。  
6. **Vitest 对 `src/api` 提高覆盖**（与 quality/00 B 层一致）。

### Wave C（专项）

7. **V2 性能压测**、**ApiCoverageTest 启用策略**、**GP-03+ 全栈 E2E**（`E2E_FULL_STACK=1`）。
