## 一、增量事实复核（以仓库当前代码为准）

### 1.1 鉴权白名单（S1）

- **`SecurityConfig`**：`private static final String[] WHITELIST` — 8 条 auth + messaging webhook。  
- **`AuthTokenFilter`**：`private static final Set<String> WHITELIST` — **同上 8 条**。  
- **额外行为**：Filter 另有 `app.openclaw.auth-free` 下 `/api/v1/ai/knowledge-base/openclaw/**` 逻辑；Spring Security 侧对 `/api/v1/**` 整体 `permitAll()`，与迭代一「业务鉴权在 Filter」一致。

**结论**：迭代一所述「双处维护易漂移」仍成立，但**当前无内容不一致**；优先做 **DRY（单一数组/配置）** 而非紧急安全事件。

### 1.2 监控模块（Monitoring）

- **`MonitoringController`** 类注释写明：已对接 `/metrics/realtime`（`MeterRegistry` + JVM）、`/health/*`（`HealthContributorRegistry`）；**部分接口仍 `stub=true`**（日志、告警确认等）。  
- **对 Phase6**：「20+ 接口全部 stub」需按**方法级别**更新为「**核心指标与健康度已接，辅助接口仍桩**」。

**六维影响**：**监控运维** 由迭代一 **2.5~3.0** 上调至约 **3.2~3.6**（主观，用于排序）。
