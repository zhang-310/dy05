# ADR-001: 所有 API 使用 POST 方法

## 状态
已采纳

## 背景
RESTful 通常推荐 GET/POST/PUT/DELETE 对应 CRUD 操作，但在实际业务中存在以下问题:
1. GET 请求的查询参数有长度限制
2. 复杂查询条件难以用 URL 参数表达
3. 查询参数可能包含敏感信息（出现在日志和浏览器历史中）
4. 统一使用 POST 简化前后端对接

## 决策
所有 API 统一使用 POST 方法，请求体为 JSON。

## 后果
- 正面: 简化开发，支持复杂查询，保护敏感参数
- 负面: 无法利用 HTTP 缓存，不符合 RESTful 惯例
