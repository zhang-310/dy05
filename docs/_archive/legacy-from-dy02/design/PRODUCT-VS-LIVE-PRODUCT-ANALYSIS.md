# 商品管理 vs 直播商品 — 深度业务逻辑分析

> 分析日期：2026-03-02

---

## 一、现状概览

| 维度 | 商品管理 | 直播商品 |
|------|----------|----------|
| **前端路径** | `/admin/product` | `/admin/live/product` |
| **菜单归属** | 独立菜单「商品管理」 | 直播 → 直播商品 |
| **后端模块** | `module/product` | `module/live` |
| **数据表** | `dy_product` | `live_product` |
| **实体** | DyProduct | LiveProduct |
| **API 前缀** | `/api/v1/product` | `/api/v1/live/product` |

---

## 二、数据模型关系

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                          dy_product（商品库）                                  │
│  商品主数据：名称、价格、库存、上下架、推荐、分类、图片等                      │
│  用户隔离：user_id                                                            │
└─────────────────────────────────────────────────────────────────────────────┘
                                    │
                                    │ product_id (FK 引用)
                                    ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│                          live_product（直播场次-商品关联）                     │
│  session_id + product_id → 某场直播选了哪些商品                               │
│  冗余字段：product_name（快照）                                               │
│  场次维度数据：sale_quantity、revenue、position（上播顺序）                   │
└─────────────────────────────────────────────────────────────────────────────┘
                                    │
                                    │ session_id
                                    ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│                          live_session（直播场次）                              │
└─────────────────────────────────────────────────────────────────────────────┘
```

**业务含义：**

- **商品管理**：管理「商品库」本身，是主数据，可被多场直播复用
- **直播商品**：管理「某场直播选了哪些商品」及该场次的销售数据，是「场次-商品」关联表

---

## 三、业务逻辑分析

### 3.1 设计文档的预期

| 文档 | 描述 |
|------|------|
| product 模块 | 商品全生命周期：录入 → 上下架 → 库存 → **直播选品** → 销售记录 |
| live 模块 | 场次创建 → **从 douyin 产品库选品** → 设置上播顺序 → AI 话术 → 数据同步 |

设计文档中 product 和 live 的职责是：

- **商品管理**：商品主数据（CRUD、上下架、库存、推荐）
- **直播选品**：在「场次详情」内，从商品库选品，添加到 live_product

### 3.2 当前实现的问题

- **live 文档写「产品数据来自 douyin 模块」**：实际实现中 product 模块使用 `dy_product`，没有独立的 douyin 产品表，属于文档与实现不一致。

- **直播商品作为独立菜单**：`/admin/live/product` 展示的是 `live_product` 的**扁平列表**（所有场次-商品关联混在一起），用户会看到：
  - 同一商品在不同场次重复出现
  - 无法按「场次」筛选（除非传 sessionId）
  - 与「在场次内选品」的预期不符

- **直播商品与商品管理的混淆**：两个菜单都带「商品」，但：
  - 商品管理：管理商品本身（增删改）
  - 直播商品：管理「场次-商品关联」（选品 + 销售数据）

## 四、是否符合业务逻辑？

### 4.1 数据模型层面：✅ 符合

- `dy_product` 作为商品主数据
- `live_product` 作为场次-商品关联，符合「主数据 + 关联表」的常见模式
- 直播商品通过 `product_id` 引用商品库，逻辑正确

### 4.2 功能职责层面：✅ 符合

- **商品管理**：商品主数据 CRUD、上下架、库存、推荐、销售历史
- **直播商品**：场次选品、上播顺序、场次销售数据

职责划分清晰，无功能重叠。

### 4.3 用户入口与操作流程：⚠️ 存在冲突

| 问题 | 说明 |
|------|------|
| **入口重复感** | 用户看到「商品管理」和「直播商品」两个菜单，容易误以为都是管商品 |
| **直播商品独立列表不合理** | 设计文档期望「在场次内选品」，但当前是「直播商品」独立页，展示所有 live_product 的扁平列表 |
| **选品入口缺失** | 场次详情页应提供「选品」入口，从商品库选品并加入 live_product，当前实现可能未体现 |

## 五、结论与建议

### 5.1 结论

| 维度 | 结论 |
|------|------|
| **数据模型** | 业务逻辑正确，无冲突 |
| **功能职责** | 商品管理 = 主数据，直播商品 = 场次-商品关联，符合设计 |
| **用户入口** | 存在混淆，直播商品独立列表与「场次内选品」不符 |

### 5.2 建议

1. **菜单命名优化**
   - 「商品管理」：可保持或改为「商品库」
   - 「直播商品」：改为「直播选品」或「场次选品」，避免与「商品管理」混淆

2. **直播商品入口调整**
   - 将「直播商品」从独立菜单改为**场次内的子功能**：进入直播场次详情 → 选品 Tab
   - 或保留独立菜单，但增加「按场次筛选」能力，默认展示「当前场次」的选品列表

3. **选品流程**
   - 场次详情页应提供「添加商品」按钮，从商品库（dy_product）选择，写入 live_product
   - 直播商品列表应支持按 session_id 筛选，默认展示某场次的选品

4. **文档同步**
   - 将 live 模块文档中「产品数据来自 douyin 模块」改为「产品数据来自 product 模块（dy_product）」

## 六、附录：当前 API 与数据流

| 操作 | API | 数据表 |
|------|-----|--------|
| 商品列表 | POST /product/search | dy_product |
| 商品保存 | POST /product/save | dy_product |
| 直播商品列表 | POST /live/product/search | live_product |

live_product 的 product_id 引用 dy_product.id，无数据库外键约束，由应用层校验。
